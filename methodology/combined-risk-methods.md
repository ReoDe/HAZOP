# 위험도분석 결합 방법론 카드

HAZOP, FMEA, MLD, 운전경험, STPA, LOPA 등을 결합해 초기사건(IE)이나 위험을 도출한 방법론과 경험을 카드 한 장씩으로 모읍니다. 새 사례를 찾으면 맨 아래 템플릿을 복사해 카드를 덧붙이고 색인 표에 한 줄을 더합니다.

- 처음 작성: 2026-11-08. 근거 조사는 [초기사건-HAZOP 조사](../기획서/초기사건-HAZOP-조사.md)에 있습니다.
- 확인 표기: **원문**은 해당 절을 직접 읽음(대부분 키워드 주변 절만), **초록**은 초록만, **2차**는 요약·인용만 봄. [추론]은 작성자 해석, [일반지식]은 출처 없이 쓴 일반 지식입니다.
- "앱 적용" 칸은 모두 [추론]입니다. 구현 결정이 아닙니다.
- 용어 정의는 [조사 보고서 §2](../기획서/초기사건-HAZOP-조사.md#2-용어와-정의-출처)를 따릅니다. 미국 원전 용어는 NRC 정의(NUREG-2122 등)를 우선합니다.

## 공통 교훈 (카드 전체에서 반복된 것)

1. 원자로 IE 식별에서 자주 보이는 구성은 "귀납(HAZOP 또는 FMEA) + 연역(MLD) + 문헌·운전경험 대조"의 3중 구조입니다 [추론]. M04, M08이 이 구조이고, MSFR·ITER(M03)는 귀납+연역 2중입니다. RG 1.254와 IAEA SSG-3 Rev.1은 이 조합을 권고합니다(원문).2. HAZOP 원인 하나는 PRA IE 하나가 아닙니다. 플랜트 응답·성공기준·시간·완화계통 영향이 비슷한 것을 묶는 그룹화가 꼭 필요합니다(M01, M03, M04, M05).
3. IE 단위를 먼저 정해야 합니다 [추론]. 대상 범위(MSRE 대 일반 액체연료 MSR)와 정의 수준이 다른 두 문헌에서 IE 수가 약 26개와 약 140개로 달랐습니다(KNS 22A-311 재인용, 2차).
4. 계통 성격에 따라 기법을 나눕니다. 기계·공정 계통은 HAZOP, 전기·제어 계통은 FMEA, 디지털 제어 로직은 STPA가 강합니다(M01, M11).
5. 기록 품질이 결과를 좌우합니다. 비완화 결과, 자동/운전원 구분, 구간 경계 결과 기록이 없으면 사건 시퀀스 조립과 HRA 연결이 어려워집니다(M01, M12).

## M01. PHA-to-PRA (HAZOP → 사건수목·고장수목)

| 항목 | 내용 |
| --- | --- |
| 출처 | Krahn, Chisholm, Sowder, PSAM14 paper 382 (2018, 원문). Chisholm, Krahn, Afzali, Harvey, PSAM14 paper 383 (2018, 원문). EPRI 사업명은 이후 Safety-in-Design(SiD)으로 바뀜(2024 발표자료, 원문). 같은 변환 규칙을 무료 공개본 EPRI 3002015752(2019, §2.3.6~2.3.7)에서 원문으로 확인했고, 워크시트에서 사건수목·고장수목·기본사건 표까지 이어진 전체 사례는 EPRI 3002018340(2020, 원문 일부)에 있음 |
| 언제 쓰나 | 상세 P&ID가 있고, 정성 위험분석 결과를 PRA 모델로 이어 쓰고 싶을 때. 설계 정보가 적으면 HAZOP 대신 What-if를 씀 |
| 입력 | 계통을 나눈 구간(노드), 공정 변수와 가이드워드, 설계 문서 |
| 출력 | 편차별 원인·비완화 결과·보호수단·조치 표 → IE 후보, 사건수목 표제, 최종상태, 고장수목 구조 |
| 단계 | ① 구간 분할: 구간마다 주기능 하나, 운전조건이 비슷한 것끼리, 구간 interface 문서화 ② 변수 × 가이드워드로 편차 생성 ③ 편차마다 원인, 비완화 결과, 보호수단(계기 태그 포함), 조치 기록 ④ 원인 중 일부를 IE로, 보호수단을 사건수목 표제로, 결과를 최종상태로 옮김 ⑤ 표제 실패확률은 FT로 산출하고 FMEA 고장모드를 기본사건으로 씀 |
| 결합 논리 | HAZOP이 상향식으로 원인과 결과를 망라하므로 IE 식별의 포괄성을 높입니다. 같은 기록을 설계 피드백과 PRA에 함께 씁니다 |
| 장점 | 설계 초기에 시작할 수 있음. 기존 문헌에 없던 시나리오가 나옴(MSRE off-gas 계통 HF 생성) |
| 단점 | 변환 규칙이 개념 수준이고 자동화 규칙은 아님. 여러 구간의 결과를 합쳐야 사건수목 하나가 완성됨. 전기·제어 계통은 FMEA보다 세부 수준이 낮음 |
| 실무 사례 | MSRE 회고 적용: 구간 20개 이상, off-gas 이탈 35개, 기기냉각 38개(PSAM14 383 기준. EPRI 3002018340은 36개·40개로 적음), 동결밸브 FMEA 고장모드 170개 이상. 상용 위험분석 소프트웨어 사용. EPRI 3002018340은 PRA 모델에 쓴 워크시트 행을 굵게 표시함 |
| 앱 적용 [추론] | ⑤ 워크시트에 비완화 결과, 보호수단의 자동/운전원 구분, 구간 간 결과 연결을 구조화 필드로 두면 변환 규칙을 데이터 규칙으로 옮길 수 있음. 스키마 설계안의 `safeguards[].role`, `consequence_refs`와 연결 |

## M02. 귀납 + 연역 (HAZOP + MLD)

| 항목 | 내용 |
| --- | --- |
| 출처 | Chisholm, Krahn, Fleming, Prog. Nucl. Energy 129, 103507 (2020, 초록). MLD 데이터셋 Mendeley DOI 10.17632/xdvzvcmsgh.1(내용 미확인). 구조 설명은 KNS 22A-311 (2022, 원문) 인용 |

| 장점 | 완전성 논증 가능. 여러 POS와 인벤토리를 체계적으로 다룸 |
| 단점 | MLD 최하단 정의가 분석자 판단에 의존. 두 결과를 합치는 규칙이 문헌마다 다름. 본문에서 실제 결합 방식은 확인하지 못함 |
| 실무 사례 | MSRE: POS 5개(출력운전, 충전, 정지, 연료염 처리, 정비), 인벤토리 3곳(연료염, off-gas, 연료처리), PIE 약 26개(2차 인용) |
| 앱 적용 [추론] | HAZOP 원인을 MLD 말단 가지(기능 상실 범주)에 대응시키는 역추적 표를 두면, 후보가 하나도 없는 가지가 바로 드러남 |

| --- | --- |
| 출처 | Oeing, Holtermann 외, preHAZOP (Chem. Ing. Tech. 2023, DOI 10.1002/cite.202200222, GitHub README 원문). Li, Zhao, HAZOP 지식그래프 (ESCAPE-34, 2024, 원문 초록·결론). Elhosary, Moselhi, ITcon 29 리뷰 (2024, 원문 요약·결론). Lee 외, Safety Science 194 (2026, 2차) |
| 언제 쓰나 | 기계가 읽을 수 있는 P&ID와 과거 HAZOP 기록이 있을 때 |
| 입력 | DEXPI P&ID, 시뮬레이션 값, 과거 HAZOP 보고서 |
| 출력 | 규칙 기반 HAZOP 표, 누락 원인-결과 링크 후보 |
| 단계 | ① P&ID를 그래프로 변환 ② 미리 정의한 시나리오 패턴(preHAZOP은 15개)을 그래프에서 탐지 ③ 과거 HAZOP 보고서에서 개체를 인식해 KG 구축 ④ 링크 예측으로 누락 원인-결과 제안 |
| 결합 논리 | 결정적 그래프 규칙이 재현 가능한 1차 후보를 만들고, KG와 학습 모델이 과거 경험으로 누락을 보완 |
| 장점 | 재현 가능. 표준 P&ID 형식 사용 |
| 단점 | 시나리오가 미리 정의한 패턴으로 제한. HAZOP KG 연구는 계장·제어 정보를 넣지 않음. LLM 단독 생성은 의미 타당성이 낮다는 보고(2차, 수치 미확인) |
| 실무 사례 | HAZOP KG: 엔티티 2,988개, 관계 72종, 정답 약 67%가 상위 10개 예측 안 |
| 앱 적용 [추론] | 우리 앱의 ①~④ 흐름과 가장 가까운 공개 구현. "규칙·KG로 후보 → AI 서술 → 사람 확정" 순서의 근거. 편차 → IE까지 그래프로 추적한 원자력 구현은 찾지 못함 |

## M16. 시나리오 번호로 잇는 DOE 위험성 평가

| 항목 | 내용 |
| --- | --- |
| 출처 | DOE-HDBK-1100-2004(2022 재확인, 원문 일부). DOE-STD-3009-2014(본문 미열람, DOE 설명회 자료와 요구사항표로 확인). DOE-STD-3009-94 CN3 표 3-1(제3자 전사본, 2차). INL MARVEL ECAR-6440(INL/MIS-23-75407, 원문 일부) |
| 언제 쓰나 | 여러 위험분석 양식(HAZOP, What-if, FMEA, 고장수목)을 한 시설에 함께 쓰고, 그 결과에서 대표 사고(DBA)를 골라야 할 때 |
| 입력 | 위험 식별 요약(형태·종류·위치·총량), 공정 구간, 운전 절차 |
| 출력 | 위험성 평가표(비완화 결과·발생가능성·위험도 구간·예방/완화 조치), DBA 후보 |
| 단계 | ① 위험 식별과 등급분류 ② HAZOP·What-if·FMEA로 시나리오를 만들고 시나리오 번호를 매김 ③ IE마다 예방·완화 조치가 없다고 본 비완화 결과를 수신자(시설 작업자, 인접 작업자, 공중)별로 매김 ④ 발생가능성 구간(Anticipated, Unlikely, Extremely Unlikely, Beyond Extremely Unlikely)과 위험도 구간(I~IV) 지정 ⑤ 예방 조치로 가능성, 완화 조치로 결과를 다시 추정 ⑥ 사고 유형(화재, 폭발, 누출 등)마다 대표 사고와 고유 사고를 DBA로 고름 |
| 결합 논리 | HAZOP·What-if·FT 단절집합 양식에 Scenario 열을 두어 같은 사고를 서로 참조합니다(FMEA 양식에는 Scenario 열이 없음). DOE-HDBK-1100은 HAZOP 보호 열이 고장수목에서 IE와 AND 게이트로 만나는 보호계통 입력이 된다고 적었습니다 |
| 장점 | 공개 정부 문서라 양식을 그대로 참고할 수 있음. 정성 구간이 분명해 위험도 필드로 옮기기 쉬움 |
| 단점 | 원자로가 아닌 핵시설 기준이라 빈도 경계가 원자력발전소 PRA(NEI 18-04 AOO/DBE/BDBE)와 다름. 2014판 본문은 직접 읽지 못함 |
| 실무 사례 | INL MARVEL 마이크로로: 사고진행 분석표에 IE, 사건 시퀀스, 최종상태, 수신자별 결과, 위험도 구간, 후보 안전 SSC를 한 행에 담음(IE 식별은 기존 목록 검토와 FMEA) |
| 앱 적용 [추론] | ⑤ 결과에 시나리오 ID를 두어 한 편차 행의 여러 원인을 나누고, HAZOP 행과 나중의 IE 후보를 같은 번호로 잇는다. FMEA 행에는 앱이 시나리오 ID 열을 따로 더해야 한다. DOE 빈도 구간 수치는 원전 IE에 쓰지 않는다 |

## M17. 첫 고장(IPF) 범주 → SPAR IE 그룹 2단 분류

| 항목 | 내용 |
| --- | --- |
| 출처 | INL/NRC RADS "Initiating Events Coding Guidance"(원문, 범주 정의). INL/EXT-21-65055 "Industry-Average Performance for Components and Initiating Events: 2020 Update" 표 4와 부록 C(원문). INL/RPT-24-79433 "Initiating Event Rates: 2023 Update"(원문 일부) |
| 언제 쓰나 | 경수로에서 원인 단위 IE 후보를 PRA IE 그룹으로 묶을 때. 일반 IE 목록과 대조할 때 |
| 입력 | HAZOP 원인(첫 고장), 노형(PWR/BWR), 운전상태 |
| 출력 | 원인별 IPF 범주 코드, PRA IE 그룹(SPAR 코드) |
| 단계 | ① 원인을 IPF 범주(위험 중요 대분류 B~P의 26개 범주와 일반과도 Q 범주)로 분류 ② IPF 범주를 SPAR IE 코드(LOCA 크기별, LOCHS, LOMFW, LOSWS, LOCCW, LOIA, LOOP, LOAC, LODC, TRANS 등 49개)에 대응 ③ 크기·유량 경계는 부록 C 정의로 판정 ④ 대응이 애매한 것(예: CCW 상실)은 사람이 정함 |
| 결합 논리 | 운전경험 코딩 체계(IPF)는 "정지를 일으킨 첫 고장" 단위라 HAZOP 원인과 단위가 같고, SPAR IE 목록은 PRA 사건수목 단위입니다. 둘을 잇는 대응표가 원인 단위 후보 → PRA 그룹의 두 단계를 만듭니다 [추론] |
| 장점 | 공개 미국 정부 자료. 범주 정의가 포함·제외 문장으로 쓰여 있어 분류 규칙으로 옮기기 쉬움. 노형 구분과 크기 경계가 있음 |
| 단점 | 두 표를 잇는 공개 대응표가 없어 직접 만들어야 함. Q 범주 수가 문서 본문(22개)과 추출 결과(23개)에서 다름. 출력운전 중 IE 위주이고 정지 중은 LOOP만 있음. 발전소마다 실제 모델링하는 IE 집합이 다름 |
| 실무 사례 | RADS 코딩 지침과 SPAR 표 4는 모두 NUREG/CR-5750 정의를 인용함(2차). 두 체계를 이어 쓴 공개 사례는 찾지 못함 |
| 앱 적용 [추론] | 경수로 기본의 일반 IE 목록과 그룹표로 씀. 그룹 행에 코드, 이름, 분류, 노형, 운전상태, 정의·경계, 모이는 IPF 범주, 도전받는 안전기능, 묶은 근거, 출처 판을 둠. 빈도 열은 두지 않음. 내보내기는 Open-PSA MEF 2.0의 IE·IE 그룹 요소가 이 2단 구조를 손실 없이 담음 |
