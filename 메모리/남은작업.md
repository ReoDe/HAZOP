## 결정 반영 대기(2026-11-06 사용자 결정)

- T2 W8-B: GPL 전용 Qt 모듈 빌드 제외
- 고지 원문 내려받기: 파일명·출처·크기 목록을 사용자에게 보여 승인받은 뒤 동봉(Qt WebEngine·Chromium, UCRT, VC++ 재배포 조건 등)

- pdfplumber를 전용 빌드 venv·배포본에 포함(설치 전 목록 확인, 의존성 고지 추가)
- 반투명 관계선: 보조 선은 예외 기록, 색만으로 의미를 전하는 선은 3:1로 조정
- T3 W4 착수 때 OpenCV·Tesseract 설치 항목 확인 후 설치(T3 D2)

- ['출력화면 AX' 데모 분석](../디자인/출력화면AX-데모분석.md)을 바탕으로 HAZOP 고유 화면(구간 선택, 편차 목록, 경로 강조, 워크시트 검토) 설계
- 참고 화면 일부의 MVP 포함 여부, 질의응답(자유 질문) 기능의 범위 포함 여부, 디자인 토큰 값 결정(토큰 정리는 [디자인 체계 트랙](../docs/2026-11-05-design-system/README.md))

## 1차 슬라이스 구현 후속

- 2차 입력 어댑터(PDF·PNG/JPG)와 drawio 결과 대비 정확도 평가: 작업 공간 [docs/2026-11-05-input-adapter](../docs/2026-11-05-input-adapter/README.md)에서 관리
- T3 알려진 한계 4건: 합성 점선 경계 사례(T3 D6). W5 또는 실제 도면 확보 뒤 처리
- 도면 간 continuation 연결
- 체크밸브 flow_direction 기준 작성 규칙 확정
- 포트 규칙
- 경로 탐색에 밸브 정상 위치 반영(④)
- 실제 마우스 조작·Edge 브라우저 수동 확인
- 실제 draw.io 압축 저장 파일 검증
- ④ 실제 Claude API(`--live`) 실행 검증: `output_config` json_schema·`fallbacks`("default", beta `server-side-fallback-2026-07-01`) 수용 여부와 비용 확인. 고정 응답이 없는 후보 20건 채우기
- ④ AI 서술 문장 속 설비명 자동 대조(현재는 구조 필드 검증과 AI 자기 신고만 있으며, 결과의 `drawing_only_check`에 한계를 명시)
- ④ 원전용 위험도 기준(강도 범주·정량 빈도) 확정 후 임시 기준표 교체
- ④ 설계 의도·패턴·고정 응답 내용 사용자 확인(현재 [일반지식]·[추론] 샘플)
- ④ 탐색 2단계에서 `max_depth` 기록의 `not_expanded` 목록 보강(사소)
- ⑤ 설계보완 후보 확정 화면
- 연속 공정용 KOSHA HAZOP 지침 확보 검토
- `run_samples.py`는 `출력/`에 등록 경로 결과를 덮어씀(`--samples` 결과와 같은 위치). 사용 시 주의 또는 출력 경로 분리 검토
- `analyze.py`는 실행마다 `출력/분석/<구간>/`에 실행 폴더를 누적(실행 기록 보존 의도). 정리 정책 검토
- `출력/지식그래프/` 아래 이전 형식 산출물(옛 경로 파일·이전 버전 폴더)의 정리 정책 미정

## 후속 기능 (MVP 검증 후)

- 웹 등록 화면(파일 선택·드래그 앤 드롭), 개정 충돌 판정, 메타데이터 수정 이력
- 선택 구간 재처리, 웹 원본 대조·수동 편집, AI 보정 제안
- 실제 자료형(PDF·이미지·CAD 등) 읽기 어댑터: PDF·이미지는 [입력 어댑터 트랙](../docs/2026-11-05-input-adapter/README.md), CAD는 후속
- 여러 도면·문서의 동일 대상 통합과 값 충돌 관리
- AI 연결 확장: Claude 팀 구독제 활용 방식 확인·구현, 로컬 LLM 연결
- 후보 판단 화면, 자동 구간 분할, 기동·정지 모드
- ⑤ 검토 화면, 편차별 확정·이력, 개선 조치·자료 요청 메모, 변경 알림과 구간 전체 재검토(영향 없음 판정 포함)
