## 1차 슬라이스 구현 후속

- 2차 입력 어댑터(PDF·PNG/JPG)와 drawio 결과 대비 정확도 평가
- 도면 간 continuation 연결
- 체크밸브 flow_direction 기준 작성 규칙 확정
- 포트 규칙
- 경로 탐색에 밸브 정상 위치 반영(④)
- 실제 마우스 조작·Edge 브라우저 수동 확인
- 실제 draw.io 압축 저장 파일 검증
- ④ 실제 Claude API(`--live`) 실행 검증: `output_config` json_schema·`fallbacks`("default", beta `server-side-fallback-2026-07-01`) 수용 여부와 비용 확인. 고정 응답이 없는 후보 20건 채우기
- ④ AI 서술 문장 속 설비명 자동 대조(현재는 구조 필드 검증과 AI 자기 신고만 있으며, 결과의 `drawing_only_check`에 한계를 명시)
- ④ 원전용 위험도 기준(강도 범주·정량 빈도) 확정 후 임시 기준표 교체
- ④ 설계 의도·패턴·고정 응답 내용 사용자 확인(현재 [일반지식]·[추론] 샘플)
- ④ 탐색 2단계에서 `max_depth` 기록의 `not_expanded` 목록 보강(사소)
- ⑤ 설계보완 후보 확정 화면
- 연속 공정용 KOSHA HAZOP 지침 확보 검토
- `run_samples.py`는 `출력/`에 등록 경로 결과를 덮어씀(`--samples` 결과와 같은 위치). 사용 시 주의 또는 출력 경로 분리 검토
- `analyze.py`는 실행마다 `출력/분석/<구간>/`에 실행 폴더를 누적(실행 기록 보존 의도). 정리 정책 검토

## 데스크톱 인터페이스 후속

- 독립 실행 뷰어 색상을 앱과 맞추기
- 패키징: LibreOffice 내장 Python이 아닌 전용 venv 필요, `scripts/*.py` importlib 로딩 재검토(`hazop/app/data.py`), 신뢰 경계·Pretendard 글꼴([인터페이스 §9](../기획서/인터페이스.md))
- `os.link` 배타적 생성은 NTFS에서만 확인됨
- API 오류 메시지에 일부 필드명 노출
- 권고 후속 조치 관리는 나중에
- 그래프 알고리즘(비P&ID 성분 통합, 옵시디언식 그래프 뷰): 작업 공간 [docs/2026-11-05-knowledge-graph](../docs/2026-11-05-knowledge-graph/README.md)에서 관리

## 후속 기능 (MVP 검증 후)

- 웹 등록 화면(파일 선택·드래그 앤 드롭), 개정 충돌 판정, 메타데이터 수정 이력
- 선택 구간 재처리, 웹 원본 대조·수동 편집, AI 보정 제안

- AI 연결 확장: Claude 팀 구독제 활용 방식 확인·구현, 로컬 LLM 연결
- 후보 판단 화면, 자동 구간 분할, 기동·정지 모드
- ⑤ 검토 화면, 편차별 확정·이력, 개선 조치·자료 요청 메모, 변경 알림과 구간 전체 재검토(영향 없음 판정 포함)
