# ③ 지식그래프 화면 — 시각 규칙과 배치

[그래프 활용 기획 §2·§4·§5](../기획서/그래프활용.md) · [그래프 조사 §1](../기획서/그래프조사.md) · [인터페이스 §4](../기획서/인터페이스.md) · [시안 README](시안/README.md) · 시안 [`시안/kg-graph-mockup.html`](시안/kg-graph-mockup.html)

그래프활용 §5.1이 "디자인 담당 필요"로 남긴 지식 노드 색·배지 등 시각 규칙을 정합니다. 화면은 Obsidian 그래프 보기처럼 P&ID 레이어와 지식 레이어를 한 캔버스에 보여 주되, 사용자가 **근거 있음 / 미확인·가설 / 충돌 / 계산 제외**를 바로 구분할 수 있게 하는 것이 목표입니다([공통 원칙](../기획서/전체기획.md#principles)).

- 시안 데이터: `출력/지식그래프/kg-SNP-SAMPLE/v-43034b88b9c9/knowledge_graph.json`(current.json이 가리키는 버전), 같은 kg_version의 `algo/…/entity-node-001-r2/algo_result.json`, `데이터/지식/SNP-SAMPLE/link_candidates.csv`, `출력/그래프/SNP-M-102/graph.json`을 발췌해 HTML 안에 넣었습니다. 모두 가상 샘플입니다.
- 시안 렌더러: force-graph를 인라인하지 않고 **SVG + 간이 힘 계산**(결정적, 시안 전용)으로 대신했습니다. 실제 구현은 그래프활용 §5.2대로 force-graph(Canvas)입니다. 아래 규칙은 Canvas에서도 그릴 수 있는 것(채움·테두리·파선·글자)만 씁니다.

## 1. 노드 색 그룹

### 1.1 층 구분: 모양이 먼저, 색은 보조

| 층 | 모양 | 이유 |
| --- | --- | --- |
| P&ID 층 | **원** | ② 'P&ID 구조' 탭과 같은 모양. 도면 오버레이와 색 토큰 공유(그래프활용 §5.1) |
| 지식 층 | **각진 도형**(종류별로 다름) | 색을 못 구분해도 "도면에서 온 것 / 문서에서 온 것"이 모양으로 갈림 |

- 색을 고른 기준: 기존 데이터 색(파랑·청록·하늘·남색·초록·보라·호박·빨강·주황·자홍)이 쓰지 않은 색상 영역(슬레이트·황토·분홍·연두·적갈)에서 골랐습니다. 문서와 문서 조각은 "조각은 문서의 일부"라는 관계를 살려 같은 슬레이트 계열에 명도만 다르게 두고, 모양(쪽 vs 사각형)과 크기로 구분합니다.
- UI 파랑 `--ui`는 노드 색에 쓰지 않습니다. 선택 표시(파란 고리)에만 씁니다(인터페이스 §4.1).
- 남는 약점: 설정치 분홍 `#be185d`는 ④·⑤의 보호수단 자홍 `#c026d3`과 색상이 가깝습니다. ③에는 보호수단 강조가 없어 같은 화면에 함께 나오지 않지만, 화면을 오가면 연상될 수 있습니다. 계장 `#0ea5e9`의 대비 부족은 기존 토큰 문제로, 이번 범위에서 바꾸지 않았습니다(다른 화면과 공유하는 값이라 바꾸면 ②④⑤에 영향).

### 1.3 크기 (A3)

- 반지름 = `min(15, 4.5 + 2.3·√연결 수)`. 연결 수는 V5 차수(algo_result `A3.degree`)입니다. 배관 구간은 크기 고정(3.5), 도면 연결점은 6, 계산 제외 노드는 6.5로 고정합니다(V5에 없어 차수가 없음).
- "구간 접기"를 켜도 설비 차수는 같습니다(algo_result `A3.fold_limit`). 크기 식은 바꾸지 않습니다.

### 1.4 색 보기 전환

캔버스 위 알약 탭 `종류 | A1 상·하류 | A5 연결 성분`으로 채움 색만 바꿉니다. **모양은 어느 보기에서도 바뀌지 않으므로** 층·종류 구분은 유지됩니다.

| 보기 | 채움 색 | 비고 |
| --- | --- | --- |
| 종류(기본) | §1.2 | — |
| A1 상·하류 | §3.2 방향 색. 지식 노드·관계는 35%로 흐림 | A1은 P&ID 레이어만 계산(그래프활용 §4.2) |
| A5 연결 성분 | 성분 순서대로 `--comp-1`~`--comp-6`(Okabe–Ito 팔레트에서 고름), 7번째부터 회색 | 범례에 "성분 n · 크기"와 V1 기준 성분 수(9개)를 함께 표시 |

### 1.5 다크 모드

**지원하지 않습니다(MVP).** 현재 앱(`tokens.py`)과 ①②④⑤ 시안에 다크 모드가 없어, ③만 어둡게 하면 화면 사이 일관성이 깨집니다. Obsidian 그래프의 어두운 바탕은 따르지 않습니다. 대신 모든 색을 CSS 변수로 두었으므로, 후속에 다크 모드를 넣을 때는 `:root[data-theme=dark]`에 같은 이름으로 값만 다시 정하면 됩니다. 그때 지식 층 색은 어두운 바탕 대비를 다시 재야 합니다(현재 값은 흰 바탕 기준).

## 2. 상태 표시

색만으로 구분하지 않고 **선 모양(실선/파선) + 불투명도 + 글자 표시**를 함께 씁니다.

| 상태 | 판정 필드 | 노드 표현 | 관계 표현 | 기본 표시 |
| --- | --- | --- | --- | --- |
| 확인됨 | `knowledge_status: confirmed`(+관계는 `link_status: confirmed`), `compute_view.v4: true` | 채운 도형 + 흰 테두리 | 실선 | 보임 |
| 미확인 | `knowledge_status: unknown` | **흰 속 + 종류 색 파선 테두리(3·2) + 50% 불투명** + 글자 "미확인 · 계산 제외" | 파선(5·4) + 50% | **토글 "미확인·가설 항목"을 켤 때만** |
| 가설 | `knowledge_status: hypothesis` | 미확인과 같은 모양 + 글자 "가설 · 계산 제외" | 같음 | 같음 |
| 후보 링크 | `link_candidates.csv`의 `link_status: candidate` | — | 파선(5·4) + 50% + 가운데 글자 "후보" | **토글 "후보 링크"를 켤 때만** |
| 기각 | `link_status: rejected` | — | 그리지 않음(CSV 이력에만) | 안 보임 |
| 재확인 필요 | `recheck`(§3.2 재확인), `validation.unknowns` | — | **호박색 파선(`--kg-flag`) + "⟳ 재확인 필요"** | 토글. 개수는 도구줄 칩 "재확인 필요 n"으로 늘 보임 |
| 근거 없음 | `has_source: false` | 노드 오른쪽 위 빨간 글자 "∅ 근거 없음" | 상세 패널 배지 | 해당 항목이 보일 때 |
| 충돌 | `conflict_with` 비어 있지 않음 | **빨간 고리(`--kg-conflict`) + "≠ 충돌"** | — | 보임(계산 포함 항목이라도 충돌은 늘 표시) |
| 고아 (A2 a) | `A2.orphans` | **호박색 두꺼운 고리(`--kg-flag`, 3px) + "고아"** | — | 토글 "고아 강조" |
| 근거 공백 (A2 b) | `A2.evidence_gaps` | 호박색 고리 + "근거 공백" | — | 토글 "근거 공백 강조" |
| 지식 입력 없음 | `A2.no_knowledge_input` | 캔버스 표시 없음. 상세 패널에 호박 글자 "지식 입력 없음 — '해당 없음'이 아님" | — | 상세에서만 |
| 선택 | — | UI 파랑 고리(3px) | 관계는 파랑 굵은 선 | — |
| 호버 | — | 호버 노드와 이웃만 진하게, 나머지 `--hl-dim`(16%) | 호버 노드에 닿은 관계만 진하게 | — |

- 후보·미확인·가설·재확인 토글은 **표시만** 바꿉니다. 켜도 V4·V5·알고리즘 결과에 들어가지 않으며, 좌측 패널에 이 문장을 늘 적어 둡니다(그래프활용 §4.1).
- 고아와 근거 공백을 같은 호박색으로 둔 이유: 둘 다 "자료 요청 후보"라는 같은 행동으로 이어집니다. 글자("고아"/"근거 공백")와 층 모양(지식 도형/P&ID 원)으로 구분됩니다. 호박색은 기존 화면의 "미확인"(`--warn-*`)과 같은 뜻 계열입니다.
- 미확인 값(빈 칸)은 상세 패널에서 호박 글자 "미확인 — 사유"로 보이고 0·"없음"으로 바꾸지 않습니다(시안 README §2와 같음). 단위·압력 기준이 빈 설정치는 라벨에도 "단위 미확인"을 붙입니다.

## 3. 관계 선 스타일

### 3.1 종류별 (색 보기 "종류")

| 묶음 | `kind` | 선 | 색 | 화살표 |
| --- | --- | --- | --- | --- |
| 물리 연결 | `has_endpoint` | 실선 2.4px | `--physical_connection` | 배관 구간의 `flow_direction`이 있을 때만, 선 가운데에. 없으면 그리지 않음 |
| 계측 연결 | `measurement_connection` | 실선 1.4px | `--measurement_connection` | 없음 |
| 신호 연결 | `signal_connection` | 실선 1.4px | `--signal_connection` | 없음 (시안 결정, 아래 미확인 참고) |
| 언급 | `mentions` | 실선 1.4px | `--kg-rel-mentions` `#64748b` | 없음 |
| 설비 적용 | `governed_by`, `has_setpoint`, `has_condition`, `analyzed_in` | 실선 1.8px | **지식 쪽 끝 노드의 종류 색** | 없음 |
| 문서 안 위치 | `part_of`, `specified_in` | 실선 1px | `--kg-rel-docpos` `#cbd5e1`(옅게) | 없음 |
| 문서 근거 의존 | `depends_on` | 실선 1.6px | `--kg-rel-depends` `#334155` | 없음. 샘플에 없음(범례·필터만) |

- 설비 적용 관계를 끝 노드 색으로 그리면 "이 설비에 붙은 것이 요건인지 설정치인지"가 선만 봐도 보입니다. 문서 안 위치 관계는 설비 적용이 아니므로(그래프활용 §2.3) 가장 옅게 둡니다.
- `depends_on`은 도면에 그려진 연결이 아니므로 물리 연결 초록을 쓰지 않습니다.
- 지식 관계에는 화살표를 그리지 않습니다. 저장된 방향(P&ID → 지식)은 의미 방향이지 흐름이 아니며, 화살표를 두면 물리 흐름과 헷갈립니다.
- **배관 구간 접기**: 구간 노드를 숨기고 양 끝 설비를 구간 위치를 지나는 꺾은선 하나로 그립니다(배치가 바뀌지 않음). 흐름 화살표는 꺾이는 점에 둡니다. 계산은 구간 노드를 그대로 씁니다.

### 3.2 A1 방향 (색 보기 "A1 상·하류")

| 표시 | 판정 필드(`reached[]`) | 노드 채움 | 글자 | 경로 관계 |
| --- | --- | --- | --- | --- |
| 시작 | `start` | `--a1-start`(`--ink`) + 겹고리 | "시작" | — |
| 하류 | `direction_from_start: downstream` | `--a1-down` `#0072b2` | "↓하" | 같은 색 실선 |
| 상류 | `upstream` | `--a1-up` `#d55e00` | "↑상" | 같은 색 실선 |
| 혼합 | `mixed` | `--a1-mixed` `#cc79a7` | "↕혼" | 같은 색 실선 |
| 방향 미확인 | `unknown` | `--a1-unknown` `#9ca3af` | "?" | 같은 색 실선 |
| 인접 구간 | `adjacent` | `--a1-adj` `#009e73` | "접" | 같은 색 실선 |
| 방향 해당 없음 | `not_applicable`(계장, `material_flow_path: false`) | `--a1-na` `#6b7280` | "—" | 같은 색 실선 |
| 미도달·대상 아님 | 구간 멤버인데 도달 안 함, 지식 노드 | `--a1-off` `#d1d5db` | "미도달"(구간 멤버만) | 회색 |
| **정상 유로 아님** | `normal_operation_flow: false`(경로에 NC·LC 밸브) | 방향 색 그대로 | 방향 글자 뒤에 **"⊘"** | **속 빈 이중선**(방향 색 6px 위에 흰 2.2px) |
| 밸브 정상 위치 | `valves_on_path[].normal_position`, 노드 `normal_position` | — | 밸브 옆 "NC"/"NO"/"LC"/"LO", 값이 없으면 호박 "위치 미확인" | — |
| 도면 경계에서 멈춤 | `truncations[].reason: external_drawing` | — | "도면 경계에서 멈춤" | — |

- 경로 관계는 각 도달 노드의 `path_edges` 마지막 관계(탐색 트리)만 색칠합니다. 순환·합류 관계(`cycle_or_merge_edges`)는 회색입니다.
- 방향 색은 색각 이상 배려 팔레트(Okabe & Ito, "Color Universal Design") [일반지식, 원문 미확인]에서 골랐고, 글자(하/상/혼/?)를 늘 함께 씁니다. 하류 파랑은 선택 고리 파랑과 가깝지만 선택은 **고리**, 방향은 **채움**이라 모양이 다릅니다.
- 상류 `#d55e00`은 ④의 경로 주황 `#ea580c`과 가깝습니다. A1 보기에서는 경로 강조가 없어 함께 나오지 않으나, 의미가 다르다는 점(방향 vs 시나리오 경로)을 범례에 적었습니다.
- "정상 유로 아님"은 경로를 버리거나 흐리게 하지 않습니다. 범례와 상세 패널에 "역류·과압 전파를 배제하지 않음", "도달은 인과관계를 입증하지 않음"을 적습니다(그래프활용 §4.1).
- A1 결과는 시작점이 정해진 사전 계산입니다. 단독 모드(브라우저)에서는 다른 노드로 재실행하지 않고 범례에 그 사실을 적습니다(그래프활용 §5.2). 앱에서는 `runAlgorithm` 메시지로 재실행합니다.
