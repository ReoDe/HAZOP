# '출력화면 AX' 데모 분석

[프로젝트 소개](../README.md) · [검토·결과 관리](../기획서/검토결과관리.md) · [결정 로그](../메모리/결정로그.md)

## 이 문서의 위치

결과 화면 디자인의 출발점이 된 외부 데모를 분석한 참고 문서입니다. 화면 헤더의 제품명은 "설계검증 AX"이지만, 이 프로젝트에서는 **'출력화면 AX' 데모**라고 부릅니다(사용자 결정).

- 목표로 하는 것: 도면 위 오버레이, 레전드별 레이어 전환, 컴포넌트 클릭 시 노드 정보 표시, 도면 넘김, Obsidian과 같은 그래프 화면, 채팅식 질의응답, 그리고 모더니즘 계열의 시각 언어입니다.
- 범위: 결과 화면은 Windows 데스크톱 프로그램(PySide6)에 기존 HTML 뷰어를 내장 웹뷰로 넣어 구현합니다([데스크톱 인터페이스 기획](../기획서/인터페이스.md), 사용자 결정 2026-11-04). 이 문서는 MVP 범위를 바꾸지 않습니다.
- 자료와 한계: 전시 부스에서 TV 화면을 찍은 사진 4장(저장소에는 포함하지 않음)만 사용했습니다. 사진이 비스듬하고 해상도가 낮아 작은 글씨 일부는 추정해서 읽었으며, 해당 부분에는 "(추정)"을 표시했습니다. 색상과 치수도 사진에서 짐작한 값입니다. 호버·스트리밍 같은 동작은 정지 사진을 보고 추론한 것입니다.

## 1. 공통 화면 틀

| 영역 | 구성 |
| --- | --- |
| 상단 헤더 | 파란 원형 로고, 제품명, 세로 구분선, 현재 위치 표시 "도면 **Fig 6.3-1 Sh.1** · PXS"(도면번호는 굵게, 계통명은 회색) |
| 우측 상단 | 알약 모양 탭 `도면 \| 지식그래프`(선택된 탭만 옅은 회색 배경), 상태 점이 붙은 "● 설계변경 시나리오" |
| 본문 | 화면 전체를 캔버스(도면 또는 그래프)로 쓰고, 조작 도구는 캔버스 위에 떠 있는 패널로 배치 |
| 우측 하단 | 검은 알약 모양 플로팅 버튼 "질의응답" |
| 하단 검은 띠 | 단계 번호 배지와 설명 문구. 앱 기능이 아니라 전시용 설명 오버레이로 보임 [추론] |

핵심은 **캔버스를 우선하는 배치**입니다. 화면을 고정 영역으로 나누지 않고 도면을 최대한 크게 띄운 다음, 필요한 패널만 위에 얹습니다.

## 2. 화면별 분석

### 2.1 도면 인식

- 흑백 원본 도면 위에 색 있는 벡터 오버레이를 겹쳐 그립니다. 심볼은 파란 사각 테두리, 태그 문자는 파란 배경 하이라이트, 배관은 녹색 선입니다.
- **레이어 토글**(우측 상단 카드): 심볼(파랑), 배관(녹색), 태그(검정), 근거(노랑). 체크박스 색이 곧 범례 역할을 합니다.
- **줌 컨트롤**(좌측 하단 알약): 축소, 배율(145%), 확대, 이동(손), 전체화면.
- 원본의 NOTES 블록은 그대로 둡니다. 인식 결과는 덧칠할 뿐 원본을 가리지 않습니다.

### 2.2 근거 연결

- 밸브 V053을 클릭하면 해당 심볼이 빨간색으로 채워집니다.
- **호버 카드**: `V053`과 `KG` 배지, 이름 "PXS-PL-V053 시험연결 (IRC, 벤트)", 요약 한 줄 "Manual(수동) · 상시 Closed → Closed · IRC", 하단에 분류 "밸브 · V053".
- **우측 상세 패널**: 작은 분류 라벨 "밸브", 큰 제목 "V053", 회색 부제, 키–값 표(이름, symbol_type: Valve(밸브), symbol_class: Manual(수동), 위치: IRC, 정상 위치(추정): Closed, 실패 위치(추정): Closed, 빈 값은 "—").
- `KG` 배지는 해당 심볼이 지식그래프 노드와 연결되어 있다는 표시입니다.
- 속성 키는 영문(`symbol_type`) 그대로, 값은 한글을 병기합니다. 실사용 화면에서는 한글 라벨로 바꾸는 것을 고려합니다.
- 계장 신호선은 보라색 파선, 배관번호 라벨(P0273 등)은 녹색입니다.

### 2.3 지식그래프

- **좌측 플로팅 패널**
  - 검색창 "태그·이름으로 찾기"
  - 노드 종류 범례(색 점·이름·개수): 설비 192, 배관 구간 119, 요건 63, 문서 조각 35, 신호 9, 문서 9, 지지물 7, 설정치 7, 해석 사례 7. 합계 448로 상단 통계와 일치합니다.
  - `모두 / 모두 끄기` 버튼
  - 관계 목록: HAS_ENDPOINT 238, GOVERNED_BY 187, SPECIFIED_IN 168, TOPO_CONNECTED 119, DEPENDS_ON 79, PHYS_FLOWS_TO 66. 보이는 항목의 합은 857이며 나머지 171은 스크롤 아래에 있는 것으로 보입니다.
- **우측 상단 통계 칩**: "448 노드 · 1028 관계 · 고립 12 제외(추정)", 전체화면·새로고침 아이콘.
- **캔버스**: force-directed 그래프입니다. 점은 작고 선은 아주 옅습니다. 노드에 마우스를 올리면 그 노드와 이웃만 진하게 남고 나머지는 흐려집니다.
- 노드 색이 도면 오버레이 색(설비=파랑, 배관=녹색)과 같아 **두 화면이 같은 색 체계를 공유**합니다.

### 2.4 도면 질의응답

- 우측 패널이 채팅 화면으로 바뀝니다.
  - 시스템 메시지(회색 카드): 도면을 불러왔다는 안내와 사용 방법
  - 사용자 질문(우측 정렬 파란 말풍선): "RCS가 1700 psig 이하로 떨어질 때, CMT … 형성 과정이 P&ID상에서 어떻게…"(뒷부분 추정)
  - 진행 상태 "답변 정리 중… ⌄": 펼치면 조회·추론 단계를 볼 수 있는 것으로 보입니다 [추론]
  - 스트리밍 답변과 `■ 중단` 버튼, 입력창 "도면에 대해 물어보기"
  - **근거 집계 한 줄**: "근거 48 중 도면 표시 34 · 추정선 1 (파선 — 실제 배관 경로 아님) · 미표시 14"
- 도면에서는 답변과 관련된 경로가 빨간 선으로, 관련 기기(CMT, RCS 저온관, 원자로 용기)가 빨간 박스로 강조됩니다. 이때 레이어 토글의 "근거"가 켜집니다.

근거 집계 표시는 이 데모에서 가장 중요한 디자인 요소입니다. AI 답변의 근거를 도면에서 확인된 것, 추정한 것, 화면에 표시하지 못한 것으로 나누어 숫자로 보여 줍니다.

## 3. 시각 언어

| 요소 | 관찰 내용 |
| --- | --- |
| 색 | 바탕은 흰색·연회색 무채색이고 UI 강조색은 파랑 하나뿐입니다. 빨강·녹색·보라 등 다른 색은 데이터(심볼·배관·근거)에만 씁니다. |
| 형태 | 큰 둥근 모서리(약 16–20px, 추정), 알약 모양 버튼·탭, 얇은 테두리, 아주 옅은 그림자 |
| 계층 | 위계를 색 대신 글자 크기와 굵기로 표현합니다(작은 회색 라벨 → 큰 굵은 제목 → 회색 부제). |

| 상태 표시 | 점(●), 배지(KG), 진행 스피너 등 작고 절제된 표시 |

## 4. 이 프로젝트에 적용하는 방향

### 그대로 가져올 것

| 데모 요소 | 이 프로젝트의 대응 |
| --- | --- |
| 도면/그래프 탭 전환, 레이어 토글, 도면 넘김 | ③ 통합 그래프와 원본 도면 조회 |
| 클릭 → 호버 카드 → 상세 패널 | 노드 속성과 근거. 정상·실패 위치는 [최소 그래프 정의](../기획서/정보통합관리.md#definitions)와 대응 |
| 도면과 그래프의 색 체계 공유 | 노드 종류별 색을 한 곳에서 정의해 두 화면에 함께 사용 |
| 채팅 답변 → 도면 경로 강조 | ⑤ 검토 화면에서 선택한 편차의 원인→결과 경로 강조 |
| 근거 집계(표시·추정·미표시) | [공통 원칙](../기획서/전체기획.md#principles)의 근거·미확인 표시를 화면에 드러내는 방법. 추정 경로는 파선으로 구분 |
| 설계변경 시나리오 | ⑤의 변경에 따른 구간 재검토 표시 |

### 데모에는 없지만 필요한 화면 [추론]

데모의 목적은 설계 검증이므로 HAZOP 고유의 화면이 없습니다.

- HAZOP 구간 선택: 도면에서 영역을 지정하거나 여러 기기를 선택
- 편차 목록(파라미터 × 가이드워드)과 후보별 선택·제외·보류
- 편차 선택 시 원인→결과 경로와 보호수단을 도면에 강조
- 워크시트 검토·확정 화면과 Excel 출력

### 구현상 차이

데모는 PDF·이미지 도면을 인식한 뒤 오버레이를 그리는 방식으로 보입니다. 이 프로젝트의 MVP 입력은 draw.io 원본이며, 객체 좌표와 커넥터 경유점을 원본에서 직접 읽습니다([정보 추출](../기획서/정보추출.md)). 그래서 오버레이 위치는 인식 오차 없이 맞출 수 있습니다 [추론]. "흑백 원본 + 색 오버레이" 연출을 살리려면 draw.io 도면을 흑백 바탕으로 렌더링하는 단계가 따로 필요합니다.

## 5. 미결정 사항

- 참고 화면의 일부를 MVP에 포함할지, 후속으로 둘지
- 질의응답(자유 질문) 기능을 범위에 넣을지. 현재 기획의 AI 용도는 ④의 HAZOP 추론입니다.
- 색·서체·모서리 등 디자인 토큰의 실제 값
