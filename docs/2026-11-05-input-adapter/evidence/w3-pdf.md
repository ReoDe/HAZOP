## 2. 어댑터 규칙 요약

모듈 머리말(`pdf_vector.py` 1~25행)에 전체 규칙이 있다. 파일명·도면별 분기는 없다. 문턱은 모두 `PARAMS`에 있고 실행마다 `run.settings.params`에 기록된다(재작업 1회차에 하드코딩 문턱 10개를 옮김, 6세트 출력은 params 외 바이트 동일).

- **원시 요소**: 흰 채움+검은 외곽 = 기호 몸체, 검은 채움 작은 조각 = 점선 조각(짧은 변 ≤ 1.5pt, 긴 변 ≤ 8pt, 꺾인 모서리 다각형은 ≤ 4.5pt) 또는 화살촉(≤ 7pt), 열린 선 = 배관 후보. 페이지 80% 이상을 덮는 배경·테두리, 변을 공유하며 이어 붙은 사각형(표제란 표)은 제외한다. 검은 채움과 같은 bbox의 외곽선은 채움 쪽으로 본다. 스트로크 점선(pdfplumber `dash` 배열과 위상, 예 `([4, 2], 0)`)은 보존해 배열·위상을 실제로 적용한 보이는 구간만 4pt 이하 조각으로 만들고(보이는 구간이 없으면 선도 없음), 같은 원본 경로의 조각끼리만 한 사슬로 이어 신호선으로 다룬다(교차하는 다른 점선과 합치지 않음, 사슬 끝은 경로의 첫·마지막 보이는 점)(샘플 PDF는 모두 채운 사각형 점선이라 메모리 PDF로 시험).
- **기호 묶기**: 겹치는 몸체 → 몸체 bbox 안 선(끝이 화살촉·다른 기호에 닿으면 제외) → 끝이 몸체 깊숙이 들어간 선(구동부 축, 반대 끝 기호와 합침) → 끝이 아무 데도 닿지 않는 장식선(스프링·체크밸브 선·응축기 대각선 등, 기호 밖으로 나간 길이가 기호 긴 변의 0.6배 이하일 때 흡수, 닿는 기호가 없으면 4~60pt 크기의 선 기호로) 순서로 반복한다. 연결이 하나도 없는 작은 기호가 큰 기호 옆(큰 기호 긴 변의 0.1배 안)에 있으면 부속(가압기 히터 등)으로 합친다.
- **연결**: 선 끝이 기호 bbox 2.5pt 안이면 접속, 화살촉 안이면 화살촉이 닿은 기호에 접속, 선 끝 3개 이상이 1.5pt 안에서 만나거나 선 끝이 다른 선 중간에 닿으면 분기점(`tee`), 끝 2개(또는 화살촉 하나를 사이에 둔 끝 2개)는 통과점으로 이어 붙인다. 교차만 하는 선은 잇지 않는다. 점선은 조각 간격 3pt 안을 한 사슬로 묶고 양 끝 조각이 8pt 안의 서로 다른 기호 둘에 닿을 때만 관계로 둔다.
- **관계 종류**: 점선 = `signal_connection`, 실선이 계기 원에 닿음 = `measurement_connection`, 그 밖의 실선 = `physical_connection`. `line_type`은 `pdf_solid`·`pdf_dashed`, 흐름 방향은 만들지 않고 미확인(`unknown_flow_direction`)으로 남긴다.
- **글자**: 단어 → 줄 → 문단. 표 칸 안 = 표제란(`drawing.title_block`, drawio와 같은 행 2칸 규칙), 흰 바탕 마스크 안이거나 가로선이 글자 위를 지나면 선 라벨(`texts`), 밸브 몸통·구동부 안 글자(M, E/H)는 기호 표기(`evidence.symbol_marks`), 나머지는 15pt 안 가장 가까운 기호에 1:1로 붙인다.
- **종류**: 형상(계기 원, 두 삼각형 밸브 몸통 + 구동부: 없음 = 수동, 돔 = 조절, 원 또는 표기 M = 전동, 평행 사선 스프링 = PSV, 표식 있는 선 기호 = 체크밸브, 축 정렬 평행 판 = 오리피스, 작은 닫힌 몸체·연결 1개 = 배관 끝막음)과 일반 P&ID 표기(ISA 5.1 뒤 글자 T·C·I, TE — 기능 문자와 번호를 나눠 읽어 `PT\n101`·`PT-101`·`PT 101` 모두 transmitter, 원형 기호인데 계기 문자가 아니면 장비 이름 낱말로 재판정(원형 펌프 기호에 PUMP 등), 장비 이름 낱말 `PUMP`·`TANK`·`HX` 등, `TO|FROM <번호>` = 도면 연결). 근거가 없으면 `kind` 없음(unclassified)과 미확인 `missing_kind`.
- **출력**: drawio와 같은 최상위 키·노드·관계·끝점·source_locations 필수 키. 좌표계 `pdf_page_pt`/`pt`(원점 왼쪽 위, y 아래쪽 증가). `tag`는 PDF에 속성이 없어 모두 null + 미확인 `missing_tag`(보이는 글자는 `label_text`에 보존). 원본 근거로 노드·관계에 `evidence`(분류 근거, PDF 경로 ID 목록) 키를 더했다(W1 §6 선택 필드 제안).

## 5. 좌표 정렬 잔차

- [사실] 6세트 모두 같은 변환이 나왔다: scale ≈ 1.391292(x·y), offset ≈ (−0.509, −0.500). 1/1.391292 = 0.718757로 PDF 내용 스트림의 `cm` 배율(0.24 × 2.9948196)과 같다. 페이지 크기 비(drawio 1654×1169 / PDF 1191.12×841.92 = 1.388609·1.388493)와는 약 0.2% 다르므로 페이지 크기 비로 정렬하면 페이지 끝에서 약 3 canvas_unit 어긋난다 [추론: 1654 × 0.002].
- 이상치 제외 후 잔차 RMS 0.0004~0.0006, 최대 0.0012 canvas_unit. 제외된 기준점은 조절밸브 `RC-PV101`·`CV-PV201`·`FW-FV501`과 오리피스 `CV-FO01`이며, 제외 전 RMS는 0.81~1.01이다. [추론] drawio 조절밸브 도형 bbox는 구동부 위 빈 여백을, 오리피스는 양쪽 짧은 관을 포함하지만 PDF에서 읽은 bbox는 그려진 선까지만이라 중심이 몇 단위 다르다(대응 IoU 0.89·0.70).
- [추론] 기준점이 모두 0.0012 이내로 맞으므로 샘플 PDF는 현재 `.drawio`와 같은 판에서 내보낸 것으로 보인다(W1 사용자 결정 5의 판 일치 확인에 대한 간접 근거, 확정은 사용자 몫).

## 8. 한계·확인 필요

- **[중요] 표본 내 측정이다.** 형상 규칙과 문턱은 같은 6세트를 보며 정했다. 따로 떼어 둔 시험 도면이 없으므로 위 지표는 낙관적이며, 다른 도구·다른 스타일로 그린 실제 도면에서의 성능은 확인하지 않았다. 샘플 6세트는 모두 draw.io가 같은 스타일로 내보낸 것이다(W1 §2).
- 선 굵기를 쓰지 못한다: 샘플 PDF는 선 굵기를 ExtGState(`gs`)로 지정하는데 pdfplumber(pdfminer) 결과의 `linewidth`가 0으로 나온다 [사실]. 주 배관(굵기 2)과 보조 배관(굵기 1)을 구별하지 못하지만 둘 다 `physical_connection`이라 이번 지표에는 영향이 없다.
- 실선 관계 종류는 "계기 원에 닿으면 측정" 규칙에 기댄다. 계기에 닿는 실제 공정 배관이 있는 도면에서는 틀린다 [추론].
- 정답지의 차수 1·2 tee(§4)는 화면 근거가 없어 PDF로 복원할 수 없다. 평가 쪽에서 별도 범주로 뺄지는 열린 판단이다(평가 하네스 변경은 이번 범위 밖).
- `tag`는 모두 null이다. 그래프 단계(③) 호환은 확인됨(§7): `build_graph`·`render_report`·`entity_mapping_document`가 6세트에서 validation passed. 다만 출력 위치는 `출력/어댑터/pdf_vector/`로 분리되어 있어 기존 그래프 스크립트가 자동으로 읽지는 않는다. `line_type` 값 `pdf_solid`·`pdf_dashed`는 `rules.LINE_TYPE_RELATION`에 없다.
- ISA 5.1 계기 문자 규칙의 판(edition)은 원문을 대조하지 못했다 [미확인]. 흔히 쓰이는 판은 ANSI/ISA-5.1-2009로 알려져 있으나 [일반지식], 규칙은 기능 문자 뒤 글자(T·C·I·E)만 쓴다.
- 샘플별 품질 하한(`QUALITY_FLOORS`)은 현재 측정값을 바닥값으로 고정한 회귀 방지 장치이며 목표치가 아니다. kind는 하네스에 F1이 없어 kind 정확도로 대신했다.
- 노드·관계에 더한 `evidence` 키: 그래프 단계(③)에서는 문제없음을 확인했다(§7, `build_graph`·`render_report`·`entity_mapping_document` 6세트 passed). 그 밖의 소비자(뷰어 등)는 미확인.
- 점선 사슬 규칙(재작업 3회차): 스트로크 점선은 같은 원본 경로의 연속 조각만 한 구간이며, 기호 안에서 흡수된 조각 자리에서 끊는다(A–B–C 관통 → A–B, B–C). 서로 다른 경로는 경로 끝점끼리 정확히 두 개가 1.5pt 안에서 만날 때만 잇는다(경로 중간 교차·셋 이상 만남은 잇지 않음). 채운 사각형 점선은 간격 3pt 안이면서 장축 방향(20° 안)과 직선(1.5pt 안)이 같을 때 잇고, 방향이 다르면 두 조각이 모두 자기 직선 구간의 끝일 때만(꺾임) 잇는다. 보이는 조각이 없는 점선 경로는 미확인 `dashed_path_no_visible_piece`로 남긴다.
- 한계: 셋 이상이 한 점에서 만나는 점선 분기, 대각선 점선 조각(bbox가 정사각형에 가까워 방향 없음으로 봄)이 다른 점선과 교차하는 경우는 잘못 이을 수 있다 [추론]. 샘플 PDF에는 스트로크 점선이 없어 스트로크 규칙은 메모리 PDF로만 시험했다.
- **알려진 한계(Codex 4차 재검토 반려, 사용자 결정으로 수용 — D6)**. 모두 합성 메모리 PDF 재현이며 샘플 6세트 지표에는 영향이 없다. `W5`(열화 시험)나 실제 도면 확보 뒤 우선순위를 정한다.
  1. 방향 없음으로 보는 아주 작은 채운 점선 조각(예: 1×0.7pt)끼리 교차하면 하나로 합쳐져 관계 2개 대신 관계 0개·미해결 1개가 된다(`_filled_chains`의 방향 없는 조각 무조건 결합).
  2. 중심선 간격이 3pt 정도인 평행 채운 점선 두 개의 끝 조각이 꺾임으로 결합되어 관계 2개 대신 관계 0개·미해결 1개가 된다(끝 조각 결합에 공선 조건 없음).
  3. 보이는 조각이 없는 닫힌 점선 경로(예: 1pt 정사각형, `[1 200] 20 d`)가 점선 처리보다 먼저 닫힌 도형으로 분류되어 가짜 기호 노드 1개가 생기고 `dashed_path_no_visible_piece`가 기록되지 않는다.
  4. 채운 점선 교차 테스트(`test_memory_pdf_filled_dashes_crossing`)는 관계 종류·개수와 노드 수만 검사해 연결 상대가 바뀌어도 통과한다.
- 스캔(래스터) PDF는 `no_vector_content` blocker로 막는다. 혼합 PDF·여러 쪽 PDF는 시험하지 않았다(`--page`만 지원).
- PDF 등록(`hazop/register/`)은 범위 밖이라 결과는 `not_registered` 미확인 3건을 가진다.
