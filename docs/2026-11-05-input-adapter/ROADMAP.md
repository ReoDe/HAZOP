# 입력 어댑터 전체 그림 · 실행 로드맵

> **용도**: “지금 어디까지 왔고, 무엇을 어떤 순서로 진행하며, 나는 무엇을 하면 되는가”를 한 장으로 보여주는 브리핑.
> 상세 상태·완료 기준·증거는 [`PROGRESS.md`](PROGRESS.md)가 관리한다. 내용이 충돌하면 `PROGRESS.md`와 실제 저장소 상태를 우선한다.
> PROGRESS 기준일: 2026-11-06 18:00

## 1. 문제와 목표 — 30초

PDF·PNG/JPG 도면을 읽는 2차 입력 어댑터를 만들고, drawio 추출 결과 대비 정확도를 평가한다.

## 2. 지금 어디까지 왔나

| 구분 | 요약 |
|---|---|
| 완료 | `W1` 조사([evidence/w1-조사.md](evidence/w1-조사.md)), `W2` 평가 하네스([evidence/w2-하네스.md](evidence/w2-하네스.md)), `W3` 벡터 PDF(D6) |
| 현재 단계 | `W4` 래스터 어댑터 구현 완료, 검토 대기([evidence/w4-래스터.md](evidence/w4-래스터.md), D7) |
| 막힌 것 | 없음 |
| 다음 게이트 | `W4` 검토 통과 → `W5` 열화 시험 |

## 3. 무엇을 어떤 순서로 진행하나

| 순서 | 단계 | 왜 이 순서인가 | 게이트 | 상태 |
|---|---|---|---|---|
| `W1` | 초기 조사와 실행 계획 구체화 | 범위와 근거를 먼저 고정해야 후속 작업을 안전하게 나눌 수 있다. | [`README.md`](README.md)의 범위 확인과 조사 증거 기록 | 완료 |
| `W2` | 평가 하네스 | 어댑터를 재려면 정답지 대비 지표가 먼저 있어야 한다. | 정답지끼리 F1=1, 오류 주입 기대 감점 | 완료 |
| `W3` | 벡터 PDF 어댑터 | 설치 없이(pdfplumber) 바로 측정할 수 있다. | 6세트 blocker 0, 지표 표 기록, 재검토 통과 | 완료(D6) |
| `W4` | 래스터 어댑터 | 설치 승인 후 진행. | 샘플 PNG 지표 기록 | 구현 완료(검토 대기) |
| `W5` | 열화 시험 | `W3`·`W4` 결과가 있어야 비교할 수 있다. | 열화 단계별 지표 표 | 측정 완료(검토 대기) |

> 실행 구조에 **분기**, **병렬** 실행, GO/HOLD **게이트** 또는 **원복** 경로가 생기면 이 표 아래에 같은 작업 ID를 사용하는 Mermaid `flowchart`를 추가한다. 단순 선형 흐름이면 표만 유지한다.

## 5. 공통 실행 규칙

1. 작업 전에 `README.md`에서 편집 범위와 작업 확장 규칙을 확인한다.
2. 조사·검증 결과는 `evidence/`에 먼저 남긴다.
3. 설계·정책 판단은 [`decisions.md`](decisions.md)에 기록한다.
4. 작업 ID별 상세 상태·완료 기준·다음 행동은 `PROGRESS.md`만 갱신한다.
5. `PROGRESS.md`의 단계·순서·게이트·현재 행동이 바뀌면 이 브리핑과 `PROGRESS 기준일`을 함께 맞춘다.
