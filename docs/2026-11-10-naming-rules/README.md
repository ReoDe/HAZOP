# 작업물 관리·이름 규칙 설계 (초안)

작성 2026-11-10. 상태: 사용자 선택 전 초안. 이 문서는 설계만 담는다. 파일을 옮기거나 이름을 바꾸지 않았다.

## 결론

1. 지금 제각각인 것은 대부분 **코드가 읽지 않는 곳**(저장소 밖 시험 폴더, 문서 작업 공간, 브랜치, 작업 단위 ID)에 몰려 있다. 코드가 경로를 읽는 곳은 2026-11-09 정리로 이미 `hazop/paths.py` 폴더 표 하나에 묶였다.
2. 그래서 **중간안(안 B)**을 권한다. 새로 만드는 것부터 규칙을 따르게 하고, 기존 것은 코드가 읽지 않는 것만 옮긴다. 스크립트·데이터 폴더 이름처럼 코드와 기준값이 묶인 이름은 바꾸지 않는다.
3. 규칙은 사람이 기억하지 않아도 되게 시험 하나(`tests/test_naming_rules.py`)와 `scripts/preflight.py` 경고로 지키게 한다. 원자력 문서관리에서 가져올 것은 "문서번호와 개정은 파일 이름이 아니라 문서 머리에 적는다"는 점 하나면 충분하다.

## 0. 먼저 알아 둘 말

| 말 | 뜻 |
| --- | --- |
| 형상관리(Configuration Management, CM) | 무엇이 있는지 이름을 붙여 구분하고, 바뀔 때마다 누가 왜 바꿨는지 남겨, 언제든 특정 시점의 상태를 되짚을 수 있게 하는 일. 원자력의 설계 형상관리와 같은 뜻이다 |
| 저장소(repository) | git이 이력을 관리하는 폴더. 여기서는 `D:\HAZOP` |
| 추적 파일 | git이 이력을 남기는 파일. 추적하지 않는 파일(`작업/` 등)은 지워지면 되살릴 수 없다 |
| 커밋(commit) | 저장소에 남기는 변경 한 묶음. 원자력 문서의 개정 한 번과 비슷하다 |
| 브랜치(branch) | 본선(`main`)과 따로 작업하는 갈래. 끝나면 본선에 합친다(병합) |
| 작업트리(worktree) | 같은 저장소를 다른 폴더에 하나 더 펼친 사본. 다른 세션과 겹치지 않게 시험할 때 쓴다 |
| 접두어(prefix) | 이름 앞에 붙이는 분류 표시. 예: `check_apr1400.py`의 `check_` |
| 태그(tag) | 특정 커밋에 붙이는 고정 이름표. 배포본 `v0.1.0`처럼 쓴다 |
| 기준값(baseline) | 회귀 검사가 비교 기준으로 삼는 점수 파일(`tests/baselines/`) |
| 재생성물 | 명령 하나로 다시 만들 수 있는 결과물. 지워도 손해가 없다 |

### 1.4 바꾸면 안 되는 이름(계약)

이름이 곧 데이터이거나 코드가 이름으로 찾는 것들이다. 어느 안을 고르든 그대로 둔다.

| 이름 | 묶인 곳 | 바꾸면 생기는 일 |
| --- | --- | --- |

## 3. 선택지

### 세 안에 공통으로 들어갈 원칙

1. **이름이 계약인 것은 건드리지 않는다**(§1.4).
2. **새로 만드는 것부터** 규칙을 따른다. 기존 것은 옮길 값어치가 있고 위험이 낮을 때만 옮긴다.
3. **날짜는 `YYYY-MM-DD`**, 이름 맨 앞에 둔다. 정렬하면 시간순이 된다. 코드가 찍는 시각(`20261108T124409Z`)은 그대로 둔다.
4. **이름에 공백·`&`·괄호를 쓰지 않는다.** 단어는 `-`로 잇는다. Python 파일만 `_`(import 이름 규칙 때문).
5. **저장소 밖에 둔 것에도 주인과 지울 날짜를 적는다.**

### 안 A. 최소안: 새것만, 저장소 밖 위주

**규칙**

| # | 대상 | 규칙 | 예 |
| --- | --- | --- | --- |

**바뀌는 것:** 저장소 안 이동 0. 정리 대상은 병합된 로컬 브랜치 16개, 시험 폴더 루트 낱개 파일 53개, README 없는 시험 폴더 14개(`wt-*` 5개는 작업트리라 별도). 시험 폴더 정리는 지우는 일이라 사용자 확인 뒤에 한다.

**위험:** 거의 없다. 코드가 읽는 경로를 건드리지 않는다. 브랜치는 병합된 것만 지우므로 이력이 사라지지 않는다.

**지키게 하는 법:** `scripts/preflight.py`가 시험 폴더 루트의 낱개 파일, README 없는 폴더, 지울 날짜가 지난 폴더, 병합된 브랜치를 경고만 한다(실패하지 않음).

**한계:** 저장소 안의 사례 1·5~16은 그대로 남는다. 특히 ID 겹침(사례 16)이 계속된다.
