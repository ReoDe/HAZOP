# 화면 원칙

[도면 중심 웹 화면](app-shell-web.md)(HZ-DSN-05) · [쉬운 흐름](guided-flow.md)(HZ-DSN-06) · [프로젝트 의도 §3.8](../../INTENT.md)

화면을 만들거나 고칠 때 무엇을 보이고 무엇을 뺄지 정하는 기준이다. 2026-11-25~26에 사용자가 앱을 직접 써 보며 준 지시를 하나의 방향으로 묶었다. 낱낱의 지시를 나열한 목록이 아니라, 새 화면을 만들 때 이 문서만 보고도 같은 결론에 이르게 하려는 것이다. 다른 화면 문서와 어긋나면 이 문서가 앞선다.

## 1. 방향

**화면은 도면과 결과만 보인다. 프로그램이 한 일은 설명하지 않고, 사람이 한 일은 바로 반영하며, 잘못한 일은 되돌린다.**

사용자는 원전 설계 도면을 보는 사람이다. 프로그램이 어떻게 읽었는지, 지금 무슨 상태인지, 누가 만들었는지를 알고 싶은 것이 아니라 도면과 그 위의 구간·분석을 보고 싶어 한다. 화면의 글자와 단추 하나하나는 그 사람의 눈을 도면에서 떼어 놓는다. 그러니 꼭 필요한 것만 남긴다.

아래 다섯 원칙은 모두 이 한 문장에서 나온다.

## 2. 원칙

### 2.1 결과만 보인다

프로그램이 만든 것은 만든 순간 결과다. 과정, 출처, 상태를 꼬리표로 붙이지 않는다.

- 'AI 초안', '적용됨', '확정', '미확인 12개'처럼 **어떻게 만들어졌는지**나 **지금 무슨 단계인지**를 알리는 표시는 두지 않는다. AI가 지은 이름도 그냥 이름이다.
- 개수, 요약 줄, 내부 기록(묶음 번호, 이어짐 목록)처럼 **없어도 일에 지장이 없는 정보**는 보이지 않는다. 고름 줄에 '더함 0 · 뺌 3'을 쓰지 않는 것도 같다. 무엇이 더해지고 빠지는지는 도면의 강조가 보여 준다.
- 남기는 표시는 **사람이 다르게 행동해야 하는 것**뿐이다. 읽지 못한 구성요소의 빨간 네모, 범위가 바뀌어 다시 승인해야 하는 판정, 잠긴 구간의 자물쇠가 그렇다.

판단 기준: 이 글자를 지웠을 때 사용자가 무언가를 잘못하게 되는가. 아니라면 지운다.

### 2.2 할 일이 없으면 말하지 않는다

안내, 경고, 확인은 사용자가 그것을 보고 **할 수 있는 일**이 있을 때만 띄운다.

- '구간이 이미 있습니다', '몇 개는 넣을 수 없어 뺐습니다', '아직 확정하지 않았습니다' 같은 알림은 띄우지 않는다. 프로그램이 알아서 처리하고 결과만 보인다(이미 있는 구간이면 그 구간을 고른 상태로 둔다).
- 빈 칸의 자리표 글, 추천 질문, '여기를 눌러 ~하세요' 같은 사용법 안내를 쓰지 않는다. 화면이 설명 없이 쓰이지 않는다면 화면을 고친다.
- 진짜로 막힌 일(저장 실패, 파일을 읽지 못함)은 알린다. 이때도 무엇을 하면 되는지를 함께 적는다.

### 2.3 만들면 확정이고, 고치고 싶으면 바로 고친다

단계를 밟게 하지 않는다. '만들기 → 검토 → 확정' 같은 사람용 절차를 화면에 두지 않는다.

- 도면을 올리면 읽고, 모자란 것은 AI가 채우고, 지식그래프에 넣는 일까지 묻지 않고 한다.
- 구간은 만들면 곧바로 분석에 쓰인다. 고치려면 그 구간을 고른 채 도면에서 바로 고친다. 고치기 전에 풀어야 하는 잠금이나 해제 단계를 두지 않는다.
- 값은 그 자리에서 고친다. 연필을 누르면 그 칸이 입력 칸이 되고, Enter로 저장하고 Esc로 버린다. 따로 뜨는 편집 창을 만들지 않는다.
- 잘못 읽힌 것은 AI 채팅에 말해서 고친다. 고치기 전용 화면을 따로 두지 않는다.

안전은 단계가 아니라 자료에서 지킨다. 범위가 바뀐 판정은 사람이 다시 승인하기 전까지 초기사건 인계에 들어가지 않는다. 이 규칙은 화면이 단순해져도 그대로다.

### 2.4 묻지 않고, 되돌릴 수 있게 한다

'정말 지울까요?'를 묻지 않는다. 대신 **Ctrl+Z**로 방금 한 일을 되돌린다.

- 되돌리기는 화면 전체에서 하나다. 구간을 만들고 고치고 지운 일뿐 아니라, 실수로 끌어 도면이 치우친 것 같은 보기 변화도 되돌린다.
- 화면 곳곳에 '되돌리기' 단추를 두지 않는다. 묶음 단위의 작업 기록은 설정 화면 한 곳에 둔다.
- 되돌릴 수 없는 일(디스크에서 파일을 지우는 일 등)만 예외로 묻는다. 그런 일은 되도록 만들지 않는다.

### 2.5 도면이 중심이고, 조작은 어디서나 같다

도면은 늘 한 장 전체가 가운데에 보인다. 같은 조작은 어느 화면에서나 같은 결과를 낸다.

| 하는 일 | 결과 |
| --- | --- |
| 도면을 연다(목록에서, 도면 연결 칩으로, 다른 탭에서) | 한 장 전체가 도면 칸 가운데에 맞춰진다. 앞 도면의 확대를 물려받지 않는다 |
| 무엇을 눌러 도면에서 찾아간다(채팅의 구성요소, 지식그래프, 분석 결과) | 확대하지 않는다. 걸려 있던 강조를 풀고 그것만 잠깐 강조한다 |
| 구간을 고른다 | 확대하지 않고 그 구간만 진하게 보인다. 아무 구간도 고르지 않았으면 구간 색을 칠하지 않는다 |
| 끈다 · 휠을 돌린다 | 도면을 옮긴다 · 확대한다. 도면 위에 얹힌 것은 같은 프레임에 따라 움직인다 |
| 구성요소를 누른다 | 그 구성요소의 사양을 보인다 |
| **Ctrl**을 누른 채 누르거나 끈다 | 고른다. 구간을 고르지 않았으면 새 구간을 만들 것으로, 골랐으면 그 구간에 더하거나 뺄 것으로 모은다. 도면을 넘어가도 유지된다 |
| 바깥을 누른다 · **Esc** | 떠 있는 것(말풍선, 메뉴, 일시 강조, 모으던 고름)이 닫히거나 풀린다 |
| **Enter** | 모은 것을 적용한다 |
| **Ctrl+Z** | 방금 한 일을 되돌린다 |

- 방식(모드)을 바꾸는 단추를 두지 않는다. '이동'과 '고르기'를 오가는 대신 Ctrl 하나로 가른다.
- 마우스 포인터는 평소 화살표다. 지금 무엇이 되는지를 알릴 때만 바꾼다(Ctrl을 누르면 십자).
- 도면과 구간 패널은 늘 떠 있다. 닫거나 접는 단추를 두지 않고, 폭은 도면을 가리지 않을 만큼만 쓴다.
- 도면 탭에서는 읽은 구성요소의 네모가 늘 보인다. 켜고 끄는 단추를 두지 않는다.
- 한 번 누르면 끝나야 하는 일은 한 번으로 끝낸다. 내보내기는 폴더를 묻지 않고 정해진 자리에 쓴 뒤 그 폴더를 여는 단추를 보인다.

## 3. 새 화면을 만들 때 묻는 것

새 요소를 넣기 전에 차례로 묻는다. 하나라도 '아니오'면 넣지 않는다.

1. 이것이 없으면 사용자가 일을 못 하거나 잘못하는가.
2. 도면의 강조나 자리만으로는 같은 것을 전할 수 없는가.
3. 사용자가 이것을 보고 할 일이 있는가.
4. 이미 있는 조작(§2.5의 표)으로는 안 되는가.

넣기로 했다면, 글보다 모양(색, 강조, 아이콘)을 먼저 쓰고, 글을 쓴다면 낱말 하나로 줄일 수 있는지 본다.

## 4. 이 문서가 다루지 않는 것

- 색, 글꼴, 간격 같은 모양의 값은 [도면 중심 웹 화면](app-shell-web.md)과 시안을 따른다.
- 분석 판정의 승인·기각과 초기사건 인계의 규칙은 제품 규격(`docs/specs/`)이 정한다. 이 문서는 그 규칙을 화면에 얼마나 드러낼지만 정한다.
- 이전 Qt 화면(`hazop/app/`)에는 적용하지 않는다.

## 5. 이 원칙이 나온 지시

2026-11-25: 요약 줄·칩·안내 문구·추천 질문 삭제, 줄을 눌러 도면 열기, 도면 탭 고치기 삭제와 구성요소 사양 카드, 쓸데없는 경고 삭제, AI 채팅으로 고치기, DEXPI 내보내기 한 번에, 되도록 자동 확정.
2026-11-26: 도면 패널 고정, 바깥을 누르면 닫기, 추출 네모 항상 표시, 이동·고르기 합치기와 Ctrl 고르기, 전체 맞춤 단추 삭제, 칩이 끌기를 따라옴, 도면은 늘 전체가 가운데, 구간은 확대 없이 강조, 찾아가기는 일시 강조, 구간 확정 없애기와 바로 수정, 구간 상세 줄이기, 되돌리기는 Ctrl+Z로, 'AI 초안'·'더함/뺌' 삭제.

사용자가 붙인 말: "기본적인 유저 인터페이스", "사람 관점에서 필요한 것만", "최대한 심플하게".
