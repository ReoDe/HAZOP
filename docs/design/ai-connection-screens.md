# AI 연결 화면 설계: API 키와 Claude 구독

- 상태: 사용자 결정 반영(2026-11-09). D1은 '구독 기본', D2~D6은 권장안 ①로 채택했습니다(§11).
- 기준 문서: 상태값·오류 분류·저장 필드·화면 이름은 [AI 연결 기술 설계](../specs/ai-subscription.md) §0이 기준입니다. 이 문서는 그 값을 화면에 어떻게 보일지 정합니다. 어긋나거나 더 정해야 할 점은 §12에 모았습니다.
- 기준 화면: 지금의 API 키 설정 창(커밋 62eedba, `hazop/app/settings_dialog.py`), 상태줄 AI 표시(`hazop/app/main_window.py` `_status_bar`), AI 실행 확인·진행 표시(`hazop/app/screens/results.py` `request_ai`·`_progress_text`·`_on_finished`), Excel 표지(`hazop/export/study_xlsx.py` `_summary_sheet`). 그 밖에 [인터페이스 기획](../specs/interface.md), [INTENT.md](../../INTENT.md) §3.5·§3.8, 디자인 토큰 `hazop/app/tokens.py`.
- 시안: [mockups/ai-connection/](mockups/ai-connection/index.html). `python docs/design/mockups/ai-connection/build.py`로 HTML과 1366·1920 PNG를 다시 만듭니다. 셸 모양은 [완성본 B안](mockups/final/b-dense-workbench/)의 CSS를 그대로 읽어 씁니다.
- 단위: **호출**은 AI를 한 번 부르는 것이고, **칸**은 구간×편차 한 칸입니다. 호출 하나가 구간 하나의 같은 변수 편차를 묶어 처리하므로(`ai_cells.plan_units`) 호출 수와 칸 수는 다릅니다. 시안의 예는 구간 5개 × 편차 6개(유량 4, 압력 2) = 30칸, 호출 10회입니다.

## 2. 연결 방식과 상태

### 2.1 연결 방식(`provider`)

| 값 | 화면 이름 | 칩 약칭 | 비용 성격(설정 창·실행 확인에 쓰는 한 줄) | 보이는 때 |
| --- | --- | --- | --- | --- |
| `api` | API 키 | API 키 | 호출마다 요금이 나갑니다. Anthropic Console에서 발급한 키가 필요합니다. | 늘. 배포본에서는 유일한 방식 |
| `subscription` | Claude 구독 | 구독 | 건별 요금이 없습니다. 쓴 만큼 구독 사용 한도에서 빠집니다. | 개발자 PC에서만(설정 파일의 개발자 표시). 배포본에서는 목록에도 없음 |
| `fixed` | 고정 응답(시험) | 시험 | AI를 부르지 않고 저장해 둔 응답으로 칸을 채웁니다. 화면과 흐름을 시험할 때 씁니다. | 디버그 실행(`--debug`)만 |

### 2.2 연결 상태(`conn_state`)와 사유(`conn_reason`)

값은 기술 설계 §0.2·§0.3 그대로입니다. 화면 글자는 칩에 쓰는 짧은 말입니다.

| `conn_state` | `conn_reason` | 화면 글자 | 아이콘 모양 | 색 토큰(바탕·글자·테두리) | AI 실행 |
| --- | --- | --- | --- | --- | --- |
| `unchecked` | — | 확인 안 함 | 원 안 물음표 | `surface-2` · `ink-2` · `line` 1px | 됨(시작할 때 먼저 확인) |
| `checking` | — | 확인 중 | 점선 원 | `surface-2` · `ink-2` · `line` 1px | 확인이 끝날 때까지 기다림 |
| `ready` | — | 연결됨 | 원 안 체크 | `ok-bg` · `ok` · `ok` 1px | 됨 |
| `limit_warning` | — | 한도 가까움 | 시계 | `warn-bg` · `warn-ink` · `warn-line` 1px | 됨(실행 확인에 경고) |
| `limit_reached` | — | 한도 도달 | 시계 | `warn-bg` · `warn-ink` · `warn-line` 1.5px | 막음 |
| `not_ready` | `cli_not_found` | 미설치 | 아래 화살표와 받침 | `warn-bg` · `warn-ink` · `warn-line` 1.5px | 막음 |
| `not_ready` | `cli_too_old` | 업데이트 필요 | 아래 화살표와 받침 | 같음 | 막음 |
| `not_ready` | `cli_unsupported_shim` | 설치 방식 바꿈 필요 | 아래 화살표와 받침 | 같음 | 막음 |
| `not_ready` | `not_logged_in` | 로그인 필요 | 삼각형 느낌표 | 같음 | 막음 |
| `not_ready` | `login_expired` | 다시 로그인 필요 | 삼각형 느낌표 | 같음 | 막음 |
| `not_ready` | `not_subscription` | 구독 계정 아님 | 삼각형 느낌표 | 같음 | 막음 |
| `not_ready` | `no_key` | 키 없음 | 원 안 물음표 | `surface-2` · `ink-2` · `line-strong` 1.5px | 막음 |
| `not_ready` | `key_rejected` | 키 거부됨 | 원 안 가위표 | `err-bg` · `err-ink` · `err-line` 1.5px | 막음 |
| `failed` | `network` | 연결 못 함 | 원 안 가위표 | `err-bg` · `err-ink` · `err-line` 1.5px | 다시 확인 안내 |
| `failed` | `unknown` | 오류 | 원 안 가위표 | 같음 | 다시 확인 안내 |
| (고정 응답) | — | 준비됨 / 응답 폴더 없음 | 플라스크 / 원 안 물음표 | AI 빗금(`ai-hatch-a`·`ai-hatch-b`) · `ai-ink` · `line-strong` 점선 | 됨 / 막음 |

- 배포본에서 구독이 숨겨진 것은 상태가 아니라 목록에서 빠지는 것입니다. 칩·설정 창·안내 문구 어디에도 구독이 나오지 않습니다.
- 실행할 수 없는 상태는 모두 테두리 1.5px입니다. 색이 아니라 굵기로도 '손볼 것이 있다'를 알립니다.
- 아이콘은 글꼴 기호가 아니라 앱이 그리는 SVG 아이콘(QIcon)입니다. 맑은 고딕에 없는 기호가 네모로 깨지는 일을 피합니다. 같은 아이콘을 쓰는 상태도 글자가 다르므로 흑백에서도 구분됩니다.

### 2.3 한도 상태(`usage_view`)

구독의 한도는 호출 중에 받은 `rate_limit_event`로만 압니다(기술 설계 §5.3). 화면 규칙은 다음과 같습니다.

| 한도 값 | 사용량 줄 글자 |
| --- | --- |
| `limit_unknown` | 한도 정보가 없습니다. 첫 호출 뒤에 보입니다. |
| `limit_ok` | 5시간 한도 38% 사용 · 17:40 재설정 (14:02 호출 기준) |
| `limit_warning` | 5시간 한도 86% 사용 · 17:40 재설정 (14:02 호출 기준). 다음 줄에 주황 글자 "한도가 가까워 도중에 멈출 수 있습니다." |
| `limit_reached` | 5시간 한도 도달 · 17:40 재설정 |

- 주간 한도(`seven_day` 등) 이벤트를 받은 적이 있으면 둘째 줄에 같은 형식으로 보입니다.
- 사용률이 없고 상태만 있으면 퍼센트와 막대를 빼고 상태 글자만 보입니다. "여유 있음"이라고 쓰지 않습니다.
- 남은 호출 수나 이번 실행이 쓸 사용률을 어림해 보이지 않습니다. 근거 수치가 없습니다.

### 2.4 확인 시점

- 앱을 켤 때 지금 쓰는 방식만 확인합니다. 구독은 `check()`(설치·버전·로그인, 토큰을 쓰지 않음), API 키는 지금처럼 '확인 안 함'으로 둡니다.
- 다시 확인하는 때: 설정 창을 열 때, 칩 상세 창의 '다시 확인', AI 실행 직전, 실행 중 오류가 났을 때.
- 마지막 확인 시각을 상세 창과 설정 창에 보입니다("14:02 확인").

시안: [1-연결설정-구독](mockups/ai-connection/1-settings-subscription.html), [2-연결설정-API키](mockups/ai-connection/2-settings-api-key.html), [3-연결설정-실행중](mockups/ai-connection/3-settings-running.html), [4-구독처음사용](mockups/ai-connection/4-subscription-first-use.html), [10-배포본](mockups/ai-connection/10-bundle.html).

### 3.1 들어가는 길

- 파일 메뉴 'AI 연결 설정…'(지금의 'API 키 설정…' 자리), 명령 팔레트 'AI 연결 설정', 상태줄 연결 칩 → 상세 창 → '연결 설정…'.
- 창 제목: **AI 연결 설정**.

### 3.2 구조

크기는 760×560(최소 720×520)입니다. 1366×768에서 작업표시줄을 빼고도 들어갑니다. 1920×1080(125%)은 논리 1536×864라 여유가 있습니다.

```
┌ AI 연결 설정 ───────────────────────────────────────────────┐
│ 연결 방식(W)          │ Claude 구독                    [사용 중] │
│ ┌──────────────────┐ │ 건별 요금이 없습니다. 쓴 만큼 구독 사용 한도에서… │
│ │ Claude 구독       │ │ ┌ 상태 ──────────────────────────────┐ │
│ │ ✓ 연결됨 · 사용 중 │ │ │ ✓ 연결됨 · 14:02 확인   [연결 확인(T)] │ │
│ ├──────────────────┤ │ │ 프로그램  claude 2.1.319 · C:\…\claude.exe │ │
│ │ API 키            │ │ │ 계정      로그인됨 · Max 20x 요금제     │ │
│ │ ? 확인 안 함       │ │ │ 사용량    5시간 한도 38% · 17:40 재설정  │ │
│ └──────────────────┘ │ └──────────────────────────────────┘ │
│                      │ 모델(M)  [Opus 5.5 · 한도 소모 큼 ▾]      │
│                      │ 안내 문구(한도 공유, 학습 설정)            │
│ 메시지 줄                                 [이 방식으로 사용(U)] [닫기] │
└──────────────────────────────────────────────────────────────┘
```

- **왼쪽 목록**: Claude 구독, API 키, (디버그에서만) 고정 응답 순서입니다. 배포본에서는 API 키 하나뿐이라 목록을 빼고 API 키 상세만 보입니다(§3.8). 항목마다 두 줄이고, 둘째 줄은 `아이콘 상태`와 지금 쓰는 방식이면 ' · 사용 중'. 위아래 화살표로 옮기면 오른쪽 상세가 바뀌고 방식은 바뀌지 않습니다.
- **오른쪽 머리**: 방식 이름, 지금 쓰는 방식이면 '사용 중' 배지(검은 채움, 글자 포함), 비용 성격 한 줄(§2.1).
- **아래 줄**: 왼쪽에 메시지(성공은 회색, 실패는 빨간 글자), 오른쪽에 '이 방식으로 사용(&U)'과 '닫기'. 보고 있는 방식이 이미 사용 중이면 단추를 숨기지 않고 비활성으로 두고 글자를 '사용 중'으로 바꿉니다(단추 자리가 흔들리지 않게).
- '이 방식으로 사용'은 그 방식이 실행할 수 없는 상태여도 누를 수 있습니다. 누르면 바로 다시 확인하고, 실행할 수 없으면 메시지 줄에 이유를 적습니다("로그인한 뒤 AI를 실행할 수 있습니다"). 미리 바꿔 두고 로그인은 나중에 할 수 있게 하려는 것입니다.
- **API 키로 바꿀 때만** 확인 상자를 한 번 띄웁니다: "API 키로 바꾸면 호출마다 요금이 나갑니다. 지금 모델(Opus 5.5)로 검토구간 1개를 분석하면 약 $0.86입니다. 바꿀까요?" [API 키로 바꾸기] [취소]. 구독·고정 응답으로 바꿀 때는 묻지 않습니다.

### 3.3 Claude 구독 상세

| 줄 | 내용 | 알 수 없을 때 |
| --- | --- | --- |
| 상태 | 상태 칩 + 마지막 확인 시각 + [연결 확인(&T)] | — |
| 프로그램 | `claude 2.1.319 · C:\Users\사용자\.local\bin\claude.exe` + [위치 지정…] | "찾지 못함" + [설치 방법 보기] |

### 3.6 구독 처음 사용(이용 조건 창)

시안: [4-구독처음사용](mockups/ai-connection/4-subscription-first-use.html). 구독으로 처음 AI 분석을 실행할 때, 실행 확인 대화상자보다 먼저 한 번 뜹니다. 설정 창에서 Claude 구독을 고르고 '이 방식으로 사용'을 처음 누를 때도 같은 창이 뜹니다. 기술 설계 §4.3·§7.1과 U11(처음 한 번)의 내용을 화면 문구로 옮긴 것입니다.

> **Claude 구독으로 분석하기 전에**
>
> 이 PC에 설치하고 본인 계정으로 로그인한 Claude Code를 거쳐 본인 구독 사용량으로 AI 분석을 합니다.
>
> - 본인 계정을 본인 PC에서 쓰는 경우만 해당합니다. 다른 사람의 계정이나 공용 계정으로 쓰지 마세요.
> - Claude 구독은 소비자 약관을 따릅니다. claude.ai 개인정보 설정에서 '모델 개선'이 켜져 있으면 보낸 도면 정보가 학습에 쓰일 수 있습니다. 보안 등급이 있는 자료를 분석하기 전에 그 설정을 확인하세요.
> - 앱은 로그인 정보를 읽거나 저장하지 않습니다. 로그인은 Claude Code에서 직접 합니다.
>
> ☐ 위 내용을 확인했습니다
>
> [확인하고 계속(&O)] [API 키로 분석…] [취소]

- '확인하고 계속'은 확인란을 고를 때만 누를 수 있습니다. 누르면 확인한 시각을 설정 파일에 남기고 실행 확인 대화상자로 넘어갑니다. 다음부터는 이 창을 띄우지 않습니다.
- 'API 키로 분석…'은 설정 창을 API 키 상세로 엽니다(§3.2의 요금 확인을 거침).
- '취소'는 실행하지 않고 닫습니다. 방식은 구독 그대로이고, 다음 실행 때 이 창이 다시 뜹니다.

### 3.7 실행 중일 때

AI 분석이 돌고 있으면 오른쪽 상세 맨 위에 안내 띠를 띄우고 다음을 막습니다: '이 방식으로 사용', 모델 선택, API 키 선택·삭제. 이름 변경, 새 키 추가, 연결 확인은 막지 않습니다.

> AI 분석이 돌고 있어 연결 방식과 모델을 바꿀 수 없습니다. 실행이 끝나거나 실행을 취소한 뒤 바꾸세요. [실행 취소]

### 3.8 배포본

시안: [10-배포본](mockups/ai-connection/10-bundle.html). 배포본(설정 파일에 개발자 표시가 없음)에서는 구독을 숨깁니다(기술 설계 U3).

- 설정 창은 왼쪽 목록 없이 API 키 상세만 보입니다. 창 제목은 그대로 'AI 연결 설정'이고 폭은 600px로 줄입니다.
- 상세 맨 위에 회색 한 줄: "이 배포본은 API 키로만 AI에 연결합니다."
- 칩은 늘 `API 키 · 모델 · 상태`입니다. 구독 관련 상태·문구·단추(구독 처음 사용 창, 'API 키로 이어서 실행' 등)는 나오지 않습니다.
- 한도 도달 흐름(§7.3)도 구독 문구 대신 API 429 문구(§9.2)만 씁니다.

## 4. 처음 쓸 때의 안내

기본 방식은 앱이 정합니다. 따로 고르는 창은 띄우지 않습니다.

| 경우 | 기본 방식 | 사용자에게 보이는 것 |
| --- | --- | --- |
| 개발자 PC, 고른 방식이 없고 구독 확인 통과 | Claude 구독 | 칩 `✓ 구독 · Opus 5.5 · 연결됨`. 첫 분석 때 §3.6 이용 조건 창 |
| 개발자 PC, 고른 방식이 없고 구독 확인 실패, API 키 있음 | API 키 | 토스트 한 번: "Claude Code를 쓸 수 없어 API 키로 연결했습니다. 구독을 쓰려면 AI 연결 설정을 여세요. [AI 연결 설정]" |
| 개발자 PC, 고른 방식이 없고 구독 확인 실패, API 키 없음 | Claude 구독(실행할 수 없는 상태) | 칩이 그 상태(예: `⚠ 구독 · Opus 5.5 · 로그인 필요`). AI 분석을 실행하면 설정 창을 구독 상세와 해결 띠(§9.1)로 엶 |

| 개발자 PC, 사용자가 '이 방식으로 사용'으로 고른 적 있음 | 고른 방식 | 바꾸지 않음 |

- 앱이 정한 방식은 사용자가 고른 것이 아니므로, 사용자가 '이 방식으로 사용'을 누르기 전까지 앱을 켤 때마다 다시 정합니다. 오늘 로그인이 풀려 API 키로 연결됐더라도 다시 로그인하면 다음에 켤 때 구독으로 돌아옵니다.
- 기본 방식이 바뀔 때만 토스트를 띄웁니다. 결과가 같으면 조용히 넘어갑니다.

- 지금 방식이 실행할 수 없는 상태면 확인 대화상자 대신 그 상태의 해결 안내(§9)를 띄웁니다. 예: "Claude Code 로그인이 필요합니다. … [터미널에서 로그인] [AI 연결 설정…] [닫기]".

## 7. 실행 중 표시와 도중 사건

시안: [7-한도도달](mockups/ai-connection/7-limit-reached.html).

### 7.1 진행 줄

막대 옆 짧은 줄과 상태줄 긴 줄의 마지막 칸(지금의 비용 칸)만 방식에 따라 바뀝니다.

| 방식 | 막대 옆 줄 |
| --- | --- |
| API 키 | AI 4/10 호출 · S3 · 유량 분석 중 · 2:41 경과 · 약 4:00 남음 · $0.36 |
| Claude 구독 | AI 4/10 호출 · S3 · 유량 분석 중 · 2:41 경과 · 약 4:00 남음 · 구독 사용량 차감 |
| Claude 구독(한도 가까움) | … · 약 4:00 남음 · 한도 가까움(86%) |
| 고정 응답 | 시험 4/10 · S3 · 유량 · 고정 응답 |

- 도구 설명의 "이번 실행" 줄: API 키는 지금처럼 토큰과 $, 구독은 토큰만("입력 412k · 출력 38k 토큰, 구독 사용량에서 차감"), 고정 응답은 "AI 호출 없음".
- 실행 중 연결 칩의 글자는 그대로 두고, 상세 창에만 진행 줄을 보입니다. 칩이 진행률로 깜빡이면 상태줄이 어수선해집니다.

### 7.2 실행 중 방식·모델 변경

막습니다(A6, §3.7). 사용자가 터미널에서 로그아웃하는 것처럼 앱 밖에서 바뀌는 경우는 다음 호출이 실패하므로 §7.4의 흐름을 탑니다.

### 7.3 한도 도달

1. 한도 오류를 받은 호출의 칸은 기술 설계대로 `error_kind: limit_reached`로 기록합니다. 행렬에는 '실패'가 아니라 **'한도로 멈춤'**으로 보입니다(빨간 실패와 다르게 주황, 글자 포함). 아직 돌지 않은 칸은 '분석 전'으로 둡니다.
2. 남은 호출은 부르지 않고 실행을 끝냅니다(재시도로 한도를 더 쓰지 않음).
3. ⑤ 화면 위에 주황 안내 띠를 띄웁니다.

> 구독 사용 한도에 닿아 AI 분석을 멈췄습니다. 호출 10회 중 4회의 결과(12칸)는 저장했습니다. 남은 6회(18칸)는 17:40 재설정 뒤에 이어서 돌리거나 API 키로 돌릴 수 있습니다.
> [남은 칸 이어서 실행(&C)] [API 키로 이어서 실행…] [닫기]

   - 재설정 시각을 모르면 "재설정 시각은 아직 알 수 없습니다."로 바꿉니다.
   - '남은 칸 이어서 실행'은 이번 실행에서 '한도로 멈춤'과 '분석 전'으로 남은 칸만 돌립니다. 재설정 전에도 누를 수 있고, 아직 한도면 첫 호출에서 같은 띠가 다시 뜹니다.
   - 'API 키로 이어서 실행…'은 API 키 기준 실행 확인 대화상자(남은 6회, 예상 비용 $)를 띄웁니다. 확인 대화상자 위에 "이번 남은 호출만 API 키로 돌립니다. 끝나면 Claude 구독으로 돌아갑니다."를 적습니다. 키가 없으면 설정 창의 API 키 상세를 엽니다.
4. 연결 칩은 '한도 도달 · 17:40 재설정'이 됩니다. 재설정 시각이 지나면 앱이 다시 확인하고 칩을 '연결됨'으로 돌린 뒤 토스트를 띄웁니다: "구독 한도가 재설정됐습니다. 남은 18칸을 이어서 실행할 수 있습니다. [이어서 실행]". 자동으로 실행하지는 않습니다(§11 D2).
5. 끝난 뒤 상태줄 메시지: "AI 분석 멈춤(한도 도달): 4/10 호출 · 2:41 걸림 · 저장: …".

### 7.4 그 밖의 도중 사건

| 사건(`error_kind`·사유) | 실행 | ⑤ 띠 | 단추 |
| --- | --- | --- | --- |
| `not_ready` · `not_logged_in`·`login_expired` | 남은 호출 멈춤 | 빨강: "Claude Code 로그인이 풀려 AI 분석을 멈췄습니다. 받은 칸은 저장했습니다. 다시 로그인한 뒤 이어서 실행하세요." | 터미널에서 로그인 · 다시 확인 · 닫기. 확인에 성공하면 '다시 확인' 자리에 '남은 칸 이어서 실행' |
| `not_ready` · `not_subscription` | 남은 호출 멈춤 | 주황: "Claude Code가 구독이 아닌 계정으로 로그인돼 있어 AI 분석을 멈췄습니다. 이대로 쓰면 건마다 요금이 나갑니다." | 로그인 방법 보기 · 다시 확인 · 닫기 |
| `transient`·`timeout`·`bad_output`·`refused`·`other` | 그 칸만 실패, 실행은 계속 | 없음(지금처럼 '실패 칸 다시' 단추) | — |
| 같은 `transient`·`timeout`이 3회 연속 | 남은 호출 멈춤 | 빨강: "같은 오류가 3번 이어져 AI 분석을 멈췄습니다. 연결 상태를 확인하세요." | 다시 확인 · 오류 내용 복사 · 닫기 |
| `cancelled` | 이미 멈춤 | 없음 | — |

'3회 연속'은 이 문서의 제안입니다(§12).

## 8. 결과 기록에 연결 방식 남기기

시안: [8-결과기록](mockups/ai-connection/8-result-record.html).

### 8.1 ⑤ 화면

- **칸 상세(워크시트 패널)** 머리 아래 회색 한 줄: "AI 초안 · Opus 5.5 · Claude 구독 · 11-09 14:20 KST". 요청 모델과 실제 응답 모델이 다르면 "AI 초안 · Sonnet 5.5(요청 Opus 5.5) · …"로 둘 다 적습니다.
- 행렬 칸에는 API 키·구독 구분을 보이지 않습니다. 같은 모델이면 결과의 성격이 같고, 행렬이 이미 빽빽합니다.
- 도구줄 사용량 도구 설명: "이 결과의 AI 호출: 구독 13회(Opus 5.5) · API 키 4회(Sonnet 5.5) $0.36 · 토큰 …". 요금은 API 키 호출분만 더합니다.
- **시험용 파일을 열었을 때**: ⑤ 맨 위에 빗금 띠 "시험 결과를 보는 중입니다. 고정 응답으로 채운 칸이며 실제 분석 결과가 아닙니다. [실제 결과로 돌아가기]". 칸 상세 머리 줄은 "시험 · 고정 응답 · 응답 파일 S2-유량.json · 11-09 13:05 KST".

### 8.2 Excel

- **표지·요약** 시트에 두 줄을 더합니다.
  - "AI 초안 생성": `Opus 5.5 · 구독 39칸, Sonnet 5.5 · API 키 12칸`
  - "AI 사용 요금(API 키 호출분)": `$0.36`. 구독 호출은 요금 칸에 넣지 않습니다.
- **워크시트** 시트 오른쪽 끝에 "AI 초안 생성" 열(폭 22)을 더합니다. 값 예: `Opus 5.5 · 구독 · 11-09 14:20`. 검토자가 새로 더한 항목은 빈칸입니다.
- **시험용 파일에서 내보낼 때**: 표지 "고지" 줄 바로 아래에 빨간 굵은 글씨로 "시험용 고정 응답으로 채운 결과입니다. 실제 검토 결과로 쓰지 마세요."를 넣고, 파일 이름 끝에 `-시험`을 붙입니다.

### 8.3 저장 필드

기술 설계 §0.4·§4.1·§5.4의 필드를 화면이 읽습니다.

- 칸 `ai_run`과 `ai_log[]`: `provider`(`api`·`subscription`·`fixed`), `model`(실제 응답 모델), `error_kind`.
- 화면이 더 필요로 하는 것: `model_requested`(요청 모델). 기술 설계 §4.3은 실제 모델 확인 방법만 정했으므로 §12에 올립니다.
- `cost_usd`는 `billing: per_call`(API 키) 기록에만 값이 있고, 구독·고정 응답은 `null`입니다. 0으로 두면 화면이 "$0.00"을 보이게 됩니다. 구독의 API 환산값 `api_equiv_usd`는 기록에만 두고 화면에 보이지 않습니다(U6 ①).
- `provider`가 없는 옛 기록은 `api`로 읽습니다(구독 연결 전에는 API뿐이었음).
- 고정 응답을 실제 결과 파일에 돌리면 안 되는 이유: `ai_cells.apply_unit`은 칸의 AI 제안 항목을 새 응답으로 바꿉니다. 같은 파일에 시험을 돌리면 이미 받은 AI 초안이 시험 값으로 덮입니다. 그래서 A8은 시험용 파일을 따로 둡니다.

### 10.2 키보드

- 설정 창 탭 순서: 연결 방식 목록 → 오른쪽 상세의 단추·입력칸(위에서 아래) → 이 방식으로 사용 → 닫기. 단축 글자: 연결 방식(&W), 연결 확인(&T), 터미널에서 로그인(&L), 모델(&M), 이 방식으로 사용(&U), 사용할 키(&K), 응답 폴더(&F). 지금 API 키 상세의 단축 글자(R·D·N·P·V·A)와 겹치지 않습니다.
- 구독 켜기 창: 확인란(Space) → 켜기(&O) → 취소. Esc는 취소.
- 연결 칩: Tab으로 닿고 Enter·Space로 상세 창. 상세 창 단추는 다시 확인(&R), 연결 설정…(&S). Esc로 닫으면 칩으로 포커스가 돌아갑니다.
- 실행 확인: 시작(&S)이 기본 단추, Esc는 취소.
- ⑤ 안내 띠: 띠가 떠도 포커스를 옮기지 않습니다(작업 방해 없음). F6으로 띠에 닿고, 띠 안 첫 단추가 남은 칸 이어서 실행(&C)입니다.

## 12. 기술 설계와 맞출 점

[AI 연결 기술 설계](../specs/ai-subscription.md)와 대조한 결과입니다. 1~4는 화면이 기술 설계에 더 바라는 것이고, 5~9는 확인이 필요한 것입니다.

1. **구독 꺼짐 상태.** 기술 설계 §0.2에는 구독이 설정에서 꺼져 있을 때의 상태가 없습니다. 화면은 목록 항목에 '꺼짐'을 보이므로, 설정 값(`subscription_enabled`)과 켠 시각(이용 조건 확인 시각)을 저장할 자리가 필요합니다. (D1 결정 뒤: '꺼짐'은 없어졌고, 이용 조건 확인 시각과 '사용자가 고른 방식인지 앱이 정한 방식인지' 표시만 저장하면 됩니다. §3.6·§4)
2. **요청 모델.** 칸 상세에 "Sonnet 5.5(요청 Opus 5.5)"를 보이려면 `ai_run`·`ai_log[]`에 `model_requested`가 필요합니다. 기술 설계 §4.3·M4는 실제 모델 확인까지만 적었습니다.
3. **이어서 실행 범위.** '남은 칸 이어서 실행'은 '이번 실행에서 `limit_reached`로 끝난 칸 + 돌지 않은 칸'을 돌립니다. 기술 설계 §5.3은 "재설정 시각 이후 실패 칸 다시 실행"이라고 적었으므로, 돌지 않은 칸까지 포함하는 실행 범위를 `plan_units`에 더할지 정해야 합니다. 더하지 않으면 띠의 단추를 '실패 칸 다시 실행'과 '모든 구간 실행' 둘로 나눕니다.
4. **연속 오류 멈춤.** §7.4의 "같은 `transient`·`timeout` 3회 연속이면 멈춤"은 기술 설계 §0.4(이 둘은 '계속')에 없는 규칙입니다. 받아들일지와 횟수를 정합니다.
5. **API 잔액 부족.** 크레딧 부족은 지금 `key_rejected`의 문구로 처리합니다. 따로 사유(`no_credit` 같은)를 둘지 기술 설계에서 정합니다.
6. **API 429의 칩 표시.** 기술 설계는 API 429도 `limit_reached`로 분류합니다. 칩은 구독과 같은 '한도 도달'을 보이되 재설정 시각 대신 "잠시 뒤 다시"를 붙입니다. API 응답에 재시도 시각이 있으면 그것을 씁니다.
7. **사용량 단위.** 사용률·재설정 시각은 `rate_limit_event`(M3)로 확정됩니다. `resets_at` 단위와, 주간 한도 이벤트가 실제로 오는지에 따라 §2.3의 둘째 줄을 넣거나 뺍니다.
8. **요금제 이름.** `account.plan`의 `planTier` 값(예: `max_20x`)을 화면 이름("Max 20x 요금제")으로 바꾸는 표가 필요합니다.
9. **터미널 열기.** 새 명령 프롬프트 창에서 `claude auth login`·`claude update`를 띄우는 방식이 회사 PC 정책에서 막히지 않는지. 막히면 단추를 '방법 보기' 하나로 줄입니다.
10. **창 닫을 때(U9).** 진행 중 호출을 기다릴지 끊을지 묻는 창은 이 문서 범위 밖입니다. U9가 ③(묻기)으로 정해지면 별도로 그립니다.
