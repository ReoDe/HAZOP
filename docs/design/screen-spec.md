# 현재 화면 명세 (①~⑤)

[데스크톱 인터페이스 기획](../specs/interface.md) · ['출력화면 AX' 데모 분석](output-screen-ax-demo.md) · [③ 지식그래프 화면](kg-screen.md) · [시안 README](mockups/README.md) · [공통 원칙](../specs/overview.md#principles)

## 이 문서의 위치

- 이 문서는 새로 설계한 것이 아닙니다. 이미 구현된 데스크톱 앱(`hazop/app/`) 화면 ①~⑤를 거꾸로 읽어 **현재 화면이 어떻게 생겼고 어떻게 쓰이는지** 적은 명세입니다([남은작업](../records/backlog.md), 총괄 결정(권고안, 사용자 위임 2026-11-06)).
- 기준은 코드(`hazop/app/main_window.py`, `hazop/app/screens/*.py`)와 2026-11-06 스크린샷(①②④⑤ 1440×860, ⑤ 1366×768, ③)입니다. 화면 규칙의 정본은 [interface.md](../specs/interface.md)이고, 이 문서는 그 규칙이 화면 어디에 있는지를 보여 줍니다. 규칙이 다르면 기획서가 우선하며, 어긋난 점은 §9에 적었습니다.
- 색·글자 크기 값은 적지 않고 토큰 이름만 씁니다. 값의 정본은 `hazop/app/tokens.py`입니다(`COLORS`, `FONT_SIZE`, `HL_DIM`, `KG_*`). 모서리는 토큰이 없어(스타일시트에 값이 직접 들어 있음) 적지 않습니다.
- 화면 번호는 기획서 단계 번호입니다. 앱 내부의 화면 순서(index)는 ③을 나중에 추가해 다르지만, 단계 탭에는 ① ② ③ ④ ⑤ 순서로 보입니다.

## 1. 공통 틀

```
┌ 메뉴: 파일 · 보기 · 도움말 ─────────────────────────────────────────────────────┐
│ ● HAZOP 분석 도구  구간 이름 · 도면 번호 · 실행 ID(회색)   [① ② ③ ④ ⑤]  검토자 이름 │ ← 헤더(Qt)
├────────────────────────────────────────────────────────────────────────────────┤
│                      화면별 본문 (§2~§6)                                         │
├────────────────────────────────────────────────────────────────────────────────┤
│ [결과 검증 칩] 진행 중 작업 · 최근 저장 시각                         안내 메시지 │ ← 상태줄(Qt)
└────────────────────────────────────────────────────────────────────────────────┘
```

| 영역 | 구성 | 기획서 |
| --- | --- | --- |
| 헤더 | 로고, 프로그램 이름, 현재 위치(구간·도면은 굵게, 실행 ID는 `muted`), 단계 알약 탭(선택 탭만 `ui` 채움), 검토자 이름. 현재 위치는 폭이 모자라면 잘리고 전체 문장은 툴팁 | §2.1 |
| 메뉴 | 파일(Excel 내보내기(⑤ 분석 결과), 설정(검토자 이름), 끝내기), 보기(각 화면, 도면 보기, 그래프 보기, 웹 속성 패널 숨기기/보이기, 이전 MVP(옛 화면 둘, 구간 열기, 실행 열기)), 도움말(버전·데이터 위치) | §2.1 |
| 상태줄 | 결과 검증 칩(열린 실행 기준. 통과면 "형식·참조 검증 통과 — 보류 없음을 뜻하지 않음"을 함께 표시), "진행 중: <작업> (취소 불가)", "최근 저장 <KST 시각>", 오른쪽 안내 메시지 | §2.1, §2.4, §3 공통 |
| 단계 탭 이동 | 자유 이동. 앞 단계 결과가 없으면 그 화면이 빈 상태 안내를 보여 줌 | §2.1 |
| 웹뷰 | 인스턴스 하나를 ②③④⑤가 공유하고, 화면을 바꿀 때 그 화면의 캔버스 자리로 옮김 | §2.2 |
| 처음 실행 | 검토자 이름이 설정에 없으면 입력 대화상자 | §3.4 |

공통 표시 규칙(화면마다 반복하지 않음):

| 상태 | 표현 | 토큰 |
| --- | --- | --- |
| AI·자동 산출(원안, AI 해석, 위험도 제안, 표제란 자동 후보) | 옅은 회색 바탕 + 점선 테두리 상자, "[AI] 제안"·"자동 후보" 배지, 위험도는 속 빈 칩("제안") | `ai-hatch-*`, `ai-ink` |
| 사람 확정 | 흰 바탕 + 진한 실선 상자, 검은 "확정" 배지, 위험도는 채운 칩 | `human-line`, `card` |
| 미확인 | "미확인" 글자 + 사유. 빈칸·0·"없음"으로 바꾸지 않음 | `warn-*` |
| 오류·차단 | 빨간 띠 + 사유·다음 조치. 화면 전체를 막지 않음 | `err-*` |
| 경고 | 호박 띠 | `warn-*` |
| 검증 칩 | 통과 = 초록, 차단 = 빨강, 경고 = 호박 | `ok`, `err-*`, `warn-*` |
| 위험도 | 〈표9〉 허용 구분 3단으로만 색 구분, 숫자와 등급명을 항상 함께 | `risk-ok-*`, `risk-cond-*`, `risk-deny-*` |

Qt에서는 빗금 무늬를 쓰지 않고 옅은 회색 + 점선 테두리로 대신합니다(`tokens.py` 주석). HTML 시안의 빗금과 모양이 다릅니다.

## 2. ① 자료 등록

**목적**: draw.io P&ID 원본 1개를 등록하고 추출·그래프 생성까지 실행합니다(인터페이스 §3.1).

```
┌ 등록 자료 (패널) ───────────────────┐┌ 등록 (패널) ─────────────────────────────┐
│ 자료 ID│버전│원본│도면번호│개정│     ││ 프로젝트 ID [            ]               │
│ 등록 시각│상태│추출│그래프           ││ ┌ 파일 놓기 영역(점선) ─────────────┐    │
│ ...                                ││ └───────────────────────────────────┘    │
│                                    ││ [파일 선택]  파일 정보·SVG 함께 등록/경고  │
│                                    ││ 식별정보(비우면 미확인)                   │
│                                    ││  도면번호 [  ] [후보 확정] 자동 후보 값     │
│                                    ││  개정번호 [  ] [후보 확정] …              │
│                                    ││  제목     [  ] [후보 확정] …              │
│                                    ││ 등록자 [ ]  사유 [ ]                      │
│                                    ││ [등록] [추출·그래프 만들기]               │
│                                    ││ ┌ 결과 영역 ────────────────────────┐    │
└────────────────────────────────────┘└──────────────────────────────────────────┘
```

| 요소 | 동작 |
| --- | --- |
| 파일 놓기·선택 | 1개만. 여러 개를 놓으면 "한 개씩 등록하세요"를 빨간 글자로 보이고 아무것도 고르지 않음 |
| SVG | draw.io: 같은 이름의 SVG가 있으면 "SVG 함께 등록(파생 자료)", 없으면 호박 경고 "도면 오버레이를 만들 수 없음(그래프 보기만 가능)". PDF: "PDF N쪽 · 등록하면 첫 쪽을 자동 추출해 ② 도면에 표시(도면은 PDF에서 그림)" |
| 식별정보 | 표제란 자동 판독값은 "자동 후보" 배지로 옆에 표시. '후보 확정'을 눌러야 입력란에 들어감. 비우면 미확인 |
| 결과 영역 | 등록 결과, 단계(형식 확인 → 해시 → 저장 → 저장 후 해시 확인), 확정값은 "확정" 배지, 값이 없으면 호박 "미확인", `validation.unknowns` 목록, 파생 SVG 해시 앞자리 |
| 추출·그래프 만들기 | PDF는 등록 성공 직후 자동 실행하고 ②로 이동. 목록에서 상태가 등록 완료인 행을 골라야 켜짐. 결과: 추출 검증·노드·관계·미해결·미확인 수, SVG 대응과 출처, 그래프 버전·구조 검증 |

| 상태 | 표시 |
| --- | --- |
| 빈 상태 | 목록 자리에 "등록된 자료가 없습니다. 오른쪽에 draw.io 원본 또는 벡터 PDF를 놓아 등록하세요." |
| 진행 | 결과 영역에 단계 문구, 상태줄에 "진행 중: 등록 (취소 불가)" |
| 오류 | "실패 — 완료로 표시하지 않음"과 사유(손상·빈 파일, 확장자 불일치, 저장 후 해시 불일치 등) |
| 보류 | 등록 상태 `on_hold`(보류)는 목록 상태 열에 표시. 추출 버튼은 켜지지 않음 |
| 재검토 | 같은 해시가 이미 있으면 결과 영역에 "기존 등록 재사용(같은 해시)"을 안내 |

## 3. ② 도면·그래프

**목적**: 추출 결과를 도면 위에서 원본과 대조합니다(인터페이스 §3.2). 화면 대부분은 기존 독립 뷰어(`hazop/viewer/template.html`)를 그대로 쓰되, 도면/P&ID 구조 탭은 숨깁니다(사용자 결정 2026-11-06).

```
도면 [추출 결과 선택 ▾] [구조 검증 칩] [노드 N · 관계 M · 미확인 K]        ← Qt 도구줄
[차단 띠] [경고 띠]                                                      ← 필요할 때
┌ 웹뷰 ───────────────────────────────────────────────────────────────────────┐
│ 도면 번호 · 제목                                         구조 검증 칩(웹)    │
│ ┌검색┐                                     ┌레이어 토글·범례┐ │ 속성 패널   │
│                 도면 SVG + 오버레이                           │ (클릭한     │
│                                           ┌경로 질의(그래프 검증용)┐│  객체)   │
│ ┌− 배율 + 맞춤┐                           └────────────────────┘│            │
└─────────────────────────────────────────────────────────────────────────────┘
```

| 요소 | 동작 |
| --- | --- |
| 도면/P&ID 구조 탭 | ②에서는 숨김(`hide_graph`). ④⑤는 그대로 씀(인터페이스 §3.2) |
| 레이어 토글 | 심볼·배관/연결·태그 체크. 체크 색이 범례 역할. 관계 종류와 "점선 = 미확인 항목 있음"을 범례로 표시 |
| 노드 클릭 | 웹 속성 패널에 속성 표시, 선택은 `ui` 테두리. 마우스를 올리면 툴팁 카드 |
| 경로 질의 | 시작·끝 태그로 경로 찾기(그래프 검증용) |

| 상태 | 표시 |
| --- | --- |
| 빈 상태 | "추출 결과가 없습니다. ① 자료 등록에서 등록한 뒤 '추출·그래프 만들기'를 실행하세요." |
| 오류 | 추출 결과를 읽을 수 없으면 사유를 빈 상태 자리에 표시 |
| 차단 | 그래프 `blocked`면 빨간 띠 "그래프 구조 검증 차단 — 도면은 조회만 허용"과 차단 목록 |
| 경고 | 그래프가 없으면 칩 "그래프 없음"(호박). SVG가 없으면 그래프 보기만 표시하고 상태줄에 안내 |

## 4. ③ 지식그래프

**목적**: P&ID 그래프와 지식 레이어를 한 캔버스에서 탐색하고 알고리즘 결과를 확인합니다(인터페이스 §3.5). 시각 규칙·배치·상태 표현의 정본은 [kg-screen.md](kg-screen.md)이고, 여기서는 사용 흐름에서의 위치만 적습니다.

```
지식그래프 [▾] 도면 [▾] [kg_version] [검증] [graph_version] [충돌] [재확인] [계산 제외] [알고리즘]  ← Qt 도구줄(폭에 따라 줄바꿈)
[차단 띠 + 이전 버전 보기] [알고리즘 비활성 띠] [S1 상한 띠] [재확인 띠]
┌ 좌측 필터(웹) ┐┌ 캔버스(웹) ───────────────────────┐┌ 우측 상세(Qt) [접기] ┐
│ 검색·종류·관계 ││ [전역|로컬] [종류|A1|A5] 표시 n·관계 m ││ 속성·근거·A1~A3     │
│ 계산 제외 표시 ││          그래프                     ││ 연결 목록            │
│ A2·표시·깊이·힘 ││ 범례(접기)        배치는 근거가 아님 ││ [도면에서 보기]      │
└───────────────┘└───────────────────────────────────┘└──────────────────────┘
```

| 진입·이탈 | 동작 |
| --- | --- |
| 단계 탭 | 마지막에 고른 지식그래프를 다시 읽음 |
| ⑤ '③에서 보기' | 실행의 지식그래프·도면을 고르고 해당 노드를 선택. ③이 연 버전이 분석 당시 버전과 다르면 이동만 하고 상태줄에 안내 |
| '도면에서 보기' | ②로 전환하고 해당 객체로 이동·강조 |

| 상태 | 표시 |
| --- | --- |
| 빈 상태 | "지식그래프가 없습니다" + 입력 CSV 위치·빌드 방법 + "P&ID 도면 추출 결과는 ②에서 보세요" |
| 오류 | 참조한 도면 그래프가 없거나 읽을 수 없으면 사유를 빈 상태 자리에 표시 |
| 차단 | `blocked`면 차단 목록과 "이전 버전 보기"(직전 통과 버전). 알고리즘 비활성 |
| 미확인·가설·후보·재확인 | 표시 토글로만 보이며 계산에 들어가지 않음(지식그래프화면 §2) |

## 5. ④ HAZOP 분석

**목적**: 고정 응답으로 분석하거나 기존 실행을 열어, 편차별 시나리오·보호수단·위험도 제안·설계보완 후보·자료 요청을 도면과 함께 확인합니다(인터페이스 §3.3).

```
구간 [▾] 실행 [▾] [근거 묶음 내보내기] [새 분석 실행] [결과 검증 칩] 형식·참조 검증 통과(보류 항목이 없다는 뜻이 아님)
후보 44(선택 · 제외 · 보류) · 시나리오 · 위험도 제안 · 설계보완 후보 · 열린 보류            ← 집계(muted)
분석 단계: 입력 확인(완료) → 후보 → 탐색 → 패턴 → AI(일부) → 위험도                       ← 단계 기록
[결과 차단 띠] [실행 열기 오류 띠] [그래프 버전 경고 띠 + 그래프 재연결…] [그래프 버전 불일치·도면 표시 안 됨 띠]
┌ 편차 후보 [전체▾] ──────┐┌ 캔버스(웹뷰) ───────────────┐┌ 편차 제목 · 판단 — 사유 ────┐
│ ID│편차│판단│사유│AI 상태 ││ 도면 | P&ID 구조             ││ [시나리오|설계보완 후보|     │
│ 시나리오│최고 위험도 제안 ││                              ││  자료 요청|AI 실행 기록]    │
│ 설계보완 후보│열린 보류   ││  원인·경로·보호수단 강조      ││ 시나리오 목록               │
│ (제외 행은 muted)       ││  강조 범례(웹, 아래 가운데)   ││ 시나리오 카드               │
│ [판단 변경…]            ││ 근거 N 중 도면 표시 a ·      ││ [검토하기 → ⑤]              │
│                        ││ 추정 경로 b · 미표시 c        ││                             │
└────────────────────────┘└─────────────────────────────┘└─────────────────────────────┘
```

| 요소 | 동작 |
| --- | --- |
| 구간 선택 | §7.1 |
| 실행 선택 | 그 구간의 `output/analysis/<구간>/` 실행 목록. 고르면 읽기 전용으로 엶. 다른 구간의 실행을 열면 구간 선택도 맞춰짐 |
| 근거 묶음 내보내기 | 선택 후보의 근거 묶음·프롬프트·응답 틀을 폴더로 내보냄. 실행 폴더는 만들지 않음 |
| 새 분석 실행 | 대화상자: AI 응답 출처(고정 응답 폴더만 켜짐, "API 호출(후속)"은 꺼진 항목), 응답 폴더 선택, "프로그램은 AI를 호출하지 않습니다" 안내 |
| 편차 목록 | §7.2 |
| 판단 변경 | 대화상자: 현재 판단, 새 판단, 사유(비면 확인 버튼이 꺼짐), "구간 버전이 올라가고(vN → vN+1) 재분석이 필요합니다. 열린 분석 결과는 바뀌지 않습니다." |
| 시나리오 카드 | 출처·상태 배지(패턴·가설·초안 등), 검토 상태, 패턴 원안과 AI 해석을 따로 상자로, 원인·전제 설비, 보호수단(그래프 확인 / AI 제시 구분), 위험도 제안, 근거 ID |
| 경로 강조 | §7.3 |
| 검토하기 → ⑤ | 같은 편차·시나리오를 고른 채 ⑤로 이동. 열린 실행이 선택 구간과 같을 때만 켜짐 |

| 상태 | 표시 |
| --- | --- |
| 빈 상태 | "구간을 선택하거나 새 분석을 실행하세요." 구간을 바꾸면 이전 실행을 닫고 "구간이 바뀌었습니다…" |
| 진행 | 작업 중에는 구간·실행 선택과 실행 버튼이 모두 꺼짐. 상태줄 "진행 중" |
| 오류 | 실행을 열 수 없으면 빨간 띠와 사유, 이전 상태 유지 |
| 결과 차단 | 빨간 띠 "결과 검증 차단 — 열람만 가능. ⑤ 확정 저장과 Excel 출력이 막힘" + `validation.errors` |
| 보류 | 판단 '보류' 후보는 표에 남고 시나리오를 만들지 않음. 위험도 제안 보류는 "제안 보류". 열린 보류 수는 표·집계·자료 요청 탭에 |
| 재검토 | 구간의 그래프 버전이 현재와 다르면 경고 띠 + '그래프 재연결…'(차이 확인 → 변경자·사유 → 확인). 분석 당시 그래프와 현재 도면 그래프가 다르면 도면 탭과 강조를 끄고 그래프 보기만, 근거 집계는 "모두 미표시" |

## 6. ⑤ 설계보완·확정

**목적**: 시나리오와 설계보완 후보마다 수용·수정·기각·보류와 사유를 기록하고 Excel로 내보냅니다(인터페이스 §3.4·§5·§6).

```
실행 <ID> (읽기 전용) [미검토 · 검토 중 · 보류 · 확정 · 판정 제외] [지식 v-…]   검토자 [   ] [검토자 저장] [Excel 내보내기]
[열람 전용 띠] [Excel 출력 막힘 띠] [지식그래프 변경 띠]
┌ 편차 후보 ─────────────┐┌ 캔버스(웹뷰) ──────┐┌ 편차 제목 ─────────────────────────────┐
│ ID│검토 상태│편차│…   ││ 도면 | P&ID 구조    ││ 이전 검토(참고) [실행 선택 ▾]           │
│                        ││                     ││ ┌ 스크롤 ───────────────────────────┐ │
│ 시나리오 · 설계보완 후보││ 선택 항목의 시나리오 ││ │ 시나리오 폼 × n                    │ │
│  시나리오 p86-d09-01   ││ 강조                 ││ │ 설계보완 후보 폼 × m               │ │
│  설계보완 후보 …       ││                     ││ │ (시나리오 0개면 '시나리오 없음 확인')│ │
│                        ││                     ││ │ 자료 요청 메모                     │ │
│                        ││                     ││ └───────────────────────────────────┘ │
│                        ││                     ││ [오류 목록]                            │
│                        ││                     ││ 검토 요약 사유 [          ] [저장(새 버전)]│
└────────────────────────┘└─────────────────────┘└────────────────────────────────────────┘
```

시나리오 폼(위에서 아래로):

1. 저장된 결정이 있으면 사람 확정 상자: "확정" 배지, 결정·사유, 검토자·KST 시각, 확정 위험도 칩과 출처.
2. 원안(읽기 전용): 시나리오 카드(④와 같음) + '관련 지식(참고)'(기본 접힘, 지식그래프 없이 분석한 실행이면 "이 실행은 지식그래프 없이 분석됨").
3. 검토값: 수용·수정·기각·보류 라디오, 사유(필수).
4. 수정(수정을 고를 때만): 원인·결과(필드마다 값 출처 "AI 해석 원안 — 수정하면 사람 수정" 등), 보호수단 목록(그래프 노드 콤보에서 추가·제거, "도면에 없는 보호수단은 자료 요청 메모로 남깁니다").
5. 위험도 확정: 강도(1–4)+근거, "보호수단 효과를 반영하지 않음", 빈도(보호수단 미반영)·빈도(확정)+근거, 인정 보호수단(확인 근거를 넣기 전에는 체크 불가, "적정성·독립성 미확인 — 근거 입력 전 선택 불가"), 위험도(〈표5〉 계산, 직접 입력 불가, 값이 없으면 "미확정"), 'AI 제안 가져오기'(가져오면 "AI 값에서 가져옴 — 근거 확인 필요").
6. 이전 검토 가져오기: 대응 0개 "대응 없음", 1개 '가져오기', 2개 이상 대상 선택 후 가져오기.

설계보완 후보 폼: 원안(발생 조건·근거·연결 보류), 결정 라디오, 사유, 개선 권고 문안(수용·수정에서 켜짐), 발생 조건 설명(수정에서만). 연결 시나리오를 기각하면 "해당 없음" 배지 + "연결 시나리오 기각 — 사유 상속"이 뜨고 입력이 잠깁니다.

## 7. HAZOP 고유 기능이 있는 곳

데모 분석(§4 "데모에는 없지만 필요한 화면")이 꼽은 네 가지가 현재 화면 어디에 있는지 정리합니다.

### 7.1 구간 선택

| 항목 | 현재 |
| --- | --- |
| 위치 | ④ 도구줄 '구간' 콤보, 메뉴 보기 > 이전 MVP > 구간 열기 |
| 대상 | `data/regions/*.json`(구간 정의 파일). 구간 정의 자체는 사람이 파일로 작성·검토합니다([신뢰 경계](../specs/overview.md#trust-boundary) "구간 정의 \| 사람 검토와 버전 관리") |
| 검사 | 구간이 가리키는 그래프 파일이 없거나 버전이 다르면 경고 띠, 버전 차이는 '그래프 재연결…'로 갱신 |
| 없는 것 | 도면에서 영역을 지정하거나 여러 기기를 골라 구간을 만드는 화면. 자동 구간 분할은 기획서상 후속(인터페이스 §1.2). 수동 구간 편집 화면은 기획서에 없음(§9) |

### 7.2 편차 목록

| 항목 | 현재 |
| --- | --- |
| 위치 | ④ 좌측 '편차 후보' 표, ⑤ 좌측 같은 표 + '검토 상태' 열 |
| 열 | ID, 편차(파라미터·가이드워드 한·영), 판단(선택·제외·보류), 사유, AI 상태, 시나리오 수, 최고 위험도 제안(속 빈 칩), 설계보완 후보 수, 열린 보류 수 |
| 제외 후보 | 숨기지 않고 `muted` 글자로 남김. ④는 판단별 필터(전체·선택·제외·보류) |
| 값이 없을 때 | 제외·보류 후보는 "해당 없음(제외)" 등, 시나리오가 없으면 "시나리오 없음", 제안이 없으면 "제안 보류" — 빈칸으로 두지 않음 |
| 판단 바꾸기 | ④ '판단 변경…'(사유 필수, 구간 버전 +1, 재분석 필요) |

### 7.3 경로 강조

| 항목 | 현재 |
| --- | --- |
| 위치 | ④ 시나리오 목록에서 고를 때, ⑤ 항목 목록에서 고를 때 |
| 표현 | 원인 설비 = `hl-cause` 채움 + 굵은 테두리, 경로 = `hl-path` 굵은 선, 추정 경로 = 같은 색 파선, 보호수단 = `hl-safeguard` 이중 테두리 + "보호수단" 배지(미계수는 홑 테두리 + 흰 배지). 강조 중 나머지는 `HL_DIM`으로 흐림. 캔버스 아래 가운데에 강조 범례 |
| 근거 집계 | ④ 캔버스 아래 한 줄 "근거 N 중 도면 표시 a · 추정 경로 b · 미표시 c". 웹이 그리지 못했다고 알린 ID는 미표시로 다시 셈. ⑤에는 이 줄이 없음 |
| 막힘 | 분석 당시 그래프와 현재 도면 그래프가 다르면 도면 탭을 끄고 그래프 보기만, 근거는 모두 미표시 |

### 7.4 워크시트 검토

| 항목 | 현재 |
| --- | --- |
| 위치 | ⑤ 우측 검토 폼(편차 단위로 시나리오·설계보완 후보·메모를 한 번에 저장) |
| 출력 | ⑤ 'Excel 내보내기' 또는 메뉴 파일 > Excel 내보내기. KOSHA P-86 〈별표7〉·〈별표9〉 기준 시트(인터페이스 §6) |

되돌아가는 흐름: ⑤ '③에서 보기' → ③, ③ '도면에서 보기' → ②, ④ '판단 변경' 저장 → 재분석(④ '새 분석 실행') → ⑤에서 이전 검토 가져오기.

### 9.2 코드·화면과 기획서가 어긋나거나 기획서에 없는 것

디자인 담당은 코드와 기획서를 고치지 않으므로 여기에 적기만 합니다. 분류는 다음과 같습니다.

- **코드 결함(수정 대상)**: D2, D3
- **기획 결정 대상**: D1, D4~D7
- **기획 담당 문서 정리**: D8

| 번호 | 분류 | 내용 | 근거 | 제안 |
| --- | --- | --- | --- | --- |
| D1 | 기획 결정 대상 | 구간을 만들거나 고치는 화면이 없고, 기획서에도 수동 구간 편집 화면이 없음. 데모 분석이 꼽은 "도면에서 영역 지정·여러 기기 선택"은 어디에도 배정되지 않음 | `data.list_regions()`는 파일 목록만 읽음. 인터페이스 §1.2 후속은 "자동 구간 분할"만 | 기획 확인 필요: 범위 밖(파일 작성 유지)으로 명시할지, 후속에 넣을지 |
| D2 | 코드 결함(수정 대상) | 웹뷰 안의 구조 검증 칩은 "구조 검증 passed"(영문 값), 같은 화면의 Qt 칩은 "구조 검증 통과"로 표기가 다름(②④⑤) | 스크린샷 02·04·05 | 웹 칩 표기를 Qt와 같게 맞춤. 독립 뷰어와 같은 템플릿이라 고칠 곳은 구현 담당이 판단 |
| D3 | 코드 결함(수정 대상) | ④⑤ 강조 범례(웹, 캔버스 아래 가운데)가 캔버스가 좁으면 여러 줄로 접혀 왼쪽 아래 줌·맞춤 버튼을 가림. ⑤는 1440·1366 모두, ④는 1440에서도 일부 겹침. 원인은 `tokens.py` 105–107행 `.hz-legend`(캔버스 아래 가운데 절대 위치, `max-width: 92%`, 줄바꿈 허용) | 스크린샷 04, 05, 05-review-1366-risk | 범례 위치를 옮기거나 접기를 둠 |
| D4 | 기획 결정 대상 | 인터페이스 §4.2 "패널은 접을 수 있고 접으면 캔버스가 넓어짐"과 화면마다 방식이 다름: ①④⑤는 분할선(`QSplitter`) 끌기만 가능. ②는 보기 메뉴 '웹 속성 패널 숨기기/보이기'로 웹 패널을 숨김(`main_window.py` 155행). ④⑤는 들어갈 때 `set_mode(hide_panel=True)`로 웹 속성 패널이 자동으로 숨음(`analysis.py` 290행, `review.py` 840행). ③만 접기 버튼이 있음 | 코드 | 기획 문장을 현재 방식에 맞출지 확인 |
| D5 | 기획 결정 대상 | 인터페이스 §2.1 메뉴 "보기(레이어·패널)" — 보기 메뉴에 레이어 항목은 없고 화면 이동·도면/그래프·웹 속성 패널만 있음. 레이어는 웹 안 토글 | `main_window._menus` | 기획 문장 정정 또는 현 상태 유지 확인 |
| D6 | 기획 결정 대상 | ⑤ 보호수단 추가는 그래프 노드 콤보에서 고름. 캔버스에서 노드를 클릭하면 상태줄에 태그만 보이고 폼에 들어가지 않음 | `ScenarioForm`, `ReviewScreen.on_node` | 인터페이스 §3.4 "그래프 노드를 골라서"와 모순은 아님. 캔버스 클릭으로 추가할지는 기획 판단 |
| D7 | 기획 결정 대상 | ⑤에는 근거 집계 한 줄이 없음(④에만) | `review.py`에 근거 집계 없음 | 인터페이스 §3.4 "④와 같은 강조"는 강조만 말함. 필요 여부 기획 확인 |
| D8 | 기획 담당 문서 정리 | 인터페이스 §1.3 표의 "'출력화면 AX' 데모 분석 … `design/` 문서 갱신은 디자인 담당 필요" 행은 이 문서와 데모 분석 §5 갱신으로 처리됨 | — | 기획 담당이 그 행의 처리 상태를 갱신 |

## 11. 읽은 자료와 한계

- 코드: `main_window.py` 전체 틀, `screens/register.py`·`viewer.py`·`analysis.py`·`review.py`는 화면 구성·상태 처리 부분, `knowledge.py`는 앞부분(구성·읽기)만, `tokens.py` 전체. `render.py`·`runctx.py`·`webview.py`·웹 템플릿 내부는 읽지 않았습니다. 시나리오 카드·근거 집계 문구의 세부는 스크린샷과 기획서로 적었습니다.
- 스크린샷: ①②④⑤(1440×860), ⑤ 확정 상태·1366×768, ③. ③ 스크린샷은 Qt 영역 한글이 □로 찍혀 있어(촬영 환경의 글꼴 문제로 보임, 미확인) ③의 Qt 영역은 코드와 [kg-screen.md](kg-screen.md)로 적었습니다.
- 빈 상태·오류·차단 문구는 코드의 문자열을 옮긴 것이며, 이번에 그 상태를 실제로 띄워 보지는 않았습니다.
