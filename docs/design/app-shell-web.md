# 도면 중심 웹 화면

[이전 화면 명세](screen-spec.md) · [채팅 창 규격](../specs/chat-panel.md) · [AI 연결 규격](../specs/ai-subscription.md) · [검토구간 나누기](../specs/study-node-segmentation.md) · [시안](mockups/app-shell-web/index.html) · [프로젝트 의도](../../INTENT.md)

엔진(추출, 그래프, 지식그래프, 구간 저장, 분석, 초기사건(initiating event, IE) 인계, 채팅 세션·도구)은 그대로 두고, PySide6 위젯으로 만든 화면을 HTML·CSS·JS 화면 하나로 바꿔 앱 안의 웹 화면(QtWebEngine)에 띄운다. 이 문서가 새 화면의 정본이다. 지금 화면은 '이전 화면'이 되고, 그 명세는 [screen-spec.md](screen-spec.md)에 남는다.

근거는 사용자 결정(2026-11-13 질문 답변)이다. 지금 화면은 낡고 난잡하며, 바로 쓸 기능도 모드·탭·토글을 골라서 켜야 쓸 수 있다. 사용자는 안트로피 AutoPID '실제 화면' 데모처럼 깔끔하고 단순한 화면을 원했다. 이 결정으로 [INTENT.md §3.8](../../INTENT.md)의 '단계 구조는 유지'가 바뀐다. 그대로 이어지는 결정은 다음과 같다.

- 채팅 창이 늘 대기한다.
- 답 카드와 도면 위 경로를 표시하고, 예시 질문을 보인다.
- 도면에서 네모로 끌어 고르고, 클릭으로 더하거나 빼서 구간을 만든다. 구간을 누르면 그 구간만 강조한다.
- 추출 전에 AI 검토를 켤지 고른다.
- 구독이 없는 PC에는 안내만 한다.
- 밝은 화면만 쓴다.

원자력 확률론적 안전성평가 용어는 처음 나오는 곳에 영문을 함께 적었다. 출처는 U.S. NRC, NUREG-2122 *Glossary of Risk-Related Terms in Support of Risk-Informed Decisionmaking*(2013)이다.

| 이 문서의 말 | NRC 영문 | 뜻 |
| --- | --- | --- |
| 초기사건 | initiating event (IE) | 정상 운전을 깨뜨려 사고 경위로 이어질 수 있는 사건 |
| 사건수목 표제 | event tree top event (heading) | 사건수목의 열 머리에 놓는 안전기능·계통의 성공·실패 사건 |
| 최종상태 | end state | 사건수목 한 경위의 끝 상태(예: 노심손상) |
| 기본사건 | basic event | 고장수목의 가장 아래 사건으로, 더 나누지 않고 확률을 주는 것 |
| 고장 시 위치 | fail position(fail-open FO, fail-closed FC, fail-as-is FL) | 구동 동력·신호를 잃었을 때 밸브가 가는 위치. 영문은 ANSI/ISA-5.1-2009의 말이다. NUREG-2122 용어집에 올라 있는지는 확인하지 못했다 |

### 2.2 골라서 켜는 기능을 줄이는 원칙

1. **도면 옆에 늘 떠 있는 곁 패널을 두지 않는다.** 도면 옆에는 채팅만 있다. 속성·연결점·관련 항목은 누른 대상 옆 말풍선에 나온다.
2. **모드는 도구 막대의 두 개뿐이다.** '이동'(V)과 '네모로 고르기'(S)다. 이동 모드에서도 Shift+끌기로 네모를 그을 수 있어, 모드를 바꾸지 않고 고를 수 있다. 도면 고치기는 도구 막대의 모드가 아니라 따로 켜는 '도면 고치기' 띠다(아래 §2.4). 켜 둔 동안 구성요소를 누르면 말풍선 대신 고치기 카드가 뜬다. 기기 추가·연결 추가·끝 잇기·경로 다시 그리기처럼 도면을 여러 번 눌러야 하는 고침만 띠의 도구를 쓴다(A5에서 정함: 말풍선 하나로는 '놓을 자리'를 받을 수 없다).
3. **탭 대신 한 쪽 스크롤을 쓴다.** 탭은 내용 종류가 완전히 다를 때만 쓴다. 지금 쓰는 탭은 ⑥의 7개, ④의 하위 3개, ③ 상세의 2개, 오른쪽 열의 채팅|관련 항목 2개다. 새 화면에서는 초기사건 패널의 보기 셋(그룹·완전성 대조·품질 경고)만 남는다.
4. **토글의 기본값은 자주 쓰는 쪽에 두고, 드물게 쓰는 조정은 '보기 설정' 아래 접어 둔다.** 지식그래프의 힘 슬라이더 4개, 깊이 슬라이더, 색 모드가 여기에 해당한다.
5. **한 기능은 한 자리에만 둔다.** 그 자리 말고는 채팅과 찾기(Ctrl+P)로만 부른다. 지금은 Excel 내보내기가 네 곳, AI 연결 설정이 네 곳, 단계 이동이 다섯 곳에 있다.
6. **상태는 그 대상 옆에 표시한다.** 메뉴 배지, 목록 행의 칩, 패널 머리에 둔다. 상태줄은 없앤다.
7. **보일 것이 없으면 자리를 차지하지 않는다.** 빈 띠, 빈 패널, '여기에 표시됩니다' 안내 칸을 두지 않는다.

### 2.3 지금 기능의 새 자리

### 2.4 도면 고치기(A5, 2026-11-14)

PDF 읽기 수준이 낮으니 사람이 화면에서 도면을 고친다(INTENT §3.2). 엔진은 이전 화면과 같은 사람 수정 기록(`hazop/extract/corrections.py`)이고, 새 화면은 **고침 하나가 곧 저장 하나**다(이전 화면은 모아서 '저장'). 명령은 `edit.apply`·`edit.undo`·`edit.redo`(`hazop/shell/api_corrections.py`), 화면은 `canvas/edit.js`다.

## 3. 상호작용

### 3.1 도면

| 동작 | 이동 모드(V, 기본) | 고르기 모드(S) |
| --- | --- | --- |
| 끌기 | 화면 옮기기 | 네모 안 구성요소를 고른 것에 더하기 |
| Shift+끌기 | 네모로 더하기 | 같음 |
| Alt+끌기 | 네모 안을 고른 것에서 빼기 | 같음 |
| Space+끌기, 가운데 단추 끌기 | 화면 옮기기 | 화면 옮기기 |
| 클릭 | 말풍선 열기 | 넣고 빼기(다시 누르면 빠짐) |
| 두 번 누르기 | 그 구성요소에 맞춰 확대 | 같음 |
| 휠 | 마우스 자리 중심 확대·축소 | 같음 |
| Esc | 말풍선 닫기 → 표시 지우기 | 고른 것 비우기 → 이동 모드 |

- **네모에 걸리는 기준.** 구성요소는 외곽 상자가 네모와 겹치면 고른다. 배관 구간은 선이 네모를 지나면 고른다. 지금 ④ `set_select_mode("pick")`와 같은 기준이다.
- **말풍선.** 태그·종류·도면, 배관, 속한 구간, 읽음 상태(읽음 확인·미확인·사람 수정)를 보인다. 단추는 '채팅에 묻기'(그 구성요소를 질문 문맥으로 넣음), '고치기', '경로 시작'·'경로 끝'(P로 이어짐), '더 보기'(관련 항목)다. 말풍선은 대상 오른쪽에 뜨고, 칸이 모자라면 왼쪽에 뜬다.
- **고른 것 막대.** 하나 이상 고르면 도구 막대 위에 뜬다. 개수, 조작 안내, '채팅에 묻기', '구간 만들기'(Enter)가 있다. 고른 것은 채팅 입력 옆 칩으로도 보이고, 질문을 보내면 [채팅 규격 §3](../specs/chat-panel.md#3-읽기-도구)의 `view.selection`으로 함께 간다.
- **구간 강조.** 도면의 구간 꼬리표(S1 등)나 구간 패널의 행을 누르면 그 구간만 진하게, 나머지는 16% 불투명도로 흐리게 그린다(`HL_DIM`). 그 안에서 구성요소를 누르면 말풍선이 뜬다.
- **경로 표시.** 답 카드나 P가 경로를 보내면 도면을 흐리게 하고 경로를 굵은 주황 선(`--path`)과 단계 번호 원으로 그린다. 출발은 파랑 상자, 확인 못 한 곳은 호박색 점선 상자다. 범례가 왼쪽 아래에 뜨고 '지우기'(Esc)로 끈다.
- **다른 도면.** 경로가 여러 도면에 걸치면 답 카드의 도면 칩을 누른다. 그 도면이 열리고 그 도면 몫의 경로가 그려진다([채팅 규격 §6](../specs/chat-panel.md#6-뷰어-api) `ViewerHost.show_marks`).

### 3.2 채팅

내용은 [채팅 규격 §5](../specs/chat-panel.md#5-답-카드)를 따르고, 새 화면에서는 생김새만 정한다.

- 질문은 오른쪽 말풍선, 답은 왼쪽 정렬 글이다. 답은 상자로 감싸지 않는다.
- 답 카드는 위에서부터 다음 순서로 놓는다.
  1. '도면에서 확인' 글(초록 왼쪽 선)
  2. 경로 단계 목록(번호 원 + ID 칩 + 설명 + 경고 표시)
  3. 경고 줄(호박 바탕)
  4. 'AI 일반 지식' 글(회색 왼쪽 선)
  5. 도면별 칩
  6. 동작 단추
  7. 바닥줄(도구 횟수, 걸린 시간, 확인한 근거 ID 수)
- ID 칩을 누르면 그 구성요소에 맞춰 확대하고 말풍선을 연다. 단계 줄에 마우스를 올리면 도면에서 그 단계가 깜빡인다.
- 적용한 쓰기 동작(구간 만들기 등)은 '적용함 · 묶음 B1' 상자로 보이고, 상자 안에 '되돌리기'가 있다. 확인이 필요한 동작은 앱이 그린 확인 상자로 묻는다([채팅 규격 §4](../specs/chat-panel.md#4-쓰기-동작)).
- 예시 질문 칩은 입력 위에 늘 보인다. 대화가 길어지면 한 줄로 접힌다. 누르면 입력칸에 들어가고 바로 보내지 않는다.
- 바닥줄에 연결 방식과 모델(빠름·보통·깊게)을 보이고, 누르면 고른다.
- AI 연결이 없는 PC에서는 입력칸이 잠기고, 채팅 자리에 안내 카드가 뜬다. 카드는 연결 없이 되는 일(도면 보기, P로 경로 찾기, 구간 만들기, 결과 보기, Excel)을 함께 보인다(시안 6).
- 1366 폭에서도 채팅은 펼친 채 시작한다(폭 320px). 접으면 36px 띠가 되고 새 답이 오면 띠의 아이콘이 강조색으로 바뀐다. 지금 '논리 폭 1,500px 미만이면 접힌 채 시작'은 바꾼다(§8 UW4).

### 3.3 패널

- 메뉴 아이콘을 누르면 패널이 열리고, 같은 아이콘을 다시 누르거나 Esc를 누르면 닫힌다. 다른 패널을 열면 앞 패널은 닫힌다.
- 좁은 패널은 도면 왼쪽을 덮고 그림자를 둔다. 덮이지 않은 도면 부분은 그대로 조작할 수 있다.
- 넓은 패널은 도면 칸 전체를 덮는다. '도면에서 보기'를 누르면 패널을 닫고 도면에 표시하고, 위 막대에 '분석 결과로 돌아가기' 칩을 띄운다. 칩을 누르면 같은 칸이 고른 채로 패널이 다시 열린다.
- 패널마다 마지막 스크롤 위치와 고른 행을 기억한다(앱을 닫으면 잊는다).
- 패널 안 대화상자는 패널 위에 뜨고, 패널 밖을 누르면 닫히지 않는다. 사유 같은 필수 입력이 있기 때문이다.

### 3.5 자주 하는 세 가지 흐름

수는 시안과 지금 코드를 따라 센 값이다. 지금 화면은 `hazop/app/screens/*.py`의 단추 배치, 새 화면은 시안 1~4로 셌다. 실제 창에서 잰 값이 아니다. 실제 창 측정은 1단계 완료 기준에 넣는다(§6).

| 흐름 | 지금: 화면 이동 · 클릭 | 새: 화면 이동 · 클릭 | 무엇이 줄었나 |
| --- | --- | --- | --- |
| 1. 도면 넣고 읽기(파일 2개를 넣고 추출해 첫 도면 보기) | ① → ② 2화면 · 파일 선택 2 + 표제란 확정 3 + 등록 1 + 추출 1 + 두 번째 파일에서 같은 일 7 + ② 이동 1 + 도면 고르기 2 = 약 17 | 패널 1개 · 메뉴 1 + 끌어 놓기 0 + 표제란 먼저 확정 2 + 추출 시작 1 + 행 누르기 1 = 약 5 | 파일 여러 개 받기, 등록·추출 합치기, 표제란 한꺼번에 확정 |
| 2. 묻기(경로를 묻고 다른 도면 몫 보기) | ② 1화면 · 채팅 펴기 1(1366 폭) + 입력 1 + 보내기 1 + 도면 단추 1 = 4 | 이동 없음 · 입력 1 + 보내기 1 + 도면 칩 1 = 3 | 채팅이 늘 펼쳐져 있다. 예시 칩으로 시작하면 입력 1이 칩 1로 바뀐다 |
| 3. 구간 만들고 분석(구간 하나 만들어 분석하고 칸 하나 수용) | ④ → ⑤ 2화면 · 고르기 토글 1 + 끌기 1 + 구간 만들기 1 + 이름 F2 + 확정 1 + ⑤ → 1 + 선택 구간 분석 1 + 실행 확인 1 + 칸 1 + 행 1 + 승인 1 = 약 10 + 키 1 | 패널 1개 · Shift+끌기 1 + 구간 만들기 1 + 만들기 1 + 구간 상세 '분석' 1 + 실행 확인 1 + 칸 1 + 행 1 + 수용 1 = 약 8 | 화면을 바꾸지 않고, 이름·설계 의도 초안이 카드에 채워져 온다 |

흐름 3은 클릭 수가 크게 줄지 않는다. 줄어드는 것은 화면 전환이고, 도면과 채팅이 계속 보이는 것이 이득이다.

### 4.2 글꼴과 라이선스

- 본문은 **맑은 고딕**이다. Windows에 들어 있는 글꼴이라 배포본에 넣지 않는다. 앱이 Windows 전용이므로 다른 PC에서도 같은 글꼴로 보인다. 2026-11-10 사용자 결정(Pretendard를 배포본에 넣지 않음, [인터페이스 §4.2](../specs/interface.md))과 같다.
- ID는 **Cascadia Mono**, 없으면 **Consolas**다. 둘 다 Windows에 있는 글꼴이고 넣지 않는다. Cascadia Mono는 Windows 터미널과 함께 깔리므로 없는 PC가 있을 수 있다. 그래서 Consolas를 뒤에 둔다.
- 웹 글꼴은 받지 않는다. CSS의 `@font-face`가 없으므로 실행 중 글꼴 요청도 없다.

### 4.3 아이콘

- **출처.** Tabler Icons 3.51.0 outline(MIT)이다. 쓰는 것만 [`resources/library/icons/tabler/`](../../resources/library/icons/tabler/README.md)에 원본 그대로 두고 `manifest.json`에 SHA-256을 적는 지금 규칙을 따른다. 시안에 쓴 38개 가운데 아직 그 폴더에 없는 것은 1단계 구현 단위가 더한다.
- **모양.** 크기는 18px, 작은 칩 안에서는 14~15px로 쓴다. 선 두께는 1.75(원본 2에서 낮춤), 색은 `currentColor`다.
- **넣는 방법.** `Icon({name, size})` 구성요소(`web/js/ui/icon.js`)가 `<svg>`와 그 안의 `path`·`circle`·`rect`·`line` 요소를 Preact 요소로 만든다. 도형 자료는 `web/js/ui/icons_data.js`(이름 → `[태그, 속성]` 목록)에 있다. 이 파일은 `scripts/build_shell_icons.py`가 아이콘 폴더의 `manifest.json`에 적힌 SVG에서 만든다. 문자열을 HTML로 넣지 않으므로 `innerHTML`·`dangerouslySetInnerHTML` 금지(§5.5)와 부딪치지 않는다. `<img>`는 색을 바꿀 수 없어서, 바깥 문서를 가리키는 `<use>`는 맞춤 주소 체계에서 동작을 따로 확인해야 해서 쓰지 않는다. 시험이 `icons_data.js`와 `manifest.json`이 같은지 본다.
- **글자.** 아이콘만 있는 단추에는 마우스를 올리면 이름과 키가 뜬다(`title`). 메뉴 아이콘은 글자 없이 두고 이름은 말풍선으로만 보인다.
- 시안에서 고른 메뉴 아이콘은 도면 `files`, 구간 `route`, 분석 결과 `table`, 초기사건 `alert-octagon`, 지식그래프 `affiliate`, 연결 `plug-connected`, 설정 `settings`다.

## 5. 기술 구조

### 5.1 프런트엔드 방식

조건은 다섯 가지다. 실행 중 네트워크 요청이 없어야 하고, 라이선스가 MIT·ISC·Apache 2.0이어야 한다. Node 빌드 없이 저장소 파일 그대로 돌아가는 쪽을 앞에 둔다. 오프스크린 시험으로 확인할 수 있어야 한다. 구성요소 수천 개짜리 도면과 큰 표에서 느리지 않아야 한다.

| 후보 | 라이선스 | 빌드 | 크기(축소본) | 장점 | 약점 |
| --- | --- | --- | --- | --- | --- |
| A. 바닐라 JS ES 모듈 + 작은 도우미 | 해당 없음 | 없음 | 0 | 의존성 없음 | 화면 갱신 코드를 손으로 쓴다. 패널 다섯 개·표·카드마다 갱신 방식이 갈라지기 쉽고, 다음 구현자가 가까운 예를 베끼며 방식이 늘어난다 |
| **B. Preact + htm** | MIT, Apache-2.0 | 없음 | 약 16KB(preact·hooks·htm) | 구성요소와 상태 모형이 하나라 패널·표·카드를 같은 모양으로 만든다. htm은 태그 템플릿을 실행 중에 풀고 `eval`을 쓰지 않는다. 그래서 엄격한 CSP(`script-src` 자기 주소만)를 지킬 수 있다 | 템플릿에 형 검사가 없다. JSX 생태계 예제를 그대로 못 쓴다 |
| C. Vue 3 전역 빌드 + 실행 중 템플릿 컴파일 | MIT | 없음 | 약 150KB | 익숙한 사람이 많다 | 실행 중 컴파일이 `new Function`을 써서 CSP에 `unsafe-eval`이 필요하다. 크다 |
| D. Alpine.js | MIT | 없음 | 약 45KB | HTML 속성만으로 짧다 | 식이 `new Function`으로 돈다(CSP 판은 기능이 줄어듦). 로직이 HTML 속성에 흩어진다. 큰 표 창 그리기(가상 스크롤)에 맞지 않는다 |
| E. React + TypeScript + Vite 빌드 | MIT | Node 필요 | 약 45KB + 앱 | 형 검사, 큰 생태계 | 빌드 단계가 패키징과 CI에 붙는다. 저장소 파일과 실행 파일이 달라져 오프스크린 시험에 빌드 결과가 필요하다 |
| F. Lit | BSD-3-Clause | 없음 | 약 16KB | 웹 표준 구성요소 | 조건의 라이선스 목록 밖 |

**고른 것은 B(Preact + htm)다.** A와 B를 두 개의 다른 모양으로 끝까지 견줬다. A는 갱신 함수를 화면마다 손으로 쓰고, B는 `상태 → 화면` 함수 하나로 쓴다. 갈린 지점은 '한 파일만 보고 고친 사람이 저장소 전체에 맞게 고치게 되는가'다. B에서는 새 패널도 `function Panel(props) { return html\`…\` }`와 `useStore(sel)` 두 가지만 쓰게 되므로 가까운 예를 베껴도 같은 모양이 나온다. A에서는 갱신 함수가 화면마다 달라진다. 크기 차이(16KB)는 내장 웹뷰에서 문제가 되지 않는다. C·D는 CSP를 풀어야 해서 뺐다. E는 형 검사가 탐나지만 Node 빌드가 패키징·CI·시험에 모두 끼어든다. '빌드 없이'를 앞에 둔 조건에 맞지 않는다.

- **형 검사를 대신하는 것.** 모듈 머리에 JSDoc 형 주석을 단다. 엔진과 주고받는 자료는 Python 쪽 시험이 모양을 검사한다(§5.6).
- **가져오는 방식.** 상태 관리 라이브러리(`@preact/signals` 등)는 넣지 않는다. 작은 저장소 모듈 `store.js`(get·set·subscribe, 약 60줄)와 `useStore` 갈고리로 충분하다.
- **묶음.** `hazop/shell/web/vendor/`에 ES 모듈 파일로 넣는다. 받은 버전과 SHA-256, 라이선스 원문은 지금 Tabler 규칙처럼 적는다(`licenses/preact/LICENSE`, `licenses/htm/LICENSE`). npm 레지스트리 기준(2026-11-13 확인) 최신판은 Preact 11.2.0(`"license":"MIT"`), htm 3.1.1(`"license":"Apache-2.0"`)이다. 1단계 구현 단위(`s-frame`)가 받은 꾸러미의 `LICENSE`로 다시 확인해 고정한다.
- **htm의 Apache-2.0 처리.** 라이선스 원문을 `licenses/htm/LICENSE`에 둔다. 꾸러미에 `NOTICE` 파일이 있으면 `licenses/htm/NOTICE`로 함께 두고, 없으면 `licenses/README.md`의 고지 목록에 '`NOTICE` 없음'을 적는다. 받은 파일을 고치지 않는다(고치면 바뀐 파일에 그 사실을 적어야 한다). 배포본에는 지금 고지 규칙대로 실행 파일 옆 `licenses/`째 들어간다. 조건의 라이선스 목록(MIT·ISC·Apache 2.0) 안이다.

**ES 모듈과 `file://` 문제.** Chromium은 `file://`에서 ES 모듈을 막는다. 출처가 `null`이라 CORS 검사를 통과하지 못하기 때문이다. 그래서 앱 전용 주소 체계 `hazop-app://`를 둔다.

- **등록.** `QApplication`을 만들기 전에 등록한다.

  ```python
  s = QWebEngineUrlScheme(b"hazop-app")
  s.setSyntax(QWebEngineUrlScheme.Syntax.Host)          # 출처 = hazop-app://shell
  s.setFlags(QWebEngineUrlScheme.Flag.SecureScheme | QWebEngineUrlScheme.Flag.LocalScheme
             | QWebEngineUrlScheme.Flag.CorsEnabled | QWebEngineUrlScheme.Flag.FetchApiAllowed)
  QWebEngineUrlScheme.registerScheme(s)
  ```

  - 형식은 `Syntax.Host`다. 기본값 `Syntax.Path`로 두면 출처가 불투명(`null`)해져 `file://`과 같은 이유로 ES 모듈과 `fetch`가 막힌다.
  - `FetchApiAllowed`가 있어야 웹이 `fetch("hazop-app://shell/api/…")`로 읽을 수 있다.
  - `LocalAccessAllowed`는 넣지 않는다. 새 화면이 `file://` 자원을 읽을 일이 없기 때문이다.
- **호스트는 `shell` 하나다.** 화면과 읽기 API를 같은 호스트에 두어 같은 출처로 만든다. 화면은 `hazop-app://shell/index.html`, 정적 파일은 `hazop-app://shell/static/…`, 읽기 API는 `hazop-app://shell/api/…`다. 다른 호스트로 온 요청은 `fail(UrlInvalid)`로 끊는다.
- **정적 파일만 폴더 범위로 돌려준다.** 정적 파일은 `hazop/shell/web/`(vendor 포함)와 아이콘 폴더 `resources/library/icons/tabler/` 둘이다. 경로 검사는 지금 채팅 도구와 같은 `realpath`·`commonpath` 방식이고, MIME은 확장자 표로 정한다(`.js`는 `text/javascript`).
- **프로젝트 자료는 ID로만 받는다.** 도면 SVG가 그 예다. SVG의 실제 자리는 작업 루트, 저장 루트, 참고 폴더, 절대 경로 가운데 어디든 될 수 있다(`hazop/viewer/build.py`의 `_svg_path`). 또 `output/`·`store/`는 모든 프로젝트가 함께 쓴다. 그래서 '지금 프로젝트의 폴더'라는 범위를 정할 수 없다. 처리 순서는 다음과 같다.
  1. 웹은 `api/sheet/<graph_id>.svg`처럼 ID로 묻는다.
  2. 엔진은 ID가 형식(`^[A-Za-z0-9_.-]{1,128}$`)에 맞는지 본다.
  3. 지금 프로젝트 그래프(`project.pick_graphs(project_id)`)에 그 ID가 있는지 본다.
  4. 그 추출 결과의 `svg_file`을 `_svg_path`의 허용 루트 검사로 푼 경로를 연다.
  5. 주소의 경로 조각을 파일 경로로 쓰는 일은 없다. 없는 ID와 다른 프로젝트의 ID는 같은 `fail(UrlNotFound)`로 끊는다.
- **새 화면 웹뷰의 허용 체계.** 지금 `webview.py`의 `ALLOWED_SCHEMES`(`file`, `qrc`, `data`, `blob`, `about`)는 이전 화면이 쓰므로 바꾸지 않는다. 새 화면 웹뷰는 자기 허용 집합 `SHELL_SCHEMES = {"hazop-app", "data", "blob", "about"}`를 쓰고 `file`을 허용하지 않는다. CSP(§5.5)도 `file:`을 어떤 출처 목록에도 넣지 않는다.
  - 그래서 두 겹이 된다. 요청 가로채기가 1차로 막고(`LocalOnlyInterceptor`를 허용 집합을 받게 넓힌 것), CSP가 2차로 막는다.
  - 둘 중 하나가 빠져도 `file://` 읽기는 막힌다.
- **주 프레임 이동 제한.** `LocalPage`와 같은 규칙을 쓴다. 허용 대상만 `hazop-app://shell/index.html` 하나로 바뀐다.

### 5.2 웹 화면과 엔진 잇기

지금 `Bridge`(`hazop/app/webview.py`)는 QWebChannel로 `toWeb` 신호와 `fromWeb` 칸(웹 → Python 문자열 하나)을 쓴다. 새 화면은 이 꼴을 본뜬 **따로 된 `ShellBridge`**(`hazop/shell/bridge.py`)를 둔다. 이전 화면의 `Bridge.fromWeb`과 그 신호들은 고치지 않는다. 같은 길이 상한(`MAX_MESSAGE_CHARS`, 64KB)과 JSON 파싱 규칙은 함수로 함께 쓴다.

| 방향 | 메시지 | 예 |
| --- | --- | --- |
| 웹 → 엔진 | `{"t":"cmd","id":"c12","name":"nodes.apply","args":{…}}` | 구간 만들기, 표제란 확정, 수용 |
| 엔진 → 웹 | `{"t":"reply","id":"c12","ok":true,"data":{…}}` 또는 `{"ok":false,"error":{"code","message"}}` | 명령의 답. `code`는 `bad_args`, `stale`, `locked`, `not_found`, `busy`, `failed` |
| 엔진 → 웹 | `{"t":"changed","topic":"nodes","ver":"s14"}` | 저장한 자료가 바뀜. 웹이 그 주제를 다시 읽는다 |
| 엔진 → 웹 | `{"t":"event","name":"job.progress","data":{…}}` | 추출 진행, 분석 진행, 연결 상태, 채팅 답 |
| 웹 → 엔진 | `{"t":"ui","name":"selectionChanged","data":{…}}` | 지금 뷰어 신호(`selectionChanged`, `nodeSelected` 등)를 이 꼴로 옮긴다 |
| 웹이 읽기 | `fetch("hazop-app://shell/api/<topic>")` | 도면 목록, 구간 목록, 행렬, 워크시트, 겹쳐 그리기 자료. 답에 `ver`가 붙는다(§5.3) |

**누가·언제는 엔진이 채운다.**
- 저장하는 기록의 `by`(검토자 이름), `at`(시각), `origin`(`user`), 묶음 ID, 실행 기록 필드는 엔진이 채운다. 웹 인자로 받지 않는다.
- 웹이 `args`에 이런 키를 넣으면 `bad_args`로 거절한다. 채팅 규격 §4.7(기록 위조 거절)과 같은 규칙이다.

**채팅 동작 표(`hazop/chat/actions.py`)와의 관계.**
- `actions.py`는 `s-conn`이 만드는 중이다. 채팅 동작마다 '인자 검사 + 엔진 호출' 함수를 갖는다.
- 화면 명령 가운데 이름이 같은 것(`nodes.apply`, `results.set_status` 등)은 그 함수를 그대로 부른다. 화면 단추와 채팅이 같은 길로 저장하게 하려는 것이다.
- 채팅 전용 규칙(바로·확인 분류, 누적 상한, 승인 표지의 10분 만료)은 화면 명령에 걸지 않는다. 사람이 화면에서 누른 것이 곧 확인이기 때문이다.
- 판 검사(§5.3)는 채팅과 화면 명령이 같은 함수를 쓴다.
- `actions.py`에 없는 이름(`project.*`, `ui.save`, `search.*`)은 `api.py`에만 있다.

**명령 표.** `hazop/shell/api.py`의 `COMMANDS`가 이름 → (인자 검사, 판 검사, 처리 함수)를 갖는다. 영역별 처리 함수는 `api_<영역>.py`로 나눠 단계마다 주인을 따로 둔다(§6).

| 명령 | 인자(웹이 보냄) | 처리 | 판 검사(§5.3) | 단계 |
| --- | --- | --- | --- | --- |
| `project.list` · `project.open` · `project.create` | — · `project_id` · `name` | 등록부의 `project_id` 모음, 지금 프로젝트 바꾸기, 새 프로젝트 | `create`는 같은 ID가 있으면 `bad_args` | 1 |
| `register.add` | (웹이 보내지 않음) | 끌어 놓기·파일 고르기는 Qt가 받는다. 웹 안에서는 파일 경로를 알 수 없기 때문이다. `ShellWindow.dropEvent`와 `QFileDialog`가 경로를 받아 엔진 등록 함수를 지금 프로젝트로 부른다 | — | 1 |
| `register.confirm_title` | `material_id`, `fields`, `ver` | 표제란 후보 확정 | 등록 기록 파일 지문 | 1 |
| `register.extract` | `material_ids`, `ai_review{on, cap, pages}` | 추출·그래프 작업 시작, 작업 ID 답 | 추출 결과가 이미 있으면 `bad_args`(다시 추출은 4단계 확인 상자) | 1 |

| `links.pair` · `links.unpair` | `a`, `b`, `ver` | 도면 연결 짝 지정·끊기 | 두 도면의 사람 수정 파일 지문 | 1 |
| `search.components` | `q`, `limit≤50` | 엔진 색인에서 찾기(§5.4) | 읽기 | 1 |

| `chat.ask` · `chat.stop` · `chat.new` | `text`, `view` · — · — | `ChatSession` | 읽기 | 1 |
| `ai.recheck` · `settings.reviewer` · `ui.save` | — · `name` · `state` | 연결 다시 확인, 검토자 이름, 보기 상태 저장 | — | 1 |

- **웹 → 엔진 메시지 길이.** 64KB 상한은 그대로다. 웹이 보내는 것은 명령과 ID 목록뿐이라 넉넉하다. 고른 것이 2,000개를 넘으면 지금처럼 잘라 `truncated`를 붙인다.
- **큰 자료.** 엔진 → 웹 방향의 큰 자료는 신호로 보내지 않고 웹이 `api/`로 읽는다. 읽기 API는 읽기 함수만 부른다. 쓰기는 이 길로 받지 않는다.
- **오래 걸리는 일.** 추출과 분석은 지금처럼 작업 스레드에서 돈다. 명령은 작업 ID를 바로 답하고, 진행은 `event`로 보낸다.
- **채팅.** `ChatSession`([채팅 규격 §2.4](../specs/chat-panel.md#24-채팅-프로세스-규격))은 엔진에 남는다. 답 카드 검사(`hazop/chat/card.py`)를 거친 카드만 `event: chat.answer`로 보낸다. 도면 표시 함수 `mark`·`clear_marks`·`draw_path`·`set_select_mode`·`set_selection`·`selection`·`zoom_to`([채팅 규격 §6](../specs/chat-panel.md#6-뷰어-api))는 이름과 인자를 그대로 둔다. Python에서 부르면 `toWeb`로 웹의 도면 구성요소에 전한다.

### 5.3 화면 상태의 주인과 판 검사

| 상태 | 주인 | 저장 | 바뀌면 |
| --- | --- | --- | --- |
| 프로젝트, 도면, 추출 결과, 사람 수정, 구간, 분석 결과, 검토 판정, 초기사건, 지식그래프 판단, 설정, AI 연결 | 엔진 | 지금 파일 그대로 | 엔진이 쓰고 `changed`를 보낸다 |
| 채팅 대화 | 엔진(`ChatSession`) | 저장하지 않음([INTENT §3.10](../../INTENT.md)) | `event` |
| 실행 기록 | 엔진 | `data/chat-actions/…`([채팅 규격 §4.7](../specs/chat-panel.md#47-실행-기록)) | |
| 열린 패널, 보는 도면, 확대·위치, 고른 것, 말풍선, 표 스크롤, 입력 중인 질문 | 웹(`store.js`) | 하지 않음 | 웹 안에서만 |
| 앱을 다시 열 때 이어 갈 것(마지막 도면, 채팅 접힘, 마지막 패널) | 웹이 정하고 엔진이 쓴다 | `<작업 루트>/data/ui-state.json` | 웹이 `ui.save` 명령을 보낸다 |

**원칙.**
- 저장하는 자료는 엔진 한 곳만 쓴다.
- 웹은 읽기 API가 준 판 표시(`ver`)를 들고 쓰기 명령을 보낸다.
- 엔진은 쓰기 직전에 판을 다시 만들어 비교하고, 다르면 쓰지 않고 `stale`로 답한다. 웹은 `stale`을 받으면 그 주제를 다시 읽고 "다른 곳에서 바뀌어 저장하지 않았습니다"를 보인다.
- 이 비교는 [채팅 규격 §4.6](../specs/chat-panel.md#46-확인과-실행-사이의-재검사차단-3)의 승인 표지와 같은 재료(대상의 `rev`·`state`, `set_rev`, 파일 지문)를 쓴다.

| 자료 | 판 표시 `ver` | 같다고 보는 기준 |
| --- | --- | --- |
| 구간(`hazop/study/nodes.py`) | 구간 묶음의 `set_rev`와, 명령이 건드리는 구간마다 `{node_id, rev, state}` | `set_rev`가 같고, 대상 구간마다 `rev`·`state`가 같고, 잠기지 않았을 것. 구간 규격 v2의 판 번호를 그대로 쓴다 |
| 분석 결과, 초기사건 문서, 지식그래프 잠재 후보, 추출 결과·AI 후보, 사람 수정, 등록 기록 | 그 명령이 쓰는 파일의 지문 `"<크기>:<mtime_ns>"`. 파일이 둘이면 둘 다 | 쓰기 직전에 다시 잰 지문이 모두 같을 것. 파일이 없던 것이 생겼거나 있던 것이 없어져도 다름 |
| 읽기만 하는 명령 | 없음 | 검사하지 않음 |

- 결과처럼 파일 하나에 칸이 많은 자료는 파일 단위로 비교한다. 그래서 분석 작업이 다른 칸을 쓴 직후에도 `stale`이 난다. 그때 웹은 다시 읽고, 같은 동작을 한 번 더 누르게 한다. 칸 단위로 나누는 것보다 덮어쓰기 위험이 없는 쪽을 골랐다.
- 엔진의 쓰기는 UI 스레드에서 하나씩 처리한다. 작업 스레드(분석)가 결과 파일을 쓸 때도 같은 저장 함수를 지나므로, 판 비교와 쓰기 사이에 다른 쓰기가 끼지 않는다.
- 웹이 엔진 자료를 고쳐서 들고 있지 않는다. 낙관적 갱신을 하지 않는다는 뜻이다. 답이 늦어도 화면은 엔진 판을 보이고, 단추에 진행 표시만 한다. 틀리면 데이터를 잃는 저장 경로이기 때문이다(CLAUDE.md 규칙 3).

### 5.4 성능

기준은 APR1400 표본처럼 큰 프로젝트다(143쪽, 525구간, 구성요소 약 46,000개, [INTENT §3.8](../../INTENT.md)).

- **도면.**
  - 한 번에 한 장만 그린다. 바탕 SVG는 `<image>`로 넣어 브라우저가 그림으로 그리게 한다. 구성요소마다 DOM을 두지 않는다.
  - 누르기·네모 고르기·마우스 올림은 JS의 격자 공간 색인(칸 64px)으로 찾는다. 색인은 그 장의 구성요소만 담는다.
  - 표시용 SVG 요소는 강조·고른 것·경로만 그리고, 지금 상한(2,000개)을 그대로 둔다.
  - 확대·이동은 CSS `transform`으로 하고, 표시 요소는 움직임이 멈춘 뒤 한 번 다시 그린다.
- **찾기(`@`).** 웹은 46,000개를 들고 있지 않는다. 엔진이 프로젝트를 열 때 태그·이름 색인을 한 번 만든다. `search.components`가 앞부분 일치 → 포함 일치 순으로 50개까지 돌려준다. 입력은 150ms 멈춘 뒤에 보낸다.
- **지식그래프 패널.** 처음 열 때는 전체 그래프를 그리지 않는다. 지금 도면의 구성요소와 그 이웃(깊이 1)만 그린다. 전체 보기는 지금 화면의 노드 수 상한(S1 상한 띠)을 그대로 둔다. 상한을 넘으면 도면별로 고르라고 알린다.
- **행렬.** 525구간 × 편차 40여 개면 칸이 2만 개를 넘는다. 줄 높이를 40px로 고정하고 보이는 줄과 앞뒤 10줄만 그린다(가상 스크롤). 머리 줄과 첫 칸은 고정한다.
- **목록.** 도면 143장, 구간 525개 목록도 같은 가상 스크롤을 쓴다. 썸네일은 엔진이 한 번 만들어 `api/thumb/<graph_id>.png`로 준다(ID 방식, §5.1).
- **읽기 API의 비동기 답.** `QWebEngineUrlRequestJob`이 할 수 있는 일은 `reply`·`fail`·`redirect`·`setAdditionalResponseHeaders`뿐이다. 그래서 '나중에 다시 오라'는 상태 코드는 쓰지 않고, 요청을 붙잡아 두었다가 답한다.
  1. 처리기(`requestStarted`, UI 스레드)는 캐시에 있는 자료면 바로 `reply`한다.
  2. 캐시에 없으면 작업을 `QThreadPool`에 맡기고, 요청 객체를 표에 붙잡아 둔다.
  3. 작업이 끝나면 신호로 UI 스레드에 돌아와 `reply`한다. 작업이 실패하면 `fail(RequestFailed)`다.
  4. 웹이 요청을 버리면(쪽 이동, 취소) 요청 객체의 `destroyed` 신호를 받아 표에서 빼고 답하지 않는다.
  5. 30초 안에 끝나지 않으면 `fail(RequestFailed)`로 답한다. 웹은 "읽기가 오래 걸려 멈췄습니다"와 '다시 읽기'를 보인다.
- **목표값과 재는 조건.**
  - 도면: APR1400 표본 143쪽 가운데 구성요소가 가장 많은 쪽과 SNP-M-101
  - PC: 이 개발 PC(Windows 11, 1920×1080 125%)와 1366×768 100% 창 크기. 보고에 CPU·메모리를 적는다
  - 값: 각 10회 중앙값

  | 잴 것 | 목표 |
  | --- | --- |
  | 도면 바꾸기(누른 뒤 바탕과 표시가 다 그려질 때까지) | 300ms 이하 |
  | 네모 고르기 결과 표시 | 100ms 이하 |
  | `@` 찾기 첫 결과 | 200ms 이하 |
  | 행렬 스크롤 | 프레임 시간 50ms를 넘는 장면 없음(3단계) |

### 5.5 보안

지금 웹뷰 규칙을 이어 가되, 새 화면 웹뷰는 `file`을 허용하지 않는다(§5.1).

- 원격 요청 차단과 주 프레임 이동 제한은 지금 방식 그대로다. 허용 체계는 `SHELL_SCHEMES`이고 이동 허용 대상은 `hazop-app://shell/index.html`이다.
- CSP를 둔다: `default-src 'none'; script-src hazop-app://shell; style-src hazop-app://shell 'unsafe-inline'; img-src hazop-app://shell data: blob:; connect-src hazop-app://shell; font-src 'none'; object-src 'none'; base-uri 'none'`. `file:`은 어디에도 없다.
- 웹 → 엔진 메시지는 믿지 않는다. 길이 상한, JSON 파싱, 명령 이름 표, 인자 형 검사, 엔진이 채우는 키(`by`·`at` 등) 거절을 거친다.
- 모델이 쓴 글과 도면에서 읽은 글은 글자로만 넣는다. Preact가 기본으로 글자를 이스케이프한다. `dangerouslySetInnerHTML`은 쓰지 않고, 정적 검사로 `hazop/shell/web/` 안에 이 이름과 `innerHTML`이 없는지 본다. 아이콘도 이 규칙을 지킨다(§4.3).

## 6. 옮기는 순서

**2026-11-14부터 새 화면이 기본이다.** 새 화면이 1~3단계(도면·채팅·등록, 구간, 분석 결과·초기사건)를 갖추고 `tests.test_shell_*` 343건이 통과해, 전체 시험이 통과하는 대로 기본을 바꾸기로 총괄이 승인했다. 그 전까지는 이전 화면이 기본이었다. 1단계만 끝난 새 화면에는 구간·결과·편집이 없어서, 새 화면이 기본이면 그 일을 하려고 앱을 다시 띄워야 했기 때문이다.

- **어느 창으로 여는가**(`hazop/app/startup.py` `window_kind`, `s-frame`이 고침).

- **아직 남은 것.** 4단계(지식그래프 패널, 도면 고치기, 설정의 나머지)와 이전 화면 제거 판단이 남았다. 그 기능은 지금도 이전 화면에서만 쓴다. 그래서 이전 화면을 지우지 않고, 4단계 완료 기준을 통과한 뒤 지울지 사용자에게 묻는다(아래 표 4단계 줄).

  - `startup.single_instance`가 돌려준 잠금 객체는 `main`이 쥐고 있으므로 창을 바꿔도 풀리지 않는다. 다른 실행이 그 사이에 끼어들 수 없다.
  - 닫는 창에 저장하지 않은 수정이나 실행 중인 AI 호출이 있으면, 지금 닫기 확인을 거친 뒤에만 바꾼다.
  - 두 창을 함께 열지는 않는다. 같은 파일을 두 창이 쓰지 않게 하려는 것이다.

## 9. 남는 위험과 확인할 것

- **QtWebEngine 판과 ES 모듈.** `Syntax.Host`와 `FetchApiAllowed`로 등록한 `hazop-app://shell`에서 ES 모듈의 상대 경로 `import`와 `fetch`가 되는지 1단계 첫 시험으로 확인한다. 안 되면 처리기가 `Content-Type: text/javascript`를 주는지, 출처가 `null`로 찍히지 않는지(`location.origin`)부터 본다.
- **판 검사의 거짓 `stale`.** 파일 단위 비교라 분석 중에는 결과 판정이 자주 `stale`로 돌아올 수 있다. 3단계 측정에서 잦으면 칸 단위 판을 엔진 단위로 따로 다룬다.
- **htm 템플릿 실수.** 형 검사가 없어 오타가 실행 중에야 드러난다. 화면 시험(§5.6)이 모든 패널을 한 번씩 연다.
- **두 틀이 함께 있는 기간.** 1~3단계 동안 기능이 두 곳에 있다. 이전 화면에서만 고친 결함이 새 틀에 빠지지 않도록, 엔진을 고치는 결함은 엔진에서 고치고 화면 코드에서 우회하지 않는다.
- **INTENT.md §3.8 고치기.** '단계 구조는 유지'를 이 결정으로 바꾸는 일은 총괄이 한다(이 문서는 GOV 문서를 고치지 않는다).
- **흐름 클릭 수.** §3.5는 시안과 코드로 센 값이다. 1단계 실제 창 측정이 나오면 그 값으로 바꾼다.

## 10. 정리된 보기

지금 새 화면은 원본 도면 SVG를 바탕에 깔고 그 위에 표시를 얹는다. 사용자 결정(2026-11-13 대화)으로 **정리된 보기**를 더한다. 안트로피 AutoPID 데모 화면처럼 깔끔한 도면을 쓰려는 것이다.

**정리된 보기는 읽은 결과를 가지런히 정돈해서 그린 도면이다**(사용자 2026-11-14). 원본과 대략 같은 자리는 지키되, 작은 어긋남은 바로잡는다. 사용자의 말로는 다음과 같다.

- 시안 7번처럼 기호화하고, 가시성이 좋고, 하이라이트가 분명해야 한다.
- 도면 요소끼리 겹치지 않고, 글자는 되도록 선과 겹치지 않는다.
- 오와 열이 맞는다. 미묘하게 다른 것이 거슬린다.
- 기기는 정중앙에 맞춰 정렬되고, 선은 기기와 정확하게 이어지고, 방향은 잘 보인다.

그래서 원본 보기와 정리된 보기의 좌표는 '정돈 허용 범위 안에서 같다'. 두 보기는 같은 `viewBox`와 같은 이동·확대 값을 쓰므로 바꿔도 화면 틀은 움직이지 않지만, 도면 위 기호와 선은 정돈한 만큼 조금 움직일 수 있다. 허용 범위는 기호 중심·배관 꺾임점 하나당 6 단위(겹침을 풀 때만 24 단위)다(§10.11).

- **지금은 보기가 두 가지다.** '원본'(지금 방식)과 '정리'(읽은 결과를 정돈해 다시 그린 도면)다. 단추 하나로 바꾸고, 바꿔도 화면 틀(이동·확대)은 같다.
- **궁극적으로는 정리된 보기만 쓴다.** 읽기 정확도가 100%가 되면 정리된 보기만 남긴다. 넘어가는 조건은 §10.8에 있다.
- **총괄 권장안(사용자 동의).**
  - 기본 보기는 읽은 방법에 따른다(§10.6).
  - 못 읽은 곳은 숨기지 않고 점선 자리표로 그리며, 그 자리의 원본 조각을 볼 수 있다(§10.4).
  - 정리된 보기와 DEXPI 내보내기는 '무엇이 확정됐는가'라는 같은 조건을 쓴다(§10.7).
  - DEXPI 쪽 규격은 [`dexpi-exchange.md`](../specs/dexpi-exchange.md)다.

**이 기능의 가장 큰 위험은 놓친 것이 보이지 않는 것이다.** 정리된 보기는 읽은 것만 그린다. 추출이 기호나 배관을 통째로 놓치면 그 자리에는 자리표조차 없고, 도면은 빠짐없이 그려진 것처럼 보인다. PDF 도면에서 특히 그렇다. 그래서 이 절은 세 장치를 둔다.

1. **원본에 남은 것.** 원본에서 어느 구성요소에도 쓰이지 않은 선·글자의 수와 자리를 보인다(§10.5).
2. **원본과 견주기.** 쪽을 확정하기 전에 원본과 나란히, 또는 겹쳐 견주는 단계를 반드시 거친다(§10.7).
3. **원본 표시를 지우지 않음.** 확정된 PDF 쪽도 '읽어서 다시 그린 도면'이라는 표시와 원본으로 돌아가는 길을 늘 둔다(§10.6).

### 10.1 그리는 자료

정리된 보기는 원본 SVG를 쓰지 않고 추출 결과만으로 그린다. 입력은 두 가지다.

- 도면 읽기 API(`api/sheet/<graph_id>`)의 `items`(`hazop/shell/sheet_items.py` `build_items`).
- 그리기용 자료 API(`api/clean/<graph_id>`, `hazop/shell/clean_items.py` `build`). 구현 b8135bc·2158210에 이미 있다.

원본 보기와 같은 SVG 사용자 단위 좌표계를 쓴다. 두 보기는 `viewBox`(`width`·`height`)와 화면 이동·확대 값 `{x, y, k}`를 함께 쓴다. 정리된 보기는 이 자료를 정돈 규칙(§10.11)으로 고친 좌표(`layout`)로 그린다. 고친 양은 허용 범위 안이다.

**`items`에 있는 것**(2026-11-13, `sheet_items.py` 기준)

| 필드 | 뜻 | 정리된 보기에서 쓰는 곳 |
| --- | --- | --- |
| `id` · `layer`(`symbol`·`pipe`) | 도면 안 `local_id`, 기호인지 배관인지 | 그릴 대상과 표시 대상을 같은 ID로 잇는다 |
| `kind` | 기호는 종류(`pump`, `check_valve` …). 배관은 관계 종류(`physical_connection`·`measurement_connection`·`signal_connection`) | 기호 그림 고르기, 선 모양 고르기 |
| `bbox` | 기호의 외곽 상자 `[x0, y0, x1, y1]` | 기호를 넣을 자리와 크기 |
| `polyline` | 배관이 지나는 길(끝점과 꺾임점) | 그대로 그린다 |
| `tag` | 기호는 태그, 배관은 배관 번호(`line_no`, 없으면 붙은 글자) | 글자 |
| `label_bbox` | 기호 글자가 원본에서 놓인 자리 | 태그 자리 |
| `classification` · `unknown` | 분류 상태, 미확인 여부 | 자리표(§10.4) |

**그리기용 자료(`clean_items.build`)가 주는 것**

| 필드 | 값 | 어디서 오는가 |
| --- | --- | --- |
| `orient` | `{rot, flip_h, flip_v, basis: "drawio"\|"pipes"\|"none"}` | drawio는 도형 스타일의 `rotation`·`direction`·`flipH`·`flipV`(`drawio.py`가 이미 읽는 값. 가상 도면의 세로 밸브는 `direction=south`·`north`로 돌려져 있다). PDF는 회전 정보가 없으므로, 두 구멍 기호에 붙은 배관 끝들이 놓인 축으로 0°·90°를 정한다(`basis: "pipes"`). 못 정하면 0°, `basis: "none"` |
| `line_type` · `flow` | 선 종류, `source_to_target`·`target_to_source`·`null` | 커넥터 `line_type`, 배관 `flow_direction.basis` |
| `ends` | 배관 끝마다 `{end, point, status: connected\|open, node}` | 끝점 `status`와 `node_local_id` |
| `review` | `script`·`ai_candidate`·`ai_accepted`·`human` | AI 검토 후보 기록과 사람 수정 기록 |
| `text_items` | 기호에 속하지 않은 독립 글자 `{text, bbox}` | 추출 결과 `texts` |
| `read_method` | 읽은 방법. 값과 이름은 [`dexpi-exchange.md` §4](../specs/dexpi-exchange.md#4-등록-흐름에서의-자리) 5번의 `read_method`를 따른다(지금 `drawio`·`pdf_vector`·`raster`·`dexpi`). DEXPI 규격이 형식 이름을 한 표로 정하면 그 표를 따른다 | 추출 실행 정보·그래프 `source` |
| `unconfirmed` | 미확인 목록 전체(§10.4의 정의) | 아래 |
| `unplaced` | 위치 없는 구성요소 `{id, kind, tag, reason}` | `bbox`도 글자 자리도 없는 노드, 꺾은선을 만들 수 없는 관계 |
| `leftovers` | 원본에 남은 것(§10.5) | 엔진에 새로 필요(아래) |

- **위치 없는 구성요소를 버리지 않는다.** 지금 `build_items`와 `clean_items.build`는 좌표가 없는 노드·관계를 건너뛴다(`if bbox is None: continue`, `if len(line) < 2: continue`). 그러면 그 구성요소는 그려지지도 세어지지도 않는다. 분류 안 된 노드, 태그 없는 밸브, 열린 배관을 좌표 없이 넣으면 `unconfirmed []`, `items []`가 되어 '미확인 0 · 쪽 확정하기'가 뜬다. 앞으로는 건너뛰는 대신 `unplaced`에 넣고, 미확인 사유 `no_position`으로도 센다(§10.4).
- **읽은 방법을 모르면 엄격한 쪽으로 본다.** 지금 `clean_items.source_format`(34–38행)은 모르는 값을 그대로 돌려주고 빈 값을 `drawio`로 본다. 빈 값이나 모르는 값은 `unknown`으로 돌려주고, 화면은 그 쪽을 PDF처럼 다룬다(원본이 기본, 원본 단추가 늘 있음). 빈 값을 `drawio`로 보면 출처를 모르는 도면이 정리된 보기로 열린다.
- 엔진은 자료를 바꾸지 않고 읽기만 한다. 웹은 프로젝트 ID를 모른다는 1단계 약속도 그대로다.

### 10.2 그리는 규칙

**모습의 기준은 시안 7번이다.** 선 굵기와 글자 크기 하한은 **화면 픽셀**로 정한다. 확대해도 선 굵기는 같고(`vector-effect: non-scaling-stroke`), 글자는 도면 단위 크기로 그리되 화면에서 하한보다 작아지면 하한으로 키운다. 값은 구현(136f59e, 6b4de53, c62c587)이 쓰는 값이다. 좌표·거리(허용 범위, 화살촉 간격 등)는 도면 단위다.

| 대상 | 그리는 법 |
| --- | --- |
| 바탕 | 흰 바탕, 원본과 같은 `width`×`height`. 도면 테두리 한 줄과 표제란 칸을 그리고, 표제란 칸 안에는 ①에서 사람이 확정한 도면 번호·판·제목을 쓴다(표제란 후보 값은 쓰지 않는다). 표제란 옆에 읽은 방법 꼬리표(§10.6)를 늘 그린다 |
| 기호 | `kind`마다 표준 그림 한 벌(§10.3)에서 하나를 골라 정돈한 자리(§10.11)에 둔다. 같은 `kind`는 같은 표준 크기다(`keep`: 밸브·계기·펌프 등). `stretch` 설비(원자로 용기·증기발생기·탱크·열교환기)는 읽은 상자 크기를 격자에 맞춰 쓴다. 회전·뒤집기는 `orient`대로 기호 가운데를 축으로 한다. 선 굵기 **1.8px** |
| 기호 연결점과 배관 끝 | 기호 정의에 연결점(구멍) 위치가 있다(§10.3). 배관은 옮기지 않는다. 맞춘 뒤 연결점과 배관 끝이 떨어져 있으면, **아래 세 조건을 모두 만족할 때만** 그 사이를 같은 굵기의 짧은 선으로 잇는다. (1) 그 배관 끝의 `status`가 `connected`다. (2) 그 끝의 `node`가 바로 이 기호다(그래프에서 이 기호에 이어진 끝). (3) 연결점과 끝 사이가 8 단위 이하다(원본에서도 배관이 기호 테두리까지 오므로 대개 0~2 단위다). (1)·(2)가 아니면 잇지 않고 열린 끝(§10.4)으로 그린다. (1)·(2)는 맞는데 8 단위를 넘으면 잇지 않고, 그 끝에 호박색 짧은 눈금을 그려 미확인 사유 `port_gap`으로 센다. 기호의 방향이나 크기를 잘못 맞췄다는 신호이기 때문이다 |
| 공정 배관 | 정돈한 꺾은선(§10.11) 실선. `process` **2.0px**, `process_secondary` **1.6px** |
| 계측 연결 | `instrument_tap`(`measurement_connection`) **1.2px** 긴 점선(`6 3`px) |
| 신호선 | `signal_electric` 등(`signal_connection`) **1.2px** 짧은 점선(`2 2`px) |
| 흐름 방향 | `flow`가 있는 배관에만 그린다(추정하지 않는다). 화살촉은 길이 10·폭 7 도면 단위의 채운 삼각형, 색은 그 선의 색(경로 위에서는 경로 색)이다. 40 단위 이상인 선분마다 가운데에 하나, 긴 선분은 110 단위 간격으로 더 둔다. 기호·분기점에서 12 단위 안에는 두지 않는다 |
| 분기점 | `tee` 기호는 그림 없이, 배관이 셋 이상 실제로 만나는 점에만 지름 5 단위 검은 점. 이어지지 않고 엇갈리기만 하는 배관에는 점을 찍지 않고 건너뜀 표시를 한다(§10.11) |
| 도면 밖 연결 | `continuation`은 화살표 오각형에 이어지는 도면·글자를 원본 글자 그대로 쓴다. 도면 연결 짝이 정해져 있으면 그 도면 칩처럼 누를 수 있다 |
| 태그 | 정돈 규칙의 글자 자리(§10.11)에 쓴다. 계기 원 안 글자는 기능 글자와 번호 두 줄로 원 안에 쓴다(c62c587). 원이 화면에서 18px 미만이면 태그 전체를 옆에, 18~34px이면 기능 글자만 원 안에·번호는 옆에, 34px 이상이면 두 줄을 원 안에 |
| 배관 번호 | 그 배관의 가장 긴 곧은 선분 가운데 옆. 세로 선분이면 글자를 90° 돌린다. 같은 번호가 이어진 배관 조각 여럿에 있으면 가장 긴 조각 하나에만 쓴다. 자리는 글자 자리 규칙(§10.11)으로 고른다 |
| 글꼴 | 태그·번호·도면 글자 모두 `--mono`(`Cascadia Mono`, `Consolas`) 9 도면 단위, 화면 하한 **11px**. 계기 원 안 글자는 8.5 단위 고정. 표제란 제목만 `--font` 14 단위. 모든 글자 뒤에 바탕색 테두리 **3px**(`paint-order: stroke`)를 둬 선이 가까이 지나도 읽히게 한다 |
| 독립 글자 | `text_items`를 그 자리에 같은 글꼴로 쓴다 |
| 색 | 기호·배관·글자는 `--ink`, 도면 테두리는 `--line-strong`. 정리된 보기 자체에는 색을 쓰지 않고, 색은 표시(§10.6)와 미확인(§10.4)·원본에 남은 것(§10.5)에만 쓴다 |

### 10.3 표준 기호 한 벌

**지금 기호 사전은 그대로 그릴 수 없다.** `resources/library/symbols/`의 항목(JSON)은 인식 규칙이다. `match`(어떤 선 구조·견본이 있으면 이 `kind`인가)와 출처는 있지만 그릴 도형이 없다. `images/`의 PNG는 견본 맞추기용 무늬다. 그래서 그리기용 기호는 따로 한 벌 둔다. 사전과 이어지는 고리는 `kind`다. 2026-11-13에 사전 항목의 `kind` 값은 24가지이고, 가상 도면 추출 결과에 나오는 기호 `kind`는 12가지다(SNP-M-101 기준).

| 안 | 내용 | 좋은 점 | 나쁜 점 |
| --- | --- | --- | --- |
| **(가) 직접 정리한 SVG 한 벌** | 사전의 `kind`마다 SVG 하나를 같은 격자·같은 선 굵기로 그린다. 연결점·맞추는 법·글자 자리를 목록에 적는다 | 한 벌의 생김새가 고르다. 연결점이 우리 `kind` 이름과 바로 맞는다. 라이선스 걱정이 없다. 새 `kind`가 사전에 생기면 같은 날 하나 더 그리면 된다 | 처음에 24개 남짓을 그려야 한다(기호 하나에 간단한 도형 몇 개) |
| (나) 공개 P&ID 기호 묶음 | 아래 후보 가운데 하나를 가져와 `kind`에 짝짓는다 | 처음 그리는 수고가 준다 | 연결점이 우리 `kind`와 맞지 않아 결국 기호마다 손봐야 한다. 묶음마다 선 굵기·격자가 달라 섞으면 고르지 않다. 고지 의무가 생긴다 |

(나)의 후보와 확인한 것:

| 후보 | 라이선스 | 확인 |
| --- | --- | --- |
| draw.io 기호(`mxgraph.pid.*`, `mxgraph.pid2*`. 가상 도면이 이 기호로 그려졌다) | 저장소 `jgraph/drawio`의 `LICENSE`가 Apache License 2.0 | 저장소 `LICENSE`만 확인(2026-11-13, `raw.githubusercontent.com/jgraph/drawio/dev/LICENSE`). 기호 파일 하나하나의 표기와 위치는 **확인하지 않았다** |
| ISO 10628-2, ANSI/ISA-5.1의 기호 | 표준 문서(유료)에 실린 그림. 파일로 쓰는 허락이 따로 없다 | 그림을 그대로 옮겨 쓰는 허락은 **확인하지 못했다**. 기호의 모양(뜻)을 따르는 것과 그림 파일을 복사하는 것은 다르다 |

**권장: (가).** 기호 모양은 ISA-5.1·ISO 10628-2의 뜻(나비꼴 밸브 몸통, 원 계기, 체크밸브 삼각 등)을 따르되 그림 파일은 직접 그린다. draw.io 기호는 Apache-2.0이라 참고로 볼 수는 있다. 다만 파일 단위 표기를 확인하지 않았으므로 복사하지 않는다(§8 UW14). 구현 c5dc4f4가 이 안으로 31종을 그렸다.

**한 벌의 꼴**(구현 c5dc4f4와 같음)

- 자리: `resources/library/drawing-symbols/<kind의 밑줄을 하이픈으로>.svg`(예: `check-valve.svg`)와 목록 `resources/library/drawing-symbols/manifest.json`. 폴더 이름은 이름 규칙(HZ-GOV-02 §4)대로 하이픈을 쓴다.
- SVG는 `viewBox="0 0 가로 세로"`에 `path`·`line`·`polyline`·`polygon`·`circle`·`rect`만 쓰고, 모두 `fill="none" stroke="currentColor"`다. 글자·그림 파일·스크립트·외부 참조·`style`은 쓰지 않는다.
- 목록의 항목 하나:
  ```json
  {"kind": "check_valve", "file": "check-valve.svg", "fit": "keep",
   "ports": [{"name": "in", "x": 0, "y": 50}, {"name": "out", "x": 100, "y": 50}],
   "label": "below", "flow_axis": [1, 0]}
  ```
  `ports`는 연결점(그림 좌표), `label`은 태그 기본 자리, `flow_axis`는 회전 0°일 때 흐름 방향이다(체크밸브처럼 방향이 있는 기호만).
- 없는 `kind`(사전에는 있으나 그림이 없음)는 `generic` 그림(모서리 둥근 네모 + `kind` 머리글자)으로 그리고, 시험이 '그림 없는 kind' 목록을 알린다.
- `scripts/build_drawing_symbols.py`가 목록과 SVG를 읽어 도형 자료 `hazop/shell/web/js/canvas/symbols.json`을 만든다. 화면과 내보내기 둘 다 이 자료 하나를 읽는다. 아이콘과 같이 `innerHTML`을 쓰지 않는다(§4.3).
- 맞추기: 그림 좌표 → `orient`의 회전·뒤집기 → `bbox`에 `fit`대로 크기 맞춤 → 이동. 90°·270°면 맞출 때 상자의 가로세로를 바꿔 본다.

### 10.4 미확인과 못 읽은 곳

**미확인의 정의.** 쪽의 미확인은 **추출이 남긴 미확인 목록 전체**다. 정리된 보기가 따로 고른 몇 가지가 아니다. [INTENT §3.8](../../INTENT.md)의 '미확인을 사람이 다 확정하면'과 같은 뜻이다. 세는 대상은 사람 수정(`drawing-edits`)을 반영한 추출 결과에서 다음을 모두 합한 것이다.

| 사유 | 출처 | 예 |
| --- | --- | --- |
| 추출의 미확인 기록 | `validation.unknowns` 전체(`check` 코드마다 하나). 대상(`target`)이 있으면 그 구성요소에, 없으면 쪽 전체에 붙인다 | `missing_kind`, `ambiguous_symbol`, `actuated_valve_pending`, `unconnected_endpoint`, `unknown_flow_direction`, `unknown_check_valve_direction`·체크밸브 방향 모호·모순, `position_conflict`·`position_kind_mismatch`(고장 시 위치), `missing_port`·`ambiguous_port`, `self_loop`, `missing_drawing_number` |
| 끝이 미확정인 연결 | `unresolved_connectors` 전체 | 끝이 노드에 닿지 않은 커넥터 |
| 분류 안 된 기호 | 노드의 `classification`이 `classified`가 아니거나 `kind`가 비어 있음 | 미확인 기호 |
| 태그 없음 | 태그를 갖는 종류(설비·밸브·계기)인데 태그가 비어 있음 | 번호를 못 붙인 밸브 |
| 수락 전 AI 후보 | AI 검토 기록에서 `accepted`·`rejected`가 아닌 후보 | 제안 상태 후보 |
| 위치 없음 | `unplaced`(§10.1) | 좌표 없는 노드·관계 |
| 연결점 어긋남 | `port_gap`(§10.2). **정리된 보기에서만 세고 쪽 확정 조건(`sheet_confirmation`)에는 넣지 않는다**(2026-11-14 결정): 기호를 맞춘 그리기에서 생기는 틈이라 그래프·DEXPI 자료를 바꾸지 않고, 엔진은 기호 그림의 연결점을 모른다 | 맞춘 기호의 연결점과 이어진 배관 끝이 8 단위 넘게 떨어짐 |

- **같은 대상의 여러 사유는 따로 센다.** '미확인 n곳'의 n은 사유 건수의 합이다. 칩 말풍선에 사유별 수를 보인다.
- **사람이 끝내는 법은 두 가지다.** 값을 고치거나(종류 고르기, 태그 입력, 이을 곳 고르기, 방향·고장 시 위치 정하기, 후보 수락·거절, 위치 주기), '이대로 확인'을 누르고 사유를 적는다(예: '이 펌프에는 포트 구분이 없다'). '이대로 확인'은 사람 수정 기록(`drawing-edits`)의 기존 `confirm` 연산 `{op: "confirm", target, value: {items: [{check, reason}]}, by, at}`으로 남고(연산 이름은 코드 그대로 `confirm`), 그 미확인을 목록에서 뺀다. 추출의 미확인 기록은 `check`와 `reason`이 맞는 것을, 엔진이 정하는 사유(`unknown_symbol`·`missing_tag`·`open_end`·`unresolved_connector`·`unplaced`)는 `check`가 그 코드인 것을 뺀다. 수락 전 AI 후보는 수락·거절로만 끝나고, 대상이 없는 쪽 전체 미확인은 연산이 대상을 요구하므로 값을 고쳐야 한다. 엔진이 `by`·`at`을 채운다(§5.2).
- **수만 세지 않고 목록으로 보인다.** 미확인 칩을 누르면 사유별로 묶인 목록이 뜬다. 위치 없는 것은 도면에 자리가 없으므로 이 목록에서만 고칠 수 있다.

**도면에서 보이는 모습**

| 경우 | 보이는 모습 | 누르면 |
| --- | --- | --- |
| 미확인 기호(`kind` 없음 또는 분류 안 됨) | `bbox` 자리에 호박색 점선 네모(`--warn-line`, `4 3`)와 가운데 `?`. 붙은 글자가 있으면 호박색으로 쓴다 | 말풍선에 그 자리의 **원본 조각**(`bbox`를 사방 24 단위 넓혀 원본 SVG를 잘라 보인 것)과 '종류 고르기'·'AI에 묻기'·'도면에 없음(지우기)' |
| 끊긴 연결(배관 끝 `open`) | 배관은 읽은 데까지 그대로 그리고, 열린 끝에 호박색 빈 원(지름 6 단위). 이어 주지 않는다 | 원본 조각과 '이을 곳 고르기' |
| 연결점 어긋남(`port_gap`) | 이어 주지 않고 배관 끝에 호박색 짧은 눈금 | 원본 조각, '기호 방향 고치기' |
| 종류는 읽었지만 태그가 없음 | 기호는 그리고, 태그 자리에 호박색 점선 밑줄 `태그 없음` | 원본 조각과 태그 입력 |
| 속성만 미확인(흐름 방향, 체크밸브 방향, 고장 시 위치, 포트 등) | 기호·배관은 그리고, 그 대상 옆에 호박색 작은 점(지름 5 단위). 흐름 방향이 미확인이면 화살촉을 그리지 않는다 | 원본 조각과 그 속성의 입력·'이대로 확인' |
| AI 후보(수락 전) | 후보 `kind`의 기호를 회색 점선(`--ai-line`)으로 그리고 오른쪽 위에 작은 `AI` 꼬리표. 태그가 AI 후보면 글자도 회색 | 원본 조각, 후보 근거, '수락'·'거절' |
| 쪽 전체의 미확인(대상 없음) | 표제란 꼬리표 옆 호박색 점 | 그 미확인의 설명과 입력 |
| 위치 없음 | 도면에 그리지 않는다. 미확인 칩 옆 '위치 없음 n' 칩 | 목록. '위치 주기'(도면에서 네모로 자리 고르기)·'도면에 없음' |
| 사람이 고친 것(`review: human`) | 다른 것과 같게 그린다. 말풍선의 읽음 상태에만 '사람 수정'이 보인다 | — |

- **원본 조각은 새 그림을 만들지 않는다.** 같은 `api/sheet/<graph_id>.svg`를 작은 `<svg viewBox>` 안에 `<image>`로 넣어 그 부분만 보인다. DEXPI로 들어온 쪽처럼 원본 그림이 없으면 §10.6을 따른다.
- **다음 미확인.** 칩을 누르거나 N을 누르면 도면 안 순서(위→아래, 왼→오른)로 다음 미확인으로 옮겨 말풍선을 연다(Shift+N은 앞으로). 위치 없는 것과 쪽 전체 미확인은 순서 끝에 둔다. 원본 보기에서도 같은 칩이 보인다.

### 10.5 원본에 남은 것

**뜻.** 원본 그림에 있는데 어느 구성요소·배관·표제란·글자 기록에도 쓰이지 않은 선과 글자다. 추출이 통째로 놓친 기호·배관은 여기에 나타난다. 미확인 목록은 '읽었지만 확실하지 않은 것'이고, 원본에 남은 것은 '읽지도 않은 것'이다.

**지금 엔진이 주는 것**(`hazop/extract/`를 읽고 확인, 2026-11-14)

| 읽은 방법 | 남은 글자 | 남은 선 |
| --- | --- | --- |
| `pdf_vector` | 있다. 기호에도 배관에도 붙지 않은 문단은 추출 결과 `texts`에 남는다(`pdf_vector.py` 1846–1856행, 표제란과 기호 표시 글자는 뺌). 선 라벨 후보와 '소속 대상 미확정'이 `note`로 갈린다 | **없다.** 분석 중간 결과(`analyze`의 반환값)에는 분류한 선 묶음(`classified`: `bodies`·`polys`·`dashes`·`cells`·`dots`)과 쓰이지 않은 화살촉(`leftover_markers`)이 있지만, 추출 결과(`build_extraction`)로 넘기지 않는다. 어느 선이 기호·사슬·표제란·빗금에 쓰였는지 표시하는 필드도 없다 |
| `drawio` | 라벨 없는 독립 글자 셀은 `texts`에 남는다 | 분류하지 못한 셀은 `unclassified`, 일부러 뺀 셀(표제란 등)은 따로 남지 않는다 |
| `dexpi` | 원본 그림이 없다(§10.6). 대신 대응을 못 한 클래스·속성 목록이 남은 것이다([`dexpi-exchange.md` §5.5](../specs/dexpi-exchange.md#55-모르는-클래스와-속성)) | 같음 |

**엔진에 필요한 것**(단위 V1b, §10.10)

- PDF 추출 결과에 `leftovers`를 더한다: `{"paths": [{"bbox", "pts" 또는 "d", "kind": "line|curve|rect|marker"}], "texts": [local_id …]}`.
  - `paths`는 원본 쪽의 벡터 경로 가운데 기호 몸통·장식선, 배관 사슬, 분기점, 표제란·표 칸, 빗금·점 무늬, 흐름 화살촉 어디에도 쓰이지 않은 것이다. 추출 코드는 경로마다 '쓰인 곳'을 표시하고, 표시가 없는 것을 모은다.
  - `texts`는 `texts` 가운데 `note`가 '소속 대상 미확정'인 것의 ID다(선 라벨 후보는 뺀다).
  - 도면 테두리·표제란 칸처럼 늘 남는 것은 `kind: "frame"`로 따로 표시해 수에서 뺀다(엔진 답의 `frame`에 따로 셈).
- drawio는 분류하지 못한 셀(`unclassified`)을 남은 것으로 센다. 작성자가 일부러 뺀 셀(`drawing.ignored_objects`, 표제란·주석 등)은 `frame`과 같이 따로 세고 수에서 뺀다(구현 `confirmation.leftovers`, 정리된 보기와 같음).
- 기준값에 닿는다. `pdf_vector.py`를 고치므로 `check_apr1400.py`·`check_snp_baseline.py`가 그대로인지 커밋 전에 확인한다(CLAUDE.md 규칙 12). 점수 입력은 바꾸지 않고 필드만 더한다.

**화면**

- 미확인 칩 옆에 '원본에 남은 것 n'(선 n₁ · 글자 n₂)을 보인다. `leftovers`가 없는 추출(필드를 더하기 전의 결과)이면 '원본에 남은 것: 엔진이 세지 않음'으로 보이고, 그 쪽은 확정할 수 없다(§10.7).
- '남은 것 겹쳐 보기'(키 L)를 켜면 정리된 보기 위에 남은 선을 호박색 반투명(40%)으로, 남은 글자 자리를 호박색 점선 네모로 겹쳐 그린다. 누르면 원본 조각과 '구성요소로 만들기'(→ 미확인 기호로 더함)·'구성요소 아님'을 보인다. '구성요소 아님'을 기록할 자리는 아직 없다(사람 수정의 `confirm` 연산은 구성요소·관계만 대상으로 받음).
- 원본 전체를 옅게(30%) 겹쳐 보는 '원본 겹쳐 보기'도 같은 자리에 둔다(엔진 값이 없어도 된다). 정리된 그림과 원본이 어긋나는 곳이 눈에 띈다.

### 10.6 보기 바꾸기와 표시

**단추 자리.** 도면 도구 막대 오른쪽 끝에 두 칸 단추 `원본 | 정리`, 그 옆에 '미확인 n곳'·'위치 없음 n'·'원본에 남은 것 n' 칩을 둔다. 키는 O(원본·정리 바꾸기)다. 바꾸면 화면 이동·확대·고른 것·표시·열린 말풍선을 그대로 둔다.

**기본 보기와 읽은 방법 꼬리표**

| 읽은 방법(`read_method`) | 처음 열 때 | 원본 단추 | 늘 보이는 꼬리표 |
| --- | --- | --- | --- |
| `drawio` | 정리 | 있음 | '읽은 도면 · drawio' |
| `dexpi` | 정리 | **숨긴다.** 원본 그림이 없다. 단추 자리에 '원본 그림 없음 · DEXPI 변환' 글자 | '변환 도면 · DEXPI <판>'(`dexpi-exchange.md` §4 5번의 표시) |
| `pdf_vector`, `raster` | 원본. 그 쪽이 '확정된 쪽'(§10.7)이면 정리 | **늘 있다.** 확정된 뒤에도, '정리된 보기만'으로 넘어간 뒤에도(§10.8) 사용자가 없애기로 하기 전에는 둔다 | 확정 전: '확정 전 도면 · PDF에서 읽어 다시 그림'(호박색). 확정 뒤: '읽은 도면 · PDF · 사람 확정 <누가> <언제>'(회색). 어느 쪽이든 원본처럼 보이지 않게 한다 |
| `unknown`(빈 값·모르는 값) | 원본 | 늘 있다 | '읽은 방법 모름'(호박색) |

- 같은 쪽에서 사람이 바꾼 보기는 앱을 닫을 때까지 기억한다(§8 UW15). 프로젝트 파일에는 저장하지 않는다.
- **DEXPI 쪽의 원본 조각.** 원본 그림이 없으므로 말풍선의 원본 조각 자리에 그 구성요소의 DEXPI 원문 요약(클래스, `id`, `GenericAttribute` 이름·값 몇 줄)을 글로 보인다. 원문이 없으면 '원본 그림 없음'만 쓴다. '원본 겹쳐 보기'와 '원본과 견주기'의 그림 칸도 '원본 그림 없음'이 되고, 견주기는 DEXPI 원문 목록과 정리된 보기를 견주는 것으로 바뀐다(§10.7).

**표시를 그리는 법.** 원본 보기는 원본 위에 반투명 띠와 상자를 얹는다. 정리된 보기는 **그 객체의 색을 바꾼다.** 표시 API(`Mark`, 채팅 규격 §6)는 같고 그리는 쪽만 다르다.

| 표시 | 정리된 보기에서 |
| --- | --- |
| 경로(`path`) | 경로에 든 배관은 `--path`(주황) **4px**, 기호는 선 색 `--path` **2.6px**, 경로에 든 밸브는 몸통을 경로 색으로 채운다(90%). 흐름 화살촉도 경로 색. 단계 번호 원은 지름 **22px**, 글자 **13px** 굵게, 흰 테두리 2px |
| 출발·확인 못 한 곳 | 출발 기호는 `--accent`(파랑) 2.6px. 확인 못 한 곳은 호박색 점선 네모(`6 4`px, **2.2px**). 원본 보기의 `ov-warn`과 같은 세기 |
| 나머지 흐리기(`dim_others`) | 표시되지 않은 기호·배관·글자를 **연한 회색**으로 본다. 바탕 위에 바탕색 막(불투명도 0.62)을 한 장 깔아 만든다(dcb1369). 경로 밖도 모양은 알아볼 수 있어야 한다 |
| 구간 색(`seg:<n>`) | 구간에 든 배관은 구간 색 **2.2px**(구간을 고르면 3px), 기호는 구간 색 선과 그 색 12% 채움. 두 구간이 겹치면 둘째 색을 `6 6`px 줄무늬로 덧그린다. 구간 꼬리표(S1 …)는 원본 보기와 같은 자리 |
| 고른 것 | `--accent` **3px** 선과 14% 채움. 고르기 막대는 같다 |
| 마우스 올림 | 선 굵기만 +0.8px |

**표시가 있어도 불확실한 곳은 흐려지지 않는다.** 미확인 자리표(점선 네모, `?`), 열린 끝 원, `port_gap` 눈금, 속성 미확인 점, `AI` 꼬리표, '태그 없음' 밑줄, 원본에 남은 것 겹침은 **흐리기와 흰 막의 위**에 그린다. 표시된 객체가 미확인이면 표시 색으로 다시 그린 뒤 그 위에 자리표를 다시 얹는다(경로 색 선 + 호박색 점선 네모). 그래서 경로가 미확인 기호를 지나면 원본 보기의 '확인 못 한 곳' 상자와 같은 세기로 보인다. 범례에는 '확인 못 한 곳'과 '미확인'을 늘 함께 둔다.

**만드는 방식.** 바탕(표시 없는 정리된 도면)과 표시 걸린 객체를 나눠 그린다. 흐리기는 바탕 위에 흰 막을 한 장 깔고 그 위에 표시 객체를, 그 위에 불확실 표시를 그린다. 바탕을 엔진이 SVG 하나로 만들지(캐시) 웹이 `symbols.json`으로 그릴지는 §10.9 측정으로 정한다. 어느 쪽이든 화면과 내보내기는 같은 `symbols.json`과 같은 규칙으로 그린다.

**인쇄·내보내기.** 도면 패널의 '내보내기'에 '정리된 도면(SVG)', '정리된 도면(PDF)'을 둔다.

- 미확인 자리표, 원본에 남은 것 수, 범례를 그대로 넣는다.
- 표제란 옆에 읽은 방법 꼬리표(위 표), '미확인 n · 원본에 남은 것 n · 확정 지문 · 내보낸 때'를 찍는다.
- 확정되지 않은 쪽은 바닥에 '확정 전 도면'을 크게 찍는다. 확정된 PDF 쪽도 '원본 도면이 아님 · PDF에서 읽어 다시 그림 · 사람 확정 <누가> <언제>'를 찍는다.
- 화면의 지금 표시(경로·구간 색)를 넣을지는 내보내기 대화상자에서 고른다(처음 값: 넣지 않음).

### 10.7 확정 조건(DEXPI 내보내기와 같이 쓴다)

정리된 보기의 기본 보기, 칩, 내보내기 꼬리표, DEXPI 내보내기는 같은 함수 하나의 답을 쓴다.

```python
sheet_confirmation(name) -> {
    "unconfirmed": [{"id" | None, "reason", "detail"}],         # §10.4 정의 전체('이대로 확인'한 것은 뺌). reason = 사유 코드
    "unplaced": [...],                                            # 위치 없음(§10.1)
    "leftovers": {"paths": n1, "texts": n2, "total", "frame"} | None,  # None = 엔진이 세지 않음(§10.5)
    "fingerprint": "<세 파일 지문>",                               # 아래
    "compared": {"by", "at", "fingerprint", "mode"} | None,       # 원본과 견준 기록
    "confirmed": {"by", "at", "fingerprint", "leftovers_seen"} | None,
    "state": "open" | "ready" | "confirmed",
}
```

**확정 = '미확인 0' + '원본과 견줌' + 사람의 누름.**

1. **미확인 0.** `unconfirmed`와 `unplaced`가 모두 비어 있고 `leftovers`가 `None`이 아니다.
2. **원본과 견줌.** '쪽 확정'을 누르면 바로 확정하지 않고 견주기 화면을 연다.
   - 도면 칸을 둘로 나눠 왼쪽 원본, 오른쪽 정리된 보기를 같은 이동·확대로 묶어 보인다. 겹치기 모드(원본 30% 겹침)로 바꿀 수 있다.
   - 원본에 남은 것을 두 칸 모두에 호박색으로 표시하고, 그 목록을 옆에 둔다. 남은 것은 하나하나 '구성요소 아님'으로 끝내지 않아도 되지만, 목록을 끝까지 넘겨 보아야(스크롤 끝 또는 N으로 마지막까지) 다음 단추가 켜진다.
   - '빠진 구성요소가 없음을 원본과 견주어 확인했다' 체크 상자를 켜면 엔진이 `compared`를 남긴다.
   - DEXPI 쪽은 원본 그림 칸 대신 DEXPI 원문 목록(클래스별 수와 대응 못 한 것)을 보인다.
3. **사람의 누름.** 견주기 화면의 '이 쪽 확정'을 누른다. 엔진이 `by`·`at`, 그때의 `fingerprint`, 그때의 원본에 남은 수(`leftovers_seen`)를 남긴다. 견준 기록과 확정 기록의 지문이 지금 지문과 같아야 한다.

`state`는 1이 아니면 `open`, 1은 되었으나 2·3이 아니면 `ready`, 셋 다면 `confirmed`다.

**지문은 세 파일이다.** 각 파일 내용의 `sha256`(없으면 `-`)을 `열쇠=값`으로 `|`로 이어 다시 `sha256`한 것이다(파일별 값은 `files`). 셋 가운데 하나라도 바뀌면 견준 기록과 확정이 함께 풀린다. 처음 안의 `크기:mtime_ns`를 내용 지문으로 바꾼 것은 Windows 파일 시각이 갱신되는 간격(약 15ms) 안에 크기가 같은 변경이 생기면 놓치기 때문이다(2026-11-14, 구현 c0e2f4c).

| 파일 | 경로(작업 루트 기준) | 바뀌는 때 |
| --- | --- | --- |
| 추출 결과 | `paths.output_root("extract")` 아래 `<이름>/extraction.json`(`data.extraction_path`) | 다시 추출 |
| 사람 수정 기록 | `data/drawing-edits/<이름>.json`(`corrections`의 저장 파일) | 값 고치기, '이대로 확인' |
| AI 후보 기록 | `data/ai-review/<이름>.json`(`ai_review.load_doc`) | 후보 추가·수락·거절 |

- **확정 기록은 이 세 파일 밖에 둔다.** `data/sheet-confirmations/<이름>.json`. 사람 수정 기록 안에 두면 확정을 쓰는 순간 지문이 바뀌어 스스로 풀린다.
- **함수의 자리.** DEXPI 내보내기도 같은 함수를 부르므로, 자리와 이름은 `dexpi-exchange.md`와 맞춘다. 이 문서의 제안은 엔진 쪽 새 파일 `hazop/extract/confirmation.py`다. 화면 코드(`hazop/shell/`)에 두지 않는다. 지금 `clean_items.py`가 만드는 `unconfirmed`는 이 함수의 답으로 바꾼다(§8 UW16).
- **DEXPI와의 관계.** DEXPI 내보내기에서 미확인을 어떻게 다루는지(구성요소 단위는 빼고 속성 단위는 그 속성만 뺌)는 `dexpi-exchange.md` §6.2가 정한다. 같은 미확인 목록(사유 코드 = 미확인 코드)을 쓴다.

### 10.9 성능

**기준 도면의 크기.** '구성요소 약 5,800개 쪽'은 총괄 작업지시서(2026-11-13)에 적힌 수다. 어느 쪽을 어떻게 센 수인지 이 문서를 쓰며 재지 않았다(사용자 작업 폴더의 추출 결과를 읽지 않음). 그래서 V4 측정은 먼저 APR1400 표본 쪽마다 `items` 수(기호 + 배관 + 독립 글자)를 세어 가장 큰 쪽과 그 수를 기록하고(CLAUDE.md 규칙 16), 그 쪽으로 잰다. 그 수가 5,800에 못 미치면 그 쪽의 `items`를 옆으로 이어 붙여 5,800개 합성 쪽도 함께 잰다.

| 할 일 | 방법 | 목표(10회 중앙값, §5.4와 같은 PC) |
| --- | --- | --- |
| 정리된 바탕 처음 그리기 | (가) 엔진이 SVG 문자열을 만들어 캐시(`<work>/cache/clean/<graph_id>-<지문>.svg`)하고 `<image>`로 넣음, 또는 (나) 웹이 `symbols.json`으로 요소를 만듦(구현 b8135bc의 방식) | 5,800개 쪽 1.5초 이하. (나)로 넘지 못하면 (가)로 바꾼다 |

| 표시 색 바꾸기 | 표시 걸린 객체만 다시 그린다 | 표시 200개 100ms 이하 |
| 다음 미확인(N) | 엔진이 `unconfirmed`를 도면 안 순서로 준다 | 50ms 이하 |

### 10.11 정돈 규칙

정리된 보기는 읽은 좌표를 그대로 그리지 않고 아래 규칙으로 정돈한 좌표(`layout`)로 그린다. 정돈은 엔진(`hazop/shell/clean_layout.py`)이 한 번 하고, 화면과 내보내기가 같은 결과를 쓴다. 규칙은 위에서부터 먼저 지킨다. 아래 규칙이 위 규칙과 부딪치면 위 규칙을 지키고 아래 규칙의 어긋남을 `layout_lint`로 센다.

| 순서 | 규칙 | 하는 일 | 못 지키면 |
| --- | --- | --- | --- |
| **0** | **이어짐은 바꾸지 않는다** | 이어지지 않은 것을 잇지 않고, 이어진 것을 끊지 않는다. 그림에서 배관 끝이 닿는 것(다른 기호 안, 같은 기호를 잇지 않은 다른 배관 위)이 정돈 전에 없던 것이면 안 된다. 열린 끝과 미확인 기호에 붙은 끝은 옮기지 않는다. 정돈이 기호 겹침·기호를 지나는 배관·같은 줄 배관 겹침을 정돈 전보다 늘려도 안 된다 | 그래프로 이어진 덩이(기호·배관 한 묶음) 단위로 정돈을 버리고 읽은 좌표로 그린다. 되돌린 덩이 때문에 새로 생긴 것도 없어질 때까지 되풀이한다. `topology_changed`(늘 0), 버린 덩이 수 `reverted` |
| 1 | 허용 범위 | 축 맞춤은 6 단위, 겹침 풀기는 읽은 자리에서 24 단위, 배관 끝을 연결점으로 옮기기는 24 단위(기호 안에 그려진 끝은 예외), 기호를 붙은 공정 배관 축에 맞추기는 48 단위까지(§8 UW21) | 옮기지 않는다. `moved_too_far` |
| 2 | 직각 | 수평·수직에서 10° 안인 배관 선분은 정확히 수평·수직으로 편다. 그보다 기운 선분은 그대로 두고 센다 | `off_axis` |
| 3 | 오와 열 | 배관 꼭짓점의 x·y끼리, 기호 중심의 x·y끼리 따로 모아, 폭 6 단위 안의 값은 하나로 맞춘다. 묶음은 첫 값에서 6 단위를 넘지 않는다(이어 붙지 않는다). 맞출 값은 옮기지 않는 끝(열린 끝·미확인 기호에 붙은 끝)의 값, 없으면 그 묶음에서 가장 긴 배관 선분의 값, 없으면 평균이다. 붙은 배관이 정하는 축(세로 배관이 붙은 기호의 x, 가로 배관의 y)은 기호끼리 맞추지 않고 규칙 4가 정한다. 배관과 기호를 따로 묶는 것은 곁을 지나는 배관 축으로 기호가 끌려가 그 배관 위에 앉지 않게 하려는 것이다 | `near_miss_align`(후속, 아직 세지 않음) |
| 4 | 인라인 기기는 배관 축의 정중앙 | 두 구멍 기호(밸브·오리피스·축소관·펌프 등)는 연결점을 그 배관 축 위에 둔다. 들어오는 배관과 나가는 배관이 한 축이면 그 축에, 꺾여 있으면 각각의 축이 만나는 점에 둔다. 기호 자리는 공정 배관이 정한다. 신호선(계장·전기)은 공정 배관이 정하지 않은 축만 정하고, 제어밸브·전동밸브의 신호선은 구동부 연결점(`actuator`)에 붙는다 | `inline_off_center`(축에서 0.5 단위 넘게 벗어남) |
| 5 | 같은 `kind`는 같은 크기 | `keep` 기호는 기호 목록의 표준 크기(`manifest.json`의 `size`, 도면 단위)로 그린다. 읽은 상자 크기는 쓰지 않는다. `stretch` 설비는 읽은 크기를 2 단위 격자로 반올림 | `size_mismatch` |
| 6 | 배관 끝은 기호 연결점에 정확히 | 그래프에서 기호에 이어진 배관 끝(`status: connected`, `node` = 그 기호)은 그 기호의 연결점으로 옮긴다(규칙 1 안에서). 어느 연결점인지는 정돈 전에 읽은 그림에서 한 번 정한다. 끝이 닿던 연결점, 끝이 기호 안에 그려졌으면(drawio 가운데 연결) 배관이 들어오는 쪽 연결점이고, 한 기호의 끝들은 연결점이 모자라지 않는 한 서로 다른 연결점을 받는다. 정돈하며 기호가 움직여도 가까운 쪽으로 바꿔 고르지 않는다. 연결점이 없는 쪽에서 들어온 배관(예: 토출이 흡입보다 높게 그려진 펌프)과 `stretch` 설비는 배관이 오던 축 위에서 그려진 겉모양에 닿게 한다. 옮긴 끝의 마지막 선분은 규칙 2를 다시 지킨다(필요하면 꺾임점 하나를 더한다). §10.2의 '짧은 선으로 잇기'는 정돈한 뒤에도 남은 틈에만 쓴다 | `port_miss`(이어진 끝이 그 연결점이나 겉모양에서 0.5 단위 넘게 떨어짐, 거리 상한 없이 센다), 틈이 8 단위를 넘으면 `port_gap` 표시(§10.4, 쪽 확정 조건에는 들지 않음) |
| 7 | 겹침 없음 | 기호끼리 1 단위 넘게 겹치지 않는다(오각형끼리, 미확인 기호와도). 배관은 자기 연결점이 아닌 기호를 지나지 않는다. 같은 기호를 잇지 않는 두 배관 선분이 같은 줄에서 겹치지 않는다. 풀려면 더 작은 쪽을 규칙 1의 24 단위 안에서 옮긴다(미확인 기호는 움직이지 않는 장애물). 4 단위 간격과 평행 6 단위 띄움은 세지 않는다: P&ID는 캡·플랜지처럼 맞붙여 그리는 기호와 나란한 배관이 흔해, 세면 정상인 그림까지 어긋남으로 나온다 | 옮기지 않고 그대로 그린다. 도구 막대에 '겹침 n' 칩, 누르면 그 자리로. `symbol_overlap`·`pipe_through_symbol`·`pipe_overlap` |
| 8 | 엇갈림은 건너뜀으로 | 이어지지 않은 두 배관이 엇갈리면 위계가 낮은 선이 반원(지름 8px)으로 넘는다(신호 < 계측 < 보조 공정 < 공정, 같으면 세로 선이 넘음, §8 UW22). 분기점 점은 실제로 이어진 곳에만 | `crossing_without_hop` |
| 9 | 글자 자리 | 글자 하나마다 후보 자리(기호 위·아래·오른쪽·왼쪽·오른쪽 위·왼쪽 위, 배관 번호는 선분 양옆)를 정해진 순서로 보고, 기호·배관 선·다른 글자와 겹치지 않는 첫 자리에 둔다. 자리를 먼저 잡는 순서는 설비 → 밸브 → 계기 → 배관 번호 → 독립 글자다. 글자 뒤에는 바탕색 테두리 3px. 빈 자리가 없으면 그 확대 값에서는 숨기고, 더 확대하면 다시 본다. 호박색 '태그 없음'·미확인 글자는 숨기지 않는다 | `label_overlap`, `label_hidden` |
| 10 | 흐름 방향이 보임 | 흐름이 정해진 배관은 화살촉 규칙(§10.2)대로 적어도 하나를 그린다. 선분이 모두 40 단위 미만이면 가장 긴 선분 가운데에 하나 | `arrow_missing`, `arrow_misplaced`(기호·분기점 12 단위 안, 또는 흐름과 반대 방향) |

**정돈 결과의 꼴**(`api/clean/<graph_id>`에 더함)

```json
{"layout": {"version": 1,
            "symbols": {"<id>": {"center": [x, y], "size": [w, h], "rot": 0, "moved": 3.5}},
            "pipes":   {"<id>": {"points": [[x, y], …], "hops": [[x, y], …], "moved": 2.0}},
            "labels":  null}}
```

글자 자리는 확대 값에 따라 달라지므로 웹(`layoutLabels`)이 정한다. 엔진의 정돈은 기호·배관만 다룬다.

**정돈 검사 `layout_lint`**

`hazop/shell/clean_layout.py`의 `layout_lint`가 정돈 결과 하나를 받아 항목별 수를 돌려준다(정돈과 같은 판정 함수를 써서 둘이 어긋나지 않게 한 파일에 둔다). 글자 항목은 웹의 `labelLint`가 같은 꼴로 돌려준다(후속). `scripts/check_layout.py`가 SNP 6장과 APR1400 표본을 새로 읽어 쪽마다 보고하고 판정한다.

| 항목 | 세는 것 | 잴 때 |
| --- | --- | --- |
| `topology_changed` | 정돈 전후 연결 집합이 다른 대상 | 늘 |
| `moved_too_far` | 허용 범위(규칙 1)를 넘은 기호·꺾임점, 움직인 열린 끝·미확인 기호 끝 | 늘 |
| `off_axis` | 수평·수직이 아닌 배관 선분(0.5° 초과) | 늘 |
| `near_miss_align` | 0 초과 6 단위 이하로 어긋난 기호 중심·선분 쌍(후속: 아직 세지 않음) | — |
| `inline_off_center` | 배관 축에서 0.5 단위 넘게 벗어난 두 구멍 기호 | 늘 |
| `size_mismatch` | 같은 `kind`인데 크기가 다른 `keep` 기호 | 늘 |

**원본 보기와의 관계.** 원본 보기는 정돈하지 않는다(원본 그림 위의 표시는 읽은 좌표에 그린다). 그래서 두 보기를 바꾸면 기호가 정돈한 만큼(최대 6 단위, 겹침 풀기 24 단위) 움직여 보일 수 있다. 정리된 보기에서 고른 것·표시는 정돈한 좌표에 그린다. 엔진과 채팅이 다루는 좌표(경로, 구간, 원본 조각)는 늘 읽은 좌표이고, 정돈 좌표는 그리기에만 쓴다.
