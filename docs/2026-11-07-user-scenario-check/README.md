# 사용자 시나리오 검증

실제 HAZOP 창을 사용자처럼 키보드·마우스로 조작해, 시나리오마다 조작 수·예상 숙련자 시간·응답 시간·포커스·화면 점검 결과를 표 한 장으로 낸다. 앱 코드는 바꾸지 않는다.

## 실행

```
%USERPROFILE%\.hazop\venv-py312\Scripts\python.exe scripts/check_user_scenarios.py --out <결과 폴더>
```

| 옵션 | 뜻 |
| --- | --- |
| `--out` | 결과 폴더. 기본 `출력/사용자검증` |
| `--only S1,S3` | 고른 시나리오만 실행 |
| `--keep-temp` | 임시 작업 루트를 지우지 않음(결과 파일을 직접 볼 때) |
| `--focus-wait 120` | Windows가 창 전환을 막을 때 사람이 창을 클릭하길 기다리는 초 |

종료 코드는 0(모두 통과), 1(실패 시나리오 있음), 2(준비·실행 오류)이다. 결과는 `<out>/report.html`(표), `<out>/results.json`(원자료), `<out>/shots/*.png`(단계별 스크린샷)로 나온다.

## 실행 조건

- Windows 전용이다. 설치할 것은 없다. PowerShell UI Automation, Win32 SendInput, venv에 이미 있는 Pillow만 쓴다.
- **실행하는 동안 아무도 PC를 쓰지 않아야 한다.** 다른 사람이나 다른 세션이 창을 띄우거나 키보드를 쓰면 입력이 엉킨다. 사용자가 PC 앞에 있으면 Windows가 창 전환을 막는다. 그때는 작업 표시줄에서 깜박이는 'HAZOP 분석 도구'를 한 번 클릭하고 끝날 때까지 손을 뗀다.
- 입력을 보내기 직전마다 이 실행이 띄운 창(과 그 자식 프로세스)이 맨 앞인지 확인한다. 아니면 입력을 보내지 않고 시나리오를 중단한다. 다른 HAZOP 창에는 입력하지 않는다.
- CDP 포트 9339를 쓴다. 이미 쓰이고 있으면 실행하지 않는다.
- 작업 루트는 `%TEMP%\hazop-user-check-*`이다. 샘플 SNP-M-102(`출력/` 사본, 검토구간 확정, 가짜 AI 결과)와 `참고자료/` 사본을 둔다. `자료저장소/`·`데이터/`에는 쓰지 않는다. `출력/추출·그래프/SNP-M-102`와 `출력/지식그래프`가 있어야 한다(`scripts/run_samples.py`로 만든다).
- 실행 대상은 이 저장소의 작업 트리 그대로다. 다른 세션이 고치는 중이면 그 상태를 시험한다. 커밋 하나를 시험하려면 `git worktree add --detach <폴더> <커밋>`으로 따로 꺼내고, 위 `출력/` 폴더와 이 스크립트 두 개를 복사해 그 폴더에서 실행한다.

## 시나리오

| ID | 내용 | 조작 |
| --- | --- | --- |
| S1 | 키보드만으로 ①→⑤ 이동, Alt+← 뒤로, F1 단축키 표 | 키보드 |
| S2 | Ctrl+P → `@PZR` → Enter → 관련 항목 패널 → 다른 단계 항목 더블클릭 | 키보드+마우스 |
| S3 | ⑤ J로 칸 열기 → A 승인 → R 기각 → Ctrl+Z. 저장 파일의 상태 수로 확인 | 키보드(J가 안 들으면 클릭으로 이어 감) |
| S4 | 한글 입력 상태와 영문 상태에서 A 승인 비교 | 키보드+마우스 |
| S5 | ① 파일 선택 대화상자 → SNP-M-201 drawio 등록 → 추출 → ② 도면 확인(CDP) | 마우스+경로 입력 |
| S6 | ④ 팔레트 `>확정 해제` → 두 구간 체크(Space) → M 병합 → Ctrl+Enter 확정 | 키보드+마우스 |

| S7 | ⑤ 팔레트 `>실패 칸 다시 실행`(가짜 AI, 호출마다 4초) 뒤 손대지 않고 진행 표시를 1초마다 기록. 몇 번째/전체·무엇을 하는지·경과·남은 시간·비용·호출마다 저장되는지 | 키보드 |
| S8 | 같은 실행 중 탐색기 Sx 클릭, Ctrl+P, ④ 갔다 ⑤로 돌아오기. 의도하지 않은 화면 이동·진행 표시 사라짐·결과 줄어듦 | 키보드+마우스 |
| S9 | ④ 구간 두 개를 차례로 클릭. CDP로 도면 요소 중 강조(`selected` 등 클래스)·흐리게(불투명도 0.5 미만) 수를 잰다 | 마우스 |
| S10 | ⑤ 탐색기 묶음 이름과 수. 도면이 열렸는데 '자료' 0인지, 결과로 가는 묶음이 있는지 | 관찰만 |

실행 순서는 S1~S4, S7~S10, S5, S6이다. S5·S6은 저장 자료를 바꾸므로 마지막에 둔다. AI는 늘 가짜 클라이언트(`scripts/shoot_results.py`의 FakeClient에 지연을 더한 것)를 쓴다. 실제 API를 부르지 않아 비용이 없다. 시험용 앱은 `check_user_scenarios.py --_app`이 `run_app.py`와 같은 창을 띄우고 이 클라이언트만 바꿔 넣는다.

## 측정값

| 항목 | 방법 |
| --- | --- |
| 클릭·키 입력 수 | 보낸 SendInput 이벤트를 센다. Ctrl+P는 키 2개 |
| 화면 전환 | 머리말 위치 글자(UIA `header.where`)가 바뀐 횟수 |
| KLM 예상 시간 | 아래 연산자 합. 의도 단계마다 M 하나, 키보드↔마우스가 바뀔 때 H |
| 응답 시간 | 입력 직후부터 기대 상태(UIA 글자·저장 파일·CDP DOM)가 보일 때까지. 관찰 주기가 UIA 호출 1회(약 0.05~0.3초)라 그만큼 길게 잰다 |
| 키보드만 | 그 시나리오의 클릭 수가 0이면 예 |
| 포커스 이탈 | 입력 뒤 UIA 초점 요소가 이 앱 프로세스 밖이거나 없으면 기록 |
| 접근성 이름 | UIA에서 이름 없는 Button·Edit·ComboBox 등. 웹뷰는 이름 없는 button·input·링크 |
| 잘림·겹침·가로 스크롤 | Qt는 창 좌우 끝을 넘는 요소(스크롤 영역 항목 제외). 웹뷰는 CDP로 `scrollWidth > clientWidth`, 글자가 넘쳐 숨겨진 요소, 서로 겹친 글자 요소(svg 제외) |

KLM 연산자 값(초)은 Card, Moran & Newell(1980), "The Keystroke-Level Model for User Performance Time with Interactive Systems", *Communications of the ACM* 23(7):396-410의 표 1을 따른다. K 0.28(보통 숙련 타자), P 1.10, B 0.10(클릭은 BB), H 0.40, M 1.35. [일반지식] 값은 논문 기억에 기댄 것이라 쓰기 전에 원문 표 1과 대조한다.

## 한계

- Qt 위젯 글자가 말줄임(…)으로 잘렸는지는 UIA로 알 수 없다. 스크린샷으로 본다.
- 한/영 전환은 `WM_IME_CONTROL`(IMC_SETCONVERSIONMODE)을 창의 기본 IME 창에 보내고, 안 바뀌면 한/영 키(스캔 코드 0xF2)를 보낸다. 2026-11-07 실행 5회 중 1회만 한글 상태가 됐다. 한글 상태가 안 되면 S4는 실패가 아니라 "판정 불가"로 남는다.
- 포커스 이탈 값은 참고만 한다. 맨 앞 창이 이 앱인데도 UIA `FocusedElement`가 다른 프로세스(Claude 창, 파일 대화상자의 셸 창) 요소를 돌려준 적이 있다.
- S2는 관련 항목 패널에 다른 단계로 가는 항목이 화면에 보이지 않으면 이동을 판정하지 않는다("판정 불가").
- 웹뷰 "글자 겹침"은 후보다. 스크린샷으로 실제 겹침인지 확인한다.
- ② PDF 미확인 확정 시나리오는 아직 없다(웹뷰 편집 조작이 필요).
