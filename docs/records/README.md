# 메모리 운영

[프로젝트 소개](../../README.md)

대화에서 정한 결정과 미구현 작업을 이 폴더에 기록합니다. 장기적인 설계 설명은 README와 기획서에 두고, 이 폴더에는 결정의 이력과 남은 작업만 둡니다.

| 파일 | 내용 | 운영 규칙 |
| --- | --- | --- |
| [decision-log.md](decision-log.md) | 날짜·결정 내용·결정 주체·근거와 관련 문서 | 삭제하지 않고 누적. 결정이 바뀌면 새 항목을 추가하고 이전 항목에 대체 사실을 표시 |
| [backlog.md](backlog.md) | 구현·확인·결정이 남은 작업 | 구현과 검증이 확인되면 해당 항목 삭제. 여러 부분으로 된 항목은 완료된 부분만 삭제 |

- 작업을 시작하거나 이어갈 때 두 파일을 먼저 확인합니다.
- 기획서 작성만으로 구현 완료로 보지 않습니다.
- 결정 주체는 "사용자"(사용자가 직접 정함), "권고 승인"(Claude의 권고를 사용자가 승인), "제안"(아직 승인되지 않음)으로 구분합니다.

## 결정 번호

[결정 로그](decision-log.md)의 첫 열 `DEC-nnnn`이 결정의 고정 번호입니다. 한 번 붙인 번호는 바꾸지 않고, 줄을 옮기거나 지워도 다시 쓰지 않습니다.

- 2026-11-10까지의 결정은 번호를 매긴 날의 파일 줄 번호를 그대로 받았습니다. 그래서 `DEC-0009`에서 시작하고 `DEC-0167`은 비어 있습니다. 예전 문서의 '결정로그 n행'은 `DEC-n`입니다(예: '결정로그 237행'은 `DEC-0237`).
- 새 결정은 표 맨 아래에 마지막 번호 다음 번호로 추가합니다.
- 결정을 가리킬 때는 줄 번호 대신 `DEC-nnnn`을 적습니다.

## ID 접두 표

작업 단위나 검사 항목에 새 ID를 붙이려면 두 글자 이상의 영어 접두를 먼저 이 표에 올립니다([이름 규칙](../governance/naming-rules/README.md) §4.8).

| 접두 | 뜻 | 쓰는 곳 |
| --- | --- | --- |
| `DEC` | 결정 번호 | `docs/records/decision-log.md`의 첫 열 |
| `HZ` | 문서번호(`HZ-<분류>-<번호>`) | 문서 머리의 `doc_id`. 분류 약어는 이름 규칙 §4.6 |

한 글자 접두 `S`, `U`, `D`, `W`, `N`, `P`, `C`, `A`~`E`, `T`는 이미 여러 뜻으로 쓰였습니다(이름 규칙 §1.2의 16번). 지난 기록은 그대로 두고, 새 뜻으로 다시 쓰지 않습니다.
