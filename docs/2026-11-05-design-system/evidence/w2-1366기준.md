# W2 — Windows 1366 검사 기준과 측정 결과

> 측정 일시: 2026-11-05 · 대상: `chore/track-workspaces` HEAD `b29e5f7` + 작업 트리의 새 파일 `scripts/check_design.py`·`tests/test_design.py`(앱 코드 변경 없음) · 측정: hazop-developer
>
> 근거 결정: [D1](../decisions.md) — 1366 판정은 실제 Windows 플랫폼(100%·96 DPI) 값을 쓰고, offscreen은 회귀 감시용으로만 쓴다.

## 1. 검사 방법

- 명령: `python scripts/check_design.py --platform windows`(판정), `--platform offscreen`(회귀 감시), `--platform windows --scale 1.25`(참고치, `QT_SCALE_FACTOR`).
- 작업·저장 루트(`HAZOP_WORK_ROOT`·`HAZOP_STORE_ROOT`)와 설정 파일은 임시 폴더를 쓴다. 분석 실행은 `tests/run_fixture.py`의 고정 응답 실행이다.
- 상태: A 데이터 없음 → B 샘플 분석 실행 열림 → C 검토 기록 있음(⑤ d12 저장 뒤 새 창에서 다시 열기). 각 상태에서 ①~⑤를 한 번씩 먼저 방문(⑤는 후보 선택)하고 화면별로 잰다. 쌓인 화면의 최소 폭은 모든 화면의 최대값이고 ⑤는 첫 방문 때 문구를 채우므로, 먼저 방문해야 최악값이 나온다.
- 측정값: 창 `minimumSizeHint` 폭·높이, 화면·헤더·상태줄 최소 폭, 최소 폭에 기여하는 가장 넓은 말단 위젯 상위 5개(클래스·objectName·문구 앞 40자·폭). 숨긴 위젯과 스크롤 영역 안 내용은 빼고, 쌓인 화면의 숨은 페이지는 넣는다.
- 판정: windows·배율 100%(DPR 1.0, 96 DPI)에서 모든 측정이 폭 ≤ 1366, 높이 ≤ 768이면 종료 코드 0, 넘으면 1, 기준 환경이 아니면 2. `--scale`을 주면 물리 크기(논리 × DPR)를 보여주기만 하고 0이다. offscreen은 판정하지 않는다.
- 결과 JSON: `출력/디자인검사/design-<platform>[-s<배율>].json`(git 제외).

### 2.1 offscreen 기준선(회귀 감시)

위 표의 offscreen 행이 기준선이다. 다음 작업(W3 등)에서 offscreen으로 다시 재서 창 최소 폭이 1585(상태 B·C)·1201(상태 A)보다, 높이가 631보다 커지면 회귀로 본다. 이전 결과 JSON을 `--baseline`으로 주면 늘어난 항목을 경고로 출력한다(종료 코드는 0).

기준선을 저장소의 JSON 파일로 두고 검사를 실패시키지 않은 이유:
- offscreen 폭은 그 기계에서 대체되는 글꼴에 따라 달라진다. 맑은 고딕이 잡히지 않아 라틴·숫자 폭이 windows의 약 1.9배(572 vs 307)로 나온다. 다른 기계나 다른 PySide6 버전에서는 같은 코드라도 값이 달라질 수 있어 고정 수치로 실패시키면 거짓 경보가 난다 [추론].
- 판정 기준은 D1에 따라 windows 값 하나로 둔다. offscreen 값이 실패 근거가 되면 두 기준이 생긴다.
- 테스트(`tests/test_design.py`)는 수치 대신 측정·탐색 로직(가장 넓은 위젯이 ④ 칩·⑤ 실행 라벨과 진행 칩인지)을 검사한다.

### 2.2 배율 참고치 (`QT_SCALE_FACTOR`, windows 플랫폼)

| 배율 | DPR | 논리 화면 | 상태 A 창 최소(논리 → 물리) | 상태 B·C 창 최소(논리 → 물리) | 물리 1366×768 안에 듦 |
|---|---|---|---|---|---|
| 100% | 1.0 | 1920×1080 | 1053×673 → 1053×673 | 1282×673 → 1282×673 | 예 |
| 125% | 1.25 | 1536×864 | 1053×678 → 1317×848 | 1284×678 → 1605×848 | 아니오(높이 A·B·C, 폭 B·C) |
| 150% | 1.5 | 1280×720 | 1053×678 → 1580×1017 | 1284×678 → 1926×1017 | 아니오 |

- 논리 크기는 배율과 거의 무관하다(±5px, 글꼴 반올림). 따라서 물리 1366×768 화면에서 125%를 쓰면 논리 폭이 약 1093, 높이 약 614가 되어 데이터 없는 상태부터 높이가 넘친다.
- [추론] `QT_SCALE_FACTOR`는 Qt 쪽 배율 흉내다. 실제 Windows 표시 배율(시스템 DPI 변경)과 글꼴 힌팅·반올림이 다를 수 있다. 실제 125%·150% 장비에서 재지 않았다([미확인]).

## 3. 남는 위험·미확인

- 샘플 실행 ID·구간 이름 길이로만 쟀다. 더 긴 실제 자료에서는 ⑤ 실행 라벨이 넓어진다(W1 §1.5와 같음).
- 이전 실행의 검토를 가져오는 상태(`PriorImport`)는 만들지 않았다.
- 판정은 이 기계(1920×1080, 100%)에서 했다. 다른 Windows 기계의 글꼴 버전에 따른 차이는 확인하지 않았다.
