### 1.1 축약 규칙

1. 대상은 도구줄처럼 한 줄에 놓여 최소 폭을 정하던 칩·라벨이다. 오독을 막는 단서 문구(결과 검증 "보류 항목이 없다는 뜻이 아님")와 폼 안 설명 라벨은 줄이지 않고 줄바꿈한다(글자를 숨기지 않음).
2. 줄임표 라벨의 문구는 바꾸지 않는다. `text()`·접근성 이름은 늘 전체 문구, 툴팁은 줄여 그렸을 때만 전체 문구다. 검사는 이 규칙을 어기면 실패(rc 1)로 본다.
3. 줄임은 자리가 모자랄 때만 일어난다. 지원 화면의 작업 영역 크기(1366×689, 1536×785)로 맞춘 창에서 상태 A~E 모두 줄여 그린 라벨이 0개다(2절 "줄임" 열). 창을 최소 폭(1062)까지 줄이면 ⑤ 실행 라벨 등이 줄어든다.
4. 줄이는 위치: 앞부분이 뜻을 정하는 칩(진행 집계)은 뒤를 줄인다(`ElideRight`). 앞뒤가 모두 필요한 라벨(실행 ID와 "(읽기 전용)", 지식 버전)은 가운데를 줄인다(`ElideMiddle`).
5. 최소로 보이는 글자 수: 진행 칩 14자("미검토 N · 검토 중 N"), 실행 라벨 20자, 지식 버전 칩 10자.

### 2.2 작업 영역 수치의 근거

- 제목 표시줄 31: 이 PC에서 `GetSystemMetricsForDpi`로 읽은 값. 96 DPI: `SM_CYCAPTION` 23 + `SM_CYSIZEFRAME` 4 + `SM_CXPADDEDBORDER` 4 = 31. 120 DPI: 29 + 4 + 5 = 38 물리 px = 30.4 논리 px → 31로 올림.
- 작업 표시줄 48: 이 PC(1920×1080, 100%)의 `SM_CYFULLSCREEN` 1009 = 1080 − 48(작업 표시줄) − 23(캡션)에서 확인. [일반지식] Windows 11 기본 작업 표시줄 높이는 48 논리 px이다.
- 폭은 화면 폭 그대로(최대화 창, 작업 표시줄 아래쪽 가정). 좌우 크기 틀은 Windows 10·11에서 보이지 않는 테두리라 뺐다 [추론].

## 3. 남는 위험·미확인

- 125%는 `QT_SCALE_FACTOR=1.25` 흉내다. 실제 Windows 표시 배율 125% 장비에서는 재지 않았다([미확인]). 논리 크기가 배율과 거의 무관하다는 W2 관찰(±5px)에 기댄다.
- 작업 표시줄을 옆에 두거나 크기를 바꾼 환경, 작업 표시줄 자동 숨김, 1366×768 실제 장비는 확인하지 않았다.
- 창 최소 크기는 두 배율 모두 창을 1366×768로 맞춘 뒤 잰다(최소 크기는 창 크기와 무관). 폼·줄임은 작업 영역 크기에서도 잰다.
- 헤더(1062)가 이제 창 최소 폭을 정한다. 줄이려면 `main_window.py` 범위 결정이 필요하다(지금은 1366 안이라 필요 없음).
- 이전 실행 검토 가져오기 상태(`PriorImport`)는 이번에도 만들지 않았다.
- 줄임 그림 테스트는 offscreen이 글자를 모두 같은 네모로 그려 문구 차이가 그림에 안 나오므로, 그 테스트 동안만 `%WINDIR%\Fonts\malgun.ttf`를 등록해 쓴다(없으면 건너뜀, 끝나면 등록 해제).
