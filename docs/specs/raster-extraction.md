# 스캔 도면 읽기

[INTENT §2·§3.2·§6](../../INTENT.md) · [정보 추출](extraction.md)(HZ-PLN-04) · [자료 등록](registration.md)(HZ-PLN-03) · 조사 보고서 [P&ID 인식 방법 조사](../units/2026-11-13-drawing-knowledge/evidence/pid-recognition-survey.md) §스캔 · 앞선 구현 기록 [W4 래스터](../units/2026-11-05-input-adapter/evidence/w4-raster.md)·[W5 열화 시험](../units/2026-11-05-input-adapter/evidence/w5-degradation.md) · 구현 코드 `hazop/extract/adapters/raster*.py`

- 작성일 2026-11-14, rev 1 2026-11-14(첫 구현 뒤 OCR 두 배율 읽기와 첫 측정값을 반영), rev 2 2026-11-14(앱 등록·추출 연결, 묶음 크기 측정), rev 3 2026-11-14(검토 반영: 하위 프로세스 경계, 크기 상한, 기울기 되돌림, 스캔 근거), rev 4 2026-11-14(개선 규칙 추가, 표본 밖 합성 쪽). 상태는 **규격 초안**입니다. 완료 목록 2의 A19를 맡은 세션이 씁니다.
- 이 문서는 스캔 PDF와 PNG·JPG 도면을 읽는 규칙을 정합니다. 벡터 PDF 읽기 규칙은 [정보 추출](extraction.md)에 있고, 이 문서는 그 뒤 단계를 함께 씁니다.
- 수치에는 어느 실행에서 잰 값인지 붙입니다. 아직 재지 않은 값은 '추정'이라고 적습니다.

## 1. 목적과 범위

INTENT §2는 스캔 이미지(스캔 PDF, PNG·JPG) 도면도 받되, 벡터 PDF 추출 품질을 먼저 올린 뒤에 한다고 정했습니다. 벡터 품질 개선은 따로 계속하고, 이 문서는 스캔 단계의 규격과 첫 구현의 범위를 정합니다.

- **원칙**: 읽기는 결정적 스크립트가 먼저 합니다. AI는 후보만 냅니다. 읽지 못한 것은 미확인으로 남기고 지어내지 않습니다(INTENT §3.2).
- **첫 구현의 목표**: 가상 도면(SNP 6장)을 그림으로 바꾼 입력에서 등록 판별 → 추출 → 그래프까지 끊기지 않고 돌고, 벡터 대비 얼마나 떨어지는지를 잽니다. APR1400 표본은 값을 재서 적기만 합니다. 네 항목 95%는 이 단계의 목표가 아닙니다.
- **범위 밖(후속)**: 학습 모델 검출기, TIFF·다중 쪽 이미지, 벡터와 스캔이 섞인 PDF의 그림 부분 읽기, 손글씨 고침 표시.

## 2. 입력 판별

등록과 추출은 같은 판별 함수(`raster_scan.classify_pdf_page`, 이미지 파일은 `fileinfo.detect_format`)를 씁니다.

| 입력 | 판별 | 처리 |
| --- | --- | --- |
| 벡터 PDF | 쪽에 선·곡선 경로나 글자층이 있다 | 지금처럼 `pdf_vector` |
| 스캔 PDF | 글자층 글자가 없고, 경로가 없으며(테두리용 몇 개는 봐줌, §2.1), 그림 객체 하나가 쪽 넓이의 80% 이상을 덮는다 | 쪽을 그림으로 바꿔 래스터 읽기 |
| 섞인 PDF | 벡터 내용과 쪽 넓이 30% 이상의 그림이 함께 있다 | 벡터로 읽고, 그림 부분은 미확인 `embedded_raster`로 남긴다(후속) |
| PNG·JPG | 파일 첫 바이트(`\x89PNG`, `\xff\xd8\xff`) | 래스터 읽기 |
| 빈 PDF | 경로·글자·그림이 모두 없다 | 지금처럼 `no_vector_content` blocker |

### 2.1 스캔 PDF 판별 문턱

- 경로 객체 10개 이하, 글자층 글자 0개, 가장 큰 그림 객체가 쪽 넓이의 80% 이상. 스캐너가 붙이는 여백 선이나 쪽 번호 몇 개를 봐주려고 경로는 0이 아니라 10을 문턱으로 둡니다(추정, 실제 스캔 PDF 표본으로 다시 정함).
- OCR을 거쳐 글자층을 덧입힌 스캔 PDF(검색 가능한 PDF)는 글자층이 있어도 경로가 거의 없고 그림이 쪽을 덮습니다. 이 경우도 스캔으로 보고, 덧입힌 글자층은 쓰지 않습니다. 덧입힌 글자가 맞는지 알 수 없어서입니다. 판별 결과에 `text_layer: true`로 남깁니다.

### 2.2 해상도

해상도는 '1pt당 픽셀 수'(px/pt)로 잽니다. dpi = px/pt × 72입니다.

- 스캔 PDF: 그림 객체의 픽셀 크기 ÷ 그 객체가 차지한 쪽 크기(pt).
- PNG·JPG: 파일에 적힌 dpi(PNG `pHYs`, JPEG JFIF)를 씁니다. 없으면 그림 폭을 A3 가로(1190.55pt)로 보는 지금 가정을 씁니다. 이 경우 판별 결과에 `dpi_source: "assumed_a3"`로 남기고 미확인 `scale_assumed`를 답니다.

| 등급 | 기준 | 안내 |
| --- | --- | --- |
| 권장 | 300dpi 이상 | 안내 없음 |
| 낮음 | 200dpi 이상 300dpi 미만 | "해상도가 낮아(N dpi) 작은 글자를 놓칠 수 있습니다. 300dpi 이상으로 다시 스캔하면 낫습니다." |
| 너무 낮음 | 200dpi 미만 | "해상도가 너무 낮아(N dpi) 선과 기호가 끊겨 읽기 결과가 크게 떨어집니다. 300dpi 이상으로 다시 스캔해 주세요." 등록은 막지 않습니다 |

근거: W5 열화 시험에서 SNP PNG(약 198dpi)는 품질 하한을 넘었지만, 75%로 줄인 그림(약 149dpi)은 6장 모두 하한 아래였습니다([W5](../units/2026-11-05-input-adapter/evidence/w5-degradation.md) §2, 2026-11-06 측정). 200dpi 경계는 이 두 점 사이의 값이라 추정입니다.

- 600dpi를 넘는 입력은 400dpi로 줄여 읽습니다. 처리 시간과 메모리 때문이며(5100×3300 쪽이 300dpi에서 약 17MP), 지금 문턱으로는 400dpi 위에서 얻는 것이 없다고 봅니다(추정).
- 파일 상한은 100MB(W4 그대로)이고, 파일 전체를 읽기 전에 크기로 봅니다. 픽셀 상한은 80MP입니다(rev 3. A1 도면을 300dpi로 스캔한 쪽 약 70MP를 받으려고 W4의 50MP에서 올림).
- 스캔 PDF는 쪽을 그리기 전에 쪽 크기와 dpi로 픽셀 수를 셈합니다. 80MP를 넘으면 넘지 않는 dpi로 낮춰 그리고, 그 값이 150dpi보다 낮으면 그 쪽을 읽지 않습니다(`raster_scan.render_dpi`). 그림 크기를 크게 적은 작은 PDF가 수 GB를 그리지 않게 하려는 것입니다.

## 3. 처리 순서

```
입력 판별 → 쪽 그림 얻기 → 기울기 보정 → 잉크 분리 → 글자(OCR, 타일) → 채운 도형·기호 몸체 → 선 벡터화
  → 벡터 원소로 바꿔 pdf_vector의 묶기·종류·이름표·연결 단계로 넘김 → 좌표 표기 바꿈 → 미확인 정리
```

1. **쪽 그림 얻기.** 스캔 PDF는 `pypdfium2`(이미 배포본에 있는 PDF 의존성)로 쪽을 회색조로 그립니다. 그리는 해상도는 §2.2에서 잰 원래 해상도(400dpi 상한)로 해서 다시 표본화하지 않게 합니다. PNG·JPG는 그대로 읽습니다.
2. **기울기 보정.** 긴 가로·세로 선의 각도로 기울기를 잽니다. 0.05°~5° 사이이면 그 각만큼 돌려 바로잡고, 5°를 넘으면 돌리지 않고 미확인 `skew_too_large`를 답니다. 근거: W5에서 0.5° 회전만으로도 관계 F1 평균이 0.749에서 0.609로 떨어졌습니다(2026-11-06 측정). rev 3부터 바로잡은 그림에서 읽은 좌표를 추출 단계에서 원래 그림 좌표로 되돌려 둡니다(`raster.undo_deskew`, `coordinate_system.deskew_undone: true`). 그래서 원본 그림과 바로 겹칩니다. `deskew_deg`는 기록용입니다.
3. **잡음.** 첫 구현은 따로 걸러내지 않습니다. W5에서 가우시안 잡음 σ20까지 관계 F1 평균이 0.752로 기준(0.749)과 비슷했습니다. 실제 스캔의 얼룩·구멍 자국은 표본을 얻은 뒤 정합니다.
4. **선 벡터화와 뒤 단계.** **같은 뒤 단계를 쓰는 길**을 고릅니다. 그림에서 찾은 선·몸체·채운 도형·글자를 `pdf_vector`가 받는 원시 요소로 바꾸고, `pdf_vector.analyze`·`build_extraction`의 묶기·종류·이름표·연결·흐름 규칙을 그대로 씁니다(W4 구조 그대로).
   - 이유 1: 벡터 품질 개선(기호 사전, 이름표 배정, 연결 정리)이 스캔 쪽에도 저절로 들어옵니다. 따로 가는 길이면 같은 규칙을 두 벌 고쳐야 합니다.
   - 이유 2: 추출 결과 계약(`extraction.json`)과 그래프 단계가 하나로 유지됩니다.
   - 그림에서만 생기는 끊김은 래스터 쪽에서 메워 넘깁니다(rev 2, 근거 [스캔 읽기 기록](../units/2026-11-13-drawing-knowledge/evidence/scan-first-measure.md) §5).
     - 배관 라벨의 흰 바탕이 꺾임 바로 앞이나 짧은 배관 가운데를 가리면, 라벨 양옆 짧은 토막(1.2pt 이상)을 따로 찾고, 라벨 건너편 상대 선까지 선 끝을 늘입니다.
     - 굽은 획(펌프 외곽 곡선)은 윤곽을 줄인 닫힌 꺾은선으로 넘겨 기호 몸체로 묶이게 합니다. 열린 선으로 넘기면 배관으로 읽혀 오검출이 늘었습니다.
     - 화살촉 크기(4.5~8.5pt) 채운 도형은 삼각형 맞춤 하한을 0.66으로 낮추고, 감싸는 삼각형을 잉크 넓이로 줄여 꼭짓점 3개로 넘깁니다. 뒤 단계의 흐름 방향 규칙은 꼭짓점 3개짜리만 화살촉으로 읽습니다. 선은 화살촉 꼭짓점까지 늘여, 벡터 PDF처럼 꼭짓점이 닿은 기호에 붙게 합니다.
     - (rev 4) 밸브 몸통 삼각형 꼭짓점이 가운데 검은 공에 가려 흰 구멍이 사다리꼴로 잡히면, 공에 닿은 짧은 변을 빼고 양옆 변을 늘여 삼각형으로 되살립니다(제어밸브의 '몸통+구동부' 판정).
     - (rev 4) 1pt보다 짧은 선 토막은 넘기지 않습니다. 화살촉 꼭짓점에 남은 0.5pt 조각이 도면 연결 상자에 붙은 둘째 배관으로 세어져 상자 안 배관 번호를 매기지 못했습니다.
     - (rev 4) 같은 직선 위 선분은 중심선이 허용 오차 안에서 이어지는 것끼리 묶어 봅니다. 번짐·JPEG으로 1~2px 어긋난 두 토막이 사이 라벨을 건너 이어지지 않았습니다.
     - (rev 4) 표식(화살촉) 크기 상한은 9.5pt입니다(`PV_OVERRIDES.marker_max`). 번짐으로 화살촉이 8.2~8.9pt가 되어 몸체로 읽혔습니다.
   - 대가: 벡터에 맞춘 문턱이 스캔 잡음에 약합니다. 래스터 쪽에서만 바꿀 값은 `raster.PV_OVERRIDES`에 모으고 실행마다 `run.settings`에 남깁니다. `pdf_vector*.py`는 고치지 않고 부르기만 합니다. 뒤 단계 함수 서명이 바뀌면 벡터 담당과 맞춥니다.
5. **글자(OCR).** `rapidocr-onnxruntime`을 씁니다. 이 OCR은 긴 변이 2000px을 넘으면 그림을 줄여 읽습니다(설정 `max_side_len: 2000`, 설치된 1.4.4 판의 `config.yaml`에서 확인). 300dpi A3 쪽(약 5000px)은 40%로 줄어 작은 글자를 놓칩니다. 그렇다고 원래 해상도로 읽으면 낱말 사이 띄어쓰기를 잃습니다(SNP-M-101 PNG: 'TO SNP-M-102' → 'TOSNP-M-102'). 그러면 도면 연결 표기와 기기 이름의 종류 판정이 깨져 W4 kind 정확도가 6장 모두 하한 아래로 떨어졌습니다(2026-11-14 측정, `check_adapter.py` W4). 그래서 **두 번 읽습니다.**
   - 먼저 W4가 재던 조건(A3 가로가 2000px이 되는 배율, 약 1.68 px/pt)으로 줄여 읽고, 이 줄을 기본으로 둡니다.
   - 그림이 그보다 고우면 원래 해상도를 2000px 이하 타일(겹침 400px)로 나눠 한 번 더 읽고, 앞의 줄과 겹치지 않는 줄만 더합니다. 타일 가장자리에 닿은 줄은 다른 타일에서 온전히 읽힌 줄이 있으면 버립니다.
   - 계기 원 안을 키워 다시 읽는 W4 규칙은 그대로 둡니다.
   - **잘린 줄 바꾸기(rev 4).** 낮은 배율 줄이 '-L005'처럼 문장부호로 시작하거나 끝나고, 원래 해상도 줄('SI-L005')이 그 글자를 더 길게 담고 상자가 밖으로 나가면 원래 해상도 줄로 바꿉니다. 글자를 더 담았다는 것만으로는 바꾸지 않습니다(원래 해상도는 옆 선을 'I'로 읽기도 함).
   - **붙은 배관 번호 띄우기(rev 4).** 'RC-L003COLDLEG'처럼 배관 번호 뒤에 글자 둘 이상이 붙으면 번호 뒤를 띄웁니다. 배관 번호 규칙이 번호 뒤 띄어쓰기를 요구합니다.
   - **띄어쓰기 되살리기(rev 2).** 두 번 읽어도 rapidocr는 배율과 상관없이 띄어쓰기를 자주 잃습니다('SAFETY INJECTION PUMP' → 'SAFETYINJECTIONPUMP'). 이러면 기기 이름 낱말로 정하는 종류(펌프·탱크·열교환기)가 빠집니다. 줄 상자 안 잉크의 빈 열이 줄 높이의 0.21 이상이면 낱말 사이로 보고, 조각마다 글자 인식만 다시 해서 띄어 붙입니다. 다시 읽은 글자를 이은 것이 원래 줄과 같을 때만 바꾸고, 한 글자 조각은 앞 조각에 붙입니다(태그 'RC-L011'이 'RC-L01 1'로 갈리지 않게).
6. **기호.** 학습 데이터가 없으므로 1차는 규칙과 견본 맞춤만 씁니다. 몸체(잉크로 둘러싸인 흰 구멍)와 채운 도형을 원시 요소로 넘기면 종류는 `pdf_vector`의 기호 사전 규칙이 정합니다. 학습 모델 검출기는 후속입니다(§5).
7. **연결.** `pdf_vector`의 연결 규칙 그대로입니다. 점선은 짧은 조각 사슬로 넘깁니다.
8. **미확인.** 아래를 남깁니다. 추출을 막지는 않습니다.

| 코드 | 뜻 |
| --- | --- |
| `scan_input` | 스캔 입력이라 벡터보다 결과가 떨어진다는 안내(해상도·출처 포함). 스캔 결과에는 늘 하나 있다 |
| `low_resolution` | §2.2의 '낮음'·'너무 낮음' |

| `scan_text_layer_ignored` | 스캔 PDF에 글자층이 있으나 믿지 않고 그림을 다시 읽음(rev 3) |

### 3.1 좌표

- 추출 결과 좌표는 원래 그림의 px(`coordinate_space: image_px`)입니다. 스캔 PDF는 `coordinate_system`에 `px_per_pt`와 쪽 번호를 함께 둬서 쪽 좌표(pt)로 바꿀 수 있게 합니다. 좌표가 든 자리(노드·글자 상자, 관계 끝점·꺾임점, 출처 상자)는 `raster.map_coords` 한 곳이 함께 바꿉니다.
- 문턱의 px 환산 배율은 §2.2의 px/pt를 씁니다. 지금은 그림 폭을 A3로 가정한 배율만 썼으므로, 스캔 PDF와 dpi가 적힌 그림에서는 실제 배율을 쓰도록 바꿉니다.

## 5. 정확도를 재는 법

벡터 PDF 정답지(`tests/fixtures/read-quality/`와 SNP drawio 정답)를 그대로 씁니다. 같은 쪽을 그림으로 바꿔 스캔 읽기로 추출하고, 같은 채점(`check_read_quality.score_page`)으로 잽니다.

- 스크립트: `scripts/check_scan_quality.py`(새 파일). 쪽 PDF를 `--dpi`(기본 300)로 회색조 그림으로 그린 뒤 래스터 읽기로 추출하고, 좌표를 px ÷ (dpi/72)로 쪽 좌표(pt)로 바꿔 채점합니다. 같은 쪽의 벡터 추출 값도 함께 내어 항목별 차이를 보입니다.
- 채점 함수는 `scripts/check_read_quality.py`에서 가져다 쓰기만 하고 고치지 않습니다(그 파일은 벡터 담당 단위의 것).
- 보고: 항목마다 '맞은 수/분모 @커밋', 해상도 조건(dpi), 벡터 대비 차이(백분율 점)를 냅니다.
- 이 값은 깨끗한 렌더링 그림이라 실제 스캔보다 좋게 나옵니다. 열화(해상도·잡음·기울기·JPEG)는 `scripts/degrade_raster.py` 방식으로 따로 잽니다.
- 첫 측정값(rev 1): [스캔 첫 측정 기록](../units/2026-11-13-drawing-knowledge/evidence/scan-first-measure.md). SNP 6장 300dpi는 네 항목 모두 벡터보다 21~60%p 낮고, APR1400 세 쪽은 1~11%로 거의 읽지 못합니다. 원인은 그 기록 §3에 있습니다.
- 기준값 파일은 이번에 만들지 않습니다. 첫 측정값은 작업 기록에 적고, 값이 안정되면 기준값(`tests/baselines/`)을 따로 둡니다.

### 5.1 표본 밖 합성 쪽(rev 4)

래스터 문턱과 개선은 SNP 6장을 보며 정했으므로, 그 6장 값은 표본 안 값입니다. `scripts/build_scan_synthetic.py`는 SNP 쪽에서 기호 그림만 잘라 새 배치로 놓고 배관·화살촉·배관 번호·태그·기기 이름을 새로 그려, 쪽 그림과 정답지를 함께 만듭니다(`check_scan_quality.py --synthetic N`, 씨앗 1..N). 기호 모양은 SNP와 같으므로 새로운 도면 양식에 대한 값은 아닙니다. 배치·배관 경로·글자가 6장에 맞춰졌는지 보는 데 씁니다. 벡터 판이 없어 벡터와의 차이는 낼 수 없습니다.

## 6. 화면

새 화면 규격([app-shell-web](../design/app-shell-web.md))에 아래를 더합니다. 화면 코드는 화면 담당 단위가 고칩니다.

- **기본 보기**: 스캔 도면은 '원본 보기'를 기본으로 엽니다. 다시 그린 보기는 미확인이 많아 원본과 다르게 보일 수 있어서입니다.
- **알림**: 도면 머리에 "스캔 도면 · N dpi · 자동으로 읽은 결과가 적고 미확인이 많습니다"를 띄웁니다. 해상도가 '낮음'·'너무 낮음'이면 §2.2 안내를 함께 띄웁니다.
- **겹쳐 보기**: 원본 그림 위에 추출한 기호 상자와 배관을 겹쳐 보여 사람이 바로 고칠 수 있게 합니다. 좌표는 원래 그림 px라 그대로 겹칩니다(§3.1).
- **AI 검토 토글**: 벡터와 같이 둡니다. AI는 후보만 내고 사람이 수락해야 반영됩니다. 스캔 도면은 AI 검토가 자동으로 켜지지 않습니다. 켜면 원본 그림 조각을 보내므로 호출 수가 벡터보다 많을 수 있다는 것을 토글 옆에 적습니다.

## 7. 배포

- 2026-11-06에 정한 것처럼(결정 D7) OpenCV·numpy·OCR은 지금 배포본에 넣지 않습니다. 빌드 venv에 numpy가 있으면 PyInstaller가 openpyxl을 따라 numpy를 묶기 때문입니다.
- **스캔 읽기 묶음**을 따로 둡니다. 래스터 venv 패키지를 담은 별도 폴더(또는 실행 파일)로, 앱은 §4의 하위 프로세스 방식으로 부릅니다. 크기는 내려받기 합계 98.3MB, 설치 뒤 venv 290MB입니다(W4 기록 §3, 2026-11-06 측정). 실행 파일로 묶은 크기는 아직 재지 않았습니다.
- 묶음에 넣을 때는 각 휠의 LICENSE 원문(특히 opencv 휠 안 제3자 바이너리와 OCR 모델 가중치)을 대조해 `licenses/`에 고지를 더합니다.
- **묶음이 없을 때**: 등록할 때 "스캔 읽기 구성요소가 없어 읽을 수 없음"을 알리고 blocker `scan_reader_unavailable`로 등록을 멈춥니다(rev 2, 총괄 지시 2026-11-14). 원본 보기 그림(`page.svg`)도 추출 단계가 만들기 때문에, 등록만 하고 원본으로 보는 길은 두지 않았습니다.
- **묶음 크기(rev 2, 2026-11-14 래스터 venv에서 잼)**: 읽기에 쓰는 패키지만 합쳐 설치 뒤 약 248MB입니다. opencv-python-headless 117.6MB(Apache-2.0), numpy 54.2MB(BSD-3-Clause 외), onnxruntime 47.9MB(MIT), rapidocr-onnxruntime 16.5MB(Apache-2.0, OCR 모델 16MB 포함), shapely 6.7MB(BSD-3-Clause), protobuf 2.7MB(BSD-3-Clause), packaging·PyYAML·pyclipper·flatbuffers 합쳐 2.1MB(Apache-2.0/BSD-2·MIT·MIT·Apache-2.0)입니다. pip·networkx(검사 전용)와 배포본에 이미 있는 Pillow는 뺐습니다. 실행할 Python 자체는 따로 듭니다.
- opencv 휠에는 동영상 읽기용 FFmpeg DLL(`opencv_videoio_ffmpeg500_64.dll`, 30.9MB, LGPL)이 들어 있습니다. 스캔 읽기는 쓰지 않으므로 묶음에서 빼면 크기와 고지 부담이 함께 줄어듭니다(빼고 도는지는 아직 시험하지 않음).
- 지금 하위 프로세스는 저장소의 `scripts/extract_raster.py`를 부릅니다. 실행 파일로 묶은 앱에는 이 경로가 없으므로, 묶음에는 Python 실행 파일과 `hazop` 패키지 사본, 진입 스크립트를 함께 넣어야 합니다. 묶음 형태는 배포 결정을 받은 뒤 정합니다.

## 8. 등록

- `fileinfo.inspect`가 스캔 PDF와 PNG·JPG를 알아보고, 판별 결과(`scan`: 종류·px/pt·dpi·등급·출처)를 등록 정보에 남깁니다.
- rev 2부터 스캔 입력을 등록합니다(`fileinfo.SCAN_REGISTRATION = True`). 스캔 PDF는 모든 쪽, 그림은 `page-1` 한 쪽입니다. 그림 형식(png·jpeg)은 원본 옆 SVG를 찾지 않습니다(`NO_SVG_FORMATS`). 이 PC에 읽기 구성요소가 없으면 §7대로 멈춥니다. 값을 False로 되돌리면 첫 구현처럼 blocker `scan_not_connected`로 멈춥니다.
- **추출**: `data.extract_and_graph(등록, progress=None)`이 스캔 도면이면(`raster_scan.is_scan_record`: 형식이 png·jpeg이거나, PDF인데 첫 쪽이 스캔) `raster_scan.run_registered`로 쪽마다 읽고 그래프를 만듭니다. 쪽마다 20초 안팎이 걸리므로 `progress(끝난 쪽, 전체 쪽, 문구)`를 쪽 앞뒤로 부릅니다. 화면은 작업 스레드에서 부르고 이 값을 진행 표시에 씁니다.
- **판별 순서(rev 3)**: PDF는 벡터 읽기 전에 첫 쪽을 스캔인지 먼저 봅니다. 글자층(OCR 결과)을 덧입힌 스캔 PDF는 글자가 있어 '벡터 내용 없음'에 걸리지 않으므로, 그때만 판별하면 벡터 PDF로 등록돼 쪽이 거의 비어 보였습니다(검토 2026-11-14). 등록(`fileinfo`)과 추출(`raster_scan.is_scan_record`)이 같은 `classify_pdf_page`로 판별합니다.
- **확정처럼 들어가지 않게(rev 3)**: 스캔 추출 결과의 `source.format`은 `raster`이고 입력 종류는 `source.scan_input`(pdf·png·jpeg)에 둡니다. 쪽 확정 판정(`hazop/extract/confirmation.py`)은 래스터 쪽의 '원본에 남은 것'을 세지 못하므로 이 쪽은 확정할 수 없고, `scan_input`을 비롯한 미확인을 모두 셉니다. 노드·관계에는 `evidence.read_from: scan_image`를, 태그 노드에는 `evidence.ocr_score`를 답니다.
- **출력**: 쪽 폴더에 `extraction.json`·`validation_report.md`·`extraction_run.json`(추출기 `raster_scan`)과 `page.svg`를 씁니다. `page.svg`는 읽은 그림을 그대로 넣은 것이고(긴 변 3000px 상한으로 줄여 넣음), 추출 좌표가 그 그림의 픽셀이라 `svg_alignment`는 offset 0, `source: scan_image`입니다. 등록 식별 정보는 `pdf_vector.apply_registration`으로 채우고, `source.sha256`은 원본 파일의 해시입니다. 읽지 못한 쪽은 `not_extracted.json`(벡터 PDF와 같은 이름)에 사유를 남깁니다.
