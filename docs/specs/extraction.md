# 정보 추출 기획

[상세 플로우차트](<flows/02-extraction.md>) · [자료 등록](registration.md) · [정보 통합·관리](integration.md) · [공통 원칙](overview.md#principles)

## 목적과 범위

등록된 P&ID에서 설비·밸브·계기·태그·배관을 읽어 도면 내부의 연결 그래프 초안을 만들고, 원본 대조와 수정을 마친 결과를 정보 통합·관리 단계로 전달합니다. 여러 자료의 동일 대상 식별·병합이나 HAZOP 추론은 여기서 수행하지 않습니다.

## 결정 상태

| 항목 | 상태 |
| --- | --- |
| 입력 형식 | 사용자 결정: 사용자가 draw.io(.drawio)로 직접 만든 실험용 P&ID. 1차 입력은 `.drawio`(구조·속성의 원천)와 draw.io가 내보낸 SVG(`*.drawio.svg` 또는 `*.svg`, 요소마다 `data-cell-id`, 오버레이 배경용) |
| 다른 자료형 | 사용자 결정: 실험 성공 후 필요하면 형식별 읽기 어댑터를 모듈로 추가. 어댑터 출력은 같은 추출 결과 JSON. PNG·JPG·PDF는 2차이며, 같은 도면의 drawio 추출 결과를 정답지로 써서 성능을 잼. 벡터 PDF는 등록 경로에 연결함(사용자 결정 2026-11-06): ①에서 PDF를 등록하면 `pdf_vector`가 첫 쪽을 추출하고(식별 값은 drawio 등록 경로와 같이 사람이 확정한 값만, 표제란 값은 `title_block_candidates`), 같은 pdfplumber 좌표로 그린 도면 SVG(`page.svg`, `svg_alignment.source`=`rendered_from_pdf`, offset (0, 0))를 원본 대조 뷰어 배경으로 씀. 이미지·클리핑 경로는 그리지 않음 |
| 요소 분해 | 사용자 결정(2026-11-03): 도면을 심볼·배관 구간·태그 텍스트 같은 요소로 나눠 노드·관계로 만듦. 노드 단위는 [정의 초안](integration.md#node-unit) |
| 원본 대조 화면 | 사용자 결정(2026-11-03): 저장소 안의 로컬 정적 HTML 뷰어, 외부 전송 없음. 보기·선택은 1차, 수동 편집·AI 보정은 후속 |
| 최초 실행 | 등록 완료 후 사용자가 자료·페이지를 지정해 추출 실행. 벡터 PDF는 등록 직후 첫 쪽을 자동 추출(사용자 결정 2026-11-06, 나머지 쪽 추출은 후속) |
| 처리 범위 | 사용자 결정: 전체 추출과 선택 구간 재처리. MVP는 전체 추출만, 선택 구간 재처리는 후속 |
| 자동 처리 | Python 스크립트가 기본. 원본 대조 후 사람이 수정 가능 |
| AI | 필수 의존성 없음. 불만족스러운 결과의 선택적 검수·보정 제안 |
| 체크밸브 허용 방향(A1) | 총괄 결정(권고안, 사용자 위임 2026-11-06): 도형의 지정 속성 또는 draw.io 기호의 화살표 방향을 근거로 판정하고, 근거가 없으면 미확인(`unknown_check_valve_direction`)으로 기록. [규칙](#check-valve-direction) |
| 포트(A2) | 총괄 결정(권고안, 사용자 위임 2026-11-06): 커넥터 끝의 선택 속성. 없으면 미확인으로 기록하되 추출을 막지 않음. [규칙](#port-rule) |
| 읽기 품질 지표 | 사용자 결정(2026-11-13, DEC-0298·0299): 기호 종류·태그/번호·연결·속성 네 항목, 처음 목표 95%. 세부 규칙은 총괄 위임으로 정함. [지표](#read-quality) |
| DEXPI 참고 범위(A13) | 총괄 결정(권고안, 사용자 위임 2026-11-06): DEXPI 클래스 체계는 따르지 않고 용어 대응표만 둠. [대응표](#dexpi-terms) |

## draw.io 원본 읽기

이미지 인식 대신 원본 파일에 저장된 구조를 읽습니다. draw.io 파일은 XML이며 다이어그램이 압축되어 저장될 수 있으므로 두 경우를 모두 처리합니다.

| 읽을 정보 | 방법 | 확인할 점 |
| --- | --- | --- |
| 도형 | 객체 ID, 라벨, 스타일, 사용자 속성(Edit Data), 좌표 | 도형 모양만으로 설비 의미를 정하지 않고 속성을 우선 사용 |
| 커넥터 | source/target 연결 대상, 경유점, 스타일, 사용자 속성 | 도형에 접속된 커넥터와 떠 있는 단순 선을 구분 |
| 문자 | 라벨·독립 텍스트의 원문과 위치 | 텍스트와 기호의 소속은 거리로 확정하지 않음 |

<a id="drawio-rules"></a>

### 샘플 작성 규칙 (초안)

사용자가 직접 샘플을 그리므로, 추출이 의미를 확실히 읽을 수 있도록 다음 규칙을 제안합니다. 속성 이름은 [정보 통합·관리의 정의 초안](integration.md#definitions)과 맞추며, 실제 샘플을 보고 확정합니다.

| 대상 | 작성 규칙 |
| --- | --- |
| 설비·밸브·계기 | 도형의 사용자 속성에 `kind`(예: `pump`, `vessel`, `control_valve`, `manual_valve`, `check_valve`, `psv`, `transmitter`, `controller`)와 `tag` 입력. 샘플 6세트 사용값: 설비 `reactor_vessel`, `steam_generator`, `pressurizer`, `pump`, `tank`, `heat_exchanger`, `turbine`, `condenser`, `filter`, `demineralizer`, `orifice`, `vent` / 밸브 `manual_valve`, `motor_operated_valve`, `control_valve`, `check_valve`, `isolation_valve`, `psv` / 계기 `transmitter`, `controller`, `indicator`, `temperature_element`. 기호 번호는 `symbol_id` |
| 배관 요소 | 샘플 사용값: 분기점 `tee`(`tag`·`line_no` 보유), 배관 끝막음 `pipe_cap`, 도면 연결점 `continuation`(`tag` 없이 `to_drawing`·`to_object`·`line_no` 보유) |
| 추출 제외 | 샘플은 도면 틀·표제란·주석에 스타일 `pidIgnore=1`을 붙임 |
| 밸브 정상 위치 | `normal_position`: `NO`(정상 열림), `NC`(정상 닫힘), `LO`(잠금 열림), `LC`(잠금 닫힘). 모르면 비워 미확인으로 처리 |
| 제어밸브 실패 위치 | `fail_position`: `FO`, `FC`, `FL` 등. 해당 없으면 비움 |
| 방향성 기기 | 체크밸브는 [체크밸브 허용 방향 규칙](#check-valve-direction)을 따름. 다른 기기의 도형 `flow_direction`은 값만 보존하고 미확인으로 둠 |
| 배관·신호선 | 커넥터 속성 `line_type`: `process`, `signal` 등. 라인 번호는 `line_no`. 샘플 사용값은 `process`, `process_secondary`, `instrument_tap`, `signal_electric`이며 `signal`은 없음. 그래프 표현은 [정의 초안](integration.md#node-unit) |
| 접속 | 커넥터 양 끝을 도형에 실제로 붙임. 붙지 않은 선은 미확인 연결로 처리 |
| 흐름 방향 | 확인된 흐름만 커넥터 속성 `flow_direction: source_to_target`으로 표시. 그리는 순서(source/target)만으로는 방향으로 해석하지 않음. 예외: 체크밸브 도형의 `flow_direction`([체크밸브 허용 방향](#check-valve-direction)) |
| 설계값 | 필요 시 `design_pressure`, `design_temperature`, `set_pressure` 등을 단위와 함께 입력 |
| 포트 | 커넥터 끝의 `source_port`·`target_port` 속성(선택). [포트 규칙](#port-rule)을 따름 |

원본에 없는 의미·포트·흐름 방향은 임의로 생성하지 않습니다. 규칙을 따르지 않은 객체는 미분류·미확인으로 남깁니다.

<a id="connector-classification"></a>

**커넥터 분류(공통):** 커넥터가 `relations`에 들어갈지 `unresolved_connectors`에 들어갈지는 기존 접속 규칙만으로 정합니다. 양 끝이 모두 노드에 붙어 있어야 `relations`에 들어갑니다. 한쪽 끝이라도 붙지 않았거나 노드가 아닌 셀에 붙었으면 `unconnected_endpoint` 또는 `endpoint_not_node`를 기록하거나, 참조 대상이 없으면 차단 오류 `missing_reference`를 기록하고(`drawio.py` 557–561행) `unresolved_connectors`에 둡니다. 아래 체크밸브·포트 판정은 이 분류를 바꾸지 않습니다.

<a id="check-valve-direction"></a>

### 체크밸브 허용 방향 (A1)

총괄 결정(권고안, 사용자 위임 2026-11-06). 번호 A1·A2·A13은 총괄 작업지시서의 번호입니다. 대응하는 남은 작업은 [남은 작업](../records/backlog.md)의 "1차 슬라이스 구현 후속"(체크밸브 flow_direction 기준 작성 규칙 확정, 포트 규칙)과 "구현 전 결정"(DEXPI 클래스 체계를 참고할 범위)입니다.

**적용 범위:** draw.io 추출(`hazop/extract/drawio.py`)의 `kind=check_valve` 도형에만 적용합니다. PDF 어댑터(`hazop/extract/adapters/pdf_vector.py`)가 분류하는 `check_valve`에는 적용하지 않으며 후속 작업으로 정합니다.

**용어:** 체크밸브(check valve)는 한 방향 흐름만 허용하고 역류를 막는 밸브입니다 [일반지식]. 원전 고유 용어가 아닌 일반 배관 용어이며, NRC 용어 정의는 확인하지 못했습니다(미확인).

**정상 위치 검사 정책:** 체크밸브는 `normal_position` 누락 검사(`missing_normal_position`) 대상에서 뺍니다. 이것은 검사 범위에 관한 정책이며, 체크밸브에 정상 위치가 없다는 뜻이 아닙니다. 정상 열림·정상 닫힘 상태를 유지하는 형식의 체크밸브가 있을 수 있습니다 [일반지식, NRC 원문 미확인]. 값이 있으면 `attributes`에 보존합니다.

판정 근거는 두 가지입니다. 하나만 있어도 방향을 확정하고, 둘 다 있으면 서로 반대가 아니어야 확정합니다.

| 근거 | 입력 | 판정 |
| --- | --- | --- |
| ① 지정 속성 | 도형 사용자 속성 `flow_direction`. 허용값은 정확히 `source_to_target` 하나. 빈 문자열은 속성 없음으로 봄 | 이 밸브를 target으로 가진 커넥터를 입구, source로 가진 커넥터를 출구로 봄 [가정: 도형 속성을 "이 밸브에 붙은 커넥터의 그리는 순서가 허용 방향과 같다"는 작성자 선언으로 해석. 샘플 작성자 확인 전]. 작성 규칙 표 "흐름 방향" 행(그리는 순서만으로는 방향으로 해석하지 않음)의 예외이며, 작성자가 이 속성을 적은 경우에만 적용. 이 해석을 사람이 확인하기 전에는 ①에 근거한 결과를 "선언 기반 확정"(`"status": "declared"`)으로 표시 |
| ② 기호 방향 | 도형 스타일 `shape`·`valveType`·`direction`·`flipH`·`flipV`·`rotation` | 기호 등록표에 있는 기호만 사용. 아래 계산으로 도면 좌표의 방향 벡터 d를 구해 판정 |

**② 계산** (도면 좌표는 x 오른쪽, y 아래쪽이 양수)

1. 등록표 조회: 키는 (`shape` 값, `valveType` 값) 쌍입니다. 예: `("mxgraph.pid2valves.valve", "check")` → 기본 방향 d0. 키가 없으면 ② 없음.
2. 스타일은 밸브 셀 자신의 것만 읽습니다. 밸브의 부모가 레이어가 아닌 도형이면 부모의 회전·뒤집기를 반영할 수 없으므로 ② 없음으로 봅니다.
   - `direction`: 없으면 `east`. `east`·`south`·`west`·`north` 외 값이면 ② 없음.
   - `flipH`·`flipV`: 값이 `1`이면 적용, 없거나 `0`이면 미적용, 그 밖의 값이면 ② 없음.
   - `rotation`: 없으면 0. 숫자가 아니면 ② 없음으로 보고, 체크밸브 판정 때문에 추출을 막지 않습니다. 다만 기존 스타일 수치 검사(`drawio.py` 331–334행)가 모든 셀에 대해 `invalid_number` 차단 오류를 따로 기록하므로, 이 경우 추출 상태는 그 기존 검사 때문에 `blocked`가 됩니다(이 규칙과 무관한 기존 동작이며 바꾸지 않음). 360으로 나눈 나머지가 0·90·180·270이 아니면 ② 없음.
   - `direction`이 `east`가 아니면서 뒤집기가 있으면 ② 없음.
3. d = 회전(rotation) ∘ 뒤집기 ∘ direction(d0). `direction`은 east 0°, south 90°, west 180°, north 270°의 시계 방향 회전이고, 시계 방향 90°는 (x, y) → (−y, x)입니다. `flipH`는 x 부호를, `flipV`는 y 부호를 바꿉니다 [추론: draw.io 스타일 의미, 원문 미확인].
4. 밸브 중심 c는 추출 결과의 밸브 bbox 중심입니다. bbox가 없거나 근사(`approximate`)이면 ② 없음. 밸브나 그 조상 도형에 뒤집기(`flipH`·`flipV`)가 있는데 부모 변환을 무시하게 되는 경우(부모가 레이어가 아닌 도형)도 ② 없음.
5. 커넥터 기준점 p는 다음 순서로 정합니다. (가) 커넥터 경로에서 밸브 쪽 첫 경유점(밸브가 target이면 `waypoints`의 마지막, source이면 첫 번째). (나) 경유점이 없으면 반대 끝점의 `point`(추출 결과 값). (다) 그것도 없으면 반대 끝 노드의 bbox 중심. 이때 그 bbox가 근사(`approximate`)이면 그 커넥터는 판정 불가(총괄 직접 수정, 최종 재검토 반영). (라) 셋 다 없으면 기준점 없음으로 판정 불가. 커넥터 경로가 근사이면(그 커넥터의 `source_locations` `method`에 `parent_offset_approx`가 있음) 그 커넥터도 판정 불가입니다. 접속 위치 스타일(`entryX`·`exitX` 등)로 입구·출구 면을 판정하지 않습니다. 뒤집힌 도형에서 draw.io가 이 값을 어떻게 해석하는지 확인하지 못했기 때문입니다.
6. 수치 규약: 좌표는 추출 결과에 기록된 값을 float 그대로 쓰고, 계산 중이나 비교 전에 반올림하지 않습니다. cos 원값을 ±0.2와 바로 비교합니다. 경계값 0.2와 −0.2는 판정 가능 쪽(일치·반대)에 포함합니다. 아래 샘플 표의 cos는 표시용으로 소수 둘째 자리까지 적은 값입니다.
7. ①이 있을 때(검산): v = p(출구) − p(입구). v가 영벡터이면 판정 불가. cos(d, v) ≥ 0.2이면 일치, ≤ −0.2이면 반대, −0.2 < cos < 0.2(내적 0 포함)는 판정 불가입니다.
8. ①이 없을 때(② 단독): 커넥터마다 s = cos(d, p − c)를 구합니다(p = c이면 그 커넥터는 판정 불가). s ≤ −0.2이면 입구 후보, s ≥ 0.2이면 출구 후보, −0.2 < s < 0.2는 판정 불가입니다. 입구 후보 1개·출구 후보 1개이고 판정 불가 커넥터가 없을 때만 확정합니다. 같은 쪽 후보가 2개 이상이면(같은 값 포함) 모호입니다.
9. 대칭 충돌 검사(② 단독): 입구로 판정한 커넥터가 밸브를 source로 하고 `flow_direction=source_to_target`이면(밸브에서 나가는 흐름), 또는 출구로 판정한 커넥터가 밸브를 target으로 하고 `flow_direction=source_to_target`이면(밸브로 들어오는 흐름) 모순입니다.

0.2는 [가정]이며 샘플로 조정합니다.

**기호 등록표:** 키 형식은 위 1번과 같습니다. `("mxgraph.pid2valves.valve", "check")`의 기본 방향은 왼쪽→오른쪽 (1,0)으로 추정합니다 [추론: 아래 샘플 8건 중 7건에서 ①과 일치]. 사람이 샘플 SVG 렌더링으로 확인하고 구현 트랙의 `decisions.md`에 승인을 기록하기 전에는 등록하지 않습니다. 그동안은 ①만 사용합니다. ② 사례 테스트는 등록표를 테스트에서 주입해 실행합니다.

**입구·출구 커넥터 집합:** 밸브를 source 또는 target으로 가진 커넥터 중 관계 종류가 `physical_connection`인 것을 셉니다(`relations`와 `unresolved_connectors` 모두). 계측 연결(`instrument_tap`)과 신호선은 세지 않습니다. 다음 중 하나라도 해당하면 집합 조건 불충족입니다.

- `line_type`이 없거나 규칙에 없는 커넥터가 밸브에 붙어 있음(물리 배관인지 알 수 없음)
- 물리 배관 커넥터가 정확히 2개가 아님(분기 또는 한쪽 연결 누락)
- 그중 하나라도 `unresolved_connectors`에 있음(그래프 엔터티가 없어 전달할 수 없음. 분류는 [커넥터 분류(공통)](#connector-classification))
- source와 target이 모두 이 밸브인 커넥터(자기 루프)가 있음. ①·② 어느 경우든 같은 커넥터가 입구이자 출구가 되므로 모호로 봄
- ①이 있을 때: target=밸브인 커넥터 1개와 source=밸브인 커넥터 1개로 나뉘지 않음

### 포트 (A2)

총괄 결정(권고안, 사용자 위임 2026-11-06). 포트는 기기에서 배관이 붙는 접속점입니다(용어 출처: [정의 초안](integration.md#definitions)). 포트는 선택 속성이며, 없어도 관계를 정상 연결로 유지하고 추출을 막지 않습니다.

| 입력 | 판정 | 기록하는 미확인 코드 |
| --- | --- | --- |
| 커넥터 사용자 속성 `source_port`·`target_port`(문자열, 포트 이름) | 앞뒤 공백을 지운 값을 해당 끝점의 `port`에 넣음. 원문은 `attributes`에 그대로 둠. 포트 이름 목록 검사는 하지 않음(이름 체계 미확인, 후속) | 없음 |
| 위 속성이 없거나 공백을 지운 값이 빈 문자열이고, 끝 노드가 포트 구분 대상(아래) | 끝점 `port=null`. 커넥터 분류는 바꾸지 않음([공통](#connector-classification)) | `missing_port` (target=커넥터 local_id, field=`source_port` 또는 `target_port`) |
| 위와 같으나 끝 노드가 포트 구분 대상이 아님 | 끝점 `port=null` | 없음 |
| 커넥터에 끝을 정하지 않은 `port` 속성이 있음(끝별 속성과 함께 있어도 같음) | `port` 값은 어느 끝점에도 쓰지 않고 `attributes`에만 보존. 끝별 속성이 있으면 그 끝은 끝별 속성 값을 씀 | `ambiguous_port` 커넥터당 1건(field=`port`). 끝별 속성이 없는 대상 기기 끝에는 `missing_port`도 함께 기록(field가 달라 두 코드가 동시에 기록될 수 있음) |
| 포트 속성이 있으나 그 끝이 붙지 않았거나 노드가 아님 | 값을 끝점 `port`에 보존. 커넥터는 [공통 분류](#connector-classification)대로 `unresolved_connectors` | 공통 분류의 `unconnected_endpoint` 또는 `endpoint_not_node`. 그 끝에는 노드가 없으므로 `missing_port`를 기록하지 않음 |
| 접속 위치 스타일(`exitX`·`entryX` 등)만 있음 | 기존처럼 `constraint`로 보존하되 포트로 해석하지 않음 | 위 규칙에 따름 |

- 포트 구분 대상: 끝 노드의 `kind`가 `KINDS_NEED_PORT`에 있고, 관계 종류가 `physical_connection`인 커넥터의 끝입니다 [가정: 계측·신호 연결에는 포트 구분을 요구하지 않음]. 그 기기가 커넥터의 source 쪽이든 target 쪽이든 같게 적용합니다.
- `KINDS_NEED_PORT` 초기값은 `heat_exchanger`, `steam_generator`입니다 [추론: 서로 분리된 내부 유로를 가지는 기기, [정의 초안](integration.md#definitions)의 열교환기 예]. 다른 기기는 사람이 확인한 뒤 추가합니다.
- 그래프 변환(③)은 끝점의 `port`를 `has_endpoint` 관계와 `unresolved[]`의 끝점에 그대로 전달합니다.
- 포트별 내부 유로(어느 포트끼리 통하는지)는 이 규칙의 범위가 아닙니다.
- 이 규칙은 포트를 별도 ID나 노드로 만들지 않고 끝점의 `port` 문자열로만 둡니다. [단계 간 데이터 규격](overview.md#data-contract)의 ② → ③ 설명 문단은 "포트를 식별할 수 있으면 포트 ID를 끝점으로 사용"이라고 적고 있고, 같은 절의 JSON 예시 `endpoints`에는 `port` 필드가 없습니다. 전체기획 ②→③ 설명·예시는 끝점 `port` 필드로 맞춤(2026-11-06).

**샘플 기대값:** 샘플 6세트에는 포트 속성이 없습니다(검색 결과). 포트 구분 대상 기기에 붙은 물리 배관 커넥터 끝은 16개이며(`line_type`이 있는 커넥터 기준), 모두 `missing_port`가 기록되는 것이 기대 결과입니다.

### DEXPI 용어 대응 (A13)

총괄 결정(권고안, 사용자 위임 2026-11-06). DEXPI(Data Exchange in the Process Industry, P&ID 데이터 교환 사양)의 클래스 체계는 따르지 않고, 이 프로젝트 용어와의 대응만 기록합니다. 아래 DEXPI 쪽 이름은 [일반지식]이며 DEXPI 사양 원문과 버전은 확인하지 않았습니다(원문 미확인). DEXPI 자료를 입력으로 받는 어댑터를 만들 때 원문으로 확인합니다.

이 결정으로 [정보 통합·관리](integration.md) 정의 초안 절의 "DEXPI 클래스 체계를 참고해 맞추는 방안을 검토"와 [전체기획](overview.md)의 "노드·관계·속성 정의 관리" 절의 같은 검토 항목을 닫습니다. 두 문서의 문구도 같은 날 수정함(2026-11-06).

| 이 프로젝트 | DEXPI 대응 후보 [일반지식]. 후보일 뿐 검증된 매핑이 아니며, DEXPI 버전·원문 미확인 |
| --- | --- |
| `kind` | 객체 클래스 이름(속성 이름 미확인) |
| `tag` | 태그 이름 속성(속성 이름 미확인) |

| 포트(`source_port`·`target_port`) | 설비 쪽은 Nozzle 후보. 배관 부품 쪽 대응은 미확인 |
| `physical_connection` 관계(물리 배관 커넥터) | PipingNetworkSegment 후보 |

## 다른 자료형 (후속)

실제 P&ID는 벡터 PDF, 스캔 PDF, 혼합 PDF, 래스터 이미지, CAD 원본(DWG·DXF 등), 구조화된 설계 데이터(DEXPI 등)로 제공될 수 있습니다. 실험 성공 후 실제 자료형에 맞는 어댑터를 추가합니다. 이 기록은 고려 범위이며 지원을 확정한 것이 아닙니다.

| 처리 | 접근 방법 예시 | 한계와 확인할 점 |
| --- | --- | --- |
| PDF 정보 읽기 | 문자·벡터 선이 있으면 직접 추출 | 모든 PDF가 벡터는 아니며 선분이 실제 배관인지도 분류 필요 |
| 문자 인식 | 문자 레이어 또는 OCR | 태그 오독과 인접 기호의 소속 판별 필요 |
| 기호 탐지 | 범례 기반 템플릿·형상 규칙, 필요 시 전용 탐지 모델 | 크기·회전·표현 차이, 겹침에 따라 누락 가능 |
| 배관·신호선 추적 | 선분 검출·세선화·연결 성분과 기하 규칙 | 교차와 접속, 점선, 가려진 선은 별도 판별 필요 |

생성형 AI가 원본을 자유롭게 해석하는 방식은 기본 경로로 두지 않습니다.

## P&ID 해석 지식 관리

기호의 의미와 연결 규칙은 추출의 기반이므로 이 단계에서 관리합니다. MVP에서는 위 작성 규칙이 해석 지식의 역할을 하며, 실제 도면과 범례를 다룰 때 기계가 읽는 사전·규칙으로 확장합니다.

| 지식 종류 | 기록할 내용 |
| --- | --- |
| 기호 사전 | 기호 예시, 의미·종류, 변형·회전 표현, 대응할 노드 종류 |
| 포트·내부 유로 | 기호의 연결 가능한 위치, 포트 역할, 실제로 통하는 유로와 분리된 유로 |
| 선·접속 규칙 | 배관과 신호선의 표현, 교차·분기·접속점·점프 표시, 화살표 의미 |
| 태그·라인 규칙 | 프로젝트별 태그 구성, 라인 번호 형식, 문자와 기호의 대응 기준 |
| 도면 간 연결 | 외부 연결 기호와 상대 도면·연결 식별자. 실제 연결 확정은 통합 단계 |
| 적용 범위·근거 | 프로젝트·도면 범례·설계 기준의 출처와 버전, 규칙의 적용 범위 |

일반적인 P&ID 지식과 프로젝트 고유 범례를 구분하며, 특정 도면의 표현을 모든 프로젝트에 자동 적용하지 않습니다. 이 사전은 그림을 해석하는 기준이고, 통합 기획서의 정의는 결과를 저장·검증하는 기준이므로 두 정의의 대응을 관리합니다. 배관 연결은 선과 포트의 원본 근거로만 구성하며, 공정상 그럴듯하다는 이유로 연결을 생성하지 않습니다.

## 실행 순서

1. **입력 확인:** 자료 ID·등록 버전·원본 해시·문서·페이지를 확인합니다.
2. **원본 구조 읽기:** draw.io XML을 읽고 원본 객체 ID·속성·좌표·접속 정보를 보존합니다.
3. **문자 추출:** 라벨·속성에서 태그·라인 번호·주석을 읽고 원문·객체 ID·좌표를 남깁니다.
4. **객체 분류:** 사용자 속성과 작성 규칙으로 설비·밸브·계기·포트를 분류합니다. 근거가 없으면 미분류로 둡니다.
5. **접속 추출:** 도형에 접속된 커넥터를 우선 읽습니다. 떠 있는 선은 끝점 후보로만 유지합니다.
6. **연결 초안 구성:** 포트·배관·분기를 연결합니다.
7. **자동 검증 및 원본 대조:** 잘못된 참조·끊김·미분류 객체·미확인 방향을 표시하고 사람이 결과를 검토합니다.
8. **수정 및 재검증:** 원본 수정 후 재추출하거나(MVP), 편집 화면에서 수정한 결과(후속)를 같은 규칙으로 검사합니다.
9. **결과 버전 저장:** 통합 단계로 전달할 결과와 근거·설정·검토 내역·미확인 항목을 저장합니다.

## 추출 결과의 공통 계약 초안

| 결과 | 남길 내용 |
| --- | --- |
| 실행 정보 | 자료 ID·등록 버전, 문서·페이지 범위, 실행 ID, 스크립트·설정·작성 규칙 버전 |
| 도면 내부 노드·포트 | 임시 고유 ID, 원본 객체 ID, 종류 또는 미분류, 태그, 속성, 위치, 포트 |
| 문자·속성 후보 | 원문, 해석한 값·단위·항목, 연결 대상 후보, 미확인 상태 |
| 관계 | 임시 ID, 양 끝점(노드/포트), 관계 종류, 선 경로, 확인된 경우 흐름 방향 |
| 원문 근거 | 자료 ID·등록 버전·문서 ID·페이지·원본 객체 ID와 좌표·좌표계·단위 |
| 검토·변경 정보 | 자동/수동/AI 제안 구분, 변경 전후·사유, 검증 결과, 미해결 항목 |

임시 ID는 통합 단계의 영구 대상 ID 및 원본 객체 ID와 구분합니다. 태그 미인식 때문에 노드를 버리지 않습니다. 한 객체에서 여러 포트가 만들어지거나 여러 원본 객체가 한 대상의 근거가 될 수 있습니다. 필드와 예시는 [단계 간 데이터 규격](overview.md#data-contract)을 따릅니다.

## 원본 대조(1차)·수동 편집 (후속)

- 1차: 저장소 안의 로컬 정적 HTML 뷰어에서 ② 추출 결과의 노드 영역을 도면 SVG 위에 표시합니다. 노드를 클릭하면 속성 패널을 열고, 종류별(심볼·배관·태그) 표시 필터를 둡니다. '태그' 표시층은 별도 노드가 아니라 각 노드의 태그 라벨 위치를 표시합니다. 그래프 보기 탭과 기본 질의(이웃·연결 경로 확인)는 ③ 그래프 변환 결과를 읽어 표시하는 검증용 기능이며, HAZOP 편차용 경로 탐색은 ④에서 합니다. SVG 요소와 추출 결과는 `data-cell-id`(원본 객체 ID)로 대응하며, 자료를 외부로 보내지 않습니다. 화면 참고: `참고자료/참고 사진/`(로컬 전용, 저장소 미포함), [데모 분석](<../design/output-screen-ax-demo.md>).
- 이하는 후속입니다.
- 사람은 누락된 노드·포트·태그를 추가하고 종류·속성을 수정하며 관계를 연결·해제할 수 있습니다.
- AI는 요청된 항목과 관련 원본 영역을 대조하여 보정을 제안합니다.
- 재처리는 기존 결과와 별도 실행으로 보관하고, 기존 수동 보정과의 차이를 검토합니다.
- 선택 구간 재처리는 전체 결과와 좌표를 공유하며, 경계에서 잘린 배관은 열린 끝점으로 표시합니다. 범위 밖 결과를 지우거나 중복 노드·배관을 만들지 않습니다.

## 독립 검증

사용자가 만든 draw.io 샘플과 사람이 작성한 정답(종류·태그·포트·실제 연결·교차 비연결)을 사용합니다.

| 범위 | 사례 | 기대 결과 |
| --- | --- | --- |
| MVP | draw.io 원본(일반·압축 저장) | 객체 읽기, 원본 객체 ID·속성·좌표 추적 가능 |
| MVP | 접속된 커넥터와 떠 있는 단순 선 | 연결과 미확인 끝점 구분, 미확인 연결을 확정하지 않음 |
| MVP | 설비·밸브·계기와 태그 | 종류·태그·포트 추출, 정답과 비교 가능 |
| MVP | 밸브 정상 위치·실패 위치 속성 | 값 보존, 누락 시 미확인 |
| MVP | 선이 교차하지만 연결되지 않음 | 교차를 분기로 확정하지 않음 |
| MVP | 배관과 계장 신호선 | 관계 종류 구분, 구분 불가하면 미확인 표시 |
| MVP | 흐름 방향·태그가 없음 | 방향·태그 미확인 유지, 값 생성 금지 |
| MVP | 작성 규칙에 없는 `kind` 값 | 미분류로 유지하고 문제 목록에 표시 |
| 후속 | 수동 추가·수정·연결 해제 | 이력·근거 보존, 동일 규칙 재검증 |
| 후속 | 수동 보정 후 같은 영역 재추출 | 보정 유지 또는 변경 검토, 무단 덮어쓰기 금지 |
| 후속 | 전체 추출 후 선택 구간 재처리 | 범위 밖 결과 보존, 경계 연결 검토, 중복 생성 금지 |
| 후속 | AI 보정 제안이 잘못된 참조를 포함 | 형식 오류 검출, 정상 관계로 포함하지 않음 |

### 판정 기준

구조 검증은 ID·참조·좌표계·출처·필수 필드와 관계 종류를 검사합니다. 미해결 연결은 문제 목록으로 보관하고 정상 연결과 구분합니다. 통합 전달용 버전에는 검증 보고서와 사람의 대조 상태가 있어야 합니다. 잘못된 참조 등의 차단 오류가 있으면 반려하고, 형식에 맞게 표시한 미확인 값은 목록과 함께 전달할 수 있습니다.

추출 품질은 정답 대비 객체 분류·태그·연결 관계의 정밀도·재현율로 평가합니다. 작성 규칙을 따른 샘플에서는 높은 정확도가 예상되므로, 실제 도면 자료형의 성능은 어댑터 추가 시 별도로 평가합니다. 벡터 PDF의 읽기 품질은 아래 [읽기 품질 지표](#read-quality)로 잽니다.

## 읽기 품질 지표

도면을 얼마나 바르게 읽었는지를 기호 종류, 태그·번호, 연결, 속성 네 항목의 정확도로 잽니다. 처음 목표는 네 항목 모두 95%, 최종 목표는 100%입니다(사용자 결정 2026-11-13, DEC-0298·0299, `INTENT.md` §3.2). 세부 규칙은 총괄 위임으로 정했습니다(D-read 단위 2026-11-13). 검사는 `scripts/check_read_quality.py`, 시험은 `tests/test_read_quality.py`, 기준값은 `tests/baselines/read_quality.json`입니다.

### 네 항목

| 항목 | 정답 단위(분모로 세는 것) | 맞음 | 오검출(정답에 없는데 추출이 낸 것) |
| --- | --- | --- | --- |
| 기호 종류 | 정답지의 기호 하나. 밸브·계기·설비·배관 부속과 도면 밖 연결 화살표. 티·엘보·선 교차는 기호가 아님 | 짝지은 추출 노드의 `kind`가 같음. 사전과 정답지가 같은 기호를 달리 부르는 `psv`와 `relief_valve`는 같은 것으로 봄 | 정답 영역 안에서 정답 기호와 짝이 없는, 종류가 붙은 추출 노드(티 제외). 미분류 노드는 아무 종류도 주장하지 않았으므로 세지 않음 |
| 태그·번호 | 숫자가 든 이름표가 붙은 기호 하나. 설비 태그(`HE01A`), 밸브 번호(`V1143`, 원 안의 `021`), 계기 기능 문자와 루프 번호(`FT 073C`). 루프 번호 없이 기능 문자만 있는 `PI`는 식별자가 아니므로 세지 않음. 배관 번호는 속성에서 셈 | 글자와 숫자만 견줘 같음. 도면에 찍히지 않은 계통 앞머리를 추출기가 붙인 것(`TE 110` → `RC-TE110`)은 같은 태그. 찍힌 앞머리를 빠뜨리면 틀림 | 이름표가 없는 정답 기호에 붙인 태그, 정답 영역 안에서 짝 없는 노드에 붙인 태그. 짝지은 기호에 다른 글자를 붙인 것은 놓친 것으로만 셈 |
| 연결 | (가) 기호 쌍: 공정 배관이나 덕트로 사이에 다른 기호 없이 이어진 두 기호. 티·엘보·분기점은 지나가므로 한 분기점에서 만나는 기호는 서로 모두 쌍. 점 없이 엇갈리는 선은 이어지지 않음. 계기(전송기·지시계·조절기·스위치·기록계·온도 요소)가 낀 쌍은 계측 연결이라 세지 않음. 배관 안의 유량 요소는 셈. (나) 흐름 방향: 두 기호 사이 배관에 화살표가 있는 쌍. (다) 도면 밖 연결: 연결 화살표 하나 | (가) 추출 그래프에서 정답과 짝지은 두 노드가 짝 없는 노드(티·미분류 등)만 지나 `physical_connection`으로 닿음. (나) 그 길의 관계가 모두 같은 쪽 `flow_direction`. (다) 계통 약어(시트 번호가 둘 다 있으면 시트까지)가 같거나, 도면번호가 같거나 이름표 글자에 그대로 들어 있음. 계통도 도면번호도 없이 이름만 적힌 표기(`SERVICE AIR`)는 이름표 글자가 같으면 맞음 | (가) 정답에 없는 기호 쌍 |
| 속성 | 기호 옆에 찍힌 밸브 정상 위치(`NO`·`NC`·`LO`·`LC`·`LT`)와 실패 위치(`FO`·`FC`·`FL`·`FAI`) 하나, 글자가 없어도 몸통을 검게 칠해 정상 닫힘을 뜻하는 밸브(DCD 범례 1.7-1 1/4)의 정상 위치 `NC` 하나, 배관 옆에 찍힌 구경·배관 번호·재질·설계압력 글자 하나 | 위치: 짝지은 노드의 같은 속성 값이 같음. 배관 글자: 그 글자가 가리키는 배관 위 점에서 8pt 안을 지나는 추출 관계 가운데 하나가 같은 값(구경은 숫자와 `/`·`.`만 견줌) | 정답에 없는 위치 속성, 정답 배관 글자 근처를 지나지 않는 관계에 붙은 배관 속성 |

**위치 속성의 출처.** 정답지는 정상 위치마다 출처를 `position_sources`에 `text`(찍힌 글자)·`shape`(검게 칠한 몸통)·`text+shape`로 적습니다. 둘 다 있으면 글자 값이 정답입니다(`LC`는 `NC`를 더 자세히 쓴 것). 몸통은 닫힘인데 글자가 열림(`NO`·`LO`·`LT`)이면 글자 값을 정답으로 두고 그 기호를 `position_conflicts`에 남깁니다. 반쪽만 칠한 몸통은 범례에서 다른 기호라 정상 닫힘으로 세지 않습니다. 이 단위는 총괄 판정(2026-11-14, 사용자 위임)으로 들였습니다. 이 규칙을 들이기 전의 값과 섞지 않도록 기록은 정의 변경 앞뒤를 나란히 적습니다.

정확도는 **맞은 수 / (정답 단위 수 + 오검출 수)**입니다. 놓친 것과 잘못 낸 것을 한 값에 함께 담으려고 오검출을 분모에 더합니다. 보고는 `맞은 수/분모 @커밋`으로 하고 분모는 정답 단위 수와 오검출 수의 합입니다. 연결 항목은 (가)(나)(다)를 더한 값이고 검사는 셋을 따로도 찍습니다.

연결을 '분기점에서 만나는 기호끼리 모두 쌍'으로 세면 긴 모관에 기호가 많은 쪽(105쪽 주증기관)에서 쌍이 수백 개가 되고, 모관 한 곳이 끊기면 쌍이 한꺼번에 빠집니다. 정답지를 사람이 분기점 없이 쓸 수 있게 하려고 고른 규칙이며, 분기점을 노드로 적는 방식은 후속으로 둡니다.

### 맞춤과 위치 허용 오차

정답 기호의 가운데가 추출 노드 상자를 4pt 넓힌 안에 있거나 두 가운데가 10pt 안이면 짝 후보입니다. 가까운 것부터 하나씩 짝짓고, 종류가 붙은 노드와 먼저 짝지은 뒤 남은 기호를 미분류 노드와 짝짓습니다. 정답 좌표는 10pt 격자 그림에서 ±3pt로 읽고, APR1400 밸브 몸통은 폭 8~12pt라서 이 값으로 정했습니다. 정답지의 `regions` 밖에 있는 추출 노드는 오검출로 세지 않습니다.

### 기존 검사와의 관계

- `check_apr1400.py`의 대리 지표(계기 원 태그 `tag_exact` 872/1619 @ae51cf5)는 계기 원 글자의 재현율만 봅니다. 새 태그·번호 항목은 계기 태그를 포함하고 밸브 번호와 설비 태그로 넓힌 것입니다.
- `tests/fixtures/apr1400/answer_key/`의 `instruments`·`valve_numbers`·`valve_positions`·`connectors`는 새 정답지의 `symbols`(태그), 기호 `attributes`, `continuations`로 옮겼습니다(012·062·063쪽을 그림으로 다시 확인).
- 두 검사는 따로 돌고 기준값도 따로입니다. `check_apr1400.py`의 기준값과 톱니는 그대로 둡니다.

### 스크립트만과 스크립트 + AI 후보

두 값을 따로 냅니다. '스크립트만'은 결정적 추출 결과 그대로입니다. '스크립트 + AI 후보'는 사람이 손대기 전에 AI 검토(R2 단위)가 낸 후보를 아래 규칙으로 받아들인 결과입니다.

- 후보가 여러 개면 **첫 후보만** 받아들인 것으로 봅니다. 확신도는 세는 데 쓰지 않습니다.
- 첫 후보가 틀리면 스크립트가 맞게 읽은 값도 틀린 것이 됩니다. 사람이 고르기 전 값을 재는 것이므로 후보를 그대로 믿었을 때의 값을 냅니다.
- 새 기호 후보는 그 상자 자리에 노드를 더한 것으로, 끊긴 연결 후보는 두 노드 사이 관계를 더한 것으로 봅니다.
- 후보 파일은 쪽마다 `<정답지 이름>.json`이고 `--ai-candidates <폴더>`로 넘깁니다. 꼴은 `{"candidates": [...]}`이며 후보 하나는 다음 셋 가운데 하나입니다.
  - 기호 값: `{"node_local_id" 또는 "new_id"+"bbox", "field": "kind|tag|normal_position|fail_position|to_system", "values": [...]}`. `to_system`(도면 밖 연결 계통 약어)은 그 노드의 `attributes.to_system`으로 넣어 연결 (다) 판정에 씁니다
  - 연결: `{"field": "connection", "a": 노드, "b": 노드, "values": ["connected"]}`
  - 배관 값: `{"relation_local_id", "field": "size|line_no|material|design_pressure", "values": [...]}`
- 확신 높은 후보만 묶어 받아들인 값은 R2가 셋째 값으로 더 낼 수 있습니다. 95% 판정에는 쓰지 않습니다.

### AI 검토 실행(R2)

`hazop/extract/ai_review.py`(Qt 없음), 화면은 `hazop/app/screens/ai_review_panel.py`와 ① 등록 화면입니다. 2026-11-13 R2 단위에서 총괄 지시대로 정했습니다.

- **켜기.** ① 등록 화면에 '추출 뒤 AI 검토' 토글을 둡니다. 기본은 꺼짐입니다. 켜면 도면당 호출 상한(기본 20회)과 대상 쪽(추출한 모든 쪽, 첫 쪽만)을 고르고 예상 호출 수·시간을 봅니다. AI 연결을 쓸 수 없으면 토글 대신 안내만 보입니다([채팅 규격 §8](chat-panel.md#8-배포본과-구독이-없는-pc)과 같은 문구 방식). 추출은 그대로 스크립트만으로 됩니다.
- **묻는 곳과 순서.** 종류를 못 정한 기호(추출 결과에 `missing_kind` 미확인이 있는 미분류 노드. 안전등급 경계 마름모처럼 스크립트가 일부러 종류를 비우고 `evidence.classification_basis`로 무엇인지 아는 표시는 묻지 않습니다) → 이름표가 없는 밸브·계기·설비와 정상·고장 위치가 필요한데 없는 밸브 → 한쪽 끝이 빈 배관(열린 끝에서 30pt 안의 기호 가운데 하나를 고름)과 목적지를 못 읽은 도면 밖 연결 표기 → 읽은 결과 표본 5곳 다시 확인(도면 번호로 정한 씨앗). 호출 하나에 20곳씩 묶습니다. 상한에 닿으면 남은 곳은 묻지 않고 그 수를 진행 줄과 결과에 보입니다.
- **그림 대신 글.** 구독 CLI 호출(`claude_cli.ClaudeCliClient.analyze`)은 표준 입력으로 글만 보내고 도구를 모두 끕니다. 그림 파일을 넘길 길이 없어, 그 자리의 상자 좌표, 주변 40pt 안의 글자와 상대 위치, 60pt 안의 이웃 기호(종류·태그·크기), 열린 끝 근처 후보 기호를 JSON 글로 풀어 보냅니다. 그림을 넘기려면 CLI의 stream-json 입력에 그림 블록을 싣는 기능이 `claude_cli.py`에 있어야 합니다(그 파일 주인 단위 몫).
- **답 검사.** 답은 JSON 스키마로 받고, 물은 필드만, 종류는 사전 목록 안(이웃 기호의 일부·글자 상자·선 조각이면 `not_symbol`로 답하고 후보를 만들지 않음), 위치 약어는 허용값 안, 연결은 준 후보 가운데 하나나 `none`, 태그는 숫자가 든 글자만 받습니다. 어긋난 답은 버리고 수를 셉니다. 다시 확인 표본에서 지금 값과 같은 답은 '확인'으로만 셉니다.
- **저장과 확정.** 후보는 추출 결과를 바꾸지 않고 `<작업 루트>/data/ai-review/<추출 이름>.json`에 `origin: ai`, 확신도, 근거, 상태(후보·수락·거절)로 둡니다. 수락하면 사람 수정 기록(`corrections`)에 `set_kind`·`set_tag`·`set_normal_position`·`set_fail_position`·`set_endpoint` 연산을 더하고, 그 연산에 `origin: "ai"`, `ai_candidate`(후보 번호), `accepted_by`, `accepted_at`을 적습니다. 되돌리면 그 연산을 지웁니다. 그래서 AI 검토 없이 다시 추출하면 스크립트 결과는 늘 같습니다. 도면 밖 연결의 계통 약어(`to_system`)는 맞는 수정 연산이 없어 후보 문서에만 남습니다(후속).
- **사람 수정 지키기.** 사람 수정 기록에서 `origin: ai`가 아닌 연산이 가리키는 자리의 후보는 수락하지 않습니다(`INTENT.md` §4 사람이 고친 것은 잃지 않는다). AI 검토는 이미 정한 자리(사람이 고친 자리, AI 후보를 수락한 자리, 거절한 후보의 자리)를 다시 묻지 않고 예상 호출 수에도 넣지 않습니다. 되돌린 후보의 자리는 다시 묻습니다.
- **함께 쓰기.** 후보 문서는 읽은 판의 지문으로 저장해, 그새 다른 쪽(작업 스레드·다른 창)이 바꿨으면 거절합니다. 수락·되돌리기는 후보 문서가 읽은 판인지 먼저 보고, 사람 수정 기록과 후보 문서를 함께 씁니다(뒤쪽이 실패하면 앞쪽을 되돌림). 작업 스레드의 저장은 거절되면 다시 읽어 합칩니다.
- **연결 방식.** 사용자 결정(AI 검토는 구독제 연결로 돈다)에 따라 API 연결이면 돌리지 않고 안내를 돌려줍니다.
- **확정 창.** 후보는 할 일(못 읽은 기호의 종류, 태그·속성, 끊긴 연결, 다시 확인)별로 보입니다. 확신도 0.85 이상인 태그·속성·연결 후보는 할 일별로 묶어 한 번에 수락하고(확인을 한 번 거침), 기호 종류 후보와 다시 확인에서 스크립트와 다른 값이 나온 후보는 확신도와 관계없이 묶음에서 빼고 하나씩 확정합니다(AI 종류 후보가 미분류 조각·이웃 기호의 일부에 종류를 붙여 오검출이 늘었기 때문, 읽기 품질 기록 'AI 후보 포함' @1731277). 후보를 누르면 도면의 그 자리로 가서 강조합니다. 수락·거절은 되돌릴 수 있습니다. 새 화면(`hazop/shell/api_aireview.py`)은 수락·되돌리기 뒤 그 도면의 그래프와 지식그래프를 바로 다시 만들고, 다시 만들기가 실패하면 저장은 그대로 두고 '그래프가 낡음' 표시를 남겨 다음에 열 때·다음 결정 때 다시 만듭니다. 쓰기는 추출 결과·사람 수정 기록·AI 후보 세 파일의 지문(쪽 확정과 같은 세 파일)을 대조합니다.
- **멈춤과 상한.** 응답 상태와 관계없이 `error_kind`로 `providers.halts`(한도·초과 사용·인증·취소는 바로, 같은 오류 3번이면) 규칙을 따릅니다. 호출은 끝났는데 한도·초과 사용이 온 응답은 받은 답을 반영하고 남은 호출을 멈춥니다. 도면당 상한(기본 20회)과 한 번 실행 상한(300회, `RUN_CAP`)을 로직이 함께 지킵니다. 추출 전 예상은 실제 PDF를 분석해 쪽마다 미확인 수로 셉니다(`estimate_pdf`·`estimate_pages`). 진행 줄에 호출 수와 남은 곳을 보이고 '멈추기'는 다음 호출 전에 멈추며 진행 중인 호출을 끊습니다. 호출 중 예외는 실행을 죽이지 않고 오류로 셉니다.
- **답 검사(덧붙임).** 확신도는 0~1의 수만, 태그는 24자 이하이고 그 자리 주변 글자(또는 지금 이름표 글자)에 실제로 있는 글자만 받습니다. 어긋난 답은 그 후보만 버립니다. 지시문에는 정답지·표본 도면의 값을 넣지 않고(시험으로 확인), 맥락의 글자는 자료이지 지시가 아니라고 적습니다.
- **검사.** `check_read_quality.py --ai-run subscription|fixed --ai-cap N --only <쪽> --ai-save <폴더>`가 쪽마다 AI 검토를 돌려 두 값을 함께 냅니다. 남긴 후보 파일은 `--ai-candidates <폴더>`로 다시 잴 수 있습니다. 이 값은 실제 AI에 따라 달라지므로 기준값 톱니에 넣지 않습니다.
- **실측.** 조건(모델·명령·후보 파일·커밋)과 값은 `docs/units/2026-11-13-drawing-knowledge/evidence/ai-review-measure.md`에 둡니다.

### 정답지 절차

1. **그림만 보고 쓴다.** 정답지는 쪽을 렌더한 그림(`check_read_quality.py tiles`, 10pt 격자 타일)에서만 씁니다. 추출 코드·추출 결과·기준값을 열지 않고, PDF 텍스트 층으로 글자를 읽지 않습니다. 추출이 틀린 값을 정답지가 따라가는 순환 채점을 막기 위해서입니다. 작성 지침은 `D:\HAZOP-trials\2026-11-13-answer-key\KEY-GUIDE.md`(저장소 밖)에 두었습니다.
2. **형식.** `tests/fixtures/read-quality/apr1400/apr1400-<순번>.json`, `schema: hazop_read_quality_key`, `version: 1`. 좌표 규약(PDF pt, 왼쪽 위 원점, `[x0, y0, x1, y1]`)과 `method`·`verified`·`scope` 같은 기록 칸은 기존 `answer_key` 형식을 따르고, 내용은 `symbols`(종류·상자·태그·위치 속성), `lines`(배관 글자), `connections`, `continuations`, `regions`로 넓혔습니다. 기존 폴더에 쪽을 더하지 않고 새 폴더를 쓴 이유는 `check_apr1400.py`가 `answer_key/` 전체를 읽어 그 기준값에 묶여 있기 때문입니다.
3. **독립 두 판과 판정.** 같은 쪽을 다른 하위 에이전트가 첫 판을 보지 않고 한 번 더 씁니다(영역만 같게 줌). 두 판을 `check_read_quality.py compare <B 폴더> <출력> --crops`로 위치 맞춤해 견주고, 항목별 일치율(기호 유무·종류·태그·속성·연결)을 기록합니다. 어긋난 항목은 셋째 에이전트가 그림 조각과 타일만 보고 A·B·둘 다 아님 가운데 하나로 판정하고, 판정 기록을 남깁니다. 저장소 정답지는 판정을 반영한 최종본입니다. 총괄 지시(2026-11-13)로 사용자 표본 확인을 기다리지 않고 이 절차로 정답지 품질을 지킵니다. 근거와 일치율은 `docs/units/2026-11-13-drawing-knowledge/evidence/answer-key-agreement.md`에 둡니다.
4. **사용자 확인.** 쪽마다 정답 단위 전체에서 무작위로 20건을 뽑습니다(`check_read_quality.py sample`, 씨앗 20261113 + 순번). 사용자는 목록과 그림 조각을 보고 맞음·틀림을 적습니다. 20건 가운데 **틀림이 1건 이하면** 그 건을 고쳐 정답지를 채택하고, **2건 이상이면** 그 쪽을 다시 씁니다(다시 쓴 쪽은 새로 20건을 뽑음). 정답지 오류가 95% 목표를 흔들지 않으려면 오류율이 몇 % 아래여야 하는데, 오류율 5%인 정답지는 20건에서 2건 이상 걸릴 확률이 약 26%, 오류율 1%면 약 2%라서 이 선으로 정했습니다. 확인 결과는 쪽마다 확인 건수·일치 건수·일치율·확인한 사람과 날짜로 정답지의 `verified`와 작업 단위 근거 문서에 적습니다.
5. **가상 도면(SNP).** `resources/references/pid-samples/`의 SNP 6벌은 사람이 그린 drawio 원본이 정답입니다(순환 채점이 아님). drawio 좌표를 PDF 좌표로 옮기는 배율과 이동은 계기 원의 두 줄 이름표(`TT` 위 `110`)를 PDF 낱말 쌍과 맞춰 구하고, 맞춘 짝이 1pt 안에 들어야 씁니다(6벌 모두 배율 0.7188, 이동 (0.4, 0.7)). 글자 값(태그·배관 번호·밸브 위치)은 PDF에 실제로 찍힌 것만 정답에 둡니다. PDF 텍스트 층은 찍혔는지 거르는 데만 씁니다.

### AI 검토 호출 수

AI 검토는 못 읽은 것을 묶어 한 번에 보냅니다. 쪽 하나의 호출 수는

> 호출 수 = ⌈미분류 노드 / b⌉ + ⌈태그 없는 밸브·계기·설비 / b⌉ + ⌈열린 끝 / b⌉ + r

로 어림합니다. b는 호출 하나에 넣는 그림 조각 수, r은 읽은 결과 다시 확인에 쓰는 호출 수(쪽마다 1)입니다. 권장값은 b = 20입니다(조각 하나가 작아 한 호출에 20개를 넣어도 답이 길어지지 않음).

143쪽 전체를 지금 추출기로 센 값(2026-11-13, 커밋 47f1283의 `pdf_vector`, 시험용 venv): 미분류 노드 6,976, 태그 없는 밸브·계기·설비 3,507, 열린 끝(`unresolved_connectors`) 11,726. 쪽마다 올림해 더하면 다음과 같습니다.

| b | 143쪽 합계 | 쪽당 중앙값 | 쪽당 90% | 쪽당 최대 |
| --- | --- | --- | --- | --- |
| 10 | 2,553 | 16 | 37 | 70 |
| 20 | 1,453 | 9 | 19 | 36 |
| 30 | 1,102 | 7 | 14 | 24 |

열린 끝이 호출의 절반 가까이를 차지합니다. 열린 끝에는 짧은 선 조각도 들어 있어, 연결 후보로 보낼 것을 거르면 호출이 줄어듭니다(R2에서 정함).

**기본 상한(권장).** 쪽당 20회(90%의 쪽이 다 들어감), 한 번 실행에 300회입니다. 추출 전에 예상 호출 수와 상한을 보여 주고, 사람이 상한을 바꿀 수 있습니다. 상한에 닿으면 미분류 기호 → 태그 없는 기호 → 열린 끝 → 다시 확인 순서로 보내고 나머지는 '보내지 않음'으로 남깁니다. 구독 연결은 호출당 비용을 재지 않으므로 상한은 호출 수로만 겁니다(`CLAUDE.md` 규칙 16).
