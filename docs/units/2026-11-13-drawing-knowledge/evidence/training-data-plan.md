# 기호 검출 학습 자료를 AI로 만드는 길 (2026-11-14)

## 결론

1. **AI로 정답지를 만들 수 있고, 벡터 반자동 (나)가 가장 싸고 정확합니다.** APR1400 두 쪽 시험에서 기호 종류 122/154(79.2%), 태그 108/126(85.7%)였습니다. 같은 쪽을 스크립트만으로 읽으면 기호 종류가 81/150(54.0%)입니다. 스크립트와 AI가 같은 종류를 낸 라벨은 77개 가운데 76개가 맞아, 이것은 사람 확인 없이 받고 나머지 약 40%만 사람이 봅니다.
2. **(가) 합성은 정답이 100%지만 모양이 실제 도면과 다릅니다.** 가상 도면 6장과 무작위 20쪽의 정답을 스크립트가 6초 안에 만듭니다. 합성만으로 학습하면 실제 도면에서 크게 떨어진다는 보고가 있어, 사전 학습과 드문 종류 보충에만 씁니다.
3. **이 PC에서는 학습할 수 없습니다.** NVIDIA GPU가 없고 AMD 내장 그래픽(512MB)뿐입니다. 학습은 GPU가 있는 곳에서 하고, 앱은 ONNX Runtime으로 CPU에서 추론합니다.
4. **APR1400 DCD는 열람만 공개입니다.** 원본 1장 PDF 둘째 쪽에 KHNP의 "All Rights Reserved" 표시와 함께, NRC의 설계인증 검토 밖의 복제·사용·배포를 금한다는 문구가 있습니다. 쪽 그림, 그림 조각, 그것으로 학습한 가중치는 공개 저장소에 넣지 않고, 쓸 범위는 사용자가 정해야 합니다(§5).
5. **권장 순서.** (나)로 APR1400 학습 후보 102쪽을 만들고(구독 호출 약 550회), 합성으로 사전 학습한 RF-DETR Nano를 그 자료로 미세 조정합니다. 12쪽 시험 집합에서 기호 종류가 스크립트 + AI 후보보다 낫지 않으면 멈춥니다(§6).

## 2. 작은 시험

### 2.1 (나) APR1400 012·063쪽

**방법.** `scripts/train-data/build_vector_labels.py`가 다음 순서로 만듭니다.

1. `pdf_vector.extract`의 기호 후보(분기점 제외)마다 둘레를 360dpi로 잘라 빨간 상자를 그립니다.
2. 조각 20개를 한 장에 모아 구독 AI(`claude-opus-5-5`, 강도 medium)에 묻습니다. 묻는 것은 종류(작성 규칙 종류 59개 + `unlisted` + `not_symbol`), 이름표, 상자가 기호 하나를 덮는지입니다.
3. 스크립트가 정한 종류는 AI에 알려 주지 않았습니다.
4. 정답지는 만드는 동안 읽지 않았고, 다 만든 뒤 `compare_vector_labels.py`로 견줬습니다.

- 그림을 보내는 호출은 앱의 구독 클라이언트를 넓힌 `vision_client.py`가 합니다. stream-json 입력에 PNG를 넣고, 인증·한도 처리는 앱 것을 그대로 씁니다.
- 셈은 읽기 품질 지표와 같습니다(`check_read_quality.score_kind`·`score_tag`, 맞은 수/(정답 단위 + 오검출)).

**호출과 시간.** 모두 45회, 실패 0입니다. 과금은 모두 구독(`billing: plan`)이었습니다.

## 3. 학습 자료의 꼴과 양

### 3.1 꼴

세 파일 모두 쪽 그림 하나에 맞춥니다. 좌표는 픽셀, 쪽 그림은 200dpi 회색조입니다. 같은 꼴을 세 길이 함께 쓰므로 섞어 학습할 수 있습니다(`scripts/train-data/coco_format.py`).

| 학습 대상 | 파일 | 꼴 |
| --- | --- | --- |
| 기호 검출(상자 + 종류) | `symbols.coco.json` | COCO 검출. 범주는 작성 규칙 종류 59개에서 `tee`를 빼고 `unlisted`를 더한 59개. 주석마다 `attributes`에 `tag`, `label_source`(drawio·generator·script·ai), `box_flag` |
| 글자 영역 | `text.coco.json` | COCO 검출, 범주 `text` 하나, `attributes.text`에 글자. 글자 인식 학습용 조각은 여기서 잘라 씀 |
| 선·연결 | `graph.json` | 쪽마다 `nodes`(기호 주석 id), `edges`(배관으로 바로 이어진 기호 쌍, 흐름 방향), `pipes_px`(배관 꺾은선). PID2Graph의 graphml로 바꾸기 쉬운 꼴 |

APR1400 (나) 자료는 지금 기호만 만듭니다.
- 글자 영역은 벡터 PDF 텍스트 층의 낱말 상자를 그대로 쓰면 됩니다. 사람이 그린 정답이 아니라 PDF에 찍힌 글자이므로 순환 채점이 아닙니다.
- 연결은 추출기 값(연결 46.5%)이 낮아 아직 정답으로 쓰지 않습니다.

### 3.3 종류 불균형

정답지 12쪽(1,270개)의 종류 분포:
- 많은 쪽: manual_valve 236, continuation 154, transmitter 67, relief_valve·check_valve 62, motor_operated_valve 61.
- 10개 아래인 종류가 20개쯤입니다(sight_glass 1, nozzle 1, pressurizer 1, chiller 2 등).

드문 종류는 이렇게 다룹니다.
- 검출기 범주를 처음에는 묶습니다. 예를 들어 설비 대부분을 `equipment`로, 드문 배관 부속을 `fitting_other`로 묶고, 세부 종류는 지금처럼 스크립트(설비 태그·범례 견본)가 정합니다.
- 생성기에서 드문 종류를 일부러 더 자주 그립니다.
- 실제 쪽의 드문 기호 조각을 합성 쪽에 붙이는 copy-paste 보강을 씁니다.
- 학습 자료의 종류별 개수는 만들 때마다 표로 남깁니다(스크립트가 이미 찍음).

### 3.4 쪽 나누기

- **시험.** 정답지 12쪽만 씁니다. 학습·검증에는 넣지 않습니다. 같은 그림의 다른 시트(25쪽)도 학습에서 뺍니다. 같은 계통은 기호 배치·태그 체계·밸브 번호가 이어지므로, 섞이면 시험 값이 부풀기 때문입니다.
- **검증.** 남은 102쪽을 그림번호 단위로 묶어 약 15%(15쪽 안팎)를 떼어 둡니다.
- **학습.** 나머지 약 87쪽 + 합성 + SNP 6장입니다. SNP 6장은 그림 하나가 한 묶음이라 검증에 넣어 합성 → 실제 차이를 따로 볼 수도 있습니다.
- 나누기는 `group` 칸(그림번호, SNP는 도면 계열)으로 하고, 스크립트가 같은 group이 두 쪽에 걸치지 않는지 검사하게 합니다(다음 단위).
