# 지식그래프 다시 만들기 시간 줄이기 (`hazop/kg/auto.py` `build_project`)

측정: 2026-11-14, 하위 세션 d-kg(Opus 5.5 medium). 도구는 `D:\HAZOP-trials\2026-11-14-kg-panel\kgperf.py`이고, 원본 출력은 같은 폴더의 `eq-*.txt`다. 다른 세션이 함께 돌던 조건이다.

**조건.**
- APR1400: S-viewer 측정 루트의 `graph.json` 143개(70MB)만 이 폴더 `work-kgperf/apr`에 복사했다. 문서 지식은 없다.
- SNP: 샘플 6장을 추출하고 프로젝트를 `SNP-SAMPLE`로 묶었다.
- 고치기 전 코드는 HEAD 분리 작업트리(측정 뒤 지움)에서, 고친 뒤 코드는 작업 폴더에서 같은 입력으로 돌렸다.

**무엇을 바꿨나.**
1. **도면 읽기 캐시:** `auto.project_graphs`가 도면 `graph.json`을 바뀐 시각·크기를 열쇠로 기억한다. `graph_head`와 같은 열쇠다. 고친 쪽만 다시 읽고, 지운 도면은 잊는다. 고치기 전에는 다시 만들 때마다 143쪽을 모두 읽었다(cProfile 1.2초).
2. **한 번만 직렬화:** `build.write_outputs`가 새 버전 폴더를 쓸 때, 해시를 내려고 이미 만든 바이트를 그대로 쓴다. 전에는 `knowledge_graph.json`을 두 번 직렬화했다.
3. **메모리:** 파싱한 도면 143장을 기억하는 데 약 163MB가 든다(tracemalloc).

**같음(결과 바이트, sha256 앞 12자).** 고치기 전 코드와 고친 뒤 코드가 같은 입력에서 같은 파일을 냈다. '캐시를 비운 뒤 짓기'는 같은 프로세스에서 `forget_graphs`·`forget_heads`를 부른 뒤 다시 지은 것이고, 이것도 캐시를 둔 짓기와 바이트가 같았다.

| 입력 | 짓기 | knowledge.json | knowledge_graph.json |
| --- | --- | --- | --- |
| SNP 6장 | 그대로 | da85ce0ca5d1 | 39baa9b80701 |
| SNP 6장 | 첫 쪽 태그 하나·판 바꿈 | da85ce0ca5d1 | 3962f1379f5a |
| APR1400 143쪽 | 그대로 | 41ffcbdaa162 | 4ec1961beb45 |
| APR1400 143쪽 | 첫 쪽 태그 하나·판 바꿈 | 41ffcbdaa162 | 97acce60085d |

이 같음은 `tests.test_kg_auto.RebuildCacheTest`로 고정했다.
- 캐시를 둔 짓기 = 처음부터 짓기
- 고친 쪽을 다시 읽음
- 빌드가 캐시한 도면을 바꾸지 않음
- 직렬화 횟수

**시간(ms, APR1400).**

| 짓기 | 고치기 전 | 고친 뒤 |

| 처음(같은 프로세스 첫 번째) | 1402.7 | 1132.5 |

- **한 쪽을 고친 뒤 다시 짓기:** 이 실행에서 1.3초에서 0.54초로 줄었고, 목표 1초 안이다.
- **값의 범위:** 앞선 cProfile 없는 실행(같은 날, 같은 입력, 고치기 전 코드)은 2.6·1.9·2.2초였다. `shell-perf.md`의 S-viewer 측정은 2.2~3.5초다. 컴퓨터 부하에 따라 값이 두 배쯤 달라지니 위 값은 범위로 읽는다.
- **남은 몫:** `knowledge_graph.json` 직렬화(들여쓰기 2, 키 정렬)와 `build_kg`(쪽별 속성 근거 `claims.drawing_claims` 포함)다. 직렬화 형식은 결과 바이트라 바꾸지 않았다. Python 3.12의 C 인코더는 들여쓰기를 지원하지 않는다.
