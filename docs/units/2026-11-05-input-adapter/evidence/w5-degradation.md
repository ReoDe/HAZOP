## 1. 산출물·실행

| 경로 | 내용 |
|---|---|
| `scripts/degrade_raster.py` | 샘플 PNG 6장(`check_adapter.raster_samples()`, `.drawio.png` 제외)에 열화를 **한 축씩** 적용해 래스터 어댑터 지표를 잰다. 열화 영상은 실행 중 임시 폴더(`tempfile`)에만 만들고 지운다. 측정 순서는 `check_adapter.evaluate_raster`와 같다(추출 → blocker → 그래프 단계 호환 → `align` 정렬 → 평가 → `RASTER_QUALITY_FLOORS`). 다만 두 번 실행 결정성은 확인하지 않는다. 어댑터 예외는 죽지 않고 결과로 기록한다. `--out 폴더`에 `results.json`·`summary.md`를 남기고, `--only 축`으로 한 축만 잴 수 있다 |

- [사실] 명령: `PYTHONUTF8=1 %USERPROFILE%\.hazop\venv-raster-py312\Scripts\python.exe scripts/degrade_raster.py --out <세션 임시 폴더>`(저장소 밖). 14개 조건 × 6장 = 84회를 실행했고, 1회에 1.1~4.5초가 걸렸다.
- 열화 방법(Pillow 13.0.0·numpy 2.5.4):
  - 해상도: LANCZOS로 가로·세로를 같은 비율로 줄였다.
  - 잡음: 회색조(L)로 바꾼 뒤 가우시안 잡음 N(0, σ²)을 더하고 0~255로 잘랐다(σ는 회색 단계). 샘플별로 씨앗을 고정했다.
  - 회전: 중심 기준 반시계로 돌렸다. 크기는 유지하고 빈 곳은 흰색으로 채웠으며 BICUBIC으로 보간했다.
  - JPEG: Pillow에 quality만 지정해 저장했다.
  - 기준(100%·σ0·0°): 원본 PNG 파일을 그대로 썼다. 참고 조건으로 샘플 폴더의 기존 `.jpg`도 쟀다.
- **W3 벡터 PDF는 열화 대상이 아니다.** 벡터 좌표·글자를 직접 읽으므로 해상도·잡음·회전·JPEG 열화가 생기지 않는다. 지표는 [W3 §6](w3-pdf.md)(관계 F1 0.870~1.0)을 그대로 비교 기준으로 둔다. 래스터로 찍은 PDF(스캔 PDF)는 범위 밖이며 이번에 재지 않았다.

## 3. 품질 하한 아래로 떨어지는 시점 [사실]

| 축 | 처음 하한 미달 단계 | 미달 지표 | 관찰 |
|---|---|---|---|
| 해상도 | **75%**(6/6) | 관계·객체 F1, 일부 kind | 50%에서 관계 F1 평균 0.38로 떨어진다. 후보 노드가 늘어난다(예: 201 기준 27개 → 75%에서 50개, 정답 22개). 선·기호가 조각나는 것으로 보인다 |
| 잡음 | **σ5**(3/6), σ10부터 6/6 | **kind 정확도만** | 관계·객체 F1은 σ20까지 모든 샘플이 하한 이상이다. 미확인 수가 늘어난다(예: 401 기준 73건 → σ20에서 88건) |
| 회전 | **0.5°**(4/6) | 관계·객체 F1 | 2°에서 관계 F1 평균 0.45였다. 평가용 기준점 사용 수가 줄어든다(101 기준 16/21 → 2°에서 3/19) |
| JPEG | q75(1/6), q50(3/6) | kind 정확도만 | q95와 샘플 `.jpg`는 0/6이다. 관계·객체 F1은 q50까지 기준과 같다 |

- [사실] 기준과 차이가 거의 없는 열화에서도 한 장의 관계 F1이 크게 움직였다. 102는 잡음 σ5·JPEG q75에서 0.850 → 0.973으로 올랐다. 기준 결과가 규칙 문턱 근처에 걸린 곳이 있어 픽셀이 조금만 바뀌어도 판정이 뒤집힌다는 뜻이다. 따라서 장당 ±0.1 정도의 변동은 측정 잡음으로 본다 [추론].

## 4. 사용 권고 [추론]

아래 권고는 깨끗한 합성 도면 6장(draw.io 출력)으로 잰 결과에서 끌어낸 판단이며, 실제 스캔 도면으로 확인하지 않았다.

1. **해상도**: A3 도면 전체 폭 기준으로 원본 샘플 수준(가로 약 3,270 px, 약 2.75 px/pt ≈ 200 dpi 상당) 이상으로 입력한다. 75%(약 150 dpi 상당)부터 모든 샘플이 하한 아래로 떨어졌으므로, 200 dpi 미만 입력은 결과를 쓰지 않거나 사람이 전수 확인해야 한다. 스캔이라면 300 dpi를 권장한다. 다만 200 dpi보다 높은 해상도에서 지표가 유지되는지는 재지 않았다.
2. **회전**: 어댑터는 가로·세로 획을 기준으로 선을 찾고, 기울기를 보정하는 단계가 없다. 0.5° 기울기에서도 하한 아래로 떨어지므로, 스캔본은 입력 전에 기울기를 0.5° 미만으로 바로잡아야 한다. 앞으로 어댑터에 기울기 보정을 넣을지는 후속 과제다.
3. **JPEG**: 관계·객체 지표는 q50까지 유지됐다. kind 정확도까지 지키려면 q95 이상 또는 PNG를 쓴다.
4. **잡음**: 연결(관계·객체)은 σ20까지 견뎠지만 기호 종류(kind)가 먼저 무너진다. 잡음이 있는 스캔본은 kind 결과를 사람이 확인해야 한다.
5. 하한 미달이어도 blocker가 0이라 추출은 막히지 않는다. 사용자가 품질 저하를 알아챌 수단이 지금은 미확인 수 증가뿐이다. 따라서 해상도·기울기 같은 입력 조건을 미리 점검하는 일이 필요하다.

## 5. 한계·확인 필요

- **회전 결과에는 평가 하네스의 한계가 섞여 있다.** `align.py`는 배율·이동만 맞추고 회전은 맞추지 않는다. 2° 회전이면 도면 가장자리 객체가 정답 좌표에서 최대 약 28 canvas_unit 어긋난다(가로 반폭 약 1,637 px × sin 2° ≈ 57 px, 배율 0.5) [추론]. 그래서 회전에서 떨어진 객체 대응 지표 일부는 어댑터가 아니라 평가 쪽 원인일 수 있으며, 이번 측정으로는 둘을 나누지 못했다. 관계 F1 하락의 주원인은 가로·세로 획 검출로 본다 [추론].
- 해상도 35%의 301·401은 정렬 실패로 지표를 재지 못했다(하한 미달로 셌다).
- 축을 하나씩만 바꿨다. 실제 스캔처럼 저해상도·잡음·기울기가 겹친 조합은 재지 않았다.
- 잡음 조건은 회색조로 바꾼 뒤 잡음을 더했다. 기준은 원본 RGB 파일이므로 σ5에는 회색조 변환 차이도 함께 들어 있다(어댑터는 어느 쪽이든 회색조로 읽는다).
- 표본 6장 안에서 정한 규칙·문턱 위에서 잰 것이다([W4 §8](w4-raster.md)). 실제 도면에서는 기준선 자체가 더 낮을 것이다.
- W1 §8 `W5` 완료 기준 중 `specs/extraction.md` 다른 자료형 절 갱신안은 이번 작업지시서 범위 밖이라 쓰지 않았다(기획서는 수정 금지).

## 6. 직접 검증할 부분

- 열화 영상 몇 장을 직접 만들어(예: `--only rotate`) 결과 extraction을 영상과 겹쳐 보고, 회전 하락이 선 검출 때문인지 대응 거리 때문인지 표본 확인할 것.
- 권고 1의 dpi 환산은 "이미지 폭 = A3 가로(420 mm)" 가정에 기댄다. 실제 스캔 도면의 용지와 여백으로 다시 확인할 것.
