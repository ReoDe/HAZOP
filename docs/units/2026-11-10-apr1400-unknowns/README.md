## 2. 근본 원인과 단위

### 3a. 신호선 빗금(//)이 배관 가지가 됨

APR1400은 공압 신호선을 실선 위 빗금 두 줄(//)로 그린다(범례 1.7-1 4/4). 빗금 한 줄은 1~2pt라 끝이 선 끝 맞춤 허용 오차(1.5pt) 안에 들어온다. 그래서 추출기가 빗금마다 배관 분기점을 만들고, 빗금과 그 사이 토막을 같은 분기점으로 돌아오는 자기 고리 조각으로 만들었다. 계기 공기선 자체도 공정 배관(`physical_connection`)으로 남았다.

고친 것은 다음과 같다.
- **빗금 판정.** 4pt 이하 직선 조각이 10pt 이상 열린 선을 비스듬히(30~80°) 실제로 가로질러야 한다. 두 끝이 선의 양쪽에 떨어져 있어야 하므로, 한 끝만 닿은 탭은 빗금이 아니다. 빗금은 가장 가까운 선 하나에만 딸린다. 평행하고 가까운 빗금 2~3개가 묶음 하나이고, 묶음이 둘 이상인 선만 신호선 후보다.
- **빗금 빼기.** 빗금은 기호 묶기가 끝난 뒤 남은 선에서만 뺀다. 기호 장식선으로 흡수된 빗금은 그대로 두므로, 143쪽 모든 기호 노드의 id·kind·위치가 바뀌기 전과 같다. 뺀 빗금은 `ignored_objects`(`line_tick`)에 남긴다.
- **공압 신호선 표시.** 빗금 선으로만 되고 그 사슬 위에 빗금 묶음이 실제로 있는 사슬만 `signal_connection`(`pdf_pneumatic`)이다. 배관과 섞이거나 빗금 없는 쪽 토막이면 배관으로 둔다.
- **분기점 태그.** 계산으로 만든 분기점은 태그가 있을 수 없으므로 `missing_tag`를 남기지 않는다.
- **사람 수정 보존(D14).** 빗금 조각이 빠지면 연결·분기점 번호가 밀린다. 그래서 수정 적용 때 대상 id가 없거나 지문이 다르면, 같은 위치·같은 종류의 대상이 정확히 하나일 때 그 대상에 적용하고 `corrections.retargeted`에 남긴다(`hazop/extract/corrections.py`). 117~125쪽에서 이전 추출로 만든 수정을 새 추출에 대 보니, 살아남은 대상 2,716개 중 2,689개(99%)에 적용됐다. 다른 자리에 들어간 것은 0개다. 남은 27개는 같은 자리 후보가 없거나 둘 이상이라 일부러 적용하지 않았다.

결과는 다음과 같다.
- 미확인 99,308 → 74,974(−24.5%). 자기 고리 12,203 → 6,251, 태그 없음 23,078 → 11,963, 흐름 방향 39,207 → 31,940. 120쪽은 3,111 → 537.
- 태그 정확 781, 연결 표기 284/293, 짝 234, 틀린 대상·틀린 짝 0(후퇴 없음).
- SNP 노드·관계 동일. 분기점 태그 없음 미확인만 6개 도면에서 줄었다.
- 검토(적대 2, Codex 1)에서 바꾼 것: 가로지르지 않는 탭 오인, 한 자리에 몰린 빗금을 묶음 둘로 셈, 나뉜 경로 전파, 빗금을 기호 묶기 전에 빼서 응축기·구동 밸브가 안전밸브로 바뀜, 번호 밀림으로 사람 수정이 빠짐.

### 3c. 매설 배관 무늬의 점이 외톨이 신호선 조각이 됨

APR1400은 매설 배관(BURIED PIPE, 범례 1.7-1 1/4)을 선 위에 작은 검은 점을 찍어 그린다(090쪽 소화 본관, 022쪽 등). 점은 긴 변 1.5pt 이하라 추출기가 채운 점선 조각으로 분류했다. 점끼리는 8pt쯤 떨어져 점선 사슬로 이어지지 않으므로, 점마다 양 끝이 빈 점선 신호 조각이 됐다(090쪽 끝점 미연결 1,030개).

고친 것은 다음과 같다.
- **선 위 점.** 꽉 찬(면적이 상자의 절반 이상) 정사각형에 가까운 1.5pt 이하 채운 조각이 실선 위 1pt 안에 있고 같은 선에 2개 이상이면 선 장식이다. 점선 조각에서 빼서 `ignored_objects`(`line_dot`)에 남긴다. 선에서 떨어진 점(열선 추적 표시)과 점선 경로 위 점은 건드리지 않는다.
- **선 종류는 바꾸지 않는다.** 처음 구현은 점이 얹힌 스트로크 점선을 매설 배관(`pdf_buried`)으로 바꿨다. 하지만 검토 결과 143쪽에서 그렇게 바뀐 16개가 모두 분기점 점이 있는 가는 점선 신호선이었다(예: 123쪽 손스위치 → 급수 부스터 펌프). APR1400의 실제 매설 배관은 실선이나 채운 조각으로 그려진다. 그래서 선 종류 변경은 뺐다.
- **끝막음 뒤처리 규칙.** 몸체 안에 원이 든 기호에는 끝막음(`pipe_cap`) 규칙을 쓰지 않는다. HEAD에서 끝막음으로 잘못 정해지던 소화전 13개(090쪽)와 E/H 구동부 원·작은 계기 원이 kind 없음으로 돌아간다.
- **사람 수정(D14).** 같은 자리에서 틀린 kind가 지워진 경우도 같은 대상으로 본다(채워진 경우와 대칭). 088~090·123·022쪽에서 HEAD 추출로 만든 수정이 살아남은 대상 1,765개에 모두 적용됐다.

결과는 다음과 같다.
- 미확인 74,769 → 71,203(−4.8%, U4 뒤 기준값 대비). 끝점 미연결 15,981 → 12,391, kind 없음 8,008 → 7,919.
- 태그 정확 872, 연결 표기 286/295, 짝 257, 틀린 대상·틀린 짝 0(후퇴 없음). SNP 노드·관계 동일.
- 검토(적대 2, Codex 1)에서 바꾼 것: 매설 배관 재분류 제거(16개 모두 오판), 가는 대각 대시를 점으로 오인, 점선 경로 끝 밖의 점, 지워진 kind의 사람 수정 보존.

### 3d. 연결 표시 화살표가 자기 행선지 문단을 못 받음

10.3.2-1 S1(105쪽)처럼 화살표 안까지 이어지는 행선지 문단('DRAIN TO / DRAIN HEADER A / SHEET 2 "E"')은 화살표로 들어가는 배관이 문단 상자를 지나간다. 그래서 배관 글자(`line_label`)로 분류돼 화살표 라벨 후보에서 빠졌다. 화살표는 대신 옆의 관 크기 '2"'를 라벨로 가져갔다(APR1400 세션 보고, 놓친 짝).

- 고친 것: 연결 표시 화살표 상자와 겹치고 'SHEET' 낱말이 든 문단은 배관 글자로 표시하지 않는다. 'SHEET'가 없는 문단(예: 138쪽 'CHEMICAL WASTE PUMP / 2"'처럼 pdfplumber가 합친 배관 글자)은 그대로 배관 글자다.
- 결과: 짝 257 → 279(+22, 틀린 짝 0). 화살표 29개의 라벨이 바뀌었고 다른 점수는 그대로다. SNP 노드·관계 동일.
- 남은 부작용: 105쪽 'BI|DII' 마름모 4개가 화살표가 놓아준 관 크기 '2"'를 라벨로 받는다. kind·태그는 바뀌지 않는다. 관 크기를 배관 글자로 돌리는 규칙을 시험했지만, 빈 라벨이 된 작은 기호가 끝막음·펌프 등으로 잘못 정해지는 연쇄가 생겨(검토에서 확인) 넣지 않았다.
- 검토(적대 2, Codex 1)에서 바꾼 것: 화살표와 겹치는 모든 문단을 풀던 첫 구현이 배관 번호를 화살표·밸브로 넘김(→ 'SHEET' 조건), 관 크기 규칙의 연쇄 오판.

### 3e. 계기 원 ISA 글자 보강

마지막 글자 규칙(T·C·I·S·R, TE)이 못 정한 계기 원만 다룬다. 조건은 다음과 같다.
- '기능 문자 2~6자 + 루프 번호' 꼴이고 짧은 변이 8pt 이상인 원(태그 규칙과 같은 기준)
- 변수 수식 문자와 끝의 H·L·M을 떼고, 마지막 글자가 기능 문자(T·C·S·R·I·G·L·A·K)일 것

kind는 출력 > 판독 순서(T>C>S>R>I>G>L)로 고른다. G(유리·게이지)·L(표시등)은 지시계로 본다. 다음은 정하지 않는다.
- W(보호관): 범례 1.7-1의 TEW는 TE가 아니다.
- V(밸브): PSV, PCV 등
- E(검출부): 원 안 FE를 배관 부품 `flow_element`로 두면 계기 원마다 검토구간이 따로 생긴다(검토에서 확인).

결과는 kind 없음 14개에 kind가 붙은 것이다(지시계 11, 전송기 2, 제어기 1). 기존 kind·태그 변화는 없다. 미확인은 71,203 → 71,189(−0.02%)다. 검토(적대 1, Codex 1. 바뀐 노드가 99개뿐인 작은 단위라 적대 검토를 하나로 줄임)에서 다음을 바꿨다: FE의 배관 부품 판정 제거, 스위치 우선(PISL), 작은 원 크기 기준, V·설비 번호 제외.

### 3f. 배관을 가로지르는 판(플랜지·버터플라이·볼 밸브)

범례 1.7-1 1/4의 FLANGED CONNECTION('—| |—'), BUTTERFLY('|\●|'), BALL('|○|'·'|●|')은 배관을 가로지르는 3pt 남짓한 짧은 판으로 그린다. 판이 기호로 묶이지 않았다. 그래서 배관 끝이 판 가운데에 닿아 분기점이 생겼고, 판 반쪽(1.5pt 토막)이 끝점 미연결과 자기 고리를 대량으로 남겼다(028쪽 확인). 플랜지가 낀 배관은 그 자리에서 끊겼다.

- 판: 길이 2~5pt 직선. 나란하고 길이가 같으며 같은 축 위에 있는 판끼리 짝을 짓는다. 점 순서와 상관없이 방향을 맞춘다.
- 플랜지: 두 판 사이가 비어 있고(선·점·채운 조각 없음) 간격이 2.6pt 이하인 경우다. 판마다 바깥에서 배관 끝이 하나씩 판 가운데에 닿고, 판에 다른 선(계기 탭·지시선)이 닿지 않아야 한다. 이때 두 판을 지우고 두 배관 끝을 잇는다. 지우는 시점은 기호 묶기가 끝난 뒤다. 판과 두 배관이 모두 낱 선으로 남아 있고 배관 끝이 다른 기호에 붙지 않았을 때만 지운다. 먼저 지우면 배관 끝이 떠 보여 장식선으로 흡수된다(007쪽 TE 태그 3개를 잃은 첫 구현에서 확인). 판 838개를 지웠다.
- 밸브: 판 사이 가운데에 곡선으로 그린 둥근 점이 있고 그 점을 지나는 빗금이 있으면 버터플라이, 빗금 없이 점이나 원 하나만 있으면 볼이다. 바깥 플랜지 판까지 한 기호(`manual_valve`, `valve_type`)로 묶는다. 판 사이에 다른 것(오리피스의 짧은 선, 플러그의 마름모)이 있으면 건드리지 않는다.
- 구동부: 밸브 가운데로 들어가는 선(축) 끝에 다른 기호가 있거나 사전 구동부가 닿아 있으면 kind를 정하지 않고 `actuated_valve_pending`으로 둔다(S5에서 정한다). 축으로만 밸브에 이어진 기호와 실선 배관이 몸체 한가운데를 지나는 작은 기호는 끝막음 규칙에 넣지 않는다.

### 3g. 구동부·밸브 번호 원을 밸브에 합치기 (S5, 결정 D6)

구동 밸브(MOV·AOV)는 HAZOP에서 보호수단이자 원인이 되는 기기다. 그런데 사전 구동부(전동 M, 다이어프램, 솔레노이드 S, 전기유압 E/H)와 밸브 번호 원은 따로 노드가 됐다. 그래서 kind 없음·태그 없음 미확인을 남겼고, 밸브는 구동 방식을 정하지 못한 채 보류됐다.

- 구동부는 꺾이지 않은 축(밸브 가운데로 들어가는 2점 실선)으로 이어진 밸브 하나에 합친다. 축이 없으면 닿은 밸브 하나에 합친다. 밸브가 없거나 둘 이상이면 합치지 않는다.
- 합칠지는 노드 kind가 정해진 뒤 정한다.
  - 밸브 kind가 없거나 수동이면 범례가 정한 kind로 올린다. 전동은 `motor_operated_valve`, 다이어프램은 `air_operated_valve`다. 다이어프램에 솔레노이드가 같이 붙으면 파일럿이다(범례 4/4).
  - `actuator_type`·`motive_power`는 사전 항목의 attributes를 단다. 이미 같은 구동 밸브이거나 제어 밸브면 속성만 단다.
  - 그 밖의 kind(체크 밸브, 글자로 정한 펌프 등)와 범례에 없는 조합은 합치지 않는다. 구동부를 노드로 남겨 정보를 잃지 않는다.
- 솔레노이드 혼자는 합치지 않는다. 스프링 복귀·복동 실린더 구동부(범례 4/4)의 파일럿일 수 있다(037·138쪽 확인). 전기유압도 kind를 정할 근거가 없어 합치지 않는다.
- 밸브 번호 원은 원 안이 숫자 2~4자일 때만 다룬다. 지시선이 하나여야 하고, 그 반대 끝이 밸브(또는 합칠 구동부)에 닿아야 한다. 끝이 떠 있으면 가장 가까운 밸브가 6pt 안이고 두 번째 밸브가 그 두 배보다 멀어야 한다. 한 밸브에 다른 번호가 둘 이상이면 합치지 않는다. 숫자만으로는 계통 접두를 알 수 없어 태그는 만들지 않고 `evidence.ident_number`로 남긴다.
- 합친 기호와 축·지시선은 `drawing.ignored_objects`(`actuator_merged`·`actuator_stem`·`valve_number_merged`·`valve_number_leader`)에 남기고, 노드·관계 번호는 비운다. PDF 객체는 밸브의 `evidence.merged_objects`에 남는다. 합친 구동부에 닿은 다른 실선은 밸브로 옮기고 신호선으로 둔다.

결과(143쪽, 3f 대비):
- 미확인: 64,881 → 63,723(−1.8%). 2% 기준에는 못 미치지만, 총괄 지시로 분석 품질 때문에 진행했다.
- 점수판은 그대로다(태그 정확 872, 짝 279, 틀린 짝 0). SNP 후퇴 0. 태그·라벨이 바뀐 노드는 없다.
- 합친 수: 구동부 190개, 번호 원 200개.
- kind 변화:
  - kind 없음 → `motor_operated_valve` 172
  - 수동 → `motor_operated_valve` 6. 그림으로 보니 M 원이 밸브 축에 붙은 진짜 전동 밸브다(014쪽).
  - kind 없음 → `air_operated_valve` 10
  - 105쪽 'AFW PUMP…' 글자 때문에 펌프로 읽혔던 5pt 다이어프램 하나가 구동부로 합쳐졌다.
- 보류(`actuated_valve_pending`)는 352 → 170이다.

검토(적대 2, Codex 1)에서 바꾼 것:
- 합칠 구동부를 글자 후보에서 빼던 것을 되돌렸다. 구동부 안 M·S가 이웃 밸브 라벨로 붙고, 번호 '524'가 다른 밸브로 넘어갔다(063쪽).
- 솔레노이드 혼자 → `solenoid_valve`를 뺐다(037·138쪽 오판).
- 축을 꺾이지 않은 선으로 좁혔다. 063쪽에서 꺾인 신호선 끝이 축으로 잡혀 마름모가 밸브로 올라갔다.
- 합치기를 노드 kind가 정해진 뒤로 옮겼다. 체크 밸브·제어 밸브에서 구동부 속성 없이 구동부만 지우던 문제와, 터빈·펌프에 번호를 붙이던 문제를 고쳤다.
- 지시선이 분기점에 닿은 번호 원은 합치지 않는다. 같은 밸브에 다른 번호가 둘이면 합치지 않는다. 전기유압은 합치지 않는다.
- 옮긴 실선은 신호선으로 둔다. 번호는 2~4자다. 합친 객체 근거는 `merged_objects`에 남긴다.
- analysis 캐시의 기호 객체는 고치지 않는다.

남긴 것(경미):
- 1/65 표본에서 번호 원이 엉뚱한 밸브로 갔다(018쪽 322). 실제 밸브 표시가 기호로 묶이지 않고 아래 'BI|AI' 마름모가 밸브로 묶인 기존 오류 때문이다.
- 지시선 끝이 떠 있을 때 쓰는 '6pt 안 가장 가까운 밸브' 경로는 실제 도면에서 쓰인 적이 없다.

### 3h. 검게 칠한 닫힌 밸브 (2026-11-11, 단위 F1-3)

### 3i. 선에 하나뿐인 // (2026-11-11, 단위 F1-4)

## 4. 범위 밖·사람 확인

- 흐름 방향: 화살촉이 없는 배관은 도면에 근거가 없다. 사람이 정하거나 계통 지식으로 정해야 한다.
