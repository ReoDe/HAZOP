# 설계정보 PDF의 값을 도면 구성요소 사양에 붙이기: 가능성 조사

작성 2026-11-26. 조사와 실험만 했고 코드는 고치지 않았다. 실험 자료는 모두 가상이며 저장소에 넣지 않았다.

## 결론

1. **표로 된 설계정보(기기·밸브·계기 목록, 라인 리스트, 배관 등급표)는 붙일 수 있다. 다만 지금 코드로는 안 된다.** 지금 문서 읽기는 문장 규칙만 있어서 표를 줄글로 읽는다. 가상 표 4종을 넣으니 사양 카드에 맞게 붙은 값은 0/229칸이었고, **틀린 값 2개가 후보로 조용히 붙었다**(원자로용기 설계 온도에 `17.2 MPa`, 온도 검출기 설정값에 `400 °C`).
2. **표 구조를 읽고 태그로 잇는 작은 시제품은 같은 자료에서 229/229칸이 맞았고 틀린 칸은 0이었다**(테두리 있는 표, 배관 등급표 포함. 등급표가 없으면 177/229). 방법은 pdfplumber 표 추출, 머리 낱말 사전, 느슨한 태그 열쇠, 라인 리스트의 배관 번호를 구간 전체에 적용하기다. venv에 이미 있는 pdfplumber만으로 된다.
3. 틀리기 쉬운 곳은 다섯 군데다. 테두리 없는 표(열이 쪼개짐), 태그 표기 흔들림, 한 배관 번호가 여러 구간에 걸리는 경우, 카드 쪽 항목 이름 비교(띄어쓰기 하나로 값이 사라짐), 압력 기준 (g)/(a)가 카드에서 빠지는 문제다. 글로 쓴 계통 설명은 지금 경로로 3/9칸만 붙었다.
4. **자동 확정은 '표 칸에서 규칙으로 읽었고, 도면 태그와 하나로 맞고, 다른 문서·도면 값과 다르지 않은' 값까지만 허용한다.** AI가 읽은 값과 규칙으로 풀어낸 값(등급표 조인)은 가설로 두고 카드에 표시를 붙인다. 지금 카드는 후보와 확정을 구별해 보이지 않으니 이것부터 고쳐야 한다.
5. **권장안:** 규칙 기반 표 읽기를 먼저 넣고(단위 4개, 중 규모 둘·소 규모 둘), AI는 규칙이 못 읽은 표와 스캔 PDF에만 쓴다. 화면은 도면 놓는 자리에 PDF를 같이 끌어 놓으면 앱이 도면인지 설계 문서인지 가려 받는 흐름 하나로 둔다. 가장 큰 위험은 **틀린 값이 '문서 값'이라는 이름으로 확정처럼 보이는 것**이다.

## 3. 붙이는 규칙

### 3.1 태그 정규화와 일치

- **비교 열쇠는 두 단계로 둔다.** 1단계는 지금의 `inputs.normalize_tag`(대시 변형·대소문자)로 정확 일치. 2단계는 공백·하이픈·밑줄을 모두 지운 느슨한 열쇠로, **도면 안에서 그 열쇠가 하나의 태그로만 풀릴 때만** 쓴다. 실험에서 1단계는 `rc v030`을 못 찾았고 2단계는 찾았다. SNP-M-101에서 느슨한 열쇠의 충돌은 0이었다(4.4).
- 계통 접두를 추정한 도면 태그(`tag_basis`에 `[추론]`)와 맞은 값은 확정하지 않는다. 지금 `tag_links`가 하듯 사유에 적고 가설로 둔다.
- 문서 태그에 계통 접두가 없고(`PT101`) 도면에는 있으면(`RC-PT101`), 문서 머리의 계통 코드나 대상 도면 번호로 접두를 붙여 볼 수 있다. 이것은 '규칙으로 풀어낸 값'이므로 가설이다.

### 3.2 한 태그가 여러 도면에 나올 때

- 기기·밸브·계기 태그가 여러 장에 나오는 것은 보통 같은 설비의 연결 표시다. 프로젝트 전체 그래프에서 같은 설비로 묶여 있으면(도면 간 연결) 그 묶음 하나에 붙이고, 묶여 있지 않으면 잇지 않는다(지금 규칙 유지).
- **배관 번호는 다르다.** 라인 리스트의 값은 정의상 그 번호의 배관 전체에 대한 값이다. 그래서 라인 리스트에서 온 값은 같은 번호의 구간 모두에 붙인다. 이 예외는 '문서가 라인 리스트 꼴(머리에 배관 번호 열)'일 때만 쓴다. 문장 속 배관 번호에는 쓰지 않는다(문장은 배관의 한 부분을 말할 수 있다).

### 3.3 문서의 태그가 도면에 없을 때

붙이지 않고 문서 패널에 '도면에 없는 태그 n개'로 남긴다. 실험의 `RC-PP02`가 이 경우다. 도면 범위 밖 설비일 때가 많고, 태그 오타일 수도 있다. 비슷한 태그를 추천하는 일은 사람 확인이 필요하므로 자동으로 붙이지 않는다.

### 3.4 값이 문서마다 다를 때

- 지금 지식그래프의 충돌 보존(K7)을 그대로 쓴다. 충돌이 있는 칸은 자동 확정하지 않는다.
- 같은 문서 번호의 새 판은 옛 판을 대신한다(`doc_revisions`). 다른 문서끼리는 우선순위를 정하지 않는다. 예를 들어 기기 목록과 데이터시트가 다르면 사람이 고른다.
- 도면 값이 있으면 도면 값을 카드에 쓰는 지금 규칙(도면 우선)은 그대로 두되, 다르면 카드 칸에 '문서 값과 다름' 표시가 필요하다. 지금은 지식그래프 충돌 화면에서만 보인다.

### 3.5 단위와 수량 표기

- 압력 기준 `(g)`/`(a)`를 값과 함께 보이고 비교에도 쓴다(B7). 기준이 없는 압력은 '기준 미확인'으로 두고 자동 확정하지 않는다.
- 단위 환산은 하지 않는 지금 규칙(`unit_normalized` null, 단위가 다르면 충돌)을 유지하는 편이 안전하다. 환산을 넣는다면 `kgf/cm²`↔`MPa`처럼 정확한 비율만 쓰고 원문을 함께 남긴다.
- 지름 표기는 `DN`·`A`·인치가 섞인다. 등급표 조인 열쇠로 쓸 때만 표로 정한 대응(`DN50 = 50A = 2"`)을 쓴다.
- 범위(`0~400 °C`)는 한 칸 값으로 두되 하한·상한으로 나눌 수 있으면 `range_min`·`range_max`에 나눈다.

### 3.6 배관 번호에서 등급·지름 풀기

실제 배관 번호는 흔히 `<지름>-<계통>-<일련번호>-<등급>` 꼴이지만 프로젝트마다 다르다. 가상 도면 SNP 계열의 배관 번호(`RC-L001`)에는 지름·등급이 없다. 그래서 순서는 이렇다.

1. 라인 리스트가 있으면 거기서 등급·지름을 읽는다(가장 믿을 만하다).
2. 라인 리스트가 없으면 프로젝트 설정의 번호 규칙(정규식 하나)으로 푼다. 규칙은 사람이 한 번 정하거나 AI가 제안하고 사람이 승인한다. 이렇게 푼 값은 '규칙으로 풀어냄'이다.
3. (등급, 지름)으로 등급표 행을 찾는다. 행이 없거나 둘 이상이면 붙이지 않는다.

### 4.6 이 실험이 말하지 않는 것

- 앱 화면에서 카드가 실제로 어떻게 보이는지는 실제 창으로 보지 않았다(`values_for` 결과로만 셈).

## 5. 자동 확정과 출처 등급

### 5.1 등급

| 등급 | 뜻 | `origin` / `method` 제안 | `knowledge_status` 시작값 | 카드 표시 |
| --- | --- | --- | --- | --- |
| 문서 표에서 읽음 | 글자 층이 있는 PDF의 표 칸을 규칙으로 읽음. 출처는 쪽·표 번호·행·열과 원문 | `doc_rule` / `extractor` | 아래 5.2를 모두 만족하면 `confirmed`, 아니면 `unknown` | 값 + '문서명 n쪽 표 k 행 r' |
| 문서 문장에서 읽음 | 지금 문장 규칙 | `doc_rule` / `extractor` | `unknown` | 값 + '확인 전' |
| 규칙으로 풀어냄 | 등급표 조인, 배관 번호 규칙 풀이, 계통 접두 보충 | `doc_rule` / `derived`(새 값) | `hypothesis` | 값 + '풀어낸 값' |
| AI가 읽음 | 스캔·깨진 표를 AI가 읽음, 태그 없는 문장의 대상을 AI가 판단 | `ai_draft` / `ai` | `hypothesis`(KD5: 사람 확인 전 확정 불가) | 값 + 'AI 판독' |

### 5.2 사람 확인 없이 확정해도 되는 조건 (모두 만족)

1. 글자 층에서 읽은 표 칸이다(AI·OCR 아님).
2. 표 자체 검사를 통과했다: 머리 낱말이 사전에 있고, 행마다 열 수가 같고, 열쇠 열 값의 대부분이 태그 꼴이다. 하나라도 어긋나면 그 표 전체를 확인 전으로 둔다.
3. 태그가 정확 일치(1단계)로 하나에 맞는다. 느슨한 열쇠(2단계)로 맞으면 확인 전.
4. 도면 태그가 추정값(`[추론]`)이 아니다.
5. 같은 칸에 다른 문서·도면 값이 없거나 같다(K7 충돌 없음).
6. 압력이면 기준 (g)/(a)가 적혀 있다.
7. 문서가 새 판에 밀린 옛 판이 아니다.

### 5.3 틀린 값이 조용히 확정되지 않게 하는 장치

- **카드에 상태를 보인다**(B8). 확정이 아닌 값은 흐리게 하고 '확인 전'·'풀어낸 값'·'AI 판독'을 붙인다. 지금 가장 먼저 필요한 일이다.
- **표 영역은 문장 규칙이 읽지 않는다.** 표로 읽은 쪽 영역의 글자를 문장 규칙에서 빼야 4.2의 틀린 값 같은 것이 생기지 않는다.
- 자동 확정이 정한 값은 지금 도면 쪽 규칙처럼 `auto` 표시를 남긴다(`claims.drawing_claims`의 `auto` → `ai_auto` 가설 처리와 같은 꼴). 왕복(내보내기·들여오기)에서 이 표시가 확정으로 올라가지 않는 기존 규칙을 문서 주장에도 적용한다.
- 문서마다 '읽은 행 / 붙은 행 / 도면에 없는 태그 / 표 검사 실패'를 셈으로 남기고, 붙은 비율이 낮으면(예: 절반 미만) 그 문서 전체를 확인 전으로 둔다. 다른 프로젝트·다른 계통 문서를 잘못 넣은 경우를 잡는다.
- 사람이 카드에서 값을 고치면 `corrections`의 사람 고침과 같은 등급으로 두고, 문서를 다시 읽어도 덮지 않는다.

시사점은 두 가지다. 표 구조 읽기는 이미 흔한 기술이고 글자 층이 있으면 규칙으로 충분하다. 그리고 목록과 P&ID의 대조는 업계에서도 사람이 점검표로 하는 일이므로, **자동으로 할 수 있는 것은 '맞는 것을 붙이고 어긋난 것을 드러내는' 데까지**다. 속성 이름은 DEXPI·CFIHOS 쪽 이름을 레지스트리 속성 사전과 맞춰 두면 내보내기와도 이어진다.

### 7.3 화면은 이렇게 둔다

- 사용자는 도면 놓는 자리에 도면과 설계정보 PDF를 같이 끌어 놓는다. 앱이 가려 받고, 끝나면 도면 목록 아래에 '설계 문서 3개 · 구성요소 41개에 값 붙음 · 확인할 것 5'처럼 한 줄만 보인다.
- 사양 카드는 지금처럼 값과 출처를 보이되, 확정이 아닌 값만 흐리게 하고 짧은 표시를 붙인다. 따로 확인 화면을 만들지 않는다. 고칠 것은 채팅으로 시킨다('RC-V030 압력 등급은 Class 2500이 맞다').
- '확인할 것'을 누르면 채팅이 충돌·도면 밖 태그·가설 값을 목록으로 보여 준다.

### 7.4 가장 큰 위험

1. **틀린 값이 확정처럼 보인다.** 지금 코드에서 이미 재현했다(4.2). P1의 상태 표시와 P2의 표 영역 제외가 먼저다.
2. **테두리 없는 표의 열 밀림.** 값이 이웃 칸으로 밀려도 형식이 그럴듯해(압력 등급 칸에 재질 글자 등) 눈에 잘 안 띈다. 표 검사를 통과하지 못하면 확정하지 않는다.
3. **실제 자료의 다양성.** 이 결론은 깨끗한 가상 표 하나에서 얻었다. 공개 가능한 실제 꼴의 목록 표본(가상 값으로 만든 것이라도 머리 두 줄·합친 칸·쪽 넘김 포함)을 먼저 만들고 P2를 그 표본으로 재는 것이 좋다.

### 7.5 권장안

**규칙 기반 표 읽기를 먼저 넣고(P1→P2→P3→P4, P5는 따로), AI는 규칙이 못 읽은 표와 스캔에만 쓰는 안(P6)을 권한다.** 근거: 글자 층이 있는 표는 규칙으로 맞게 붙었고(229/229, 틀림 0), 규칙 값은 출처를 칸 단위로 남길 수 있어 자동 확정 기준을 세울 수 있다. AI를 먼저 쓰면 모든 값이 가설이 되어 사용자가 원하는 '자동으로 확정되는 화면'과 멀어진다. 반대로 지금 문장 규칙을 표에까지 넓히는 안은 4.2처럼 틀린 값을 만들기 쉬워 고르지 않았다.
