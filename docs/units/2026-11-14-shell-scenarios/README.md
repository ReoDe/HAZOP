# 새 화면 사용자 시나리오 (2026-11-14)

통합 검증 때 새 화면(`hazop/shell/`)을 사용자 흐름대로 확인하는 시나리오 목록이다. 사용자가 이전 화면(`hazop/app/`)을 더 쓰지 않게 되어(2026-11-14) 이전 화면 기준의 `scripts/check_user_scenarios.py`(S1~S15)와 `verify-hazop` 스킬 대신 쓴다. 그 둘은 이전 화면이 지워질 때까지 그대로 둔다.

- 점검 스크립트: `scripts/check_shell_scenarios.py`(오프스크린 부분).
- 실행:

  ```bash
  %USERPROFILE%\.hazop\venv-py312\Scripts\python.exe scripts/check_shell_scenarios.py --out D:\HAZOP-trials\<날짜>-shell-scenarios\run-1
  ```

  `--list`는 목록만 보여 준다. `--only N1,N2`는 번호를 골라 돌리고, 앞 시나리오에 기대는 것은 앞 번호도 함께 넣어야 한다. `--real-ai`는 N8 일괄 분석을 실제 구독으로 부르는데, 구간 하나만 돌리고 호출이 20회를 넘으면 부르지 않는다.
- 결과: `--out` 폴더에 `report.md`·`report.json`과 내보낸 파일(`exports/`)이 남는다. 임시 작업·저장 루트는 실행이 끝나면 지운다. 사용자의 `D:\HAZOP\work`와 `%APPDATA%\HAZOP`은 건드리지 않는다.

## 점검 방식

| 방식 | 하는 일 | 못 보는 것 |
| --- | --- | --- |
| 오프스크린 | 새 화면 창을 화면 밖에 띄운다(`QT_QPA_PLATFORM=offscreen`, 실제 웹 화면과 엔진). 웹이 보내는 것과 같은 명령 길(`Engine.dispatch`, 웹이 본 프로젝트 ID를 실음)로 조작하고, 저장된 파일과 웹 패널 글자를 함께 본다. 파일 고르기·저장 대화상자는 창의 갈고리(`engine.hooks`)에 정해 둔 경로를 넣는다. AI는 가짜다. | 진짜 대화상자, 키보드·마우스, 한글 입력기, 끌어 놓기, 캔버스 위 그리기, 실제 구독 응답 |
| 실제 창 | `scripts/desktop_lease.py run --purpose shell-scenarios -- <명령>` 안에서 실제 창을 키보드·마우스로 움직인다. | 없음. 대신 느리고 데스크톱을 잡는다. |

가짜 AI는 셋이다.
- **추출 뒤 AI 검토.** 고정 답 클라이언트(`StubReview`)를 쓴다. 물은 항목마다 첫 칸에 값을 답한다.
- **채팅.** 정해 둔 답을 내는 세션(`FakeChat`)을 쓴다. 경로는 실제 프로젝트 그래프에서 `trace_path`로 찾은 것이라, 도면 위 표시는 실제 자리를 가리킨다.
- **일괄 분석.** `tests/test_shell_results.fake_run_unit`을 쓴다. 칸 항목 ID가 프로젝트 안에서 겹치지 않도록 구간 번호를 붙인다.

## 입력 자료

- 도면: `resources/references/pid-samples/`의 SNP-M-101(1차측 배관), SNP-M-102(가압기). 원본 폴더째 복사한다. drawio 옆에 쪽 SVG가 있어야 도면 위 표시를 만든다.
- 설계 문서: `tests/fixtures/docextract/SNP-DOC-102-…-fictional.pdf`.
- 프로젝트: `SCN`. DEXPI 가져오기는 다른 프로젝트 `SCN-DEXPI`에서 한다. 같은 프로젝트에 같은 번호를 두 형식으로 넣으면 원본 형식 선택이 생긴다.

## 시나리오

번호는 차례로 돈다. 괄호 안은 기대는 앞 시나리오다.

### N1 도면 등록

- **조작.** 도면 패널(Ctrl+1)에서 '도면 추가'를 누르고 파일 고르기 창에서 SNP-M-101 drawio를 고른다. 끌어 놓아도 된다.
- **화면.** 진행 표시가 뜨고 끝나면 도면 목록에 SNP-M-101이 보인다.
- **파일.** 등록 기록(저장 루트), `extract/<이름>/extraction.json`, `graph/<이름>/graph.json`.
- **오프스크린.** `pick_files` 갈고리 → `register.pick` → 작업 끝(`job.done`, outcome `registered`, AI 검토 안 돎).
- **실제 창에서 볼 것.** 진짜 파일 고르기 창, 탐색기에서 끌어 놓기, 진행 막대.

### N2 AI 검토 켜고 등록·추출 (N1)

- **조작.** 설정 또는 도면 패널에서 'AI 검토'를 켜고(도면당 상한 5) SNP-M-102를 등록한다. AI 검토 패널(Ctrl+7)에서 후보를 보고 거절하거나 수락한다.
- **화면.** AI 검토 패널에 제안 후보 수와 '다시 확인' 같은 묶음이 보인다. 거절하면 제안 0이 된다.
- **파일.** `ai-review/<이름>.json`(후보·판단).
- **오프스크린.** `extract.set_ai_review` → 등록 → `ai_review.ran`이 참이고 호출 수가 상한 안 → `aireview` 읽기의 제안 후보 → `aireview.reject` 뒤 제안 0, 거절 수가 맞음.
- **실제 창에서 볼 것.** 실제 구독으로 도는 검토의 진행 표시와 비용 어림. 후보를 도면 위에서 고르는 손 조작.

### N3 표제란 확정 (N2)

- **조작.** 표제란 패널에서 SNP-M-102 행의 후보(번호·개정·제목)를 '후보 그대로 확정'한다.
- **화면.** 행 상태가 확정이 되고 등록 버전이 오른다. 다시 추출이 돈다.
- **파일.** 새 등록 버전, 다시 만든 그래프의 `source.drawing_number`가 확정값이다.
- **오프스크린.** `titleblock.confirm` → 다시 추출 작업 → 세 칸 확정, 버전 증가, 그래프 번호, 쪽 확정의 '등록 단계 미확인'이 사라짐.
- **실제 창에서 볼 것.** 칸을 고쳐 확정하기(입력칸·한글 입력기), 번호가 잠긴 도면의 안내 글.

### N4 도면 고치기 (N3)

- **조작.** SNP-M-102 도면에서 수동 밸브 하나를 골라 태그를 고친다. 그다음 되돌리기와 다시 하기를 한다.
- **화면.** 도면 위 태그가 바뀌고, 되돌리면 원래대로 돌아오며, 다시 하면 고친 태그가 된다.
- **파일.** `drawing-edits/<이름>.json`(사람 수정 기록), 다시 만든 그래프.
- **오프스크린.** `edit/<gid>/item` 읽기 → `edit.apply set_tag`(화면이 본 `ver`·`base`를 실음) → 그래프 확인 → `edit.undo` → `edit.redo`.
- **실제 창에서 볼 것.** 캔버스에서 기호 고르기, 태그 입력, Ctrl+Z·Ctrl+Y, 경로 다시 그리기(마우스 끌기), 지우기 확인 상자.

### N5 쪽 확정 (N4)

- **조작.** 도면 패널의 쪽 확정 칸에서 '원본과 견줌'을 누른 뒤 '이 쪽 확정'을 누른다.
- **화면.** 미확인 0, 위치 없음 0이 보이고 확정 표시가 붙는다.
- **파일.** `sheet-confirmations/<이름>.json`(확정자는 검토자 이름).
- **오프스크린.** `sheetconf` 읽기로 조건 확인 → `sheet.compare` → `sheet.confirm` → 상태 `confirmed`, 기록 파일, 패널 글자.
- **실제 창에서 볼 것.** 확정 뒤 도면을 고치면 확정이 풀리는 안내.

### N6 채팅 질문과 경로 표시 (N1, N2)

- **조작.** 채팅에 "RC-PZ01에서 (고친 밸브)까지 경로 보여줘"를 묻는다. 답 카드의 경로를 눌러 도면 위 표시를 본다.
- **화면.** 답 카드에 경로 하나가 있고, 도면 위에 경로 표시가 그려지며, 도면을 넘으면 칩으로 넘어간다.
- **파일.** 없음(채팅 기록은 세션 안).
- **오프스크린.** 실제 그래프에서 `trace_path`로 경로를 찾아 가짜 세션의 도구 사건과 답으로 낸다 → `chat.ask` → `chat.answer` 카드에 경로 하나와 `marks` → 화면에 답 글.
- **실제 창에서 볼 것.** 실제 구독 채팅의 응답 시간과 도구 호출, 글자 입력과 Enter, 경로 칩을 눌러 도면 이동.

### N7 채팅으로 구간 만들기 (N1, N2)

- **조작.** 채팅에 "대표 구간 둘 만들어 줘", 이어서 "두 구간 확정해 줘"를 묻는다. 확정은 확인 상자에서 '실행'을 누른다.
- **화면.** 첫 묶음은 바로 적용되고(되돌리기 단추), 확정은 확인 상자가 뜬다. 구간 패널(Ctrl+2)에 두 구간이 확정으로 보인다.
- **파일.** `study-nodes/<프로젝트>/project-<프로젝트>.json`, `chat-actions/<프로젝트>/*.jsonl`.
- **오프스크린.** 구간 후보(`node_tools.make_candidates`)로 `nodes.apply` 동작을 담은 답 → 구간 둘 생김 → `nodes.confirm` 동작은 토큰을 받음 → `chat.action.approve` → 두 구간 확정.
- **실제 창에서 볼 것.** 확인 상자의 '실행'·'하지 않음'을 키보드로 고르기, 구간 패널에서 구간을 골라 도면 강조 보기.

### N8 일괄 분석 (N7)

- **조작.** 분석 결과 패널(Ctrl+3)에서 '분석 실행', '모든 구간 분석', 호출 수 확인, '분석 시작'을 차례로 누른다.
- **화면.** 진행(호출 수·경과)이 보이고, 끝나면 행렬 칸이 채워진다.
- **파일.** `analysis-results/<프로젝트>/project-<프로젝트>.json`.
- **오프스크린.** `results.run_plan`(호출 수) → `results.run` → 작업 끝 → 결과 파일과 행렬 칸. 구간 둘·편차 44개는 가짜로 20회다.
- **실제 창에서 볼 것.** 실제 구독 분석의 진행·취소·창 닫기(기다림). `--real-ai`로 구간 하나(호출 10회 안쪽)만 실제 구독으로 돌릴 수 있다.

### N9 결과 판정 (N8)

- **조작.** 행렬에서 칸을 열어 항목을 '승인'(A)하고, 다른 칸 항목은 사유를 적어 '보류'한다.
- **화면.** 머리 수치 '승인 n'이 오르고, 사유 없는 보류는 막힌다.
- **파일.** 결과 파일의 항목 상태(`approved`, `on_hold`).
- **오프스크린.** 화면이 여는 칸(`results/cell` 읽기의 `editable`)만 골라 `results.set_status`를 보낸다. 승인 3건, 사유 없는 보류는 거절, 사유 있는 보류는 저장, 머리 수치를 본다.
- **실제 창에서 볼 것.** J·A·R 키 판정과 Ctrl+Z, 사유 입력칸.

### N10 Excel 내보내기 (N9)

- **조작.** 분석 결과 패널에서 'Excel로 내보내기'를 누르고, 범위를 고른 뒤 저장 위치를 고른다.
- **화면.** 끝 알림(행 수)이 뜬다.
- **파일.** 고른 위치의 `.xlsx`. 구간 이름과 판정(승인)이 들어 있다.
- **오프스크린.** `save_path` 갈고리 → `results.export_excel` → 파일, 행 수, openpyxl로 읽은 내용. 먼저 표제란을 확정하지 않은 도면(SNP-M-101)이 있는 채로 내보내 보고, 막히면 그 도면도 확정한 뒤 다시 낸다.
- **실제 창에서 볼 것.** 진짜 저장 대화상자, 같은 이름 덮어쓰기 확인.

### N11 초기사건 편집 (N9)

- **조작.** 초기사건 패널(Ctrl+4)에서 '규칙 초안'을 누른다. 그룹이 없으면 후보를 골라 새 그룹을 만들고, 그룹 이름을 고친다.
- **화면.** 그룹 목록에 고친 이름이 보인다.
- **파일.** `initiating-events/<프로젝트>.json`.
- **오프스크린.** `ie` 읽기(ver·rver·지문) → `ie.suggest` → 그룹이 없으면 `ie.create_group` → `ie.edit_group`(확인을 물으면 `confirmed`로 다시) → 파일과 패널.
- **실제 창에서 볼 것.** 후보 여러 개 고르기, 끌어 옮기기, 완전성 대조 사유 입력.

### N12 인계 묶음 (N11)

- **조작.** 초기사건 패널에서 '인계 묶음 내보내기'를 누르고 저장 위치를 고른다.
- **파일.** `.xlsx`와 같은 이름의 `.json`. JSON에 고친 그룹 이름이 들어 있다.
- **오프스크린.** `save_path`·`confirm_overwrite_files` 갈고리 → `ie.export` → 두 파일, JSON 내용.
- **실제 창에서 볼 것.** 저장 대화상자, 같은 이름 JSON 덮어쓰기 확인.

### N13 DEXPI 내보내기 (N5)

- **조작.** 도면 패널에서 확정한 SNP-M-102를 골라 'DEXPI로 내보내기'를 누르고 폴더를 고른다.
- **파일.** `<폴더>/<이름>.dexpi.xml`, `manifest.json`. XML에 확정 도면 번호와 N4에서 고친 태그가 들어 있다.
- **오프스크린.** `dexpi` 읽기 → `save_dir` 갈고리 → `dexpi.export` → 작업 끝 → 파일과 내용.
- **실제 창에서 볼 것.** 폴더 고르기 창, 덮어쓰기 확인.

### N14 DEXPI 가져오기 (N13)

- **조작.** 프로젝트를 `SCN-DEXPI`로 바꾸고 N13의 XML을 등록한다. 표제란 패널에서 후보를 확정한다.
- **화면.** 도면 목록에 가져온 도면이 보이고, 표제란 후보 번호는 SNP-M-102다.
- **파일.** 가져온 도면의 등록·추출·그래프. 그래프에 고친 태그가 남아 있다.
- **오프스크린.** `project.set` → `register.pick`(XML) → 작업 끝 → 표제란 후보(DrawingNumber) → `titleblock.confirm` → 그래프 ID `graph-SNP-M-102`와 태그 → 프로젝트를 되돌림.
- **실제 창에서 볼 것.** 프로젝트 바꾸기 화면, 같은 프로젝트에 넣을 때의 원본 형식 선택.

### N15 지식그래프·설계 문서 (N1, N2)

- **조작.** 지식그래프 패널(Ctrl+5)을 열어 찾는다. 설계 문서(Ctrl+6)에서 PDF를 등록한다.
- **화면.** 그래프가 그려지고, 문서 목록에 SNP-DOC-102가 보인다.
- **파일.** 문서 등록과 지식 추출 결과, 지식그래프.
- **오프스크린.** `kg` 읽기 → `pick_doc` 갈고리 → `docs.add` → 작업 끝 → `docs` 목록 → `kg/graph` 노드 → `kg/search`.
- **실제 창에서 볼 것.** 그래프를 끌고 확대하기, 마우스 올림, 노드 클릭으로 로컬 그래프, 잠재 후보 판단(`kg.judge`) 사유 입력.

## 실제 창 점검 계획

실제 창은 사용자 시연이 끝난 뒤 총괄이 알리면 `scripts/desktop_lease.py run` 안에서 돌린다. 오프스크린이 맡지 못하는 조작만 모은다.

| 묶음 | 시나리오 | 조작 |
| --- | --- | --- |
