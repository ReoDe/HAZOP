# 자료 등록 기획

[상세 플로우차트](<../flow chart/01-registration.md>) · [전체 기획](전체기획.md) · [공통 원칙](전체기획.md#principles)

## 목적과 범위

사용자가 제공한 P&ID 원본과 식별정보를 보존하고, 정보 추출 단계가 동일 원본·버전을 다시 참조할 수 있게 합니다. 도면 기호·배관 추출, 노드 생성·편집, 그래프 통합은 이 단계의 범위가 아닙니다.

## 결정 상태

| 항목 | 상태 |
| --- | --- |
| 입력 형식 | 사용자 결정: 사용자가 draw.io(.drawio)로 직접 만든 실험용 P&ID. 실제 도면의 자료형(PDF·DWG 등)은 실험 성공 후 형식별 어댑터로 추가 |
| MVP 입력 방식 | 권고 승인: 지정 폴더의 원본 파일 한 개를 Python 스크립트로 등록하고 등록정보를 JSON으로 저장 |
| 후속 입력 방식 | 사용자 결정(유지): 웹 화면의 파일 선택 또는 드래그 앤 드롭. 스크립트와 같은 Python 등록 처리 사용 |
| 도면 번호·개정번호 누락 | 미확인 상태로 등록 가능. 내부 ID와 등록 버전으로 원본을 구별 |
| 저장 방식 | MVP: 로컬 저장 폴더(원본)와 JSON(등록정보). DB 등은 후속에서 선택 |
| 원본 저장 위치 | 사용자 결정(2026-11-04): 기본은 `자료저장소/`이며 환경변수 `HAZOP_STORE_ROOT`로 바꿀 수 있음. 저장소(Git)에는 포함하지 않음 |
| 표제란 값 | 사용자 결정(2026-11-04): 자동으로 읽은 도면 번호·개정번호·제목은 '자동 후보'로 기록. 사람이 확정하기 전까지 확정값은 미확인 |

## MVP와 후속 범위

| 구분 | 내용 |
| --- | --- |
| MVP | 파일 1개 등록, 확장자와 실제 형식·읽기 가능 여부 확인, 해시, 내부 ID·등록 버전 발급, 동일 해시 재등록 시 기존 참조 재사용, 미확인 항목 기록, 저장 후 해시 확인 |
| 후속 | 웹 등록 화면·미리보기, 도면 번호·개정번호 충돌 판정, 메타데이터 수정 이력, 여러 파일 처리, 설계자료 10종과 기타 형식 |

## MVP 등록 절차

1. 프로젝트 ID와 자료 종류(P&ID)를 지정하고 draw.io 원본 파일 한 개를 입력합니다.
2. Python이 확장자와 실제 형식, draw.io XML(압축 저장 포함)의 읽기 가능 여부, 문서·페이지 정보를 확인합니다.
3. 해시를 계산하여 같은 프로젝트에 동일 원본이 있으면 기존 참조를 안내하고 재사용합니다.
4. 도면 번호·개정번호·제목은 등록정보 JSON에 입력하거나 미확인으로 둡니다. 표제란에서 자동으로 읽은 값은 '자동 후보'로만 기록하고, 사람이 확정하기 전까지 확정값은 미확인으로 둡니다.
5. 원본을 저장 위치에 복사하고, 저장 후 해시와 참조를 확인한 뒤 완료 상태로 전환합니다.

## 웹 등록 화면 (후속)

1. 프로젝트와 자료 종류를 선택하고, 원본 파일 한 개를 선택하거나 드래그 앤 드롭합니다. 여러 파일을 놓으면 한 개씩 등록하도록 안내합니다.
2. 파일명·형식·문서/페이지 정보와 가능한 미리보기를 표시하고 도면 번호·개정번호·제목을 입력받습니다. 렌더러 미지원과 원본 읽기 실패를 구분합니다.
3. 등록 진행 상태와 중복·충돌·오류를 표시하고, 성공하면 자료 ID·등록 버전·미확인 항목을 보여줍니다.

화면은 파일 선택과 정보 입력만 담당하고, 형식·중복·무결성 검증은 MVP 스크립트와 같은 Python 처리로 수행합니다. 미리보기는 파생 자료이며 원본을 대체하지 않습니다.

## 입력과 등록정보

원본 설계자료 10종을 공통 등록 구조로 수용하되, MVP의 검증 대상은 P&ID입니다. 자료 종류와 실제 파일 형식은 구분합니다.

| 항목 | 처리 방식 |
| --- | --- |
| 프로젝트 ID | 필수. 자료가 속한 프로젝트를 명시 |
| 자료 종류 | MVP는 P&ID. 향후 PFD·운전조건 보고서 등으로 확장 |
| 내부 자료 ID·등록 버전 | 시스템 발급. 설계 문서의 개정번호와 구분 |
| 원본 파일명·저장 참조 | 원래 파일명 보존. 저장 시 파일명 중복으로 덮어쓰지 않음 |
| 실제 형식·크기·해시 | Python 자동 확인. 해시는 원본 식별과 무결성 확인에 사용 |
| 문서·페이지 정보 | draw.io의 다이어그램(페이지) 목록 등 형식별로 확인 가능한 정보 기록 |
| 도면 번호·개정번호·제목 | 사람이 입력하거나 확정. 표제란 자동 판독값은 '자동 후보'로 따로 기록. 알 수 없으면 미확인. 파일명만 보고 확정하지 않음 |
| 등록·변경 이력 | 등록 주체, 시각, 변경 전후, 사유 |
| 상태·검증 결과 | 초안·보류·등록 완료·실패를 구분하고 미확인 항목과 문제 목록 기록 |

자동으로 읽은 파일 정보와 사람이 입력한 설계 식별정보를 구분합니다. 등록 단계의 검증은 파일과 등록정보에 대한 검사이며 도면 내용의 정확성을 보증하지 않습니다.

## 처리 원칙

1. 손상·빈 파일이나 읽을 수 없는 파일은 사유를 표시하고 완료 처리하지 않습니다.
2. 같은 프로젝트의 동일 해시 원본은 기존 등록을 재사용합니다. 같은 파일명만으로 중복이라고 판단하지 않습니다.
3. (후속) 동일 도면 번호·동일 개정번호인데 내용이 다르면 충돌로 보류합니다. 도면 번호가 같고 개정번호가 다르면 별도 버전으로 보관하며, 업로드 시각만으로 최신 설계라고 판단하지 않습니다. 개정번호가 미확인이면 내부 버전만 발급합니다.
4. 원본 파일은 변경하지 않습니다. 렌더링 등이 필요하면 별도 파생 파일과 원본 참조를 만듭니다. 원본 교체는 새 등록 버전으로 처리합니다.
5. 저장 중 실패하면 미완료 상태와 원인을 남기고, 재시도로 중복이 생기지 않게 합니다.
6. 실제 원본은 실행 환경의 자료 저장 공간에 보관합니다. GitHub의 기획 문서 폴더를 원본 저장 위치로 가정하지 않습니다. 원본은 `자료저장소/`(또는 `HAZOP_STORE_ROOT`)에 두고 저장소에는 포함하지 않습니다(사용자 결정, 2026-11-04).

## 정보 추출 단계에 전달할 내용

자료 ID, 등록 버전, 프로젝트, 자료 종류, 실제 파일 형식, 원본 저장 참조·해시, 문서 식별자와 페이지 목록, 도면 번호·개정번호와 미확인 항목을 전달합니다. 등록 단계에서는 객체를 추출하지 않으며, ②가 객체를 읽은 뒤 같은 자료·등록 버전에 원본 객체 ID와 좌표를 연결합니다.

등록 버전은 원본·메타데이터 묶음의 변경 불가한 스냅샷을 식별합니다. 메타데이터만 바뀐 버전은 같은 해시를 사용할 수 있습니다. 전달 필드와 예시는 [단계 간 데이터 규격](전체기획.md#data-contract)을 따릅니다.

등록 완료는 추출 시작의 전제이며, 사용자가 등록 자료를 지정해 추출을 실행합니다. 등록만으로 추출을 자동 실행하는 기능은 후속 검토 대상입니다.

## 독립 검증

샘플 파일과 임시 저장 폴더만으로 이 단계를 검증합니다. 추출 코드·그래프·AI는 필요하지 않습니다.

| 범위 | 사례 | 기대 결과 |
| --- | --- | --- |
| MVP | 정상 draw.io P&ID | 원본·ID·해시·등록정보 저장, 다음 단계 참조 생성 |
| MVP | 압축 저장된 draw.io 파일 | 정상 파일과 같이 읽기 확인 |
| MVP | 손상·빈 파일 | 사유 표시, 등록 완료와 추출 전달 금지 |
| MVP | 확장자와 실제 형식이 다름 | 불일치 표시, 완료 금지 |
| MVP | 같은 프로젝트에서 동일 원본 재등록 | 기존 참조 재사용, 중복 등록 생성 금지 |
| MVP | 같은 파일명에 내용은 다름 | 파일명만으로 병합하지 않고 각각 식별 |
| MVP | 도면 번호·개정번호를 모름 | 내부 ID로 등록하고 미확인 상태 전달 |
| MVP | 저장 실패 또는 저장 후 해시 불일치 | 미완료 기록, 추출 전달 금지, 재시도 시 중복 방지 |
| 후속 | 파일 선택과 드래그 앤 드롭으로 각각 등록 | 동일한 Python 검증과 등록 결과 |
| 후속 | 여러 파일을 한 번에 드롭 | 한 개씩 등록하도록 안내, 일부만 조용히 등록하지 않음 |
| 후속 | 같은 도면·개정번호에 서로 다른 내용 | 충돌 보류, 기존 원본 유지 |
| 후속 | 같은 도면의 다른 개정번호 | 버전 분리, 이전 버전 추적 가능 |
| 후속 | 식별정보 수동 수정 | 변경 이력 보존, 중복·개정 충돌 재검증 |

### 통과 기준

원본 읽기와 형식 확인, 필수 시스템 정보 생성, 저장 후 무결성 확인, 유효한 참조 생성이 완료되어야 합니다. 미확인 사항은 명시적으로 전달해야 하며, 생성된 등록정보와 원본으로 동일 입력을 재현할 수 있어야 합니다.

## 다음 작업

사용자의 draw.io 샘플을 받아 MVP 등록 스크립트와 위 MVP 검증 사례를 구현합니다. 웹 화면은 수직 슬라이스 검증 후 진행합니다.
