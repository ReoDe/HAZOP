# 검토·결과 관리 기획

[상세 플로우차트](<../flow chart/05-review-results.md>) · [HAZOP 분석](HAZOP분석.md) · [전체 기획](전체기획.md) · [공통 원칙](전체기획.md#principles)

## 목적과 범위

④의 저장 결과를 다시 열어 전문가가 편차별로 검토·수정·확정하고, 개선 조치와 변경에 따른 재검토를 관리합니다. 화면 재조회와 Excel 워크시트 내보내기를 첫 출력 범위로 합니다.

## 질의응답에서 정한 방향

| 항목 | 사용자 결정 |
| --- | --- |
| 검토 화면 | 편차 목록에서 선택하면 도면·경로·근거·AI 제안을 함께 표시 |
| 확정 단위 | 편차별 원인·결과·보호수단·위험도를 수정하고 최종 확정 |
| 개선·자료 요청 | 개선 권고만 조치로 관리하고 자료 요청은 메모로 기록 |
| 설계 변경 | 해당 검토 구간의 모든 편차를 재검토 대상으로 표시 |
| 첫 출력 | 화면 재조회와 Excel 워크시트 내보내기 |

이하 상태 이름·Excel 시트 구성·조치 필드 등은 위 결정에 따른 설계 초안이며 구현 전 조정할 수 있습니다.

## MVP와 후속 범위

| 구분 | 내용 |
| --- | --- |
| MVP | ④ 결과 JSON을 Excel 워크시트로 출력하고, 사용자 평가 기준과 비교한 결과를 기록 |
| 후속 | 검토 화면, 편차별 수정·확정·이력, 개선 조치·자료 요청 메모, 변경 재검토 운영 |

## 입력과 화면 (후속)

프로젝트·검토 구간·분석 실행·버전을 선택해 당시의 전체 후보와 판단을 조회합니다. 선택·제외·보류 상태와 별개로 전문가 검토 상태·재검토 필요 여부를 표시합니다. 제외 항목도 숨기거나 삭제하지 않고 필터로 조회합니다.

| 영역 | 표시 내용 |
| --- | --- |
| 편차 목록 | 편차, 후보 판단, 검토 상태, 위험도 제안·확정값, 재검토 표시 |
| 도면·그래프 | 당시 원본과 그래프 버전, 선택 편차의 대상·탐색 경로 강조 |
| 근거 | 원문 위치·설계조건·적용 패턴·미확인 항목·탐색 한계. 근거를 도면 표시·추정 경로·도면 미표시로 나누어 개수를 보여주고, 추정 경로는 실제 배관과 구분되게 파선으로 표시 |
| 검토 편집 | AI 원안과 전문가 수정본, 원인·결과·보호수단·위험도, 변경 이유 |
| 관련 기록 | 판단 이력, 개선 조치, 자료 요청 메모, 이전 확정본 |

근거를 읽을 수 없으면 오류·미확인으로 표시하고, 다른 버전의 자료를 원래 근거인 것처럼 보여주지 않습니다. 도면·그래프 수정이 필요하면 ②·③에 보완을 요청하며 검토 화면에서 원본 그래프를 바꾸지 않습니다. 화면 구성의 뼈대는 `디자인/` 폴더에서 작성하며, ['출력화면 AX' 데모 분석](../디자인/출력화면AX-데모분석.md)을 참고합니다.

## 편차별 검토·확정 (후속)

1. 원인·결과·보호수단과 AI 추가 가설을 원문 및 탐색 경로와 대조합니다.
2. 사람이 내용을 수정하고 판단 근거를 남깁니다. AI 원안·위험도 제안은 별도로 보존합니다.
3. 위험도는 적용한 기준표·버전과 심각도·가능성 및 근거를 기록합니다. Python이 허용값과 기준표 계산을 검사하고 사람이 확정합니다.
4. 자료가 부족해 확정할 수 없는 판단은 보류로 유지하고 요청 자료를 메모에 남깁니다. 제외한 후보는 제외 이유를 기록하며 위험도는 `not_applicable`과 사유로 둡니다.
5. 검토자·시각·근거·관련 버전을 기록해 편차별 검토본을 확정합니다. 검토본은 해당 편차의 여러 시나리오를 포함할 수 있습니다.

후보 선택 상태, 검토 상태, 재검토 표시, 개선 조치 상태를 구분하며, 구간 전체의 확정 여부가 개별 편차나 미해결 조치를 덮어쓰지 않게 합니다. 전문가 확정은 검토 결과의 승인이지 개선 조치 완료를 뜻하지 않습니다. 검토 참여자(팀) 기록과 다중 승인은 첫 범위에 넣지 않습니다.

## 개선 조치와 자료 요청 메모 (후속)

| 구분 | 관리 방식 |
| --- | --- |
| 개선 권고 | 편차·시나리오에 연결된 조치로 등록. 내용·담당자·기한·처리 상태·완료 근거를 관리 |
| 자료 보완 요청 | 해당 편차에 연결된 메모. 필요한 자료·이유·작성자·시각·참조를 기록하며 조치 업무로 자동 전환하지 않음 |
| 설계보완 후보 | ④가 기록한 후보를 사람이 검토해 확정·기각. 확정한 것만 개선 권고로 등록하며, 자동으로 확정하지 않음 (사용자 결정, 2026-11-04) |

개선 조치는 미지정 담당자·미정 기한을 허용하되 누락을 표시합니다. 상태 흐름은 미착수→진행→완료 확인 요청→종결을 초안으로 두고, 재개 시 이전 이력을 유지합니다. 메모가 갱신되었다는 이유만으로 편차 보류를 자동 해제하지 않습니다.

## 변경과 구간 전체 재검토 (후속)

도면·운전조건·그래프의 변경이 검토 구간과 연관되면 **그 구간의 모든 후보 편차**에 재검토 표시를 붙입니다(사용자 결정). 선택·제외·보류 후보와 기존 확정본을 모두 포함합니다.

- 이전 확정본과 당시 참조는 과거 버전으로 보존하며 현재 버전에 확정 결과로 승계하지 않습니다.
- 한 자료가 여러 구간과 연결되면 각 구간 전체를 재검토 대상으로 표시합니다. 변경과 구간의 대응이 미확인이면 영향 구간 확인 필요로 표시합니다.
- 재분석이 필요하면 ④에서 새 실행을 만들고 이전 결과와 비교합니다.

재검토 표시는 두 방법으로만 해소합니다(권고 승인).

| 해소 방식 | 조건 |
| --- | --- |
| 재검토 완료 (`rereviewed`) | 새 버전에서 해당 편차를 다시 검토·확정 |
| 영향 없음 판정 (`no_impact`) | 사람이 변경 내용을 확인해 영향 없음으로 판정하고 판정자·사유·대상 변경을 기록. 메타데이터 정정처럼 내용이 바뀌지 않은 변경은 구간 단위로 일괄 판정 가능 |

자동 해소는 하지 않습니다. 이 경로는 제목 오타 수정 같은 사소한 변경이 구간 전체의 재검토를 강제하여 재검토 표시가 무시되는 상황을 막기 위한 것입니다.

## 구조화 저장과 Excel 출력

기록의 식별자·버전·상태와 변경 알림은 [단계 간 데이터 규격](전체기획.md#data-contract)을 따릅니다.

| 저장 단위 | 내용 |
| --- | --- |
| 검토본 | 편차·시나리오·분석 실행 참조, 수정 내용, 검토자·시각·판단 이유·상태 |
| 위험도 확정 | 사람의 확정 등급·근거·기준표 버전, AI 제안과의 대응 |
| 개선 조치 | 편차 참조, 권고 내용, 담당·기한·상태·완료 근거·이력 |
| 요청 메모 | 편차 참조, 자료 요청 내용·이유·작성 이력·받은 자료 참조 |
| 변경·재검토 | 해당 구간, 변경 버전과 이유, 전체 후보의 재검토 상태와 해소 방식 |
| 출력 기록 | 출력 시각·대상 버전·필터·행 식별자·출력 범위 |

저장 실패나 동시 수정이 있으면 다른 검토본을 덮어쓰지 않고 충돌을 표시합니다(후속).

Excel은 아래 시트 구성을 제안합니다. MVP는 분석 정보·전체 편차 후보·HAZOP 워크시트 시트만 출력합니다. PDF 보고서와 Excel 수정본 재수입은 후속 검토 대상입니다.

| 시트 | 내용 |
| --- | --- |
| 분석 정보 | 프로젝트·구간·실행·자료/그래프 버전·운전모드·출력 범위 |
| 전체 편차 후보 | 선택·제외·보류, 이유·검토 상태·재검토 표시 |
| HAZOP 워크시트 | 편차·원인·결과·보호수단·적용 패턴·AI 위험도 제안·전문가 확정값·근거 참조 |
| 개선 조치 | 권고 내용과 처리 상태·완료 근거 |
| 자료 요청 메모 | 요청 내용·이유·관련 편차·자료 참조 |

기본 출력은 선택한 구간·버전의 전체 후보입니다. 초안·보류·과거 확정·재검토 필요 상태를 구별하고, 시나리오가 여러 개이면 행을 분리하되 편차·시나리오 ID를 남깁니다. 원문 참조는 식별자·페이지·위치로 표시하며 파일 링크로 오인하지 않게 합니다.

## 독립 검증

샘플 분석 기록, 원본·그래프 참조, 위험도 기준표, 변경 이벤트만으로 이 단계를 검증합니다.

| 범위 | 사례 | 기대 결과 |
| --- | --- | --- |
| MVP | ④ 결과 JSON의 Excel 출력 | 후보·시나리오 ID, 값·상태·버전이 JSON과 일치 |
| MVP | 빈값·긴 메모·수식 같은 입력 포함 | 원문·빈값 의미 보존, 사용자 텍스트가 수식으로 실행되지 않음 |
| MVP | 위험도 보류·비적용 항목 | 빈 위험도를 0이나 안전으로 출력하지 않고 상태·사유 표시 |
| 후속 | 과거 분석의 편차 선택 | 당시 버전의 도면·경로·근거·AI 제안이 함께 표시 |
| 후속 | 제외·보류 후보 재조회 | 이유와 이력 복원, 누락·삭제되지 않음 |
| 후속 | 편차 수정 후 확정 | AI 원안 보존, 변경 이유·검토자·시각과 확정본 저장 |
| 후속 | AI 위험도와 전문가 값이 다름 | 두 값·평가 기준·이유를 구분해서 표시 |
| 후속 | 기준표·근거 또는 필수 판단 부족 | 확정 검사에서 보류 |
| 후속 | 개선 권고와 자료 요청 기록 | 개선 권고만 조치 생성, 자료 요청은 메모로 유지 |
| 후속 | 조치 종결 및 재개 | 완료 근거·주체·상태 전후 이력 보존, 편차 확정과 별도 관리 |
| 후속 | 한 구간의 도면·조건·그래프 변경 | 해당 구간의 전체 후보 재검토 표시, 이전 확정본 보존 |
| 후속 | 메타데이터만 정정된 변경 | 재검토 표시 생성 후 사람이 영향 없음으로 일괄 판정 가능, 판정 이력 보존 |
| 후속 | 새 버전에서 편차 재확정 | 해당 새 버전의 재검토만 해소, 과거 기록 유지 |
| 후속 | 저장 실패·동시 수정 | 성공으로 표시하거나 기존 검토본을 덮어쓰지 않음 |

### 통과 기준

확정본은 유효한 참조·필수 검토정보·평가 기준과 사람의 확정 이력을 갖추어야 합니다. 보류·미확인·재검토 표시는 저장·조회·출력에서 유지되어야 하며, 개선 조치와 요청 메모를 구분하고 과거 버전을 재현할 수 있어야 합니다. 제외 판단을 확정하기 위해 가짜 위험도를 만들지 않으며, 판단할 수 없는 항목은 비적용이 아니라 보류로 남깁니다.

## 다음 작업

MVP에서는 ④ 결과의 Excel 출력과 평가 기준 비교를 구현합니다. 검토 화면과 이력 관리는 수직 슬라이스 검증 후 `디자인/`의 화면 뼈대와 함께 구체화합니다.
