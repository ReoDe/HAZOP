# 정보 통합·관리 기획

[상세 플로우차트](<../flow chart/03-integration.md>) · [전체 기획](전체기획.md)

## 목적과 범위

여러 도면·표·문서에서 추출한 결과를 공통 구조로 통합하여 같은 설비의 연결, 조건, 보호수단과 원문 근거를 관리합니다. 원본 인식과 추출은 이전 단계, 원인·영향 추론은 HAZOP 분석 단계에서 수행합니다.

이 문서는 기획 초안입니다. Python 코드나 편집 화면, 검증 기능이 구현되었다는 의미는 아닙니다.

## 역할 분담

| 주체 | 역할 |
| --- | --- |
| Python 스크립트 | 형식 정규화, 대상 식별, 관계·사실 통합, 규칙 검증, 저장·이력 처리 |
| 사람 | 노드·속성·관계의 수동 추가·수정, 연결 해제, 병합·분리, 충돌 판단 |
| AI: 선택적 검수 | 결과가 불만족스러운 항목을 원문과 대조하고 보정 제안. 사람이 반영한 결과도 스크립트로 재검증 |
| AI: HAZOP 분석 단계 | 검증된 그래프의 알고리즘 탐색 결과와 설계 근거를 바탕으로 추가 추론 및 답변 생성 |

자료 등록·정보 추출·정보 통합은 Python 자동 처리를 기본으로 합니다. AI 사용은 필수 의존성이 아니며, 검증 규칙을 통과시키기 위해 근거 없는 값을 생성하지 않습니다.

## 공통 정보 구조 초안

| 구성 | 최소 내용 |
| --- | --- |
| 대상 노드 | 내부 고유 ID, 프로젝트·공정 범위, 종류, 태그 또는 이름 |
| 관계 | 고유 ID, 시작·끝 대상 또는 포트, 관계 종류, 확인된 경우 방향 |
| 사실·속성 | 대상 ID, 항목, 원래 값과 단위, 정규화한 값과 단위, 적용 조건·운전모드 |
| 근거 | 원본 파일 ID·버전, 페이지·영역 또는 문장 위치. 수동 정보는 작성자·사유 및 근거 유무 |
| 관리 정보 | 입력 유형, 추출 실행/수동 편집/AI 보정 이력, 검토 상태, 변경 버전 |

내부 고유 ID는 도면의 태그와 구분합니다. 태그 수정으로 대상 ID가 바뀌지 않도록 합니다. 문서별 임시 ID와 통합 대상 ID의 대응을 남깁니다. 태그가 없으면 임시 대상으로 유지할 수 있습니다.

## 자동 통합 원칙

1. 프로젝트·공정 범위와 명시적인 식별 정보를 이용하여 동일 대상을 연결합니다. 이름 유사도나 도면상 거리만으로 자동 병합하지 않습니다.
2. 같은 설비의 문서별 표시는 원문 위치를 각각 보존합니다. 대상 하나에 근거 여러 개가 연결될 수 있습니다.
3. 물리적 배관 연결, 계장 신호, 제어 동작, 보호 관계를 구분합니다. 흐름 방향이 불명확하면 미확인으로 둡니다.
4. 정상 운전압력, 설계압력, 트립 설정값은 별도 항목으로 관리합니다. 운전모드나 적용 버전이 다른 값도 구분합니다.
5. 같은 대상·항목·조건의 값이 상충하면 원래 주장과 근거를 모두 보존하고 충돌로 표시합니다. 단순히 최신 입력으로 덮어쓰지 않습니다.
6. 단위는 변환 가능한 경우 정규화하고 원래 표현도 남깁니다. 압력의 게이지/절대 기준처럼 해석이 필요한 부분은 추정하지 않습니다.
7. 동일 입력을 재처리해도 중복 노드·관계·사실이 늘어나지 않도록 입력 식별자와 처리 이력을 사용합니다.

## 수동 편집과 선택적 AI 검수

- 사람은 빈 초안이나 기존 버전에서 노드·사실을 생성하고 수정할 수 있습니다. 관계 연결·해제와 잘못 병합된 대상의 분리도 지원 대상으로 둡니다.
- 원본 근거가 없는 수동 정보는 작성자와 사유를 기록하고, 원본에서 확인된 사실과 구분합니다.
- AI에는 검수 대상과 관련 원문을 제공하고, 변경 제안·이유·근거 위치를 반환하도록 합니다. 확인할 수 없는 정보는 미확인으로 유지합니다.
- 수동 편집과 AI 보정은 모두 초안에 반영한 뒤 동일한 Python 검증을 다시 수행합니다.
- 자동 재처리가 기존 수동 수정을 조용히 덮어쓰지 않도록 변경 충돌을 검토 대상으로 표시합니다.
- 삭제·병합·연결 해제 전후를 기록하여 이전 버전으로 복원할 수 있도록 합니다.

## 독립 검증

다른 단계가 미구현이어도, 정답을 명시한 샘플 입력과 기존 그래프를 이용해 이 단계만 실행·판정할 수 있어야 합니다. AI 연결은 필요하지 않습니다.

| 검증 사례 | 기대 결과 |
| --- | --- |
| P&ID와 운전조건 문서에 같은 범위의 V-101 존재 | 대상 하나에 연결 정보와 운전조건, 두 근거가 모임 |
| 서로 다른 공정에 V-101 태그 존재 | 별개 대상 유지 |
| 동일 입력 두 번 처리 | 노드·관계·사실이 중복 생성되지 않음 |
| 같은 조건에서 5 bar와 6 bar가 각각 보고됨 | 충돌 표시, 두 원문 보존, 임의 확정 금지 |
| 정상 운전압력과 설계압력이 다름 | 서로 다른 항목으로 보존, 값 차이만으로 충돌 판정하지 않음 |
| 관계의 끝 대상이 누락됨 | 오류 또는 미해결 참조 표시, 정상 연결로 확정하지 않음 |
| 수동 노드 생성 후 연결·수정·해제 | 동일 검증 수행, 변경 주체와 전후 이력 보존 |
| 수동 수정 이후 자동 재처리 | 수동 수정 보존 또는 충돌 표시, 무단 덮어쓰기 금지 |
| AI 보정에 근거 없는 값이나 잘못된 참조가 포함됨 | 미확인·검토 대상으로 남기거나 오류 처리, 검증 우회 금지 |
| 변경을 보류하거나 이전 버전으로 복원함 | 기존 검증 버전 유지, 초안 및 복원 이력 추적 가능 |

### 통과와 보류 기준

- 형식 오류, 유효하지 않은 참조, 모호한 대상 병합, 해결되지 않은 값 충돌이 있는 변경은 검증된 버전에 반영하지 않습니다.
- 미확인 항목은 명시적으로 구분하여 저장할 수 있지만 확인된 사실로 취급하지 않습니다. 검증 보고서에 범위와 미확인 사항을 남깁니다.
- 통과 결과에는 입력별 대상 매핑, 원문 또는 수동 출처, 검증 보고서, 버전과 변경 이력이 있어야 합니다.
- 그래프의 구조 검증과 설계 내용의 의미 검토를 구분합니다. 규칙 통과만으로 설계의 정확성·완전성을 보장하지 않습니다.
- 다른 상세 플로우차트에도 입력·출력·검증 사례·통과/보류 기준을 별도로 정의합니다.
