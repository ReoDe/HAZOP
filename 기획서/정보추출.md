# 정보 추출 기획

[상세 플로우차트](<../flow chart/02-extraction.md>) · [자료 등록](자료등록.md) · [정보 통합·관리](정보통합관리.md)

## 목적과 범위

등록된 P&ID에서 설비·밸브·계기·태그·배관을 찾아 도면 내부의 연결 그래프 초안을 만듭니다. 원본 대조와 수정까지 마친 결과를 정보 통합·관리 단계로 전달합니다. 여러 자료의 동일 대상 식별·병합이나 HAZOP 추론은 여기서 수행하지 않습니다.

현재는 기획 초안입니다. 추출 스크립트·모델·편집 화면은 아직 구현하지 않았습니다. 설계자료 10종 중 첫 대상은 P&ID이며, PFD·표·설명문은 이후 별도 처리 경로로 확장합니다.

## 결정 상태

| 항목 | 상태 |
| --- | --- |
| 입력 형식 | 사용자 변경 결정에 따라 등록된 FreeCAD(.FCStd)·draw.io(.drawio) 원본 |
| 최초 실행 | 제안: 등록 완료 후 사용자가 자료·페이지를 선택해 추출 실행 |
| 처리 범위 | 사용자 결정: 페이지 전체 추출과 선택 구간 재처리 모두 지원 |
| 자동 처리 | Python 스크립트가 기본. 원본 대조 후 사람이 수정 가능 |
| AI | 필수 의존성 없음. 불만족스러운 결과의 선택적 검수·보정 제안 |
| 인식 기술·정확도 목표 | 실제 도면과 범례를 확인한 뒤 확정. 전용 기호 사전·규칙·OCR 등의 선택은 아직 미정 |

## 그림을 Python으로 처리하는 방법

### 첫 대상: 직접 만든 FreeCAD·draw.io 도면

첫 실험은 이미지 인식보다 원본에 저장된 구조를 읽는 방법을 우선합니다. 두 프로그램의 형식은 서로 다르므로 별도 Python 어댑터를 두고 공통 추출 결과로 변환하는 방향입니다. 어느 도구를 먼저 구현할지는 실제 제공되는 샘플을 보고 정하며 두 형식이 이미 지원된다는 의미는 아닙니다.

| 원본 | 읽을 정보와 방법 | 확인할 점 |
| --- | --- | --- |
| draw.io `.drawio` | XML의 도형·라벨·사용자 속성·커넥터 source/target·좌표. 압축 저장 여부를 처리 | 단순 선과 객체에 접속된 커넥터를 구분. 도형 모양만으로 설비 의미가 정해지지는 않음 |
| FreeCAD `.FCStd` | FreeCAD Python API 등을 통해 문서 객체·속성·형상·참조를 읽는 방식 검토 | 객체나 형상의 연결이 공정 배관의 유체 연결을 뜻하지는 않음. 작업대·모델링 방식별 의미와 포트 표현 확인 필요 |

도면 작성 시 설비·밸브 등에 종류와 태그를 속성으로 남기고, 배관·신호선의 종류와 접속 대상을 명확히 표현하면 자동 추출이 쉬워집니다. 이 작성 규칙은 제안이며 실제 샘플로 구체화합니다. 원본에 없는 의미·포트·흐름 방향은 임의로 생성하지 않습니다.

페이지가 없는 FreeCAD 문서는 선택 객체와 작업 영역을 처리 범위로 사용합니다. 기존의 전체 페이지 추출·선택 구간 재처리 요구를 전체 문서·선택 객체/영역으로 대응시키며, 범위 밖 결과 보존 원칙은 유지합니다. 구조화 원본 읽기와 미리보기 렌더링은 분리합니다.

### 자료형 고려 범위

P&ID는 벡터 PDF, 스캔 PDF, 문자·벡터·이미지가 섞인 PDF, 래스터 이미지(PNG·JPG·TIFF 등), CAD 원본(DWG·DXF 등), 구조화된 설계 데이터 등 여러 자료형으로 제공될 수 있습니다. 장기 기획에서는 이들 자료형을 모두 고려하며, 실제 입력 형식과 내부에 포함된 문자·선·기호·연결 데이터에 따라 처리 방법을 나눕니다.

이는 고려 범위에 대한 기록이며 모든 형식의 지원을 확정하거나 구현했다는 의미는 아닙니다. 첫 지원 대상은 FreeCAD 또는 draw.io로 직접 만든 도면 원본으로 변경합니다. PDF·PNG·JPG 등 나머지 형식의 우선순위·변환 도구·정보 손실·검증 방법은 후속 기획에서 결정합니다.

Python은 처리 흐름을 실행하는 수단이며 도면 지식을 자동으로 갖는 것은 아닙니다. 문자 인식, 기호 탐지, 선 추적을 나누고 P&ID 기호·연결 규칙을 결합하는 방식으로 구상합니다.

| 처리 | 접근 방법 예시 | 한계와 확인할 점 |
| --- | --- | --- |
| PDF 정보 읽기 | 문자·벡터 선이 있으면 직접 추출 | 모든 PDF가 벡터는 아니며 선분이 실제 배관을 뜻하는지도 분류 필요 |
| 문자 인식 | 문자 레이어 또는 OCR | 태그 오독과 인접 기호의 소속 판별 필요 |
| 기호 탐지 | 범례 기반 템플릿·형상 규칙, 필요 시 전용 탐지 모델 | 크기·회전·표현 차이, 겹침에 따라 누락 가능 |
| 배관·신호선 추적 | 선분 검출·세선화·연결 성분과 기하 규칙 | 교차와 접속, 점선, 문자에 가려진 선은 별도 판별 필요 |
| 의미 연결 | 기호 종류·포트·선 종류·태그 규칙 적용 | 거리만으로 연결하지 않고 모호한 경우 검토 대상으로 유지 |

첫 실험은 실제 도면의 작은 정답 구간에서 규칙과 템플릿의 적용 가능성을 확인합니다. OCR이나 전용 탐지 모델도 머신러닝 기술을 사용할 수 있으므로, Python 자동 처리와 모델 미사용은 같은 뜻이 아닙니다. 생성형 AI가 원본을 자유롭게 해석하는 방식은 기본 경로로 두지 않습니다. 인식 기술은 실제 샘플에서 비교한 뒤 선택합니다.

## P&ID 해석 지식 관리

기호의 의미와 연결 규칙은 정보 추출의 기반이므로 이 단계에서 관리합니다. 현재는 이 기획서에 항목과 원칙을 두고, 실제 범례가 확보되면 기호 이미지·좌표 예시와 기계가 읽는 사전·규칙으로 확장합니다. 현재 기호 지식 파일이나 이미지 자료를 새로 생성하지는 않습니다.

| 지식 종류 | 기록할 내용 |
| --- | --- |
| 기호 사전 | 기호 예시, 의미·종류, 변형·회전 표현, 대응할 노드 종류 |
| 포트·내부 유로 | 기호의 연결 가능한 위치, 포트 역할, 실제로 통하는 유로와 분리된 유로 |
| 선·접속 규칙 | 배관과 신호선의 표현, 교차·분기·접속점·점프 표시, 화살표 의미 |
| 태그·라인 규칙 | 프로젝트별 태그 구성, 라인 번호 형식, 문자와 기호의 대응 기준 |
| 도면 간 연결 | 외부 연결 기호와 상대 도면·연결 식별자. 실제 연결 확정은 통합 단계 |
| 적용 범위·근거 | 프로젝트·도면 범례·설계 기준의 출처와 버전, 규칙의 적용 범위 |

일반적인 P&ID 지식과 프로젝트 고유 범례를 구분합니다. 충돌하면 적용할 설계 기준을 확인하고 미확인으로 남기며, 특정 도면의 표현을 모든 프로젝트에 자동 적용하지 않습니다. 이 사전은 그림을 해석하는 기준이고, 통합 기획서의 데이터 사전은 결과를 저장·검증하는 정의이므로 두 사전의 대응도 관리합니다.

확인된 도면상 연결과 공정 지식에 따른 연결 추정을 구분합니다. 배관이 어디로 이어지는지는 선과 포트의 원본 근거로 구성하며, 공정상 그럴듯하다는 이유로 연결을 생성하지 않습니다.

## 실행 순서

1. **입력 확인:** 자료 ID·등록 버전·원본 해시·페이지를 확인합니다. 독립 실행에서는 같은 형태의 샘플 등록정보를 입력받습니다.
2. **원본 구조 준비:** draw.io XML 또는 FreeCAD 객체를 읽고 원본 객체 ID·속성·좌표·접속 정보를 보존합니다. 미리보기와 원본 객체의 대응을 남깁니다. PDF·이미지의 렌더링·보정 경로는 후속 범위로 둡니다.
3. **문자 추출:** 객체의 라벨·속성에서 태그·라인 번호·주석을 읽고 원문·객체 ID·좌표를 남깁니다. OCR은 이미지 기반 자료 지원 시 추가합니다.
4. **기호 추출:** 객체 종류·사용자 속성과 기호 사전을 대응시켜 설비·밸브·계기·포트를 분류합니다. 형상만 있거나 의미가 없으면 미분류로 둡니다.
5. **선·접속 추출:** 명시적인 커넥터와 연결 대상을 우선 읽습니다. 일반 선·곡선만 있으면 끝점·분기·교차 후보로 유지하고 실제 접속 여부를 검토합니다.
6. **연결 초안 구성:** 기호와 태그를 대응시키고 포트·배관·분기를 연결합니다. 가까이 있다는 사실만으로 태그 소속이나 연결을 확정하지 않습니다.
7. **자동 검증 및 원본 대조:** 잘못된 참조·끊김·모호한 교차·미분류 기호를 표시하고, 사람이 결과를 검토합니다.
8. **수정 및 재검증:** 사람의 편집, 선택적인 AI 보정, Python 재추출 결과를 같은 규칙으로 검사합니다.
9. **결과 버전 저장:** 통합 단계로 전달할 결과와 근거·설정·검토 내역·미확인 항목을 저장합니다.

문자·기호·선 추출은 구현상 독립적으로 실행한 후 합칠 수 있습니다. 추후 지원할 PDF의 일부만 벡터인 혼합 도면은 영역별로 처리하되 같은 대상을 두 번 생성하지 않도록 합니다.

## 추출 결과의 공통 계약 초안

| 결과 | 남길 내용 |
| --- | --- |
| 실행 정보 | 자료 ID·등록 버전, 페이지·범위, 실행 ID, 스크립트·설정·사용한 사전/모델 버전 |
| 도면 내부 노드·포트 | 임시 고유 ID, 종류 또는 미분류, 태그 후보, 위치·영역, 기호 소속 포트 |
| 문자·속성 후보 | 원문, 해석한 값·단위·항목, 연결 대상 후보, 미확인 상태 |
| 관계 | 임시 ID, 시작·끝 노드/포트, 관계 종류, 선 경로, 확인된 경우 방향 |
| 원문 근거 | 원본 파일·버전·페이지·좌표, 파생 이미지와 원본 좌표의 대응 |
| 검토·변경 정보 | 자동/수동/AI 제안 구분, 변경 전후·사유, 검증 결과, 미해결 항목 |

임시 ID는 통합 단계의 영구 대상 ID와 구분합니다. 태그 미인식 때문에 노드를 버리지 않으며, 원문에 없는 운전조건이나 흐름 방향을 만들어 넣지 않습니다. 속성 정의는 [통합 기획서의 정의 초안](정보통합관리.md)을 기준으로 조율합니다.

## 원본 대조·수동 편집

- 웹에서 원본과 추출 오버레이를 겹쳐 보고 문자·기호·배관·문제 항목을 선택할 수 있게 구상합니다.
- 사람은 누락된 노드·포트·태그를 추가하고 종류·속성을 수정하며, 관계를 연결·해제할 수 있습니다. 원본상의 위치와 변경 이유를 남깁니다.
- AI는 요청된 항목과 관련 원본 영역을 대조하여 보정을 제안합니다. 사람이 반영한 결과도 Python 검증을 거칩니다.
- 재처리는 기존 결과와 별도 실행으로 보관합니다. 기존 수동 보정을 조용히 덮어쓰지 않고 차이를 검토합니다.
- 선택 구간 처리를 지원하는 경우 경계에서 잘린 배관은 열린 끝점으로 표시하고, 구간 밖 대상을 추정 연결하지 않습니다.
- 선택 구간 재처리는 페이지 전체 결과와 좌표를 공유합니다. 경계 연결과 기존 수정사항을 확인한 뒤 반영하여 중복 노드·배관을 만들거나 범위 밖 결과를 지우지 않도록 합니다.

## 독립 검증

실제 도면의 작은 구간과 사람이 작성한 정답 표시를 사용합니다. 정답은 기호 종류·위치·태그뿐 아니라 포트와 실제 연결, 교차 비연결을 포함합니다. 합성 예제로 처리 규칙을 검사한 뒤 실제 도면에서 성능을 별도로 평가합니다.

| 사례 | 기대 결과 |
| --- | --- |
| FreeCAD와 draw.io 원본 | 형식별 객체 읽기, 원본 객체 ID·속성·좌표 추적 가능 |
| 명시적 커넥터와 단순 선분 | 객체 참조 연결과 기하 후보 구분, 미확인 연결을 확정하지 않음 |
| 회전·확대·기울기 보정 | 추출 위치가 원본의 같은 대상과 대응 |
| 설비·밸브·계기와 태그 | 종류·태그·포트 후보 추출, 정답과 오인식·누락 비교 가능 |
| 선이 교차하지만 연결되지 않음 | 단순 교차를 분기로 확정하지 않음 |
| 실제 분기 또는 기호로 가려진 선 | 연결 후보와 불명확 구간 구분, 끊김을 숨기지 않음 |
| 배관과 계장 신호선 | 관계 종류 구분, 구분 불가하면 미확인 표시 |
| 흐름 화살표·태그가 없음 | 방향·태그 미확인 유지, 값 생성 금지 |
| 선택 구간 경계·도면 밖 연결 표시 | 열린 끝점·외부 참조 보존, 미처리 영역으로 추정 연결 금지 |
| 수동 추가·수정·연결 해제 | 이력·근거 보존, 동일 규칙 재검증 |
| 수동 보정 후 같은 영역 재추출 | 보정 유지 또는 변경 검토, 무단 덮어쓰기 금지 |
| 전체 페이지 추출 후 선택 구간 재처리 | 범위 밖 결과 보존, 경계 연결 검토, 중복 생성 금지 |
| 프로젝트별 범례와 기호 규칙 적용 | 적용 범위와 규칙 버전 추적, 미등록 기호는 미분류로 유지 |
| AI 보정 제안이 잘못된 참조를 포함 | 형식 오류를 검출하고 통과 결과에 정상 관계로 포함하지 않음 |

### 판정 기준

구조 검증은 ID·참조·좌표·출처·필수 필드와 관계 종류를 검사합니다. 미해결 연결은 별도 후보·문제 목록으로 보관하고 정상 연결과 구분합니다. 초안 보관은 가능하지만, 통합 전달용 버전에는 검증 보고서와 사람의 대조 상태가 있어야 합니다.

인식 성능은 기호 탐지, 태그 정확도, 연결 관계의 정밀도·재현율, 사람이 수정한 항목 수와 소요 시간으로 평가합니다. 구조 검증 통과만으로 인식 정확도를 주장하지 않습니다. 수치 목표와 위치 매칭 허용오차는 실제 샘플·정답 세트를 정한 뒤 합의합니다.
