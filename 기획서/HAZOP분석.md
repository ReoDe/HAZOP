# HAZOP 분석 기획

[상세 플로우차트](<../flow chart/04-hazop-analysis.md>) · [정보 통합·관리](정보통합관리.md) · [전체 기획](전체기획.md) · [공통 원칙](전체기획.md#principles) · [HAZOP 기법 지침](HAZOP기법지침.md)

## 목적과 범위

검증된 통합 그래프에서 원인·영향의 후보 경로와 관련 설계정보를 탐색하고, 원인·결과 패턴과 AI 해석을 통해 전문가 검토용 HAZOP 초안을 만듭니다. 첫 버전은 사람이 선택한 검토 구간의 정상 운전을 분석합니다.

검토 구간은 여러 설비·배관을 포함하는 HAZOP의 분석 단위입니다. 도면 재추출·그래프 수정은 ②·③에 요청하고, 확정 위험도와 최종 검토·조치 관리는 ⑤에서 다룹니다.

| 위험도 | ④ AI 제안, ⑤ 사람이 확정. MVP 기준표는 KOSHA P-86-2017 〈표5〉–〈표9〉 예시를 임시로 사용 (사용자 결정, 2026-11-04) |

## 입력 확인과 분석 준비

③에서 미확인 정보가 명시된 채 구조 검증을 통과한 그래프도 입력받을 수 있으며, 그 미확인이 영향을 미치는 판단만 보류합니다. 차단 오류가 있는 그래프는 정상 입력으로 사용하지 않습니다.

- 그래프 버전과 관련 설계자료·조건·원문 근거 버전을 분석 실행에 고정합니다.
- 검토 구간의 설계 의도, 포함 대상, 경계와 정상 운전모드를 기록합니다. 경계 밖 영향도 필요한 경우 탐색하되 확장 범위를 명시합니다.
- 미확인 조건, 자료 충돌, 방향 미확인 연결, 밸브 정상 위치 미확인을 구분합니다.

## 편차 후보와 검토 기록

파라미터와 가이드워드의 조합(유량 없음·압력 증가·유체 역류 등)으로 후보를 제시합니다. 초기 후보 목록은 [지침의 이탈 후보 목록](HAZOP기법지침.md)(5.3절, 44개)이고, 적용 불가 판정 규칙은 같은 지침의 8.2절을 따릅니다(사용자 결정, 2026-11-04). 사람이 후보를 추가할 수 있어야 합니다. 규칙상 비적용으로 분류한 후보도 평가한 후보 목록에 남기고, 규칙에 없는 편차까지 모두 검토했다고 표현하지 않습니다.

| 기록 | 내용 |
| --- | --- |
| 후보 식별 | 후보 ID, 검토 구간, 파라미터, 가이드워드, 편차 설명 |
| 생성 근거 | 규칙·버전, 관련 설계정보, 자동 제시 또는 수동 추가 여부 |
| 판단 | 선택·제외·보류, 판단 주체·시각·이유 |
| 적용 버전 | 그래프·자료·운전모드·분석 실행 참조 |
| 재검토 | 이전 판단과 새 판단을 별도 이력으로 유지 |

기존 결과를 열면 당시의 전체 후보와 판단을 복원할 수 있어야 합니다. 자료나 그래프가 바뀌면 이전 판단을 자동 승인으로 복사하지 않고, 해당 구간의 모든 후보를 재검토 대상으로 표시합니다(⑤의 사용자 결정).

## 원인·결과 패턴 라이브러리

HAZOP의 원인 도출은 대부분 기기 유형별 고장모드의 반복이므로, **기기 유형 × 파라미터 × 가이드워드**별 대표 원인·결과·확인할 보호수단을 규칙으로 관리합니다(권고 승인). 역할은 다음과 같이 나눕니다.

- 그래프 탐색: 실제 도면에서 편차와 관련된 기기·경로·보호수단을 찾습니다.
- 패턴: 찾은 기기에 해당하는 원인·결과 후보를 제시합니다.
- AI: 패턴과 근거를 해석하고, 패턴 밖의 추가 가설은 별도로 표시합니다.

| 기기 유형 | 편차 | 원인 패턴 예 | 결과·확인할 보호수단 예 |
| --- | --- | --- | --- |
| 원심 펌프 | 유량 없음 | 펌프 정지, 흡입 측 밸브 닫힘 | 하류 유량 상실, 저유량 경보 |
| 용기 | 압력 증가 | 출구 차단, 유입 제어밸브 열림 고착, 외부 화재 | 설계압력 초과, 안전밸브·고압 경보·인터록 |
| 체크밸브 | 유체 역류 | 체크밸브 고장과 하류 압력 상승 | 상류 설비 역류·과압 |

위 예시는 구조 설명용 일반 지식이며 검증된 패턴이 아닙니다. 실제 패턴은 사용자 평가 기준과 문헌으로 확인하고, 패턴마다 출처·버전·적용 조건(기기 종류, 정상 위치 등)을 기록합니다. MVP는 샘플 도면의 기기에 필요한 소수 패턴만 만듭니다. 이 라이브러리는 ②의 P&ID 해석 지식과 별개인 ④의 지식 자산입니다.

## 그래프 알고리즘의 역할

Python에서 편차와 대상에 맞는 탐색 규칙을 적용합니다. 최초에는 관계 종류·방향·깊이를 제한한 도달성 탐색(BFS/DFS 등)으로 시작하고, 구체적인 알고리즘과 한계값은 샘플로 정합니다.

| 탐색 | 고려할 정보 |
| --- | --- |
| 원인 후보 범위 | 상류·하류, 밸브 정상 위치·펌프 상태, 유틸리티 의존, 제어루프 등의 관련 대상 |
| 영향 후보 범위 | 편차가 영향을 줄 수 있는 연결 대상, 분기, 경계와 외부 시스템 |
| 보호수단 | 해당 편차·대상과 연결된 경보·인터록·안전밸브와 설정값 |
| 근거 묶음 | 경로의 노드·관계 ID, 적용 패턴, 설계조건, 원문 위치 |

물리 배관, 신호, 제어, 보호 관계를 구분하고 탐색 방향을 기록합니다. 순환 그래프는 방문 상태·깊이·경로 수 제한으로 처리하며, 탐색이 잘린 사실도 결과에 남깁니다. 연결상 도달 가능하다는 사실은 인과관계를 입증하지 않습니다. 정상 유동 방향만으로 역류·과압 전파를 일괄 배제하지 않으며, 보호수단이 그래프에 있다는 이유만으로 독립성·용량·작동 적정성을 확정하지 않습니다.

## AI 추론과 위험도 제안

AI에 편차, 설계 의도·정상 조건, 탐색 경로와 원문 근거, 적용 패턴, 누락 정보와 탐색 한계를 전달합니다. 원인·결과·보호수단의 해석과 패턴 밖 추가 가설을 구분해 반환하도록 합니다. 추가 가설은 그래프의 사실로 자동 등록하지 않습니다.

- **도면 설비 한정 (사용자 결정, 2026-11-04)**: AI의 원인·결과·보호수단은 그래프(도면)에 있는 대상만 사용합니다. 도면에 없는 설비를 전제한 가설은 거부하고, 거부 사유를 실행 기록에 남깁니다.
- **설계보완 후보 (사용자 결정, 2026-11-04)**: 도면 설비만으로 구성한 시나리오가 아래 조건 중 하나에 해당하면 '설계보완 후보'로 기록합니다. 확정은 ⑤에서 사람이 하며, 자동으로 확정하지 않습니다.
  - 제안 위험도가 KOSHA 〈표9〉 기준으로 조건부 수용(3) 이상인 경우
  - 그럴듯한 원인에 대해 그래프에서 보호수단을 찾지 못한 경우
- 설계보완 후보는 도면 설비로 확인된 문제를 다룹니다. 반면 자료 요청은 정보가 부족한 경우를 다룹니다. 따라서 '자료 요청은 개선 조치로 자동 생성하지 않는다'는 원칙과 충돌하지 않습니다. 보호수단이 '없음'인지 '미확인'인지 판단할 수 없으면, 설계보완 후보와 함께 자료 요청도 남깁니다.

### 모델 연결

구현 우선순위는 다음과 같습니다(사용자 결정).

| 순위 | 연결 방식 | 시점 |
| --- | --- | --- |
| 1 | Claude API (`claude-opus-5-5` 단일) | 현재는 Claude Code 구독제 세션에서 만든 고정 응답으로 검토하고, API 실호출 검증은 후속으로 따로 만듦 (사용자 결정, 2026-11-04, [인터페이스](인터페이스.md)) |
| 2 | Claude 팀 구독제 활용 | 후속. 구독을 애플리케이션에서 어떤 방식으로 쓸 수 있는지는 구현 시 확인 |
| 3 | 로컬 LLM | 후속. 실제 발전소 도면 사용 등 데이터 반출 제약이 생길 때 |

- 외부 API 사용은 허용됩니다(사용자 결정). 샘플 P&ID는 사용자가 직접 만든 자료이므로 MVP의 데이터 반출 제약은 없습니다. 실제 발전소 도면을 사용하기 전에 데이터 반출 정책을 정합니다.
- 세 방식을 바꿔 쓸 수 있도록 AI 호출부를 분리하고, 모델·버전·요청 템플릿을 실행 기록에 남깁니다.
- 무엇을 검증하고 무엇을 신뢰할지의 범위는 [신뢰 경계](전체기획.md#trust-boundary)를 따릅니다.
- MVP 테스트는 고정 응답으로 수행합니다. 실제 API 호출은 환경변수 `ANTHROPIC_API_KEY`가 있을 때만 합니다(사용자 결정, 2026-11-04).

### 위험도 제안

위험도 제안에는 프로젝트에서 정한 심각도·가능성 등급과 위험도 기준표를 적용합니다. AI는 등급과 설명을 제안하고 Python은 허용값·기준표 대응을 검사·계산합니다.

- MVP 기준표는 KOSHA P-86-2017 〈표5〉–〈표9〉 예시를 임시 기준표로 씁니다. 심각도는 원문의 강도(4단계), 가능성은 발생빈도(3단계)에 대응하며, 위험도(1–5)는 행렬에서 찾습니다([지침 6·8.3절](HAZOP기법지침.md)). 출처·'예시'·기준표 버전을 기록하고, 원전용 강도 기준이 정해지면 교체합니다(사용자 결정, 2026-11-04).
- 위험도 제안마다 적용 기준·버전, 평가한 시나리오, 근거, 가정·불확실성을 기록합니다.
- 발생빈도에는 현재 보호수단을 반영하고, 강도에는 반영하지 않습니다(§6.8(3)). 보호수단이 미확인이면 발생빈도에 감소 효과를 반영하지 않습니다(사용자 결정, 2026-11-04).
- 기준표나 판단 근거가 없으면 위험도 제안을 보류합니다. 확인 가능한 원인·결과 초안은 유지합니다.

## 정보 부족과 결과 저장

원인·결과·보호수단·위험도 각각의 확인 상태를 관리합니다. 보호수단 자료가 없으면 '없음'이 아니라 '미확인'으로 둡니다. 자료 요청은 ⑤에서 해당 편차의 메모로 이어지며 개선 조치로 자동 생성하지 않습니다.

| 저장 단위 | 주요 내용 |
| --- | --- |
| 분석 실행 | 실행 ID, 구간, 정상 운전 조건, 그래프·자료·규칙·패턴 버전, 탐색 설정 |
| 편차 후보·판단 이력 | 전체 제시 목록, 선택·제외·보류, 주체·이유·이전 판단 |
| 시나리오·근거 | 원인·결과·보호수단, 적용 패턴, 경로 참조, 원문 위치, 사실/해석/추가 가설 구분 |
| 위험도 제안 | AI 제안 등급·근거·가정, 기준표 버전, 계산 결과·제안 상태 |
| 보류·자료 요청 | 부족 항목, 판단 불가 범위, 요청 자료, 재검토 상태 |
| AI 실행 기록 | 모델·요청 템플릿·입력 근거 묶음·응답·실행 시각과 검증 결과 |

저장된 기록만으로 당시 결과를 다시 구성할 수 있게 합니다. AI가 실패해도 후보·탐색 결과는 보존하고 실패한 추론 단계부터 재시도할 수 있어야 합니다. AI 실패 보류 문구는 한국어 상태와 안내만 담고, 원문 오류와 필드 경로는 AI 실행 기록에만 남깁니다 (총괄 결정(권고안, 사용자 위임 2026-11-06), 구현 커밋 3048906).

## 품질 평가

구조 검증과 별도로 분석 결과가 쓸모 있는지 평가해야 합니다. 사용자가 이 리뷰를 바탕으로 평가 기준(편차별 정답 원인·결과·보호수단 등)을 직접 정리해 제공할 예정입니다. 기준을 받으면 패턴·탐색·AI 결과를 비교하여 재현율과 오류 유형을 기록하고, 기준의 형식과 판정 방법을 그때 확정합니다. 기준을 받기 전의 권고 형식과 판정 방법은 [평가 기준 비교](평가기준비교.md)에 있습니다.

## 독립 검증

샘플 통합 그래프·설계정보·편차 규칙·패턴·평가 기준표로 검증합니다. 알고리즘과 저장·상태 검증은 고정된 AI 응답 샘플로 수행할 수 있으며, AI 추론 품질은 위 품질 평가로 따로 확인합니다.

| 범위 | 사례 | 기대 결과 |
| --- | --- | --- |

| MVP | 분기·순환·경계 밖 연결 포함 | 탐색 종료 보장, 관계 종류·경계·제한 이력 표시 |
| MVP | 정상 닫힘(NC) 밸브가 있는 경로 | 정상 운전 유로와 구분하여 탐색(닫힌 밸브에서 탐색을 끊지 않고 경로에 `valve_state: closed_valve_on_path`로 표시, 워크시트에는 '정상 닫힘 밸브 경유'), 근거와 워크시트 근거 참조 열([인터페이스 §6.2](인터페이스.md#62-hazop-워크시트-열))에 밸브 상태 기록 (총괄 결정(권고안, 사용자 위임 2026-11-06)) |

### 통과와 보류 기준

전체 후보의 판단 상태, 그래프·원문 참조, 적용 패턴, 탐색 범위와 한계, 가설 표시, 보류 사유가 유효해야 합니다. 위험도 제안은 정의된 평가 기준에 맞고 제안임이 표시되어야 합니다. 해결되지 않은 참조·형식 오류는 정상 결과로 취급하지 않으며, 보류 항목은 별도 상태로 함께 전달할 수 있습니다.
