# 완성본 디자인 방향 시안 3안

[현재 화면 명세](../../screen-spec.md) · [기존 시안](../README.md) · 토큰 원본 `hazop/app/tokens.py`

완성본 화면 흐름(결정로그 2026-11-06)에 적용할 디자인 방향을 고르기 위한 시안입니다. 구현물이 아니며, 고른 방향은 3단계 구현 때 앱 전체에 적용합니다. 데이터는 모두 가상 샘플(SNP-M-102 가압기 계통)이고 실제 설계값이 아닙니다.

## 1. 보는 법

- `index.html`을 브라우저로 열면 위쪽 버튼(또는 키보드 A·B·C, 1~5)으로 안과 화면을 바꿔 볼 수 있습니다. 파일을 직접 열 때 브라우저가 iframe을 막으면 각 안 폴더의 HTML을 바로 여세요.
- 각 안 폴더에는 화면 5개의 HTML과 `-1366.png`(1366×768), `-1920.png`(1920×1080) 스크린샷, `contrast-table.md`가 있습니다.
- 모든 파일은 `build.py`가 만듭니다. 수정은 `build.py`에서 하고 아래 명령으로 다시 만듭니다. 대비 기준 미달이 하나라도 있으면 종료 코드 1로 끝납니다.

```bash
python 디자인/시안/완성본/build.py --shoot
```

| 화면 | 파일 | 담은 내용 |
| --- | --- | --- |
| ① 자료 등록 | `1-자료등록` | 등록 목록(성공·보류·실패·미확인), drawio·PDF 놓기 영역, 표제란 자동 후보 → 확정, 등록 단계 |
| ② 도면 추출 | `2-도면추출` | 도면 오버레이(노드 종류 색), 레이어 토글·범례, 미해결 관계 경고 띠, 선택 객체 속성 |
| ③ 지식그래프 | `3-지식그래프` | 필터, 로컬 그래프, AI 근거 경로 강조, 출처 문서, 재확인 경고 |
| ④ 검토구간 | `4-검토구간` | 도면 위 구간별 색, 구간 목록(S1~S5), 덮은 비율 19/22, 미포함 3개, 병합·분할·확정 |
| ⑤ 분석 결과 | `5-요약행렬` | 구간 × 편차 요약 행렬(시나리오 수·최고 위험·미검토 수) + 상세 워크시트(원인·결과·보호수단·권고, AI 근거, 상태 제안·수정·승인·기각) |

세 안은 같은 데이터와 같은 마크업을 쓰고, 토큰·간격·셸(탐색 구조)만 다릅니다. 그래서 차이는 디자인 방향에서만 나옵니다.

## 4. 권장안

**B안(고밀도 작업대)을 기본으로 하고, A안의 단계 표시를 빌려 오기를 권합니다** [추론].

- 근거 1(측정): 1366×768에서 B안만 ①~④ 화면이 스크롤 없이 모두 보이고, 검토자가 가장 오래 머무는 ⑤ 워크시트도 75%가 보입니다(A 47%, C 58%).
- 근거 2 [추론]: 이 앱은 구간 수십 개 × 편차 수십 개를 오가며 검토하는 도구라서, 첫인상보다 한 화면에 담기는 정보량과 이동 속도가 작업 시간을 좌우합니다.
- 근거 3 [추론]: 현재 앱 구조(Qt 위젯 + 웹뷰)와 가장 잘 맞아 3단계 구현 부담이 가장 작습니다.
- 빌려 올 것: A안의 단계 표시(✓ 완료·현재·남은 단계)를 B안 레일 위에 함께 표시하면 처음 쓰는 사람도 흐름을 잃지 않습니다.
- C안은 버리지 않고, 나중에 "어두운 테마"로 추가할 수 있습니다. 토큰과 대비표가 이미 있습니다. 다만 도면 캔버스는 C에서도 흰 바탕으로 두는 편이 원본 대조에 맞습니다 [추론].

"모던한 화면"을 가장 중시한다면 C안, 처음 쓰는 사람의 편안함을 가장 중시한다면 A안이 맞습니다. 결정은 사용자 몫입니다.

## 5. 색 대비(WCAG 2.1)

`build.py`가 WCAG 2.1 상대 휘도 공식으로 안마다 51쌍을 계산합니다. 기준은 글자 4.5:1(SC 1.4.3), 그래픽(입력란 테두리, AI 초안 점선, 도면 선, 노드·관계·구간 색) 3:1(SC 1.4.11)입니다. 세 안 모두 51쌍 전부 통과입니다.

| 안 | 전체 표 | 글자 쌍 최저값 | 그래픽 쌍 최저값 |
| --- | --- | --- | --- |
| A | [a-light-minimal/contrast-table.md](a-light-minimal/contrast-table.md) | 4.99(구간5 꼬리표 흰 글자) | 3.34(입력란 테두리·AI 점선) |
| B | [b-dense-workbench/contrast-table.md](b-dense-workbench/contrast-table.md) | 5.43(구간3 꼬리표 흰 글자) | 3.51(입력란 테두리·AI 점선) |
| C | [c-dark-dashboard/contrast-table.md](c-dark-dashboard/contrast-table.md) | 5.98(흐린 글자 / 보조 패널) | 3.64(입력란 테두리) |

- 색만으로 구분하지 않습니다. 위험 등급은 숫자와 등급명(수용·조건부·불허)을, 상태는 글자(제안·수정·승인·기각)와 모양(점선·빗금 / 실선 / 채움)을, 구간은 S 번호를 함께 씁니다.
- 위험도 3단 구분은 `tokens.py`의 `risk_band`(1·2 수용, 3·4 조건부, 5 불허)를 따릅니다. 〈표9〉 해석은 기존과 같이 [추론]입니다.
- 비활성 버튼(반투명)은 WCAG 대비 기준의 예외 대상이라 표에 넣지 않았습니다.

## 6. 깨짐 확인 결과(2026-11-07)

두 가지로 확인했습니다.

1. 스크린샷 30장(3안 × 5화면 × 2폭)을 Chrome 헤드리스(배율 1)로 찍고, 최종본 30장을 모두 직접 열어 봤습니다.
2. 같은 HTML을 로컬 HTTP 서버로 띄워 브라우저에서 1366×768·1920×1080 크기로 열고 스크립트로 검사했습니다. 검사 항목은 페이지 가로·세로 넘침, 잘린 글자(넘침 숨김·말줄임), 의도하지 않은 가로 스크롤, Pretendard 로드 여부, 본문이 화면 아래까지 채워지는지입니다.

최종 결과: 30개 조합 모두 페이지 넘침 0, 잘린 글자 0, 가로 스크롤 0, Pretendard 로드됨. 남은 것은 패널 안 세로 스크롤(의도한 동작, 3절 정보 밀도 값)뿐입니다.

확인 과정에서 찾아 고친 결함:

| 결함 | 해당 | 조치 |
| --- | --- | --- |
| 1366에서 등록 목록 표 가로 스크롤 | 세 안 | 파일 이름 열만 줄바꿈 |
| 열 폭 고정 시도로 상태 칩("등록 완료")이 말줄임으로 잘림 | 세 안 | 고정 폭 취소 |
| 본문이 화면 아래까지 늘어나지 않아 아래 ⅓이 빔 | B | 작업 영역 `flex:1` |
| 요약 행렬 칸에서 "검토 완료"가 "검토 완 / 료"로 끊김 | C(좁은 칸) | 칸 문구를 "완료"·"0건"으로 줄이고 줄바꿈 금지 |
| 선택 테두리가 PCV-455A 태그를 가림, V-8030 태그가 배관·점선 원과 겹침, 세로 글자가 배관선과 겹침 | 세 안 도면 | 태그·글자 위치 이동 |
| "미확인"이 고정폭 글꼴로 벌어져 보임 | 세 안 | 도면 번호가 있을 때만 고정폭 |

처음 검사는 브라우저 미리보기가 페이지를 정적 사본으로 열어 iframe이 비어 있었는데도 "모두 정상"으로 나왔습니다. 문서 요소 수를 함께 확인해 이를 잡았고, 이후 검사는 로컬 HTTP 서버로 다시 돌렸습니다.

## 7. 한계와 직접 확인할 것

- Pretendard는 CDN(jsDelivr, v1.3.9)에서 읽습니다. 인터넷이 없으면 맑은 고딕으로 바뀌며, 그 상태의 화면은 찍어 보지 않았습니다.
- 배율 1(100%)로만 찍었습니다. Windows 125%·150% 배율에서는 1366 화면의 실제 작업 폭이 더 좁아지므로, 고른 안을 실제 모니터에서 한 번 확인하세요.
- 도면은 실제 drawio SVG가 아니라 단순화해 다시 그린 그림이고, 지식그래프 배치는 고정 좌표라 일부 이름표가 선과 겹칩니다. 이 겹침은 시안 데이터의 한계이며 안 사이 비교에는 영향이 없습니다.
- 정보 밀도 값은 이 샘플 데이터 기준입니다. 실제 구간·시나리오 수가 늘면 세 안 모두 스크롤이 늘어납니다.
- 용어: 편차(deviation)·가이드워드는 IEC 61882:2016 HAZOP 지침의 용어를 따랐고, 가압기(pressurizer)·PORV(power-operated relief valve)·PRT(pressurizer relief tank)는 미국 가압경수로 계통 용어(NRC·Westinghouse 계열 문서 용례)를 따랐습니다 [일반지식].
