# 데스크톱 인터페이스 기획

[전체 기획](overview.md) · [공통 원칙](overview.md#principles) · [데이터 규격](overview.md#data-contract) · [신뢰 경계](overview.md#trust-boundary) · [HAZOP 분석](hazop-analysis.md) · [검토·결과 관리](review-results.md) · ['출력화면 AX' 데모 분석](../design/output-screen-ax-demo.md)

이 문서는 HAZOP 프로그램의 데스크톱 화면을 정의합니다. 다음 단계인 클릭 가능한 HTML 시안과, 사용자 확인 뒤의 PySide6 구현이 이 문서를 기준으로 삼습니다. 공통 원칙(근거·미확인·이력·AI 결과 취급)은 반복하지 않고 링크합니다.

## 1. 목적과 범위

### 1.1 사용자 결정 (2026-11-04)

| 항목 | 결정 |
| --- | --- |
| 형태 | Windows 전용 데스크톱 네이티브. 창·메뉴·표·입력은 PySide6(Qt), 도면 오버레이와 그래프 캔버스는 기존 HTML 뷰어(`hazop/viewer/template.html`)를 QtWebEngine으로 내장 |

| 확정 방식 | 시나리오와 설계보완 후보마다 수용·수정·기각·보류 중 하나와 사유를 기록. 검토자·시각, AI 원본 값과 사람 수정값을 구분해 보관 |
| 저장 | 단일 사용자, 로컬 PC. `자료저장소/`·`출력/` 아래 JSON 파일 |
| 패키징 | 구조만 대비하고 방안을 기획서에 기록. 실행파일 빌드는 하지 않음 |
| 디자인 | ['출력화면 AX' 데모 분석](../design/output-screen-ax-demo.md)의 방향(캔버스 우선, 무채색 바탕에 파랑 하나만 UI 강조색, 레이어 토글, 근거 집계, 도면·그래프 색 체계 공유)에 HAZOP 전용 화면을 더함 |

## 2. 프로그램 구조

### 2.1 창 구성

단일 주 창입니다. 데모의 공통 화면 틀을 따릅니다.

| 영역 | 구성 |
| --- | --- |
| 상단 헤더 (Qt) | 로고, 프로그램 이름, 현재 위치(구간 이름·도면번호 굵게, 실행 ID 회색), 단계 탭 `① 자료 등록 · ② 도면·그래프 · ③ 지식그래프 · ④ HAZOP 분석 · ⑤ 설계보완·확정`(알약 모양), 우측에 검토자 이름 |
| 본문 | 화면별 배치(§3). 캔버스가 있는 화면은 캔버스를 가장 크게 둠 |
| 하단 상태줄 (Qt) | 결과 검증 상태 칩(`passed`/`blocked`), 진행 중 작업, 최근 저장 시각 |
| 메뉴 (Qt) | 파일(구간 열기, 실행 열기, Excel 내보내기, 설정), 보기(레이어·패널), 도움말(버전·데이터 위치: 프로그램 이름·버전, 자원·작업·저장 루트, 설정 파일, 제3자 라이선스 고지 위치와 "라이선스 고지 열기"(탐색기), 법무 검토 전 내부용 안내) |

단계 탭은 자유 이동입니다. 앞 단계 결과가 없으면 해당 화면은 빈 화면 안내를 보여 주고 이동은 막지 않습니다 [제안]. 번호는 기획서 단계 번호를 그대로 씁니다. ③은 비워 두었다가 2026-11-05 사용자 확정으로 ③ 지식그래프를 채웠습니다(T1 D1).

### 2.2 Qt 영역과 내장 웹뷰 영역의 경계

| 담당 | 영역 |
| --- | --- |
| Qt | 헤더·메뉴·상태줄, 목록과 표(QTableView와 모델), 입력 폼, 파일 대화상자, 확인 대화상자, 상세 패널, 진행 표시, 모든 파일 읽기·쓰기와 Python 파이프라인 호출 |
| 웹뷰 | 도면 SVG와 오버레이, 그래프 캔버스, 도면/그래프 전환, 레이어 토글, 줌·이동, 강조 표시. 기존 `template.html`에 있는 기능 범위 |

- 웹뷰는 파일을 직접 읽거나 쓰지 않습니다. 데이터는 Python이 넘깁니다.
- 웹뷰 인스턴스는 하나만 만들어 ②③④⑤가 공유합니다 [제안]. 화면을 바꿀 때 웹뷰를 해당 화면의 캔버스 자리로 옮깁니다.
- ③ 지식그래프는 기존 `template.html`이 아닌 별도 HTML로 그립니다. 렌더러 force-graph의 vendor JS는 HTML에 인라인으로 넣습니다. 웹뷰가 `LocalContentCanAccessFileUrls`를 끄므로 `<script src>`로는 적재되지 않습니다(`W2` 확인). 상세는 [그래프 활용 §5.2](graph-usage.md#52-앱에-넣는-방식)를 따릅니다.
- 데모처럼 캔버스 위에 떠 있는 패널은 웹 안의 요소(레이어·줌·근거 집계)에만 씁니다. Qt 위젯을 웹뷰 위에 겹쳐 띄우는 방식은 렌더링 문제가 생길 수 있어 쓰지 않고, Qt 패널은 분할 창(QSplitter)으로 옆에 둡니다 [일반지식].
- ②에서는 기존 뷰어의 검색·속성 패널을 그대로 쓰고, ④⑤에서는 웹 쪽 속성 패널을 숨기고 Qt 상세 패널을 씁니다 [제안]. 이를 위해 뷰어에 '내장 모드' 표시가 필요합니다.

### 2.3 Python ↔ 웹뷰 연결

QWebChannel로 Python 객체 하나(`bridge`)를 웹에 노출합니다. 메시지는 JSON 문자열 하나로 주고받습니다 [제안].

| 방향 | 메시지 | 내용 |
| --- | --- | --- |
| Python → 웹 | `load` | 도면 HTML 생성 결과(추출 결과·그래프·SVG). 기존 `hazop/viewer/build.py`가 만든 파일을 로드 |
| Python → 웹 | `setView` | `drawing` 또는 `graph` |
| Python → 웹 | `highlight` | 원인 설비, 경로 노드·관계, 보호수단 노드, 추정 경로 관계 목록(§3.3 강조 규칙) |
| Python → 웹 | `clearHighlight`, `focus` | 강조 해제, 특정 노드로 이동 |
| 웹 → Python | `nodeSelected` | 클릭한 노드의 `entity_id`(없으면 `source_object_id`) |
| 웹 → Python | `highlightResult` | 강조 요청 중 화면에 그리지 못한 ID 목록. 근거 집계의 '미표시' 계산에 사용 |
| Python → 웹 | `loadKnowledge` | ③ 지식그래프 데이터(노드·링크·속성·근거 ID·미리 계산한 알고리즘 결과) |
| 웹 → Python | `runAlgorithm` | ③에서 알고리즘 실행 요청. 결과는 Python → 웹 `algorithmResult {algorithm, start, kg_version, result}`로 돌려줌. ③의 다른 메시지: Python → 웹 `loadKnowledge`·`selectNode {id}`, 웹 → Python `linkSelected {id}`·`nodeSelected`(T1 W6 구현) |

- 뷰어는 브라우저에서 단독으로 여는 기존 사용 방식(`출력/뷰어/*.html`)과 기존 검사(`scripts/check_viewer.py`, `check_viewer_paths.js`)를 계속 지원해야 합니다. `bridge`가 없으면 단독 모드로 동작합니다.
- `qwebchannel.js`는 템플릿에 `<script>` 태그로 넣지 않고, Qt 쪽에서 `QWebEngineScript`로 실행 시점에 주입합니다. 따라서 `hazop/viewer/check.py`의 템플릿 `<script>` 개수 검사(`TEMPLATE_SCRIPT_COUNT = 3`)는 그대로 유지합니다 (총괄 결정(권고안, 사용자 위임 2026-11-04)).
- 생성 HTML은 크기 제한을 피하려고 `setHtml`이 아니라 파일 경로로 로드합니다 [일반지식].
- 웹뷰의 외부 네트워크 접근은 끕니다. 도면 SVG는 사용자 제공 파일이므로 기존 `hazop/viewer/sanitize.py` 처리를 거친 결과만 표시합니다([신뢰 경계](overview.md#trust-boundary)).

### 2.4 처리 실행 방식

등록·추출·그래프·분석·Excel 출력은 기존 스크립트와 같은 Python 함수를 호출합니다. 화면 전용 처리 경로를 따로 만들지 않습니다(자료등록.md의 "같은 Python 처리" 원칙). 오래 걸리는 작업은 작업 스레드에서 실행해 창이 멈추지 않게 하고, 진행 단계와 취소 가능 여부를 상태줄에 표시합니다.

### 2.5 AI 확장 지점

- 분석 실행 대화상자에 'AI 응답 출처' 선택을 두고, 이번에는 **고정 응답 폴더**만 활성화합니다. 기존 `ai.FixedResponseClient`를 씁니다.
- 기존 `make_client()`처럼 클라이언트 생성을 한 곳에 모아 두면, 나중에 `ai.AnthropicClient` 등을 같은 자리에 연결할 수 있습니다. 화면에는 비활성 항목만 보이고 동작은 구현하지 않습니다.
- 고정 응답은 `<폴더>/<candidate_id>.json` 형식이며, `region_id`와 `bundle_sha256`이 요청 근거 묶음과 다르면 기존 규칙대로 `input_mismatch`로 처리됩니다. 화면은 이 상태를 후보별로 보여 줍니다(§3.3).
- **근거 묶음 내보내기 (사용자 결정, 2026-11-04)**: 구간·편차별 근거 묶음과 요청 프롬프트를 폴더로 내보냅니다. 사용자는 Claude Code 구독제 세션에서 이 폴더로 응답을 만들고, 프로그램은 그 응답 폴더를 다시 불러와 분석합니다. 이 과정에서 프로그램은 AI를 호출하지 않습니다.

**내보내기·응답 폴더 형식** (총괄 결정(권고안, 사용자 위임 2026-11-04))

```
출력/근거묶음/<region_id>/<내보낸 시각>/
  manifest.json                  구간 ID·버전, 그래프 ID·버전, 입력 파일 해시, 템플릿 정보(ai.template_info()), 후보 목록
  response_schema.json           ai.RESPONSE_SCHEMA
  system_prompt.txt              ai.SYSTEM_PROMPT
  <candidate_id>/bundle.json     근거 묶음(run.build_bundle 결과)
  <candidate_id>/user_prompt.txt ai.build_request(bundle)["user"]
  responses/<candidate_id>.json  응답 틀: region_id·bundle_sha256를 미리 채움
```

- 구간 JSON이 지식그래프를 지정하면(`inputs.knowledge_graph`) 근거 묶음에 `knowledge_context`가 들어가고, 지정하지 않으면 이 키가 없어 기존 고정 응답의 `bundle_sha256`이 그대로입니다([그래프 활용 §6.4](graph-usage.md#64-wp5-상세-규격), T1 W7).
- 대상은 판단이 '선택'인 후보입니다. 근거 묶음은 시각을 포함하지 않으므로, 입력이 같으면 내보낼 때와 분석할 때의 `bundle_sha256`이 같습니다.
- 내보내기는 분석 실행 폴더(`출력/분석/...`)와 `analysis.json`을 만들지 않습니다.
- 응답 파일(`<응답 폴더>/<candidate_id>.json`)의 필수 필드는 `ai.FixedResponseClient` 형식(`hazop/analysis/ai.py` 121행)을 따릅니다: `region_id`, `bundle_sha256`, `stop_reason`(`end_turn`·`refusal`·`max_tokens`), `output`(`RESPONSE_SCHEMA`를 따르는 객체). `sample_note`, `stop_details`는 선택입니다.
- 반출: 근거 묶음은 도면 내용을 담습니다. 데이터 반출 정책은 [HAZOP 분석 모델 연결](hazop-analysis.md#모델-연결)을 따르며, 보안 등급이 있는 실제 설계자료는 사용자 확인 뒤에만 내보냅니다.

## 3. 화면별 명세

공통 표시 규칙:

- 미확인 값은 "미확인"과 사유로 표시하고 빈칸·0·"없음"으로 바꾸지 않습니다. 해당 없음은 "해당 없음"으로 따로 씁니다([공통 원칙](overview.md#principles)).
- `knowledge_status`가 `hypothesis`인 항목에는 "가설" 배지, AI 추가 가설(`origin: ai_additional_hypothesis`)에는 "AI 추가 가설" 배지를 붙입니다.
- 결과 검증 `passed`는 "형식·참조 검증 통과(보류 항목이 없다는 뜻이 아님)"를 함께 표시합니다(`validation.note`).
- 오류는 화면 전체를 막지 않고 해당 영역에 사유와 다음 조치를 보여 줍니다.

### 3.1 ① 자료 등록

**목적**: draw.io 또는 벡터 PDF P&ID 원본 1개를 등록하고, 추출·그래프 생성까지 이어서 실행합니다. PDF는 등록이 끝나면 추출·그래프 생성을 자동으로 실행하고 ② 도면 화면으로 옮겨 그 도면을 엽니다(사용자 결정 2026-11-06). draw.io는 지금처럼 "추출·그래프 만들기"를 눌러 실행합니다. 여기서 그래프는 지식그래프의 재료가 되는 내부 도면 연결 데이터(`hazop/graph`)입니다.

| 영역 | 구성 |
| --- | --- |
| 좌측 | 등록 자료 목록 표: 자료 ID, 등록 버전, 원본 파일명, 도면번호·개정번호(미확인 표시), 등록 시각, 상태(`registered` 등록 완료·`failed` 실패·`on_hold` 보류·`draft` 저장 진행 중), 추출·그래프 생성 여부 |
| 우측 | 등록 폼: 프로젝트 ID, 원본 파일 선택 또는 끌어 놓기(1개), 도면번호·개정번호·제목(비우면 미확인), 등록자, 사유. 아래에 결과 영역 |

도면 SVG는 draw.io 원본과 같은 이름의 SVG를 파생 자료로 함께 등록합니다(사용자 결정, 2026-11-04). 원본은 바꾸지 않으며, SVG는 원본을 대체하지 않습니다(자료등록.md). PDF는 원본 옆 SVG를 찾지 않고 파생 자료도 등록하지 않습니다. 추출할 때 PDF의 벡터 요소를 추출과 같은 좌표로 그린 SVG(`출력/추출/<이름>/page.svg`)를 만들어 ② 배경으로 씁니다([정보추출](extraction.md)).

**SVG 파생 등록 형식** (총괄 결정(권고안, 사용자 위임 2026-11-04))

- 찾는 파일(원본과 같은 폴더, 등록과 추출이 같은 규칙 사용, 총괄 결정(권고안, 사용자 위임 2026-11-04)):
  - 한 페이지 문서: ① `<파일명>.svg`·`<stem>.svg` ② `<NN>_<페이지 이름>.drawio.svg`(예: 샘플의 `01_SNP-M-102.drawio.svg`) ③ 폴더에 `*.drawio.svg`가 하나뿐이면 그것(기존 추출 동작).
  - 여러 페이지 문서: ②만 씁니다. SVG가 없는 페이지는 'SVG 없음'으로 남깁니다.
  - 페이지 이름에 경로 구분자·`..`·드라이브 문자·제어문자가 있으면 ② 규칙을 쓰지 않고, 최종 경로가 원본 폴더 안인지 확인합니다.
- 저장 위치: 등록 자료 폴더 안 `originals/<material_id>/<버전>/derived/<이름>.drawio.svg`. 원본과 같은 버전 폴더에 두되 `derived/`로 구분합니다.
- 등록정보 필드: `derived_files: [{"role": "svg", "storage_ref": "...", "original_name": "...", "sha256": "...", "size_bytes": n}]`. 저장 후 해시를 다시 확인합니다. SVG가 없으면 `derived_files`에 넣지 않고 `validation.unknowns`에 "SVG 없음"을 기록합니다.
- 원본은 같고 SVG만 바뀐 경우는 새 등록 버전으로 처리합니다. 자료등록.md의 "메타데이터만 바뀐 버전은 같은 해시를 쓸 수 있다"는 규칙을 준용한 것입니다 [제안].
- 추출 규칙: `--registration` 추출은 등록정보의 `derived_files`(role `svg`)를 먼저 쓰고, 없을 때만 기존처럼 입력 경로 옆에서 찾습니다. 어느 쪽을 썼는지는 추출 결과의 `svg_alignment.source`에 `registered_derived` 또는 `input_path_sibling, unregistered`로 남깁니다.

| 표시 데이터 | 출처 |
| --- | --- |
| 등록정보 | `<저장 루트>/<프로젝트>/registrations/<material_id>/<버전>.json` (`register.py`가 만드는 형식) |
| 추출 결과 | `출력/추출/<프로젝트>__<자료>-r<버전>-p<페이지>/extraction.json` |
| 그래프 | `출력/그래프/<같은 이름>/graph.json`의 `graph_version`, `validation.status` |

사용자 조작:

1. 파일을 고르거나 끌어 놓습니다. 여러 개를 놓으면 "한 개씩 등록"을 안내하고 아무것도 등록하지 않습니다.
2. "등록"을 누르면 형식·해시·중복 검사를 거쳐 결과를 보여 줍니다. 같은 해시가 이미 있으면 기존 등록을 재사용했다고 표시합니다.
3. "추출·그래프 만들기"를 누르면 `--registration` 경로 추출과 그래프 생성을 차례로 실행합니다. PDF는 등록 성공 직후 이 단계를 자동으로 실행하고 ②로 옮깁니다(같은 해시를 재사용한 등록도 포함).

상태:

| 상태 | 표시 |
| --- | --- |
| 빈 화면 | "등록된 자료가 없습니다"와 파일 놓기 영역 |
| 로딩 | 단계 표시(형식 확인 → 해시 → 저장 → 저장 후 해시 확인) |
| 오류 | 손상·빈 파일, 확장자 불일치, 저장 후 해시 불일치를 사유와 함께 표시. 완료로 표시하지 않음 |
| 경고 | draw.io에 같은 이름의 SVG가 없으면 "도면 오버레이를 만들 수 없음(그래프 보기만 가능)". PDF에는 해당 없음 |

근거·미확인: 표제란 자동 판독값은 "자동 후보" 배지로 확정값과 구분합니다(자료등록.md). `validation.unknowns`를 목록으로 보여 줍니다.

### 3.2 ② 도면·그래프 조회

**목적**: 추출 결과를 도면 위에서 원본과 대조하고, 그래프 구조를 확인합니다.

| 영역 | 구성 |
| --- | --- |
| 상단 (Qt) | 도면 선택(추출 결과 목록), 구조 검증 칩, "노드 N · 관계 M · 미확인 K" 통계 칩 |
| 중앙 (웹뷰) | 웹뷰 캔버스(기존 뷰어: 검색, 레이어 토글, 줌, 속성 패널, 경로 질의). 도면/P&ID 구조 전환 탭은 ②에서 숨김(아래) |

표시 데이터는 기존 뷰어와 같습니다(`extraction.json`, `graph.json`, SVG). 노드 클릭 → 속성 패널 흐름은 데모의 "클릭 → 상세 패널"과 같습니다.

이 화면에는 'P&ID 구조'(그래프) 탭을 두지 않습니다(사용자 결정 2026-11-06: 이 프로젝트에서 '그래프'는 지식그래프만 뜻함). ②는 P&ID 도면 기준 추출 결과만 보여 줍니다. 앱은 ②에 들어올 때 웹뷰에 `hide_graph`를 보내 탭·그래프 범례·그래프 캔버스를 숨깁니다. 내부 도면 연결 데이터(`graph.json`)는 지식그래프 재료로 계속 만들고, ④⑤의 그래프 버전 불일치 보기(도면 탭 잠금)는 그대로 씁니다. 이전 결정([그래프 활용 §8.2 D2](graph-usage.md#82-남은-결정-권고안-표기), 탭 이름 'P&ID 구조'로 유지)을 대체합니다. 지식그래프 화면은 ③(§3.5)입니다.

상태: 추출 결과가 없으면 ①로 가는 안내, SVG가 없는 draw.io 추출 결과는 앱이 만든 그래프 전용 대체 화면을 보여 줌(그래프 탭이 아니라 도면을 그릴 수 없을 때의 대체 표시로 유지, 총괄 판정 2026-11-06), 그래프 `blocked`면 `blockers` 목록을 먼저 보여 주고 도면은 조회만 허용합니다.

### 3.3 ④ HAZOP 분석 결과

**목적**: 고정 응답으로 분석을 실행하거나 기존 실행을 열어, 편차별 시나리오·보호수단·위험도 제안·설계보완 후보·자료 요청을 도면과 함께 확인합니다.

| 영역 | 구성 |
| --- | --- |
| 상단 도구줄 | 구간 선택(`데이터/구간/*.json`), 실행 선택(`출력/분석/<구간>/<실행 ID>/`), "근거 묶음 내보내기"(§2.5), "새 분석 실행"(응답 폴더 선택), 결과 검증 칩, 집계 "후보 44(선택·제외·보류) · 시나리오 · 위험도 제안 · 설계보완 후보 · 열린 보류" |
| 좌측 패널 | 편차 목록 표 |
| 중앙 | 웹뷰 캔버스와 근거 집계 한 줄 |
| 우측 패널 | 선택한 편차의 상세 탭: 시나리오 · 설계보완 후보 · 자료 요청 · AI 실행 기록 |

**편차 목록** (출처: `analysis.json`의 `candidates[]`)

| 열 | 필드 |
| --- | --- |
| ID·편차 | `item_id`, `parameter_ko`, `guide_word_ko`(영문 병기), `deviation` |
| 판단 | `selection_status`(선택·제외·보류), `reason` |
| AI 상태 | `analysis.ai_status`(미요청·완료·입력 불일치 등) |
| 시나리오 수 | `analysis.scenario_ids` 개수 |
| 최고 위험도 제안 | 해당 시나리오의 `risk_proposal.risk` 최댓값(제안임을 표시) |
| 설계보완 후보·열린 보류 | `design_improvement_candidates[]`, `holds[]`의 개수 |

제외 후보도 숨기지 않습니다. 판단별 필터만 둡니다(검토결과관리.md). 적용 불가 후보는 사유([지침 §8.2 R1](hazop-method-guide.md), 5.3절 판단 근거 열)를 그대로 보여 줍니다.

**후보 판단 변경 (사용자 결정, 2026-11-04)**: 선택·제외·보류는 화면에서 바꿀 수 있습니다. 사유는 필수입니다. 변경은 구간 JSON의 `candidate_decisions`에 변경자·시각·사유와 함께 이력으로 기록하며, 열려 있는 실행 결과는 바꾸지 않습니다. 저장 뒤에는 "변경을 반영하려면 재분석이 필요합니다"를 안내합니다.

기록 방식은 다음과 같습니다 (총괄 결정(권고안, 사용자 위임 2026-11-04)).

- `candidate_decisions`에 항목을 **덧붙이기만** 하고 이전 항목을 고치거나 지우지 않습니다. 항목 형식은 현재 읽기 코드(`hazop/analysis/candidates.py`)가 요구하는 `candidate_id`(또는 `item_id`), `selection_status`, `decided_by`, `reason`, `decided_at`을 그대로 씁니다. 재분석 때 이 목록이 후보별 `judgments` 이력(`previous` 포함)으로 이어집니다.
- 저장할 때 `region_version`을 1 올립니다. 그래프 재연결(`run.rebind_graph`, `run.py` 183–195행)과 같은 방식으로 구간 JSON 전체를 UTF-8로 다시 씁니다.
- 열려 있는 `analysis.json`과 그 실행 폴더는 바꾸지 않습니다. 그 실행은 이전 `region_version`을 가리키는 기록으로 남습니다.

**시나리오 카드** (출처: `scenarios[]`)

- 출처 배지(패턴·AI 추가 가설), `scenario_status`(초안·보류와 `status_reason`), 검토 상태. 검토 상태는 검토 기록 파일(§5)에서 읽습니다. `analysis.json`의 `review_status`는 항상 `not_reviewed`이므로 화면 표시에 쓰지 않습니다 (총괄 결정(권고안, 사용자 위임 2026-11-04))
- 원인 → 결과: 패턴 시나리오는 패턴 원안(`cause`, `consequence`)과 AI 해석(`ai_interpretation.cause`·`consequence`·`interpretation`)을 나눠 표시합니다. AI 추가 가설은 AI 값만 있습니다. 원인 설비(`cause_equipment`의 태그), 전제 설비(`assumed_equipment`)
- 서술 검사 한계(`narrative_check.limit`)
- 보호수단: 그래프에서 확인된 보호수단(`safeguards[]`)과 AI가 제시한 보호수단(`ai_interpretation.safeguards`)을 나눠 표시합니다. 태그, 설명, 존재 확인 여부, 적정성(`adequacy: unknown`이면 "적정성 미확인")
- 위험도 제안(`risk_proposal`): 상태, 강도·빈도·위험도, 등급명·관리기준, 계산식(`calculation`), 보호수단 반영 여부와 사유, 가정·불확실성. 보류면 사유만 표시하고 등급 칸은 "보류"
- 근거 ID 목록(`graph_evidence`)

**설계보완 후보 탭** (출처: `design_improvement_candidates[]`): 발생 조건(`triggers`), 근거(`basis`), 원인·결과, 연결된 자료 요청(`hold_ids`), "미확정" 표시. `basis.risk`는 AI 제안에서 계산한 값이므로 "제안"으로 표시합니다.

| `triggers` 코드 | 화면 표시 문구 |
| --- | --- |
| `risk_conditional_or_worse` | 제안 위험도가 〈표9〉 조건부 수용 이상 |
| `no_safeguard_found_in_graph` | 그래프에서 원인과 독립인 보호수단을 찾지 못함(없음이 아니라 미확인) |

**자료 요청 탭** (출처: `holds[]`): 항목, 사유, 요청 자료, 출처(`risk`·`ai_request`·`design_improvement` 등), 열림·닫힘.

**AI 실행 기록 탭** (출처: `ai_runs[]`, `candidates[].analysis.rejected_ai_scenarios`): 시도 횟수, 응답 출처(고정 응답 폴더), 검증 결과·오류·경고, 도면 밖 설비로 거부된 시나리오와 거부 사유. 상태는 한국어 라벨로 보이고 영문 코드는 툴팁에 둡니다. 검증 오류(유형·경로·내용), 원문 오류, 병합 오류를 기술 상세로 표시합니다 (총괄 결정(권고안, 사용자 위임 2026-11-06), 구현 커밋 3048906).

**④ → ⑤ 흐름**

1. 구간을 선택합니다. 구간 JSON의 `graph_ref.graph_version`과 현재 그래프 버전이 다르면 경고 띠를 띄우고, 기존 `--rebind-graph` 처리(차이 보기 → 변경자·사유 입력 → 확인)를 대화상자로 제공합니다.
2. 편차 목록에서 편차를 고릅니다. 적용·불가와 사유를 확인합니다.
3. 시나리오를 고르면 도면에 원인→결과 경로를 강조합니다.
4. 보호수단과 위험도 제안, 설계보완 후보와 자료 요청을 확인합니다.
5. "검토하기"를 누르면 같은 편차·시나리오가 선택된 상태로 ⑤로 이동합니다.

**강조 규칙** (색과 모양: 총괄 결정(권고안, 사용자 위임 2026-11-04), 근거는 [디자인 시안 README §4.1](../design/mockups/README.md))

| 대상 | 데이터 | 표시 |
| --- | --- | --- |
| 원인 설비 | `cause_equipment` | `--hl-cause`(`#dc2626`) 심볼 채움 + 굵은 테두리 |
| 경로 | `graph_evidence.node_ids`, `relation_ids` | `--hl-path`(`#ea580c`) 굵은 선. 강조 중에는 나머지 오버레이를 흐림(`--hl-dim`) |
| 보호수단 | 보호수단 `node_id` | `--hl-safeguard`(`#c026d3`) 이중 테두리 + "보호수단" 배지. 설계보완 판정에서 세지 않은 보호수단은 홑 테두리 + "미계수" 배지 |
| 추정 경로 | 아래 '추정 경로' 기준에 맞는 관계·배관 구간 | 경로색 파선. 범례에 "실제 흐름 경로 아님" |

색만으로 구분하지 않고 채움·굵은 선·이중 테두리로 모양을 다르게 합니다.

**근거 집계** (데모의 근거 집계 한 줄 적용): "근거 N 중 도면 표시 a · 추정 경로 b · 미표시 c". 기준과 계산 규칙은 총괄 결정(권고안, 사용자 위임 2026-11-04)이며, 근거는 [디자인 시안 README §4.2](../design/mockups/README.md)입니다.

- **N**: 시나리오 하나에 대해 다음 ID를 합쳐 중복을 뺀 개수입니다. `cause_equipment`, 보호수단 `node_id`, `graph_evidence.node_ids`·`relation_ids`, `ai_interpretation.node_ids`·`relation_ids`, 노드·경로를 가리키지 않는 근거 ID(`ev-node-*`·`ev-path-*`가 아닌 것, 예: `ev-design-intent`), 그 시나리오를 범위로 하는 보류(`holds[].scope == scenario_id`). `ev-node-<id>`는 같은 노드 ID와 중복으로 봅니다.
- **분류 순서** (각 ID는 한 번만 셈)
  1. 미표시: 도면에 그릴 요소가 없는 ID, 웹이 `highlightResult`로 그리지 못했다고 알린 ID, 그래프 버전 불일치일 때의 모든 ID
  2. 추정 경로: 분석 당시 그래프(`<실행 폴더>/inputs/graph.json`)에서 `flow_direction`이 없는 배관 구간(`entity-seg-*`)과 그 구간의 `has_endpoint` 관계
  3. 도면 표시: 나머지
- 흐름을 거슬러 간 경로(`against_flow`), 닫힌 밸브를 지나는 경로, 신호·계측 연결은 도면에 실제로 그려진 연결이므로 추정 경로가 아니라 도면 표시로 셉니다.
- 현재 샘플 그래프는 모든 배관 구간에 흐름 방향이 있어 추정 경로가 0입니다.

**상태**

| 상태 | 표시 |
| --- | --- |
| 빈 화면 | 구간·실행이 없으면 "구간을 선택하거나 새 분석을 실행하세요" |
| 로딩 | 분석 단계(`analysis_run.steps`: 입력 확인 → 후보 → 탐색 → 패턴 → AI → 위험도) 진행 표시 |
| 입력 차단 | `load_inputs`의 `blockers`를 목록으로 보여 주고 분석하지 않음 |
| 결과 `blocked` | `validation.errors`를 상단에 고정 표시. 열람만 허용하고 ⑤ 확정과 Excel 출력은 막으며, 막은 사유를 표시 (사용자 결정, 2026-11-04) |
| 그래프 버전 불일치 | 분석 당시 그래프(`<실행 폴더>/inputs/graph.json`)와 현재 도면의 그래프 버전이 다르면 도면 강조를 끄고 그래프 보기만 제공. 다른 버전의 도면을 원래 근거처럼 보여 주지 않음(검토결과관리.md) |

### 3.4 ⑤ 설계보완·확정

**목적**: 시나리오와 설계보완 후보마다 수용·수정·기각·보류를 고르고 사유를 남기며, Excel로 내보냅니다.

| 영역 | 구성 |
| --- | --- |
| 상단 도구줄 | 현재 실행, 검토 진행 집계(미검토·검토 중·보류·확정), "Excel 내보내기" |
| 좌측 패널 | ④와 같은 편차 목록에 검토 상태 열 추가. 아래에 시나리오·설계보완 후보 목록 |
| 중앙 | 웹뷰 캔버스(④와 같은 강조) |
| 우측 패널 | 검토 편집 폼 |

⑤는 분석 실행을 읽기 전용으로 엽니다. 화면에서 `--resume` 같은 실행 변경을 하지 않습니다 (총괄 결정(권고안, 사용자 위임 2026-11-04)).

**검토 편집 폼**

- 결정: 수용 · 수정 · 기각 · 보류 (하나 필수). 사유 필수.
- 원안(읽기 전용)을 위에, 검토값을 아래에 둡니다(1366 폭에서 입력란이 잘리지 않도록 세로 배치, 총괄 결정(권고안, 사용자 위임 2026-11-04)). 원안은 패턴 원안과 AI 해석을 구분해 보여 줍니다(§3.3 시나리오 카드). "수정"을 고를 때만 원인·결과·보호수단을 편집할 수 있습니다.
- 수정 가능 항목: 원인, 결과, 보호수단, 위험도. 보호수단 추가는 그래프 노드를 골라서 합니다. 도면에 없는 보호수단은 자료 요청 메모로 남깁니다 [제안].
- 위험도 (총괄 결정(권고안, 사용자 위임 2026-11-04))
  - 수용·수정을 고르면 강도(1–4)·빈도(1–3)와 각 근거를 입력해야 합니다. 강도·빈도가 비어 있으면 저장할 수 없습니다.
  - AI 제안은 자동으로 복사하지 않습니다. 검토자가 직접 고르거나, 'AI 제안 가져오기' 버튼을 눌러야 값이 채워집니다. 가져온 값에는 "AI 값에서 가져옴 — 근거 확인 필요" 표시가 붙고, 저장 시 `risk_confirmation.source`에 `ai_proposal_adopted`가 남습니다. 직접 고르면 `human`입니다. 가져오는 값은 AI 제안의 `severity`·`frequency_without_safeguards`·`frequency_used`이며, `credited_safeguards`는 비워 둡니다(§5.2 위험도 확정 검사).
  - Python이 〈표5〉로 위험도를 계산해 보여 줍니다. 사람이 등급을 직접 입력하지 않습니다.
  - 보류를 고르면 위험도는 비워 두고(미확정), AI 제안은 참고로만 보입니다(사용자 결정, 2026-11-04).
- 설계보완 후보: 같은 4가지 결정과 사유. 수용은 원안을 그대로 받아들이고 개선 권고 문안을 입력합니다. 수정은 권고 문안과 발생 조건 설명을 고칩니다 (총괄 결정(권고안, 사용자 위임 2026-11-04)).
- 시나리오를 기각하면 그 시나리오에 연결된 설계보완 후보는 자동으로 "해당 없음"이 되고 시나리오의 기각 사유를 이어받습니다. 시나리오 기각과 설계보완 후보 수용·수정을 함께 저장할 수 없습니다 (총괄 결정(권고안, 사용자 위임 2026-11-04)).
- 시나리오가 0개인 선택 편차에는 '시나리오 없음 확인' 결정(사유 필수)을 둡니다.
- 자료 요청 메모: 열린 보류(`holds`)를 참조해 새 메모를 추가합니다. 메모는 조치로 자동 전환하지 않습니다.
- 관련 지식(참고, 편집 없음): 실행의 근거 묶음 `knowledge_context`에서 시나리오 관련 설비의 요건·설정치·운전조건과 출처를 보여 주고, 분석 당시와 현재 `kg_version`이 다르면 알립니다. "③에서 보기"는 기존 `selectNode` 메시지를 씁니다([그래프 활용 §6.4.3·§6.4.5](graph-usage.md#64-wp5-상세-규격), T1 W7).
- 저장하면 검토자 이름과 시각이 자동 기록됩니다. 검토자 이름은 설정에 한 번 저장하고, 저장 화면에 표시해 그 자리에서 바꿀 수 있게 합니다. 설정에 없으면 저장 전에 입력을 요구합니다(사용자 결정, 2026-11-04).

**상태**

| 상태 | 표시 |
| --- | --- |
| 빈 화면 | ④에서 실행을 열지 않았으면 안내 |
| 저장 실패 | 실패를 성공으로 표시하지 않고 입력 내용을 폼에 유지 |
| 분석 결과 변경 | 저장된 검토 기록의 `analysis_sha256`이 현재 `analysis.json` 파일 바이트의 해시와 다르면 편집과 Excel 출력을 막고 오류 표시. CLI에서 `--resume`으로 `analysis.json`을 다시 쓰면 기존 검토는 이 상태(열람 전용)가 됨 |
| 검토자 미설정 | 검토자 이름이 없으면 저장을 막고 입력을 요구 |
| 이전 실행 검토 있음 | 같은 구간의 이전 실행에 검토 기록이 있으면 읽기 전용 참고와 항목별 '가져오기'를 표시(§5.3) |
| 결과 `blocked` | 확정 저장을 막고 사유를 표시(§3.3) |

### 3.5 ③ 지식그래프

**목적**: P&ID 그래프와 지식 레이어(요건·설정치·운전조건 등)를 합쳐 Obsidian식 그래프로 탐색하고, 알고리즘 결과를 확인합니다(2026-11-05 사용자 확정, T1 D1). 번호 순서와 달리 §3.5에 둔 것은 기존 §3.3·§3.4 참조를 바꾸지 않기 위함입니다.

- 화면 요소(전역·로컬 보기와 깊이, 필터, 그룹 색, 호버 강조, 클릭 상세, 힘 슬라이더)는 [그래프 활용 §5.1](graph-usage.md#51-화면-요소)을, 앱에 넣는 방식(별도 HTML, vendor 인라인 적재, 브리지 메시지)은 [그래프 활용 §5.2](graph-usage.md#52-앱에-넣는-방식)와 이 문서 §2.2·§2.3을 따릅니다.
- 화면은 탐색·참고용입니다. 후보·미확인·가설 표시 토글은 표시만 바꾸며 알고리즘 결과에 들어가지 않습니다([그래프 활용 §4.1](graph-usage.md#41-계산용-그래프-뷰)).
- 전역 보기 노드 수가 상한(5,000, [그래프 활용 §7.3](graph-usage.md#73-성능-상한))을 넘으면 경고하고 로컬 보기를 권합니다(T1 D8).
- 지식그래프가 `blocked`이면 `blockers` 목록을 먼저 보여 주고 알고리즘을 실행하지 않습니다([그래프 활용 §7.1](graph-usage.md#71-샘플-데이터)).
- 화면 배치와 지식 노드 색·모양·배지는 [디자인: 지식그래프 화면](../design/kg-screen.md)을 따릅니다.

## 4. 디자인 원칙

### 4.1 색 토큰

③ 지식그래프 화면의 추가 토큰(`--kg-*`·`--a1-*`·`--comp-*`)과 노드 모양·상태 표시 규칙은 [디자인: 지식그래프 화면](../design/kg-screen.md)을 따른다(T1 W6).

UI 강조색은 파랑 하나입니다. 다른 색은 데이터(노드 종류·관계·강조·상태)에만 씁니다. 값의 정본은 `hazop/app/tokens.py`(`COLORS`)이고([design-system D5](../docs/2026-11-05-design-system/decisions.md)), 아래 표는 토큰과 용도만 적습니다. 독립 뷰어 `hazop/viewer/template.html`의 `:root`는 쓰는 변수만 같은 값으로 직접 적고, `scripts/check_design.py` 색 비교가 앱 값과 같은지 검사해 일치를 강제합니다(D5). 명암비 기준은 D7(WCAG 2.1 SC 1.4.3 글자 4.5:1, SC 1.4.11 그래픽 3:1, 불투명 토큰 값 기준)이며 같은 검사가 확인합니다. 밸브 청록·보호수단 자홍은 [디자인 시안 README §3·§4.1](../design/mockups/README.md)의 권고를 채택한 것입니다 (총괄 결정(권고안, 사용자 위임 2026-11-04)).

| 토큰 | 용도 |
| --- | --- |
| `--ui` | UI 강조(선택 탭, 포커스, 링크, 주요 버튼, 클릭 선택 노드 테두리) |
| `--bg`, `--card`, `--line`, `--muted`, `--ink` | 바탕·카드·구분선·보조 글자·본문 |
| `--equipment`, `--valve`, `--instrument`, `--piping_element`, `--unclassified` | 노드 종류(`category`). 밸브는 청록으로 UI 파랑과 분리 |
| `--physical_connection`, `--signal_connection`, `--measurement_connection`, `--unresolved` | 관계 종류와 미해결 연결 |
| `--hl-cause`, `--hl-path`, `--hl-safeguard`, `--hl-dim` | 원인 설비, 경로, 보호수단(자홍), 강조 중 나머지 흐림(불투명도, `tokens.py` `HL_DIM`)(§3.3) |
| `--risk-ok-*`, `--risk-cond-*`, `--risk-deny-*` | 위험도를 〈표9〉 허용 구분 3단계(1·2 수용 회색, 3·4 조건부 수용 호박, 5 불허 짙은 빨강)로만 색 구분. 숫자와 등급명(〈표6〉)은 항상 함께 표시 |

- 클릭 선택은 UI 파랑 테두리입니다(`--selected` = `--ui`). 이전 `--selected`(빨강)는 `--unresolved`·원인 설비 강조와 같은 빨강이라 바꿨고, ②의 독립 뷰어도 같은 색을 씁니다(design-system W4, D5).
- 위험도 3단계를 허용 구분으로 나눈 것은 〈표9〉 비고 칸 해석([지침 §6](hazop-method-guide.md), [추론])에 기대고 있습니다.
- AI 제안과 사람 확정은 색이 아니라 바탕 무늬(빗금↔흰색)와 칩 모양(속 빔↔채움)으로 구분합니다(시안 README §2).

**한 곳에서 정의**: 노드 종류별 색은 토큰 파일 하나에 두고, 웹 뷰어(CSS 변수 주입)와 Qt(목록의 색 점·범례)가 같은 파일을 읽습니다(구현: `hazop/app/tokens.py`, design-system D5).

### 4.2 서체와 레이아웃

- 서체: 맑은 고딕. Pretendard는 배포본에 넣지 않습니다(2026-11-10 사용자 결정, §9).
- 위계는 색이 아니라 글자 크기·굵기로 표현합니다(작은 회색 라벨 → 큰 굵은 제목 → 회색 부제).
- 모서리: 패널 16px, 버튼·탭·칩은 알약 모양. 테두리는 얇게, 그림자는 아주 옅게.
- 캔버스 우선: 패널은 접을 수 있고, 접으면 캔버스가 넓어집니다.
- 표는 촘촘하게, 폼과 패널은 여백을 넉넉하게 둡니다.
- 한 줄에 놓인 칩·라벨(④⑤ 도구줄 등)은 자리가 모자라면 줄임표로 줄이고, 전체 문구는 툴팁에 둡니다. 툴팁은 실제로 줄여 그렸을 때만 보입니다. 오독을 막는 단서 문구(예: ④ 결과 검증의 "보류 항목이 없다는 뜻이 아님")는 줄이지 않고 줄바꿈 라벨로 둡니다([design-system W3](../docs/2026-11-05-design-system/evidence/w3-workspace-125.md)).
- 지원 화면은 1366×768 100%와 1920×1080 125%(논리 1536×864)입니다. 창 최소 크기는 작업 영역(작업 표시줄 48·제목 표시줄 31 논리 px 제외, 1366×689·1536×785) 안에 들어와야 합니다([design-system D3·D4](../docs/2026-11-05-design-system/decisions.md)).
- 아이콘은 선 아이콘을 최소한으로 쓰고 텍스트 라벨을 기본으로 합니다.
- 위험도 등급은 숫자와 등급명(〈표6〉)으로 표시하고, 색은 §4.1의 3단계만 씁니다.

## 5. 검토 확정 데이터 규격

식별자·상태 이름은 [데이터 규격](overview.md#data-contract)을 따르고, 아래 필드는 그 위에 더하는 확장입니다. 저장 위치와 결정·위험도 규칙은 사용자 결정(2026-11-04)이며, 필드 이름과 형식은 제안입니다.

### 5.1 저장 위치 (사용자 결정, 2026-11-04)

```
<저장 루트>/reviews/<region_id>/<analysis_run_id>/<candidate_id>/v<review_version>.json
<저장 루트>/reviews/<region_id>/<analysis_run_id>/exports/<출력 시각>.json   (출력 기록)
```

- `<저장 루트>`는 `자료저장소/`(또는 `HAZOP_STORE_ROOT`)입니다.
- [신뢰 경계](overview.md#trust-boundary)에서 `reviews/`는 '사람 기록'으로 분류합니다. 변조는 범위 밖이며, 버전 파일로 이력을 보존합니다 (총괄 결정(권고안, 사용자 위임 2026-11-04)).
- `출력/`이 아닌 `자료저장소/`에 두는 이유: `출력/`은 스크립트로 다시 만들 수 있는 생성물로 관리되고(`.gitignore` 주석. `run_samples.py`는 `출력/samples/{추출,그래프,뷰어}`에 쓰고, 오래된 분석 실행은 `scripts/clean_outputs.py`(기본 dry-run, `--apply` 시 `출력/_보관/`으로 이동, 삭제 없음)로 정리), 검토 기록은 다시 만들 수 없는 사람의 판단이기 때문입니다.
- 저장할 때마다 새 버전 파일을 만들고 이전 파일은 고치지 않습니다.
- 검토본은 편차 단위이며 그 편차의 시나리오·설계보완 후보 결정을 모두 담습니다(검토결과관리.md).

| `decision` (설계보완 후보) | `accept`·`modify`·`reject`·`defer`와 `not_applicable`(해당 없음). `not_applicable`은 연결 시나리오가 `reject`일 때만 자동 지정되며, 사람이 직접 고를 수 없음. `inherited_from`에 시나리오 ID를 넣고 사유는 시나리오 기각 사유를 그대로 씀. 연결 시나리오가 `reject`인데 `accept`·`modify`이면 저장 차단 (총괄 결정(권고안, 사용자 위임 2026-11-04)) |

| `frequency_without_safeguards`, `frequency`, `credited_safeguards` | 보호수단을 반영하지 않은 빈도, 확정에 쓴 빈도, 빈도 감소에 쓴 보호수단 목록. `credited_safeguards`의 각 항목은 `{"node_id", "basis"}`이며, `basis`는 독립성·용량·작동 적정성을 확인한 근거(자료·근거 ID) |

| 시각 | UTC ISO 8601. 기존 실행 기록(`run.utc_now()`)과 같은 형식. 화면에는 한국 표준시(KST)로 표시 |

**위험도 확정 검사** (저장 전, 하나라도 어기면 저장 차단). [지침 §6·§8.3](hazop-method-guide.md)의 규칙을 사람 확정값에도 적용합니다 (총괄 결정(권고안, 사용자 위임 2026-11-04)).

1. 강도(1–4)·빈도(1–3)가 허용값이고, `risk`가 〈표5〉 조회 결과와 같음
2. 강도에는 보호수단 효과를 반영하지 않음(지침 §6.8(3)). 화면은 보호수단 선택을 빈도 입력에만 연결하고, 강도 입력란에는 "보호수단이 없다고 보고 정함" 안내를 둠. 이 항목은 자동 판별이 아니라 입력 구조로 지킴 [추론]
3. `frequency`가 `frequency_without_safeguards`보다 낮으면 `credited_safeguards`가 1개 이상 있어야 함
4. `credited_safeguards`의 모든 항목에 확인 근거(`basis`)가 있어야 함. 그래프에 존재만 확인된 보호수단(`adequacy: unknown`)을 근거 없이 넣으면 차단. 보호수단이 미확인이면 빈도 감소를 반영하지 않는다는 사용자 결정(2026-11-04, [HAZOP 분석](hazop-analysis.md#위험도-제안))과 같은 규칙
5. `criteria_id`·`criteria_version`이 분석 실행의 기준표와 같음

**결정 항목과 `review_status` 판정** (총괄 결정(권고안, 사용자 위임 2026-11-04)). 판정 대상은 판단이 '선택'인 편차입니다. 편차의 결정 항목은 다음과 같습니다.

| 편차 상태 | 결정 항목 | '결정됨'으로 보는 값 |
| --- | --- | --- |
| 시나리오 1개 이상 | 각 시나리오, 각 설계보완 후보 | 시나리오: `accept`·`modify`·`reject`·`defer`. 설계보완 후보: 같은 4가지와 `not_applicable` |
| 시나리오 0개 | '시나리오 없음 확인' 하나 | `no_scenario_confirmation`이 있음 |

아래 순서로 처음 맞는 값을 씁니다.

1. 검토 기록 없음 → `not_reviewed`
2. 결정되지 않은 항목이 있음 → `reviewing`
3. 그 외에 `defer` 항목이 있음 → `deferred`
4. 그 외 → `confirmed`

결정 항목이 비어 있다고 해서 `confirmed`가 되지 않습니다. 시나리오가 0개인 편차는 '시나리오 없음 확인' 하나가 항목이므로, 이 결정이 없으면 2번(`reviewing`) 또는 1번(`not_reviewed`)에 해당합니다. `not_applicable` 설계보완 후보는 '결정됨'이지만 `defer`로 세지 않습니다.

제외 후보(샘플에서 19개)는 검토 집계에서 따로 표시하고 판정에 넣지 않습니다. 판단이 '보류'인 후보도 시나리오가 만들어지지 않으므로 같은 방식으로 따로 표시합니다 [제안].

- 설계보완 후보의 `accept`·`modify`는 검토결과관리.md의 '확정'에 해당하며, 확정한 것만 개선 권고가 됩니다. 개선 권고 이후의 관리(책임부서·조치일정·진행결과·완료확인)는 후속입니다(사용자 결정, 2026-11-04).
- 위험도 확정은 사람의 값이며, AI 제안(`ai_original.risk_proposal`)과 함께 보관해 차이를 보여 줍니다.
- 제외 후보의 위험도는 기존대로 `not_applicable`과 사유이며, 확정을 위해 위험도를 만들지 않습니다.

### 5.3 재분석 시 기존 검토 기록

- 재분석은 새 `analysis_run_id`를 만듭니다. 이전 실행의 검토 기록은 그 실행 폴더 아래에 그대로 남고, 새 실행에 확정 결과로 넘어가지 않습니다(검토결과관리.md "현재 버전에 승계하지 않음").
- ⑤는 같은 구간의 이전 실행에서 같은 `candidate_id`의 검토 기록을 찾아 "이전 검토(참고)"로 읽기 전용 표시합니다. 이전 실행이 여럿이면 검토 기록이 있는 실행 중 가장 최근 것을 기본으로 보여 주고, 목록에서 바꿀 수 있습니다 (총괄 결정(권고안, 사용자 위임 2026-11-04)).
- 시나리오 대응은 패턴 시나리오면 `pattern_ref.match_id`, AI 추가 가설이면 `scenario_id`(내용 해시로 만든 ID)로 찾습니다. `cause_group`은 같은 원인의 여러 가설을 묶는 값이라 유일하지 않으므로 대응키로 쓰지 않습니다. 설계보완 후보는 연결 시나리오의 대응을 따르고, '시나리오 없음 확인'은 `candidate_id`로 대응합니다 (총괄 결정(권고안, 사용자 위임 2026-11-04)).
- 대응 결과에 따라 '가져오기'를 다르게 처리합니다 (총괄 결정(권고안, 사용자 위임 2026-11-04)).

| 대응 수 | 처리 |
| --- | --- |
| 0개 | "대응 없음"으로 표시. 가져오기 없음 |
| 1개 | 항목별 '가져오기' 가능 |
| 2개 이상 | 자동 가져오기 금지. 검토자가 대상을 하나 고르면 가져오고, 고르지 않으면 가져오기를 막음 |
- 항목별 '가져오기'로 이전 결정을 새 검토 폼에 불러올 수 있습니다. 가져온 결정도 저장할 때 사유·검토자·시각을 새로 기록하며, 자동 승계는 하지 않습니다(사용자 결정, 2026-11-04). 가져온 항목에는 `imported_from`을 남깁니다 [제안].
- `analysis.json`이 지워졌거나 해시가 달라지면 검토 기록은 열람만 하고 편집·출력은 막습니다.

### 6.2 HAZOP 워크시트 열

머리 영역(〈별표7〉): 공정(구간 이름), 검토일, 도면(도면번호), 쪽(인쇄 머리글의 '쪽 번호/전체', 사용자 결정 2026-11-04), 검토구간(`region_id`). 검토일은 해당 구간에서 가장 늦은 검토 저장 날짜(사용자 결정, 2026-11-04)이며, 구체적으로는 이 실행의 검토 기록 중 가장 늦은 `reviewed_at`을 한국 표준시(KST) 날짜로 바꾼 값입니다 (총괄 결정(권고안, 사용자 위임 2026-11-04)).

| 순서 | 열 | 값 | 근거 |
| --- | --- | --- | --- |
| 1 | 이탈 | `deviation` | 〈별표7〉 |
| 2 | 원인 | 아래 병합 규칙(`cause`) | 〈별표7〉 |
| 3 | 결과 | 아래 병합 규칙(`consequence`) | 〈별표7〉 |
| 4 | 현재안전조치 | 아래 병합 규칙(`safeguards`). 태그와 설명, 적정성 미확인 표시 | 〈별표7〉 |
| 5–7 | 위험도: 빈도·강도·위험도 | 사람 확정값(`risk_confirmation`)만. 없으면 "미확정" | 〈별표7〉 |
| 8 | 개선권고사항 | 수용·수정한 설계보완 후보의 권고 문안 | 〈별표7〉 |
| 9– | 프로젝트 추가 열 | 편차 ID, 시나리오 ID, 출처(패턴·AI 추가 가설), 적용 패턴, **값 출처**(2–4열 필드별로 패턴 원안·AI 해석 원안·사람 수정 중 무엇인지. 예: "원인=AI 해석 원안, 결과=사람 수정, 현재안전조치=그래프 확인"), AI 제시 보호수단(`ai_interpretation.safeguards`), AI 위험도 제안(상태·강도·빈도·위험도), 위험도 확정 출처(`source`), 검토 결정·사유·검토자·시각, 설계보완 후보(미확정 포함), 근거 참조(원인 설비 태그·근거 ID. 시나리오가 인용한 탐색 경로(`ev-path-*`)에 정상 닫힘(NC·LC) 밸브가 있으면 "정상 닫힘 밸브 경유: 태그(위치) — 정상 운전 유로 아님", 제어밸브에는 "(제어밸브, 운전 중 개폐 가능 [일반지식])"을 덧붙임. 정상 위치 미확인 밸브는 "정상 위치 미확인 밸브 경유: 태그 — 정상 운전 유로 여부 판단 보류"(물질 유로가 아닌 경로에서는 "물질 유로 아님"). 총괄 결정(권고안, 사용자 위임 2026-11-06), 구현 `hazop/export/worksheet.py` `VALVE_*` 상수, 커밋 3048906), 보류·미확인 | 이 프로젝트 |

**2–4열 병합 규칙** (필드마다 따로 적용, 총괄 결정(권고안, 사용자 위임 2026-11-04))

| 필드 | 1순위 | 2순위 | 3순위 |
| --- | --- | --- | --- |
| `cause`, `consequence` | `revised`에 그 필드가 있으면 `revised` 값 | `ai_interpretation`의 같은 필드(있으면) | 패턴 원안(`scenarios[].cause`·`consequence`) |
| `safeguards` | `revised.safeguards`가 있으면 그 값 | 그래프에서 확인된 보호수단(`scenarios[].safeguards`) | — |

- `modify`라도 `revised`에 없는 필드는 원안을 씁니다. 그래서 한 행 안에서 필드마다 값 출처가 다를 수 있습니다.
- AI가 제시한 보호수단(`ai_interpretation.safeguards`)은 4열에 넣지 않고 추가 열에만 씁니다.
- 같은 규칙을 ⑤ 화면의 검토값 재조회에도 써서, 화면과 Excel이 같은 값을 보여 주게 합니다.

- 시나리오마다 한 행입니다. 선택한 편차에 시나리오가 없으면 "시나리오 없음"과 사유(AI 상태 등)로 한 행을 남깁니다.
- 미검토·보류·기각 행의 2–4열에는 사람이 확인하지 않은 원안이 들어갑니다. 이런 행은 결정 열과 값 출처 열로 원안임을 드러냅니다 (2–4열 규칙: 총괄 결정(권고안, 사용자 위임 2026-11-04)).
- AI 위험도 제안은 확정 열(5–7)에 넣지 않습니다(HAZOP분석.md "AI 값을 확정값으로 저장 금지").
- 원문 참조는 식별자·위치로 쓰고 파일 링크로 만들지 않습니다.

### 6.3 확정 상태에 따른 포함 규칙

| 출력 범위 | 워크시트 행 | 개선 권고 |
| --- | --- | --- |
| 전체(기본) | 모든 시나리오. 미검토 행은 "미검토", 기각 행은 "기각", 보류 행은 "보류"로 결정 열에 표시 | 수용·수정한 후보만 |
| 수용·수정 행만 | `accept`·`modify` 시나리오만 | 같음 |

- 출력은 `blocked` 결과에서 막고 사유를 표시합니다(사용자 결정, 2026-11-04).
- 셀 값이 `=`, `+`, `-`, `@`로 시작해도 수식으로 해석되지 않게 문자열로 씁니다(검토결과관리.md 독립 검증).
- 빈 위험도를 0이나 안전으로 쓰지 않고 상태와 사유를 씁니다.
- 파일은 `출력/워크시트/<region_id>/<analysis_run_id>/worksheet-<출력 시각>.xlsx`에 새로 만들고 덮어쓰지 않습니다. 출력 기록(시각·대상 버전·범위·행 식별자)은 §5.1의 `exports/`에 남깁니다 [제안].
- 검토 기록의 `analysis_sha256`이 현재 `analysis.json`과 다르면 출력을 막습니다(§3.4).
- 라이브러리는 openpyxl을 씁니다(사용자 결정, 2026-11-04).

### 7.1 경로 분리

| 구분 | 내용 | 개발 실행 | 패키징 실행 [제안] |
| --- | --- | --- | --- |
| 프로그램 자원(읽기 전용) | 뷰어 템플릿, 토큰 파일, 이탈 카탈로그·적용 판단·패턴·기준표 | 저장소 안 경로(`자원/기준/`) | 실행 폴더 안 자원 폴더 |
| 사용자 데이터(쓰기) | 저장 루트(등록 원본·검토 기록), `출력/`, 구간 JSON, 고정 응답 | 저장소 안 `작업/`(git 제외) 아래 `자료저장소/`·`출력/`·`데이터/` | 사용자가 고른 작업 폴더(기본 `%LOCALAPPDATA%\HAZOP\`) |
| 설정 | 검토자 이름, 작업 폴더, 최근 연 구간·실행 | `%APPDATA%\HAZOP\settings.json` | 같음 |

- 경로 결정은 `hazop/paths.py` 하나에 모읍니다. 데이터 폴더는 폴더 표(`FOLDERS`)로만 열고(`paths.folder`), 다른 모듈에 `데이터`·`참고자료` 경로 문자열을 쓰지 않습니다(`tests/test_path_literals.py`). 작업 루트 안 배치는 개발 실행과 배포본이 같습니다([정리 설계](../docs/2026-11-09-data-consolidation/README.md)).
- 화면이 읽는 프로그램 코드(`scripts/extract_drawio.py`·`build_graph.py`)는 자원 루트가 아니라 프로그램 루트(개발 실행은 저장소, 묶인 실행은 묶음 폴더)에서 읽으며 `HAZOP_RESOURCE_ROOT`를 따르지 않습니다(`hazop/paths.py` `program_root`, 패키징 W3).
- 구간 JSON은 `--rebind-graph`가 이력을 덧붙여 고치는 파일이므로 사용자 데이터로 분류합니다. 고정 응답도 사용자가 만드는 파일이므로 사용자 데이터입니다.
- 실행 기록의 파일 경로는 그 파일을 찾은 루트 기준 상대 경로(`paths.rel_or_abs`)입니다. 샘플 도면 등 참고 폴더 아래 파일은 위치와 관계없이 `참고자료/<나머지>`로 적어 그래프 판이 바뀌지 않게 하고, 옛 상대 경로(`데이터/이탈후보/…` 등)는 읽을 때 `paths.resolve_rel`이 새 위치로 풉니다.
- `HAZOP_STORE_ROOT` 환경변수는 계속 우선합니다.
- 설정 파일을 읽을 수 없으면(JSON 문법 오류·JSON 객체 아님·UTF-8 아님) 기본값으로 덮어쓰지 않습니다. 대화형 실행은 경로·원인을 보여 주고 "기존 파일을 백업하고 기본값으로 시작"(`settings.json.bad-<시각>.json`으로 이름 바꿈) 또는 "종료"를 고르게 하고, `--screenshots` 실행은 안내를 표준 오류에 쓰고 종료 코드 2로 끝냅니다. 읽기 자체가 실패하면(`OSError`: 권한·잠금 등) 백업 선택지 없이 안내 후 종료(종료 코드 2)만 합니다. UTF-8 BOM이 있는 설정 파일은 정상으로 읽습니다. 미처리 예외 기록 시험 트리거(`HAZOP_TEST_EXCEPTHOOK`)는 검증용 빌드에서만 동작하고 배포용에서는 꺼져 있습니다 (총괄 결정(권고안, 사용자 위임 2026-11-06), [W10 근거](../docs/2026-11-05-packaging/evidence/w10-about-dialog.md) §5·§7).

| 신뢰 경계 | 자원 루트의 기준 자료 5종(이탈 카탈로그·적용 판단·위험도 기준표·패턴 라이브러리·[지침](hazop-method-guide.md))을 코드(`hazop/analysis/integrity.py`)에 고정한 해시와 대조함. 1바이트만 바뀌어도 분석을 차단하고 사유를 표시함(JSON은 파싱한 값이 같은 표기 차이(공백·줄바꿈·키 순서 등)와 지침서의 CRLF↔LF 변경은 제외). 데이터를 정당하게 바꿀 때는 사람 검토 뒤 `integrity.py`의 고정값(`PINNED_SHA256`·`GUIDE_SHA256`)을 갱신하고 배포본을 다시 빌드함(절차는 같은 파일 머리 주석). 패키징 T2 D1·D12, [W5 근거](../docs/2026-11-05-packaging/evidence/w5-trust-boundary.md) |

## 8. 완료 기준 (구현 단계 검사 항목)

| 범위 | 확인 사항 |
| --- | --- |
| ① | 화면으로 정상 draw.io 1개를 등록 → 추출 → 그래프 생성한 결과 JSON(등록정보, `extraction.json`, `graph.json`)이 같은 입력으로 CLI(`register.py`, `extract_drawio.py --registration`, `build_graph.py`)를 실행한 결과 JSON과 같음(시각·실행 ID 제외) |

| ① | 같은 이름의 SVG가 `derived/`에 해시와 함께 등록되고, 추출이 등록된 SVG를 우선 씀(`svg_alignment.source`). SVG가 없으면 경고 |
| ② | 기존 뷰어 검사(`check_viewer.py`의 `<script>` 개수 3 포함, `check_viewer_paths.js`)가 그대로 통과하고, 내장 모드에서 노드 클릭이 Python에 전달됨 |
| ② | 웹뷰가 정화(`sanitize.py`)를 거친 SVG만 표시하고, 외부 URL 접근이 설정으로 차단됨 |
| ③ | [그래프 활용 §7.2](graph-usage.md#72-검사-스크립트-항목)의 V1(JS 로컬 깊이 = Python), V2(오프라인), S1(화면 상한) 통과 |
| ④ | 근거 묶음 내보내기가 실행 폴더를 만들지 않고, 테스트용 응답 폴더(기존 `데이터/고정응답/region-SNP-M-102-pzr`)로 대체해 불러오면 `scripts/analyze.py` 결과 JSON과 후보·시나리오·위험도·설계보완 후보 수까지 같음 |
| ④ | `bundle_sha256`이 다른 고정 응답이 `input_mismatch`로 표시되고 결과에 쓰이지 않음 |
| ④ | 후보 44개가 모두 목록에 있고, 적용 불가 19개가 사유와 함께 남음 |
| ④ | 후보 판단 변경이 사유 없이 저장되지 않고, 구간 JSON에 이력으로 남으며 재분석 안내가 표시됨. 열려 있는 `analysis.json`은 바이트 단위로 바뀌지 않음 |
| ④ | 시나리오 선택 시 원인 설비·경로·보호수단이 도면에 강조되고, 근거 집계 "도면 표시 + 추정 경로 + 미표시"의 합이 §3.3의 N과 같음 |
| ④ | 그래프 버전이 다르면 도면 강조가 꺼지고 경고가 표시됨 |
| ⑤ | 4가지 결정 모두 사유 없이 저장되지 않음. 검토자 이름이 없으면 저장되지 않음. 검토자·시각이 기록됨 |
| ⑤ | 수정 저장 후 `ai_original`이 `analysis.json`의 원래 값과 같고, `revised`에는 바뀐 필드만 있음 |
| ⑤ | 수용·수정에서 강도·빈도가 비면 저장되지 않음. AI 제안 값은 'AI 제안 가져오기'를 누를 때만 채워지고 `source: ai_proposal_adopted`로 남음. 직접 고른 값은 `source: human` |
| ⑤ | 위험도 확정값이 〈표5〉 계산과 같고, 사람이 등급을 직접 넣을 수 없음. 보류 결정은 `risk_confirmation`이 `null` |
| ⑤ | 시나리오 기각 시 연결된 설계보완 후보가 `not_applicable`과 이어받은 사유로 저장되고, 수용·수정과 함께 저장되지 않음 |
| ⑤ | `review_status`가 §5.2 판정 순서대로 계산되고, 시나리오 0개 편차는 '시나리오 없음 확인' 없이 `confirmed`가 되지 않음 |
| ⑤ | 저장할 때마다 새 버전 파일이 생기고 이전 파일은 바이트 단위로 같음 |
| ⑤ | 재분석 후 새 실행에는 확정 결과가 자동으로 넘어가지 않음. '가져오기'한 결정도 사유·검토자·시각이 새로 기록되고 `imported_from`이 남음 |
| ⑤ | `analysis.json` 해시가 검토 기록의 `analysis_sha256`과 다르면 편집과 Excel 출력이 막힘. 두 경우를 각각 확인: `analysis.json` 삭제, 정상 CLI `--resume` 실행 뒤 파일 해시 변경 |
| ⑤ | 이전 검토 가져오기에서 대응이 2개 이상이면 자동으로 가져오지 않고, 검토자가 고르지 않으면 막힘. 대응 0개는 "대응 없음" 표시 |
| ⑤ | 시나리오 0개 편차가 '시나리오 없음 확인' 없이 `confirmed`가 되지 않고, 시나리오 기각으로 `not_applicable`이 된 설계보완 후보만 남은 편차가 판정 순서대로 계산됨 |
| ⑤ | 부분 수정(예: 결과만 수정) 저장 뒤 재조회한 화면 값과 Excel 2–4열이 §6.2 병합 규칙대로 같고, 값 출처가 필드별로 맞음 |
| ⑤ | 근거(`basis`) 없는 보호수단이 `credited_safeguards`에 있거나, 보호수단 없이 빈도를 낮추면 저장이 막힘 |
| ④⑤ | `blocked` 결과에서 확정 저장과 Excel 출력이 막히고 사유가 표시됨 |
| Excel | 행의 편차·시나리오 ID와 값·상태가 JSON과 일치. 수식 문자열이 실행되지 않음. 빈 위험도가 0으로 나오지 않음 |
| Excel | AI 위험도 제안이 〈별표7〉 위험도 열에 들어가지 않음. 〈별표9〉에는 수용·수정 후보만 있고 위험등급은 사람 확정값 또는 "미확정" |

## 9. 미결정 사항

나머지 항목은 사용자 결정(2026-11-04) 또는 총괄 결정(권고안, 사용자 위임 2026-11-04)으로 확정해 해당 본문 절에 반영했습니다. 패키징 후 신뢰 경계는 자원 루트 기준 자료의 해시 고정·대조로 확정했습니다(§7.2, 패키징 T2 D1·D12, [W5 근거](../docs/2026-11-05-packaging/evidence/w5-trust-boundary.md)).

마지막으로 남았던 글꼴도 정했습니다. Pretendard는 배포본에 넣지 않고 맑은 고딕을 씁니다(2026-11-10 사용자 결정, §4.2·§7.2). 남은 미결정 사항은 없습니다.
