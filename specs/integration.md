# 정보 통합·관리 기획

[상세 플로우차트](<flows/03-integration.md>) · [전체 기획](overview.md) · [공통 원칙](overview.md#principles)

## 목적과 범위

여러 도면·표·문서에서 추출한 결과를 공통 그래프 구조로 통합하여 같은 설비의 연결, 조건, 보호수단과 원문 근거를 관리합니다. 원본 인식과 추출은 이전 단계, 원인·영향 추론은 HAZOP 분석 단계에서 수행합니다.

## MVP와 후속 범위

| 구분 | 내용 |
| --- | --- |
| MVP | draw.io 도면 1장의 추출 결과를 그래프로 변환, 최소 노드·관계·속성 정의에 따른 구조 검증, 그래프 버전·입력별 대상 매핑·검증 보고서 저장. 검증용 그래프 보기 탭과 기본 질의(이웃·연결 경로 확인) |
| 후속 | 여러 도면·문서의 동일 대상 통합, 값 충돌 관리, 수동 편집·병합·분리, AI 검수, 데이터 사전 분리 |

그래프 저장 기술은 MVP에서 가장 단순한 방식(networkx와 JSON 파일, networkx 설치는 사용자 승인)으로 시작하고, 규모가 커지면 다시 선택합니다.

## 원본 근거와 직접 입력

이 단계의 직접 입력은 각 자료에서 이미 추출한 노드·관계·속성·조건과 원문 참조, 사람의 수동 입력, 선택적인 기존 그래프입니다. 원본 파일을 새로 해석하는 작업은 정보 추출 단계의 책임입니다.

예를 들어 P&ID의 V-101 연결, 운전조건 문서의 V-101 정상 압력, 인터록 문서의 차단 조건을 같은 대상에 연결합니다.

## 역할 분담

| 주체 | 역할 |
| --- | --- |
| Python 스크립트 | 형식 정규화, 대상 식별, 관계·사실 통합, 규칙 검증, 저장·이력 처리 |
| 사람 | 노드·속성·관계의 수동 추가·수정, 연결 해제, 병합·분리, 충돌 판단 |
| AI (선택) | 불만족스러운 항목을 원문과 대조하고 보정 제안 |

## 공통 정보 구조 초안

| 구성 | 최소 내용 |
| --- | --- |
| 대상 노드 | 내부 고유 ID, 프로젝트·공정 범위, 종류, 태그 또는 이름 |
| 관계 | 고유 ID, 양 끝 대상 또는 포트, 관계 종류, 확인된 경우 흐름 방향 |
| 사실·속성 | 대상 ID, 항목, 원래 값과 단위, 정규화한 값과 단위, 적용 조건·운전모드 |
| 근거 | 자료 ID·등록 버전·문서 ID·원본 객체 ID·페이지·좌표 또는 문장 위치. 수동 정보는 작성자·사유 및 근거 유무 |
| 관리 정보 | 입력 유형, 추출 실행/수동 편집/AI 보정 이력, 검토 상태, 변경 버전 |

태그 수정으로 대상 ID가 바뀌지 않도록 하고, 문서별 임시 ID와 통합 대상 ID의 대응을 남깁니다. 태그가 없으면 임시 대상으로 유지할 수 있습니다.

## 노드·관계·속성 정의 초안

이 절을 데이터 사전의 초기 관리 위치로 사용합니다. 아래 예시는 확정 스키마가 아니며, MVP에서는 샘플 도면에 필요한 항목만 정의합니다. 이름과 분류는 DEXPI 클래스 체계를 따르지 않으며, 용어 대응은 [DEXPI 용어 대응](extraction.md#dexpi-terms)을 봅니다 (총괄 결정(권고안, 사용자 위임 2026-11-06)).

### 기본 정의

| 적용 대상 | 속성 또는 정의 예시 | 필요한 이유·정의할 사항 |
| --- | --- | --- |
| 공통 노드 | 내부 ID, 종류(`kind`), 이름, 태그, 소속 범위 | 대상 식별, 필수 여부, 태그 없는 대상 처리 |
| 설비 | 설비 종류, 소속 공정·계통 | 설비 분류와 적용 범위 |
| 배관 | 라인 번호, 관경, 재질 | 배관 식별, 수치·표기 방식과 단위 |
| 운전조건·사실 | 항목, 값, 단위, 적용 운전모드 | 정상값·한계값 구분, 적용 조건 |
| 관계 | 종류(물리 배관·계장 신호·제어·보호; MVP 이름 `physical_connection`, `has_endpoint`, `signal_connection`, `measurement_connection`), 양 끝 대상, 흐름 방향 | 연결 가능한 노드·포트 종류와 방향의 의미 |
| 개별 사실·관계의 근거 | 출처, 원본 버전, 위치, 검토 상태 | 서로 다른 자료에서 나온 정보의 추적과 충돌 관리 |

### draw.io 도면의 노드 단위 (사용자 결정, 2026-11-03)

| 원본 요소 | 그래프 표현 |
| --- | --- |
| drawio 도형: 설비·밸브·계기·분기점(`tee`)·도면 연결점(`continuation`)·배관 끝막음(`pipe_cap`) 등 | 노드 1개 |
| 공정 배관 커넥터 1개(`process`, 보조 공정 배관(샘플에서 가는 선) [추론] `process_secondary` 포함) | '배관 구간' 노드 1개. `line_no`·`line_type`·`flow_direction`은 구간 노드의 속성. 양 끝 대상과 `has_endpoint` 관계로 연결 |
| 계장 신호선(`signal_electric`) | 구간 노드를 만들지 않고 양 끝 노드를 잇는 `signal_connection` 관계 |
| 계측 연결선(`instrument_tap`: 공정 대상 → 계기) | 구간 노드를 만들지 않고 공정 대상과 계기를 잇는 `measurement_connection` 관계. 물질 흐름 경로 탐색에서는 제외 |
| 태그 | 노드의 속성(`tag`). 별도 노드를 만들지 않음 |

메모: `instrument_tap`을 물질 흐름 탐색에서 빼면 계측 연결선 누출 같은 편차가 누락될 수 있습니다 [일반지식]. ④에서 재검토합니다.

흐름 방향은 [단계 간 데이터 규격](overview.md#data-contract)의 정규화 형식(`{"from": ..., "to": ...}`)으로 기록하고, 원본 값 `source_to_target`은 근거로만 남깁니다. 이를 위해 `has_endpoint` 관계마다 원본 커넥터의 source·target 중 어느 끝인지 남겨야 합니다 [추론]. 추출 결과 JSON은 커넥터를 [단계 간 데이터 규격](overview.md#data-contract)의 관계로 전달하고, 구간 노드는 그래프 변환에서 만듭니다 [추론].

### HAZOP 탐색에 필요한 최소 정의

④의 경로 탐색이 의미를 가지려면 다음 정보가 그래프에 있어야 합니다. 값이 없으면 미확인으로 남기고, ④는 그 미확인에 영향받는 판단만 보류합니다.

| 적용 대상 | 속성 | 필요한 이유 |
| --- | --- | --- |
| 밸브 | 밸브 종류, 정상 위치(`NO`·`NC`·`LO`·`LC`), 제어밸브 실패 위치(`FO`·`FC` 등) | 정상 운전 유로 판단, 유량 없음·증가 원인 탐색 |
| 체크밸브 등 방향성 기기 | 허용 흐름 방향 | 유체 역류 편차 탐색 |
| 포트·내부 유로 | 기기의 접속점, 포트 사이에 실제로 통하는 유로 | 기기 통과 경로 탐색. 예: 열교환기 관측·동체측 분리 |
| 제어루프 | 측정 계기 → 제어기 → 최종제어요소, 제어 변수·설정값 | 제어 실패를 원인으로 하는 편차 탐색 |
| 보호수단 | 종류(안전밸브·인터록·경보), 보호 대상, 설정값, 동작 | 편차별 보호수단 연결 |
| 설계 한계 | 설계압력·설계온도, 안전밸브 설정압력과 보호 대상의 대응 | 압력 증가 등 한계 초과 판단 |

운전조건을 별도 노드로 둘지 사실 레코드로 둘지는 미정입니다. 논리적으로 대상·값·조건·근거를 구분할 수 있어야 합니다.

### 정의를 추가·변경할 때 기록할 항목

| 항목 | 기록 내용 |
| --- | --- |
| 이름과 의미 | 일관된 속성명, 설명, 필요한 이유와 예시 |
| 적용 대상 | 어느 노드·관계·사실에 사용할지 |
| 자료형 | 문자열·수치·참조·목록 등의 형태 |
| 단위와 기준 | 사용할 단위, 압력 기준(게이지/절대) 등 해석 조건 |
| 필수 여부 | 필수·선택·조건부 여부와 미확인 값 처리 |
| 허용값·제약 | 분류값, 범위, 참조 및 연결 대상 제한 |
| 정의 버전 | 추가·변경 이유와 기존 데이터에 미치는 영향 |

정의가 늘면 데이터 사전을 분리하고 JSON Schema 등 기계가 읽는 정의를 Python 검증과 연결합니다. 정의가 바뀌면 기존 데이터의 재검증·변환 필요성을 검토합니다. ② 작성 규칙의 속성 이름은 이 정의와 맞춥니다.

## 자동 통합 원칙

1. 프로젝트·공정 범위와 명시적인 식별 정보로 동일 대상을 연결합니다. 이름 유사도나 도면상 거리만으로 자동 병합하지 않습니다.
2. 같은 설비의 문서별 표시는 원문 위치를 각각 보존합니다. 대상 하나에 근거 여러 개가 연결될 수 있습니다.
3. 물리적 배관 연결, 계장 신호, 제어 동작, 보호 관계를 구분합니다.
4. 정상 운전압력, 설계압력, 트립 설정값은 별도 항목으로 관리합니다. 운전모드나 적용 버전이 다른 값도 구분합니다.
5. 단위는 변환 가능한 경우 정규화하고 원래 표현도 남깁니다. 압력의 게이지/절대 기준처럼 해석이 필요한 부분은 추정하지 않습니다.

## 수동 편집과 선택적 AI 검수 (후속)

- 사람은 빈 초안이나 기존 버전에서 노드·사실을 생성·수정하고, 관계 연결·해제와 잘못 병합된 대상의 분리를 할 수 있습니다.
- 원본 근거가 없는 수동 정보는 작성자와 사유를 기록하고 원본에서 확인된 사실과 구분합니다.
- AI에는 검수 대상과 관련 원문을 제공하고 변경 제안·이유·근거 위치를 반환하도록 합니다.
- 삭제·병합·연결 해제 전후를 기록하여 이전 버전으로 복원할 수 있도록 합니다.

## 독립 검증

정답을 명시한 샘플 추출 결과와 기존 그래프만으로 이 단계를 실행·판정할 수 있어야 합니다.

| 범위 | 검증 사례 | 기대 결과 |
| --- | --- | --- |
| MVP | 도면 1장의 추출 결과 변환 | 노드·관계·속성이 정의대로 생성, 입력별 대상 매핑 보존 |
| MVP | 동일 입력 두 번 처리 | 노드·관계·사실이 중복 생성되지 않음 |
| MVP | 관계의 끝 대상이 누락됨 | 차단 오류 또는 미해결 참조 표시, 정상 연결로 확정하지 않음 |
| MVP | 유효한 연결의 방향·태그·밸브 정상 위치만 미확인 | 차단 오류와 구분해 미확인 상태·사유를 보존하고 전달 가능 |
| MVP | 속성 자료형·허용값 또는 관계 대상이 정의와 맞지 않음 | 오류·검토 항목 표시 |
| 후속 | P&ID와 운전조건 문서에 같은 범위의 V-101 존재 | 대상 하나에 연결 정보와 운전조건, 두 근거가 모임 |
| 후속 | 서로 다른 공정에 V-101 태그 존재 | 별개 대상 유지 |
| 후속 | 같은 조건에서 5 bar와 6 bar가 각각 보고됨 | 충돌 표시, 두 원문 보존, 임의 확정 금지 |
| 후속 | 정상 운전압력과 설계압력이 다름 | 서로 다른 항목으로 보존, 값 차이만으로 충돌 판정하지 않음 |
| 후속 | 수동 노드 생성 후 연결·수정·해제 | 동일 검증 수행, 변경 주체와 전후 이력 보존 |
| 후속 | 수동 수정 이후 자동 재처리 | 수동 수정 보존 또는 충돌 표시 |
| 후속 | AI 보정에 근거 없는 값이나 잘못된 참조가 포함됨 | 미확인·검토 대상으로 남기거나 오류 처리 |
| 후속 | 변경을 보류하거나 이전 버전으로 복원함 | 기존 검증 버전 유지, 초안 및 복원 이력 추적 |
| 후속 | 새 속성 도입 또는 정의 변경 | 정의 버전 기록, 기존 데이터의 재검증·변환 필요성 확인 |

### 통과와 보류 기준

형식 오류·잘못된 참조·대상 식별 모호성·해결되지 않은 값 충돌이 있는 변경은 검증된 버전에 반영하지 않고 초안으로 보관하며, 이전 검증 버전을 유지합니다. 태그 미인식·방향 미확인·운전조건 누락을 유효한 상태와 사유로 표시한 경우에는 검증된 구조 안에 미확인 정보로 보존할 수 있습니다.

예를 들어 연결 대상이 유효하지만 방향만 알 수 없는 배관은 방향 미확인 상태로 반영할 수 있습니다. 대상이 없는 연결을 정상 배관으로 반영하거나 어느 설비인지 모르는 대상을 임의 병합할 수는 없습니다. 별도로 보관한 미해결 연결 후보는 탐색 가능한 정상 관계로 취급하지 않습니다.

통과 결과에는 입력별 대상 매핑, 원문 또는 수동 출처, 검증 보고서, 버전과 변경 이력이 있어야 합니다. 상태 필드와 예시는 [단계 간 데이터 규격](overview.md#data-contract)을 따릅니다.
