# P&ID 기호 사전 기획

[정보 추출](extraction.md) · [지식그래프 스키마 사전](kg-schema-dictionary.md) · [데이터 일원화 설계](../docs/2026-11-09-data-consolidation/README.md) · [기호 목록 초안](../docs/2026-11-09-symbol-library/README.md)

## 목적과 범위

벡터 PDF 도면의 기호를 결정적 스크립트로 인식하는 데 쓰는 기호 사전을 만든다. 기호 규칙을 코드에서 데이터 파일로 옮겨, 새 도면 묶음이 오면 코드를 고치지 않고 사전 항목만 더해 인식 범위를 넓힌다. 사전은 git으로 관리하고 앱 배포본에 함께 묶는다. AI는 쓰지 않는다.

이 문서는 1단계(수집·설계·시제품)의 결과다. 추출기 코드는 고치지 않았다. 구현 단위와 결정 항목은 §7·§8에 있다.

## 결정 상태

| 항목 | 상태 |
| --- | --- |
| 인식 방식 | 사용자 요청(2026-11-09): 결정적 스크립트. 같은 입력과 같은 사전이면 같은 결과 |
| 관리·배포 | 사용자 요청(2026-11-09): git으로 관리하고 배포본에 묶음 |
| 사전 형식·위치·묶음 | 채택(2026-11-09, 권장안): §8 D1~D3 |
| 새 kind | 채택(2026-11-09, 권장안): §8 D4 |
| 앱 안 추가 화면 | 채택(2026-11-09, 권장안): 지금은 두지 않음(§8 D9) |
| 결정 D1~D14 | 사용자 지침 '권장안 자동 채택'에 따라 모두 권장안으로 채택(2026-11-09). D14는 S2 설계 때 두 안을 시제품으로 비교해 정함 |

## 1. 지금 기호 규칙의 흐름

`hazop/extract/adapters/pdf_vector.py`(HEAD 0a0b9e9 기준)의 흐름은 다음과 같다. 기호를 알아보는 지식이 여섯 군데에 흩어져 있다.

| 단계 | 위치 | 기호 지식 |
| --- | --- | --- |
| 원시 요소 분류 | `_classify_primitives` | 검은 채움은 크기만으로 점선 조각(짧은 변 1.5pt 이하)·표식(긴 변 7pt 이하)·검은 몸체로 나눔. 표식은 화살촉으로 쓰인다 |
| 기호 묶기 | `_group_symbols` | 몸체 겹침, 몸체 안 선, 깊이 들어간 선(구동부 축), 끝이 빈 장식선. 장식선만 모이면 선 기호 |
| 모양 판정 | `_shape_kind` | 삼각형 둘이 꼭짓점을 맞댄 나비 모양 몸통 = 수동 밸브, 바깥 원 = 전동 밸브, 바깥 몸체 = 제어 밸브, 사선 둘 이상 = 안전밸브, 선+표식 = 체크밸브, 평행 판 = 오리피스, 원 하나 = 계기. U1이 비석형 계기를 더한다 |
| 글자 판정 | `_instrument_kind`, `_kind_from_text`, `EQUIPMENT_WORDS` | ISA 뒤 글자(T·C·I, U1에서 S·R 추가), 장비 이름 낱말, TO/FROM 연결 표기 |
| 끝막음 | `_classify` 끝 | 글자 없고 연결 하나인 15pt 이하 닫힌 몸체 = 배관 끝막음 |
| kind 목록 | `hazop/kg/schema/registry.json` | kind와 범주(설비·밸브·인라인 부품·계기·배관 요소) |

모양 판정은 모두 합성 샘플(SNP)에 맞춘 조건문이다. 새 모양 하나를 더하려면 `_shape_kind`에 분기를 하나 더 써야 한다. 이 구조로는 APR1400 범례의 200여 기호를 담을 수 없다.

위 표는 기준 커밋 때의 모습이다. S7(§7.1)부터 `_shape_kind`와 `EQUIPMENT_WORDS`는 코드에 없다. 어느 구조가 어느 종류인지, 어느 낱말이 어느 설비인지와 보는 순서는 공통 묶음의 `structure`·`label_words` 견본(§3.2)이 정한다. 코드에는 기호 하나의 구조 특징을 판정하는 `_shape_features`가 남아 있다.

## 2. 수집 결과

자세한 표와 그림은 [기호 목록 초안](../docs/2026-11-09-symbol-library/README.md)에 있다.

### 2.1 범례

그림 1.7-1 네 쪽을 실제 도면과 같은 추출기로 묶고, 기호마다 오른쪽 설명 문단을 짝지었다. 239개 항목이 나왔다(1/4쪽 177, 2/4쪽 47, 3/4쪽 15, 4/4쪽 0). 국내 용어 초안은 209개에 붙였다.

자동 짝짓기는 그대로 믿을 수 없다. 1/4쪽 앞 80개를 눈으로 보니 70개가 맞았다. 틀린 경우는 설명이 기호 아래 캡션에 붙었거나 머리글을 설명으로 읽은 경우다. 범례만으로 만든 견본을 도면에 대 보면 모양 계열은 맞히지만 이름이 어긋난다. 글로브 밸브 104개가 범례 'NEEDLE'에, 전동 구동부 44개가 'OUTDOOR FIRE HYDRANT'에 붙었다(§5.3). 그래서 범례 수집 결과는 후보로만 쓰고, 이름과 범주는 사람이 확정한다(§8 D10).

### 2.2 실제 도면의 미분류

005~143쪽(139쪽, 이 중 009쪽은 이미지 쪽이라 기호 0)에서 추출기(HEAD + U1)가 묶은 기호는 14,218개이고, 그중 11,572개(81.4%)가 kind 없음이다. 시험 보고서의 "노드 25,151 중 49% 미분류"는 분기점(tee) 노드까지 센 값이라 분모가 다르다.

미분류 기호를 모양 서명(§4.1)으로 묶으니 1,139묶음이 나왔고, 분포가 한쪽으로 크게 쏠려 있다.

| 상위 묶음 수 | 덮는 미분류 기호 |
| --- | --- |
| 10 | 35.2% |
| 50 | 65.4% |
| 200 | 85.2% |
| 500 | 93.8% |

사전 항목 수십 개로 미분류 대부분을 덮을 수 있다는 뜻이다. 상위 60묶음 중 33묶음에 이름을 붙였다(`drawing-unclassified-groups.csv`).

### 2.3 범례에서 얻은 도메인 사실

- **닫힌 밸브는 검게 칠한다. 지금 추출기는 이것을 열린 배관으로 만든다.** 범례 VALVE SYMBOLS는 같은 밸브를 정상 운전 중 열림(흰색)과 닫힘(검정) 두 열로 그린다. 검정 게이트 밸브는 6.2×3.1pt라 `_classify_primitives`가 표식(화살촉)으로 분류한다. 그 뒤 `_build_solid`의 `same_marker`가 표식 양쪽 배관 끝을 한 선으로 잇는다. 결과적으로 정상 닫힘 밸브 자리에 밸브 노드 없이 이어진 흐름 경로가 생긴다. 이미 생기고 있는 잘못된 판정이다. 검정 밸브는 같은 기호에 `normal_position=NC`(레지스트리 허용값 NO·NC·LO·LC)를 붙여야 한다.
- **APR1400 밸브는 작고 한 경로다.** 게이트 밸브는 나비 모양 닫힌 경로 하나(꼭짓점 5개)다. SNP처럼 삼각형 둘이 아니어서 `_shape_kind`의 나비 판정에 걸리지 않는다.
- **구동부와 번호 원은 따로 묶인다.** 전동(M)·솔레노이드(S)·다이어프램·전기유압(E/H) 구동부와 밸브 번호 원은 밸브 몸통과 다른 기호로 묶인다. 이들은 독립 설비가 아니라 밸브의 일부이거나 주석이다.
- **계기 원 일부는 열린 곡선이다.** 묶음 32(PI 원)는 닫힌 경로가 아니라 열린 곡선 하나로 그려져 원 판정에 걸리지 않는다.
- **크기 0 도형.** 탱크 무늬 점 249개가 크기 0인 닫힌 경로로 기호가 된다(묶음 8). 버려야 한다.

## 3. 사전 형식

### 3.1 위치와 묶음

데이터 일원화 안 A에 맞춰 `resources/library/symbols/`에 둔다. `paths.FOLDERS`에 `"기호": Folder("resource", ("resources", "library", "symbols"))` 한 줄을 더하면, `build_package.DATA_DIRS`가 `root == "resource"`인 행을 모두 묶으므로 배포본에 자동으로 들어간다.

```
resources/library/symbols/
├─ bundles.json           묶음 목록과 판(이름, 출처, 쓰는 순서)
├─ common/                묶음 '공통'. ISA·일반 P&ID 기호. 옛 _shape_kind 규칙과 장비 이름 낱말을 옮긴 항목이 여기 있다(S7)
│  └─ <기호>.json
├─ SNP/                   합성 샘플 전용 표기. 아직 만들지 않았다(S7에서 옮긴 규칙 가운데 합성 샘플에만 쓰이는 것이 없었다)
├─ APR1400/               APR1400 DCD 범례·도면에서 얻은 기호
│  ├─ gate_valve.json
│  └─ images/gate_valve.png 예시 그림(긴 변 160px 이하)
└─ <새 발전소>/
```

기호 하나가 파일 하나다. 새 기호를 더하면 파일 하나가 늘어 git 변경이 깔끔하고, 두 사람이 다른 기호를 더해도 충돌하지 않는다.

### 3.2 항목 형식

JSON이다. 저장소의 다른 사전(`registry.json`)과 같고, 배포본에 YAML 해석기를 더하지 않아도 된다. 기계가 읽는 키는 영문, 사람이 읽는 값은 국문이다.

```json
{
  "id": "apr1400.gate_valve",
  "revision": 1,
  "added": "2026-11-09",
  "updated": "2026-11-09",
  "name": {"en": "GATE", "ko": "게이트 밸브"},
  "category": "밸브",
  "role": "symbol",
  "kind": "manual_valve",
  "attributes": {"valve_type": "gate"},
  "match": [
    {"fill": "white", "composition": {"closed_straight": 1},
     "size_pt": [5.9, 6.5], "size_ratio": 1.25, "rotations": "dihedral8",
     "max_distance": 0.8,
     "grid": ["........................", "....##..........##......", "..."]},
    {"fill": "black", "composition": {"filled": 1}, "size_pt": [5.9, 6.5],
     "rotations": "dihedral8", "max_distance": 0.8, "grid": ["..."],
     "set_attributes": {"normal_position": "NC"}}
  ],
  "text": {"inside": null, "forbid_inside": null},
  "sources": [{"set": "APR1400 DCD Rev.3", "figure": "1.7-1", "sheet": "1/4", "page": "1.7-9",
               "bbox_pt": [354.6, 390.2, 360.8, 393.3], "image": "그림/gate_valve.png"},
              {"set": "APR1400 DCD Rev.3", "figure": "도면 표본", "pages": ["007", "013", "015"]}],
  "note": "범례 VALVE SYMBOLS 첫 줄. 검정은 정상 운전 중 닫힘"
}
```

| 키 | 뜻 |
| --- | --- |
| `id` | `<묶음>.<영문 이름>`. 한 번 정하면 바꾸지 않는다(노드 근거에 남음) |
| `revision`, `added`, `updated` | 항목의 판과 날짜. 인식 규칙을 고치면 `revision`을 올린다 |
| `name.en`, `name.ko` | 범례 원문과 국내 용어. 국내 용어는 원자력·공정 실무 용어를 쓴다 |
| `category` | 밸브, 구동기, 계기, 배관 부속, 설비, 연결 표시, 공조, 주석, 버림 |
| `role` | `symbol`(노드가 됨), `actuator`(노드가 되지 않고 옆 밸브의 `actuator_type`·`motive_power` 속성이 됨), `annotation`(옆 기호의 글자·태그 근거), `continuation`(연결 표시), `drop`(버림. 버린 도형은 `drawing.ignored_objects`에 남김) |
| `kind`, `kind_from`, `attributes` | 앱 kind(`registry.json`에 있어야 함)와 붙일 속성. 계기 모양처럼 모양만으로 kind가 정해지지 않는 항목은 `kind` 대신 `"kind_from": "isa_letters"`로 두어 범주(계기)만 확정하고 kind는 ISA 글자 규칙에 맡긴다. 글자로 못 정하면 kind 없음 |
| `match[]` | 모양 서명 견본 여러 개. 하나라도 맞으면 맞음. 견본마다 채움, 구성, 기준 크기 `size_pt`(기호 상자의 [짧은 변, 긴 변], pt)와 허용 비 `size_ratio`, 회전 허용, 거리 상한, 격자(24줄×24칸 `#`/`.`), 맞을 때 덧붙일 속성 |
| `text` | 기호 상자 **안** 글자 조건(정규식). 예: 구동부 `^M$`, 번호 원 `^\d{2,4}[A-Z]?$`. 가장 가까운 라벨이 아니라 상자 안 글자로 본다(§5.2) |
| `sources[]` | 출처(도면 묶음, 그림, 시트, 쪽, 위치)와 예시 그림 경로 |

`match[]`의 견본은 `shape` 값으로 종류가 갈린다. `shape`을 적지 않으면 `grid`다.

| `shape` | 맞히는 것 | 견본에 적는 키 |
| --- | --- | --- |
| `grid` | 구성·크기·격자 거리(§4.1) | `composition`, `size_pt`, `size_ratio`, `rotations`, `max_distance`, `grid`, `set_attributes` |
| `zero_size` | 폭과 높이가 모두 0인 도형 | `set_attributes` |
| `structure` | 추출기가 판정한 구조 특징(S7). 격자로는 가를 수 없는 몸체 수와 배치, 선의 방향을 본다 | `requires`(특징 이름 목록, 모두 있어야 맞음), `order`(정수), `basis`(노드의 `classification_basis`에 남는 글자) |
| `label_words` | 라벨의 장비 이름 낱말(S7) | `words`(영문 대문자 낱말 목록, 모두 있어야 맞음), `order`(정수) |

`structure`와 `label_words` 견본은 격자 매칭에 끼지 않고, 다음 규칙을 따른다.

- 여럿이 맞으면 `order`가 가장 작은 견본이 이긴다. `order`는 `structure`끼리, `label_words`끼리 따로 센다. 같은 종류 안에서 `order`가 겹치면 사전을 읽을 때 오류로 멈춘다.
- `requires`에 쓸 수 있는 특징 이름은 `hazop/extract/symbols.py`의 `STRUCTURE_FEATURES`에 있는 것뿐이다. 다른 이름을 적으면 읽을 때 오류로 멈춘다.
- `structure` 견본의 `basis`는 사전 전체에서 겹치면 안 된다. 구조 규칙으로 정한 노드에는 `symbol_id`가 없어(§4.4), 이 글자가 항목을 되짚는 유일한 단서다. 겹치면 읽을 때 오류로 멈춘다.
- 추출기는 켜진 `structure` 견본과 `label_words` 견본이 각각 하나 이상 있는 사전만 쓴다. 하나라도 비면 코드보다 옛 판 사전으로 보고 오류로 멈춘다. 그대로 쓰면 밸브·계기·설비 분류가 오류 없이 통째로 빠지기 때문이다.

격자는 사람이 텍스트 편집기에서 모양을 알아볼 수 있는 그림이다. 사람은 대개 격자를 직접 고치지 않고 §6의 스크립트가 표본에서 뽑아 넣는다. 사람이 고치는 것은 이름·범주·kind·글자 조건·허용 오차다.

### 3.3 범주와 kind 대응을 한곳에

범주 → kind 대응은 `registry.json`의 클래스 계층이 이미 갖고 있다. 사전 항목은 `kind`만 적고 범주는 레지스트리에서 읽는다(`category` 값은 사람이 읽기 위한 사본이고, `check_symbols.py`가 레지스트리와 어긋나면 실패시킨다). 레지스트리에 없는 kind는 사전에 넣을 수 없다. 새 kind가 필요하면 레지스트리를 먼저 고친다(§8 D4).

## 4. 인식기 구조

### 4.1 모양 서명

추출기가 묶은 기호(`_Sym`) 하나에서 다음을 계산한다.

- **구성.** 닫힌 곡선 수, 닫힌 직선 다각형 수, 열린 선 수(6 이상은 6), 표식 수, 점선 조각 수, 채움(흰·검정).
- **크기.** 기호 상자의 폭·높이(pt).
- **격자.** 상자 긴 변을 24칸에 맞추고 가운데 정렬한 뒤, 선이 지나는 칸과 채운 도형의 **실제 윤곽 안쪽** 칸을 켠다. 곡선은 베지어를 8점으로 펴서 그린다. 지금 `_subpaths`는 곡선의 끝점만 `pts`에 남기므로, 서명용으로 펴 둔 점 목록을 따로 둔다(시제품은 같은 PDF를 다시 읽었다. 구현에서는 `_subpaths`가 함께 내놓는다). 시제품은 채운 도형을 상자로 칠해, 방향만 다른 검은 삼각형(화살촉 좌우)이 같은 서명이 됐다. 구현에서는 윤곽으로 칠한다.

두 격자의 거리는 양방향 평균 챔퍼 거리(칸 단위)다. 회전·뒤집기 8가지 중 가장 작은 값을 쓴다. 같은 최솟값이 여럿이면 고정 순서(r0, r90, r180, r270, 좌우, 상하, 전치, 역전치)의 첫 번째를 고르고, 최솟값이 하나뿐일 때만 회전을 노드 근거에 남긴다(대칭 기호는 `symmetric`). 시제품은 견본 순서에 따라 같은 입력의 회전이 바뀔 수 있었다. 회전을 체크밸브 방향 근거로 쓰는 것은 이 규칙이 들어간 뒤의 일이다.

### 4.2 매칭 순서

1. **원시 요소 단계(씨앗).** 검은 채움 작은 도형을 표식으로 보내기 전에, 사전의 `fill: black` 견본에 먼저 대 본다. 맞으면 표식이 아니라 기호 몸체로 올린다(닫힌 밸브). 그러면 `same_marker`가 밸브를 지나 배관을 잇지 않는다. 크기 규칙으로 버리는 것은 폭과 높이가 모두 0인 도형뿐이다. 시제품은 긴 변 0.5pt 미만을 모두 버렸는데(홀수 쪽 250개, 짝수 쪽 5개), 0.15×0.23pt처럼 양수 크기도 섞여 있어 넓었다. 실제 APR1400의 무늬 점은 폭 0, 길이 0.19~0.27pt인 닫힌 경로다(249개, 모두 탱크 무늬, 그림판으로 확인). 이것은 크기 규칙이 아니라 사전 항목 `common.pattern_dot`(role `drop`)의 견본으로 맞혀 버린다. 버린 도형은 `ignored_objects`에 남긴다(1단계 검토 반영).
2. **기호 단계.** `_group_symbols` 뒤, **기존 규칙이 kind를 정하지 못한 기호에만** 사전을 적용한다. 구성이 같고 크기 비가 허용 안인 견본만 거리 계산을 한다. 기존 규칙이 정한 kind와 사전이 다르게 맞으면 기존 kind를 지우지 않고 미확인 `symbol_conflict`를 남긴다. 기존 규칙을 사전으로 옮기는 S7 전까지는 이 순서가 SNP와 U1의 판정을 지킨다. S7 뒤에는 '기존 규칙'이 공통 묶음의 `structure`·`label_words` 견본을 뜻한다. 순서는 그대로여서, 이 견본들이 kind를 정하지 못한 기호에만 격자 견본을 대 본다.
3. **글자 조건.** 맞은 항목에 `text` 조건이 있으면 상자 안 글자로 확인한다. 조건이 깨지면 그 항목을 빼고 다음 후보를 본다. `kind_from: isa_letters` 항목은 범주만 정하고 kind는 ISA 글자 규칙으로 정한다.
4. **부속 합치기.** `role: actuator`는 노드를 만들지 않고, 닿거나 축으로 이어진 밸브 하나에 `actuator_type`·`motive_power` 속성을 단다(레지스트리에 이미 있는 속성). kind를 올리는 것은 전동 구동부 → `motor_operated_valve`, 다이어프램 구동부 → `air_operated_valve`처럼 범례가 분명히 정한 경우만이다. 솔레노이드는 공기구동 밸브의 파일럿일 수 있으므로(범례 4/4쪽 "SOLENOID VALVE FURNISHED MOUNTED WITH OPERATOR") 다이어프램과 함께 붙으면 `air_operated_valve`에 파일럿 속성만 단다. 전기유압 구동부는 kind를 올리지 않는다. 이어진 밸브가 없거나 둘 이상이면 합치지 않고 미확인으로 남긴다. `role: annotation`(밸브 번호 원)은 지시선으로 이어졌거나, 가장 가까운 밸브까지 거리가 상한 안이고 두 번째 밸브가 그 두 배보다 멀 때만 그 밸브의 태그 근거가 된다. 나란히 놓인 밸브처럼 이 조건을 못 채우면 미확인이다.
5. **기존 규칙 뒤처리.** 사전에 **후보가 하나도 없는** 기호만 지금의 끝막음 규칙 등으로 간다. 사전이 애매하다고 판정한 기호(§4.3)는 기존 규칙으로 보내지 않는다. 기존 규칙을 사전으로 다 옮기면(§7 S7) 이 단계는 지운다. S7은 `_shape_kind`와 `EQUIPMENT_WORDS`만 옮겼다. 끝막음 규칙, 구동부 안 `M` 표기, ISA 글자, TO/FROM 연결 표기는 코드에 남아 있어 이 단계도 남아 있다.

### 4.3 충돌 우선순위

매칭 결과는 셋 중 하나다. **맞음**(항목 하나로 정함), **애매함**(정하지 않고 미확인), **후보 없음**(기존 규칙 뒤처리로).

- 먼저 거리로 순위를 매긴다. 거리 상한 안에서 1등과 2등(다른 항목)의 거리 차가 0.1칸보다 작으면 **애매함**이다. kind 없음으로 두고 미확인 `ambiguous_symbol`에 두 후보를 적는다. 틀린 판정은 차단 결함이므로 모르면 모른다고 남긴다.
- 글자 조건은 순위를 바꾸지 않고 후보를 거른다. 조건이 깨진 후보를 뺀 뒤 위 규칙을 다시 적용한다. 그래서 글자 조건이 있는 먼 항목이 가까운 항목을 이기는 일은 없다.
- 묶음 사이에도 같은 규칙이다. 공통 묶음의 원(계기)과 APR1400 번호 원은 모양이 같아 글자 조건으로만 갈린다. 이런 쌍은 `check_symbols.py`가 "글자 조건 필수" 경고로 잡는다(§8 D3).
- 결과는 견본 순서에 영향받지 않는다. 같은 거리면 항목 id 순, 회전은 §4.1의 고정 순서로 정한다.

### 4.4 판(version)과 재확인

추출 JSON 전체가 노드 근거(`evidence`)까지 포함해 `graph_version`의 해시에 들어간다(`hazop/graph/build.py:77-80`). 추출 JSON에는 이미 `run.rules_version`·`script_version`·`params`가 있다. 사전 판이나 항목의 `revision`을 추출 JSON에 넣으면, 게이트 밸브처럼 거의 모든 도면에 나오는 항목 하나만 고쳐도 거의 모든 PDF 도면의 판이 바뀐다. 그러면 사람이 확정한 검토구간·분석결과가 재확인으로 간다. 그래서 다음과 같이 나눈다.

- 추출 JSON에는 노드별 `evidence.symbol_id`만 남긴다. 항목 판과 사전 판은 남기지 않는다. 예외가 하나 있다. `structure`·`label_words` 견본이 정한 노드에는 `symbol_id`를 남기지 않고, 옮기기 전과 같은 `classification_basis`(`valve_body`, `text_word:PUMP` 등)만 남긴다. 이 노드들은 S7 전에도 코드 규칙이 정하던 것이라, `symbol_id`를 더하면 거의 모든 PDF 도면의 `graph_version`이 바뀌기 때문이다.
- 사전 판(묶음별 내용 해시)은 등록 기록의 추출 실행 정보에 둔다. 해시에 들어가지 않는다. 실제 저장 자리는 추출 결과 폴더의 곁 파일 `extraction_run.json`이다(§8 표 아래 'D8의 실제 저장 자리').
- `symbol_id`를 처음 넣는 S2에서 사전이 분류한 노드가 있는 도면은 판이 한 번 바뀐다. 이 변화는 kind가 실제로 바뀐 결과라 피할 수 없고, S2 완료 기준에서 영향 받는 도면 수를 보고한다(§8 D8).

**사람 수정 기록과의 관계.** 노드 id는 기호 순번이다(`pdf-p%d-sym-%04d`, `build_extraction`). 사람이 원본 대조에서 고친 기록(`hazop/extract/corrections.py`)은 대상 노드의 kind와 위치 지문이 같아야 적용된다. 크기 0 도형 버리기, 검정 밸브 기호화, 구동부 합치기는 순번을 밀고, 사전이 kind를 정하면 지문의 kind가 바뀐다. 그대로 두면 기존 수정 기록이 "대상이 바뀜"으로 무더기로 빠진다(데이터 손실). 그래서 S2~S5의 완료 기준에 "기존 수정 기록 적용 수 후퇴 없음"을 넣고, 다음 둘 중 하나를 S2 설계에서 정한다(§8 D14).

- 노드 id를 순번이 아니라 기호의 위치·구성에서 만든 안정된 값으로 바꾼다.
- 순번은 그대로 두고, 사전이 바꾼 노드에 대해 수정 기록의 지문을 새 결과에 다시 맞추는 이전 절차(백업 후 적용, 다시 돌려도 같은 결과)를 둔다.

- **SNP 후퇴 0.** `scripts/check_snp_baseline.py`가 그대로 통과해야 한다. 이 검사는 종류별 수·태그 집합 같은 집계만 보므로, 노드끼리 태그가 바뀌거나 연결·속성이 달라지는 것은 놓친다. 그래서 SNP 샘플의 추출 JSON과 `graph_version`이 HEAD와 바이트 단위로 같은지 보는 비교를 S2에 더한다. 사전은 기존 규칙이 못 정한 기호에만 적용하므로(§4.2) SNP에서는 같아야 한다.
- **APR1400 후퇴 금지 기준값.** `scripts/check_apr1400.py`의 지표(tag_exact, connectors_detected, paired 등)는 후퇴하면 실패다. 여기에 더한다.
  - `unclassified`(낮을수록): 이 지표는 이미 계산하고 있다. 후퇴 금지 목록(LOWER)에 넣는다.
  - `kind_wrong`(정답 대비): 정답 쪽(`tests/fixtures/apr1400/answer_key/`)에 노드별 정답 kind와 속성(`valve_type`, `normal_position`, 구동부, 밸브 번호 귀속)을 더한다. 판정은 합계가 아니라 **노드마다** 한다. 전에 맞던 노드가 틀리게 바뀌면 다른 노드가 고쳐졌더라도 실패다. 게이트·글로브는 kind가 같은 `manual_valve`라 `valve_type`까지 봐야 구별된다.
  - 수정 기록 적용 수: 기존 사람 수정 기록 중 새 결과에 적용되는 수가 줄면 실패(§4.4).
- **사전 자체 검사.** `scripts/check_symbols.py`: 형식, id 중복, kind가 레지스트리에 있는지, 같은 묶음 안이나 묶음 사이 두 항목의 견본 거리가 0.1칸 미만인 쌍(글자 조건 없이는 구분 못 하는 항목) 경고.
- **배포본.** 배포 실행 파일에서 사전을 읽어 APR1400 정답 쪽 하나를 판정하는 검사, 사전 파일이 없거나 깨졌을 때 조용히 넘어가지 않고 오류로 멈추는지 보는 검사를 `verify_bundle`에 더한다.
- **이 검사 밖.** 판정한 kind·고장 위치가 HAZOP 분석의 원인·결과(공기 상실 → 고장 위치 → 유량 상실·역류)로 맞게 이어지는지는 기호 사전이 아니라 분석 단계 검사의 몫이다. 사전이 붙인 속성이 분석 입력에 들어가는 첫 구현 때 그 단계의 검사에 사례를 더한다.

| 구동부, 노드가 아니라 밸브 속성으로(§4.2 4번) | 332 | 5.8% |
| 번호 원 모양이지만 글자가 ISA 꼴(FE·SY 등) | 174 | 3.0% |
| 버림(긴 변 0.5pt 미만) | 5 | 0.1% |
| 애매해서 안 정함 | 0 | 0% |
| 후보 없음 | 2,642 | 46.3% |

정리하면 다음과 같다.

- 레지스트리를 고치지 않고 기존 kind로 확정되는 것은 1,806개(−31.6%)다.
- D4의 새 kind까지 더하면 2,204개(−38.6%)다.
- 구동부 합치기와 버림까지 더하면 미분류에서 빠지는 기호는 2,541개(−44.5%)다.
- 계기 범주 351개와 ISA 꼴 번호 원 174개는 계기로 넘어가지만, 지금 ISA 규칙(U1 포함)은 FE·SY·TEW·ZL 같은 글자에 kind를 주지 않는다. 그래서 감소에 넣지 않았다. ISA 규칙을 넓히면 더 줄어든다(이 문서 범위 밖).

검토 전 첫 측정은 묶음을 전체 쪽으로 만들어(대표의 절반이 짝수 쪽) 누수가 있었다. 그 값(짝수 쪽 매칭 3,116개)과 홀수 전용 묶음 값(3,066개)은 50개 차이다. 누수 영향은 작았다.

**거리 상한을 바꿔도 거의 같다.** 첫 측정 기준으로 0.6칸 3,074개, 0.8칸 3,116개, 1.0칸 3,141개다. 묶음 사이가 충분히 떨어져 있어 문턱에 민감하지 않다.

### 5.2 정확도

정밀도는 아직 재지 못했다. 독립 정답이 없기 때문이다. "묶음 라벨과 같음" 같은 자동 지표는 묶음과 매칭이 같은 거리를 쓰므로 순환 논리다.

대신 첫 측정에서 항목마다 짝수 쪽 매칭을 10개씩 고르게 뽑아 그림으로 봤다(`out/eval_sheets/`). 약 210개 중 9~10개가 틀렸다. 이 표본은 항목마다 같은 수라 빈도 가중이 아니고, 라벨을 붙인 사람이 직접 판정했으며, 표본 오차가 ±3%p쯤 된다. 그래서 전체 정밀도 값으로 쓰지 않는다. 오류가 어디서 나는지 보는 데까지만 쓴다.

- 틀린 것 대부분은 글자 조건이다. FE·PDIS 계기 원이 밸브 번호 원으로 갔다. 시제품이 상자 **안** 글자가 아니라 추출기가 붙인 가장 가까운 라벨을 봤기 때문이다. 회전된 'SX' 글자도 읽지 못했다(시험 보고서 결함 D1과 같은 원인). 그래서 형식의 글자 조건은 상자 안 글자로 정했다.
- 같은 도면 안 연결 문자(육각 화살)에 다른 상자 2~3개, 플러그 밸브에 마름모 표지 1개, 솔레노이드에 'F' 상자 1개가 섞였다.
- 독립 정밀도는 S1의 노드별 정답(§4.6 `kind_wrong`)으로 잰다. 이 그림판의 판정은 S1 정답을 만들 때 출발점으로 쓴다.

### 5.3 범례만으로는

범례에서 뽑은 견본 300개만 쓰면 짝수 쪽 미분류 5,708개 중 1,638개(28.7%)가 맞고, 1,696개는 애매해서 안 정해진다. 범례에는 열림·닫힘, LO·LC처럼 모양이 같고 글자나 채움만 다른 기호가 많기 때문이다. 모양 계열은 맞는다(동심 리듀서 141개 중 128개가 사람이 라벨 붙인 리듀서 묶음). 이름은 자동 짝 오류를 그대로 물려받는다. 범례는 후보와 예시 그림의 출처로 쓰고, 견본은 실제 도면 표본에서 뽑는 것이 낫다.

### 5.4 숫자의 한계

- 측정한 것은 사전 항목에 맞은 기호 수다. 앱이 kind를 실제로 바꾼 결과가 아니다. 구동부 합치기·검정 밸브 기호화 뒤에는 노드 수 자체가 바뀌므로, 구현 뒤 숫자와 바로 견줄 수 없다. 정답 kind 목록이 없어 정밀도도 전수로 재지 못했다. 구현 첫 단위가 노드별 정답을 만든다(§7 S1).
- 라벨은 상위 60묶음 중 33묶음만 붙였다. 상위 200묶음까지 붙이면 덮는 범위가 85%까지 오를 수 있다(§2.2 분포에서 나온 추정).
- 원시 요소 단계(검정 밸브 씨앗)는 시제품에 넣지 않았다. 검정 밸브는 지금 기호가 아니어서 미분류 수에 잡히지 않는다. 구현 뒤 기호 수 자체가 늘어난다.
- 시험 연결(test_connection)은 첫 측정에서 50개 맞았지만, 홀수 전용 묶음에서는 80% 라벨 기준을 넘는 묶음이 없어 0개다. 견본이 적은 항목은 측정 방식에 따라 크게 흔들린다.

## 6. 새 기호 추가 절차

새 도면 묶음이 오거나 미분류가 눈에 띄면 다음 순서로 돈다. 모두 다시 돌릴 수 있는 스크립트이고, 같은 입력이면 같은 결과를 낸다.

1. **범례 수집(범례가 있으면).** `python scripts/symbols/harvest_legend.py --set <묶음> --pages <범례 PDF…>` → 작업 루트의 `symbol-candidates/<묶음>/범례.csv`, 잘라 낸 그림, 그림판 HTML. 이 폴더는 S6에서 `paths.FOLDERS`에 `work` 행으로 더한다(git이 보지 않는 작업 산출물).
2. **미분류 묶기.** `python scripts/symbols/cluster_unclassified.py --set <묶음> --input-dir <도면 폴더>` → 묶음 순위표(CSV)와 그림판 HTML(묶음마다 서로 다른 쪽 예시 8개, 범례 후보 그림 나란히). 상위 묶음이 덮는 비율을 함께 보여 준다.
3. **사람이 이름 붙이기.** 그림판을 보고 `라벨.csv`에 `순위, 사전 id, 국내 용어, 범주, kind, 글자 조건, 확신`을 적는다. 같은 기호의 여러 묶음은 같은 id로 적는다. 모르면 비워 둔다.
4. **사전 항목 만들기.** `python scripts/symbols/add_symbols.py --set <묶음> --labels 라벨.csv` → 묶음 표본에서 서로 다른 격자를 빈도순으로 골라 `resources/library/symbols/<묶음>/<id>.json`과 예시 그림을 만든다. 이미 있는 항목이면 견본만 더하고 `revision`을 올린다.
5. **검사.** `python scripts/check_symbols.py`(형식·충돌), `python scripts/check_snp_baseline.py`(후퇴 0), `python scripts/check_apr1400.py --input-dir …`(후퇴 금지 기준값, `unclassified`·`kind_wrong`·수정 기록 적용 수 포함). 좋아진 값은 `--update`로 기준값을 올린다.
6. **커밋.** 사전 파일·그림·기준값을 한 커밋으로. 메시지에 묶음, 더한 항목 수, 미분류 변화를 적는다.

### 앱 안 화면이 필요한가

지금은 두지 않는 것을 권한다(§8 D9). 사전은 git에서 검토하고 회귀 검사를 거쳐 커밋해야 의미가 있다. 앱 안에서 고치면 그 단계를 건너뛴다. 사용자가 개발 환경 없이 기호를 더해야 할 때가 오면, 앱은 "미분류 묶음 보기와 라벨 CSV 내보내기"까지만 하고 사전 반영은 위 스크립트로 하는 방식을 다시 검토한다.

### 7.1 구현 기록 (2026-11-09~10)

- **1단계(595a70b).** 사전 데이터 21항목, `hazop/extract/symbols.py`, `scripts/symbols/`의 묶기·항목 만들기 도구, `scripts/check_symbols.py`, 폴더 표 두 줄(`기호`, `기호후보`).

  - 사전이 연결 표시로 본 기호도 화살표 목록에 넣어, 이웃 화살표의 계통 글자를 가져가지 않게 했다.
  - 레지스트리 0.8.0: `damper`(밸브 아래)와 `test_connection`(배관 부품 아래)을 더했고, `valve_type`에 `plug`를 더했다.
- **D14는 ②안으로 정했다.** 버린 기호도 노드 번호를 비워 두어 다른 기호의 번호가 밀리지 않는다. 분기점 번호는 기호 수에서 이어 붙인다. 사람 수정 기록의 지문 비교(`corrections._same`)는 없던 kind·태그가 새로 채워진 것을 대상이 바뀐 것으로 보지 않는다. 위치(`at`)는 여전히 같아야 한다. ①안(위치 기반 노드 id)은 모든 PDF 도면의 노드 id와 판을 한 번에 바꾸므로 고르지 않았다. 끝 기호가 계기로 밝혀져 같은 선이 `physical_connection`에서 `measurement_connection`으로 바뀐 것도 같은 대상으로 본다. 사람이 종류를 바꾸면 새 종류에 없는 레지스트리 속성(사전이 붙인 `valve_type` 등)은 지운다.
- **버린 무늬 점에 걸린 사람 수정은 '대상 없음'으로 빠진다.** 무늬 점은 폭 0, 길이 0.3pt 안팎인 탱크 해칭 조각이라 그 위에 의미 있는 수정이 있을 수 없다고 보고 받아들였다(2단계 검토 지적, 총괄 판정). 무늬 점 근처 글자는 버린 점이 가져가지 않고 독립 글자로 남는다.
- **2단계 검토(적대 검토 2, Codex 1)에서 바꾼 것.**
  - 'PC'·'IC' 상자는 범례의 격납 관통부 표시였다. 제어 장치로 읽어 격납부를 지나는 공정 배관 137개가 측정 연결로 바뀌었다. 그래서 `apr1400.control_device_box`를 껐다.
  - `apr1400.test_connection`도 껐다. 견본이 덕트 끝·배관 캡까지 맞혀 103개 중 약 84개가 틀렸다.
  - 구동부 기호(전동·다이어프램·솔레노이드·전기유압)가 몸통 긴 변 두 배 안에 있는 밸브는 수동 밸브로 정하지 않는다. kind를 비우고 미확인 `actuated_valve_pending`을 남긴다. 구동부를 밸브에 합치는 S5에서 정한다.
  - 끝막음 뒤처리 규칙은 사전에 후보가 없을 때만 쓴다(§4.2 5번).
  - 버린 무늬 점은 글자 후보에서 빼서 근처 글자를 가져가지 않게 했다.
  - 켜진 항목의 kind와 열거형 값은 추출기가 사전을 읽을 때 레지스트리와 대조한다.
  - 여러 쪽 추출(`scripts/extract_pdf.py run_pages`)은 쪽을 처리하기 전에 사전을 먼저 읽는다. 사전이 깨졌으면 이전 결과를 지우기 전에 멈춘다.
  - 구동부·전기유압 기호 노드는 kind 없이 `symbol_id`만 단 채 남는다. S5에서 밸브에 합친다.
  - 도면 한 곳(087쪽 Y0085)은 열린 댐퍼 모양 옆에 'NC'가 적혀 있다. 지금은 모양대로 `NO`를 단다. 글자와 모양이 어긋날 때 미확인을 남기는 일은 후속으로 둔다.
- **이번에 하지 않은 것.**
  - 밸브 번호 원·타원(`annotation`)은 레지스트리에 넣지 않고 꺼 두었다. 노드로 만들면 그래프에 가짜 설비가 생기므로, 밸브에 합치는 S5와 함께 켠다.
  - 검정(닫힘) 밸브 씨앗(§4.2 1번)은 사전에 검정 견본이 아직 없어 미뤘다. 표식(화살촉) 후보를 묶어 보여 주는 도구 모드가 먼저 필요하다.
  - 사전 판을 등록 기록에 남기는 일(D8)은 아직 하지 않았다. 지금은 노드의 `evidence.symbol_id`만 남는다.
- **S7 구현(2026-11-11, 16c3536).** 상세와 전후 대조는 `docs/2026-11-11-unit-f1/README.md`에 있다.
  - `_shape_kind`와 `EQUIPMENT_WORDS`를 지우고 공통 묶음에 항목 19개를 더했다(구조 규칙 8개, 장비 이름 11개). 격자 견본으로 바꾸지 않고 견본 종류 `structure`·`label_words`를 더해 옮겼다(§3.2). 격자 거리로 바꾸면 APR1400 143쪽 결과가 그대로라는 보장이 없어서다.
  - SNP 추출 JSON·`graph_version`과 APR1400 143쪽 쪽별 결과는 옮기기 전과 같다. 공통 묶음의 판만 바뀌었다.
  - 기호가 하나라도 있는 쪽은 이제 사전을 꼭 읽는다. 사전이 없거나 깨졌거나, `structure`·`label_words` 견본이 없는 옛 판이면 오류로 멈춘다.
- **D8 구현(2026-11-11).** 사전 판을 추출 결과 폴더의 `extraction_run.json`에 남긴다. 자리와 형식은 §8 표 아래에 있다. 위 '이번에 하지 않은 것'의 D8 줄은 이것으로 끝났다.
- **S5 구현(2026-11-10).** 상세와 측정은 `docs/2026-11-10-apr1400-unknowns/README.md` 3g에 있다. 위 §4.2 4번과 다르게 정한 것은 셋이다.
  - 솔레노이드 혼자는 합치지 않는다. 범례 4/4의 스프링 복귀·복동 실린더 구동부에서 솔레노이드는 파일럿이라, 혼자 붙었다고 `solenoid_valve`로 올리면 틀린다(037·138쪽).
  - 밸브 번호 원은 태그를 만들지 않는다. 원 안에는 숫자만 있고 계통 접두는 도면에 없다. 번호는 밸브의 `evidence.ident_number`로 남긴다. 사전 항목 `apr1400.ident_bubble_circle`은 여전히 꺼 두고, 추출기가 원 안 글자로 직접 고른다.
  - 합칠지는 노드 kind가 정해진 뒤 정한다. 체크 밸브, 글자로 정한 펌프 등 구동부를 받을 수 없는 kind면 합치지 않고 구동부를 노드로 남긴다.

### D8의 실제 저장 자리 (2026-11-11 구현)

D8과 §4.4는 사전 판을 '등록 기록의 실행 정보'에 둔다고 적었다. 구현하면서 보니 그 자리가 코드에 없었고, 등록 쪽에 새로 만들면 다른 규칙과 부딪혔다. 그래서 사전 판은 추출 결과 폴더의 곁 파일에 남긴다(총괄 결정 2026-11-11). D8이 지키려던 것, 곧 사전 판이 추출 JSON과 `graph_version`에 들어가지 않는다는 점은 그대로다.

- **자리.** `<작업 루트>/output/extract/<이름>/extraction_run.json`. 추출 단계가 `extraction.json`을 쓴 직후에 쓴다(`hazop/extract/runinfo.py`, 부르는 곳은 `scripts/extract_pdf.py`·`extract_drawio.py`·`extract_raster.py`의 `run_one`). 추출하지 못한 쪽(`not_extracted.json`이 남는 쪽)에도 쓴다. 등록 없이 돌린 추출(`output/adapter/…`)도 같은 이름으로 결과 폴더에 남는다.
- **등록 기록에 두지 않은 까닭.**
  - 등록정보(`store/<프로젝트>/registrations/<자료 ID>/<버전>.json`)는 추출 전에 쓰고, 등록이 끝난 버전은 고치지 않는 것이 규칙이다. 추출할 때마다 고치면 그 규칙이 깨진다.
  - 자료 목록(`store/<프로젝트>/registry.json`)은 등록 모듈만 쓴다. 추출 단계가 함께 쓰면 한 파일을 두 단계가 고치게 된다.
  - 사전 판을 알고 싶은 단위는 추출 실행이다. 결과 옆에 두면 다시 추출할 때 그 실행의 값으로 저절로 바뀐다.
- **`graph_version`과의 관계.** 그래프는 `extraction.json`만 읽는다. 곁 파일이 있든 없든 `extraction.json`의 바이트와 `graph_version`은 같다(시험 `tests/test_extraction_run.py`).
- **형식.** 키를 정렬한 JSON이고 원자적으로 쓴다(`store_io.write_json`). 사람이 고치는 파일이 아니다.

  ```json
  {
    "extracted": true,
    "extraction_run_id": "extract-pdf-SNP-M-102-p0-…",
    "extractor": "pdf_vector",
    "schema_version": "1",
    "symbol_dictionary_versions": {"APR1400": "2c997ba7e6ce", "공통": "ac25f22101ce"},
    "written_at": "2026-11-11T01:02:03Z"
  }
  ```

  | 키 | 뜻 |
  | --- | --- |
  | `extractor` | 추출기 종류. `pdf_vector`, `drawio`, `raster` |
  | `extracted` | 이 실행이 `extraction.json`을 썼으면 `true`, 추출하지 못해 `not_extracted.json`을 남겼으면 `false` |
  | `extraction_run_id` | `extraction.json`의 같은 값. 추출하지 못했으면 `null` |
  | `symbol_dictionary_versions` | 이 실행이 읽은 기호 사전의 묶음별 판(묶음 이름 → 내용 해시 앞 12자). 사전을 쓰지 않는 추출기(`drawio`)는 `null` |
  | `written_at` | 쓴 시각(UTC) |
  | `schema_version` | 이 파일 형식의 판 |

- **다시 추출하면 덮어쓴다.** 지난 실행의 값은 남기지 않는다.
- **이 파일이 없는 폴더.** 이 기록을 두기 전에 만든 추출 결과에는 파일이 없다. 앱과 검사는 이 파일을 읽지 않으므로 그대로 읽힌다. 사전 판을 알 수 없을 뿐이다.
- **작업 산출물이다.** `output/` 아래라서 작업 루트를 지우거나 다시 추출하면 사라지거나 바뀐다. 등록 저장소에는 남지 않는다.
- **하지 않은 것.** 화면이나 탐색기에서 이 값을 보여 주는 일은 하지 않았다(후속).
